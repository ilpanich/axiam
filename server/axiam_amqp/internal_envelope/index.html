The signed envelope of the server-internal queues (SA-14, N3).

axiam.mail.outbound and the four outbound kinds’ queues (axiam.webhook, axiam.ssf_push, axiam.scim_push, axiam.ciba_ping and their retry queues) are written and read only by AXIAM itself, yet what their consumers do with a message is the server’s most trusted output: tenant-branded mail through the tenant’s provider, webhook POSTs signed with the webhook’s secret, Security Event Tokens signed with the deployment key. Until SA-14 they decoded plain JSON, so broker write access to a queue was control-plane authority.

Every message on those queues now travels inside an InternalEnvelope carrying the same §8 v2 protections as the authorization and audit queues — an HMAC-SHA256 over the canonical JSON, a key_version, a per-message nonce recorded in the durable replay store, and an issued_at freshness gate — with one difference that is the point of this module: the key is server-only. It is derived from the master key under a distinct HKDF label (derive_internal_key), not from a tenant’s subkey, so the subkey a tenant’s own producers hold for the authz and audit queues cannot sign a message here. The purpose (one per queue family) is mixed into the derivation as well, so a signed mail message cannot be replayed onto a webhook queue or the reverse.

The body inside the envelope is exactly the JSON each queue carried before (OutboundMailMessage, WebhookMessage, OutboundMessage), so the envelope adds authentication without redefining any message.

Three things differ from the SDK-facing queues because these are durable work queues, where a message waits for reasons that are not tampering:

  • Age, not skew. A message is admitted while issued_at is at most max_age (AXIAM__AMQP__INTERNAL_QUEUES__MAX_AGE_SECS, 24 h by default) in the past — a consumer outage, a backlog or head-of-line blocking in a retry queue must not dead-letter queued mail — and at most the replay skew in the future (QR1-2, SR1-2). Its nonce is kept for max_age.
  • A redelivery is not a replay. A nonce already recorded is admitted when the broker marks the delivery redelivered — a consumer crashed before it settled, or requeued the original on purpose (CQ-B49) — a flag only the broker sets (SR1-1). A republished copy is a replay.
  • The received bytes are verified (split_trailing_signature), not a re-serialization of the parsed body, whose floats serde_json does not guarantee to reprint identically (QR1-9).

Rolling upgrade. A consumer verifies every envelope it receives. What it does with a message in the old, un-enveloped shape is AXIAM__AMQP__INTERNAL_QUEUES__REQUIRE_SIGNATURE: true (the default) rejects it; false accepts it with a warning, for the one deployment in which old and new replicas share the queues (see the upgrade notes in docs/deployment/README.md).
