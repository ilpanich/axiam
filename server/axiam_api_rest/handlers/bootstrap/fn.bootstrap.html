POST /api/v1/admin/bootstrap — first-run admin setup.

Creates the initial admin user with the super-admin role and seeds the default permission set. First-super-admin creation is atomic (SECHRD-04 / D-03c): a uniqueness-invariant bootstrap_lock CREATE inside the same transaction means at most one admin is ever created; no partial admin or orphan role RELATE can result. No token is issued — the user must authenticate via /api/v1/auth/login (D-11).

Mandatory gate (D-03a, SA-01): ALWAYS requires a valid, unconsumed setup_token. When AXIAM_BOOTSTRAP_ADMIN_EMAIL is set it is an additional restriction: the request email must match it. The email is not a credential and never replaces the token. The token is checked first, and every gate refusal is the same 403 with the same reason, so a caller without the token learns neither whether the email restriction is set nor whether a guessed address matches it.

A call after a successful bootstrap is refused 403 by the gate — the first call consumed the token, and the gate also refuses any token once bootstrap_lock:global exists; 409 is answered only to the loser of two calls racing with the same still-unconsumed token.
