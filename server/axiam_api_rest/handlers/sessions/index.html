Session inspection for administrators.

One endpoint: the sessions a user currently holds. It exists because of T-254 — a refresh token presented after it had already been rotated leaves a marker on the session it belongs to, and a marker nobody can read is not a control. The rest of the row is what an administrator needs to make sense of that marker: when the session was created, when the end user actually authenticated, where from.

§What is deliberately not here

The session token, in any form. Session::token_hash is the stored half of a live credential and browser_token_hash is the stored half of the OP browser cookie; neither is projected into the response type, so neither can be leaked by a future field being added to a passthrough serialization (D-03c, SECHRD-06).

Any write. Ending a session is POST /auth/logout-all and the account lifecycle around it; this is a read.
