Answer a role write that the gate cleared and its own transaction then refused because what the gate read had changed by the time it ran (R110W6-04, #701).

The gate decides a role write — a grant or revoke, an assignment or unassignment, an is_global update, a delete — on the role’s grants, holders and scope, read before the write. Two writes to one role can each pass it on a state the other is about to change (a network:join grant and the writer assigning itself the role; a grant and a group assignment; …). So the gate hands the write a claim on the role’s epochs (GateClearance::role_claim), the *_claimed repository writes compare it inside their transaction, and a write that lost comes back as AxiamError::Conflict (“the role changed since it was read …”). That answers 409 with reason_code stale_version — the network routes’ sub-code for “read again, decide again” (contract §36.3 rule 2): sent again, the request goes back through the gate, which decides on the role as it now is. It is audited as the gate audits its own refusals: one network_role.*_refused row, outcome denied, with the internal rule (version:stale, as the network routes record a stale write), the reason and the values.

Any other error is returned unchanged, unaudited, as it was before.

error itself, when it is not that conflict or write is not a role write.
