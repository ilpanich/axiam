Module network_gate 

Source
Expand description

The REST side of the network write gate (RADIUS Live profile, W6.2).

Every handler that can create a reply profile, a segment, a network-sensitive grant or assignment, or a certificate binding — and every generic handler that could reach into the reserved network: namespace or /network subtree — calls authorize before its repository write. The decision itself is axiam_authz::network_gate::authorize_network_write (design note §5.1: one domain function, not handler logic); this module only supplies its reads from AppState, writes the audit row of a refusal (§5.4) and turns the refusal into the response.

tests/network_gate_enumeration_test.rs reads the sources and fails if a write of that kind reaches its repository from a function that does not call authorize first (the T-429 lesson); segment and profile writes cannot even compile without the clearance authorize returns.

write_and_record
Run the repository write of a network-sensitive write that the gate cleared, and record it once it landed (R110W6-06, #703, T-484): one network_role.assigned / .unassigned / .granted / .revoked / .deleted or certificate_binding.bound row (one of the six), with the role, the grantee, the node and the network: permissions the write conferred (or removed); an assignment’s row also carries exemption, the named exemption it cleared under (organization-bootstrap) or null. Without it a cleared write is visible only in the route’s generic request row, which says neither that it touched the network namespace nor where a join landed.
