Expand description

append_blocking on the runtime’s blocking pool, for a caller on an async task (a request handler): the file I/O, including the sync, does not hold the worker. Returns when the line is written and synced.

The write runs to completion even if the caller is dropped meanwhile, and a task that panicked or was cancelled is reported as an I/O error, the same as a write that failed. Needs a Tokio runtime.

An I/O failure is logged here, inside the blocking task, so the line does not depend on the caller still being there to read the result (#690): it names the path and the I/O error and nothing of the record. The caller therefore does not log it again. The other failure, a write task that panicked, is only seen by the awaiter below, so it is logged only if the caller is still there; when the caller was cut, the panic hook alone reports it.
