Expand description

The most rows the worker writes in one statement.

The worker appends whatever is already queued when it is ready for more, up to this many rows, with one [AuditLogRepository::append_many] — one round trip — instead of one round trip per row. It never waits to fill a batch, so a quiet server still writes each row as it arrives. 64 is past the knee measured in claude_dev/db-query-optimization.md: by then the statement’s fixed cost is a few percent of the batch’s, and a batch the store refuses is retried row by row, which a smaller batch makes cheaper.
