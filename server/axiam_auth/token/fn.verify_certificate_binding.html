verify_token_binding for a validator that can check a client certificate and nothing else (X5.1, RFC 8705 §3.2).

Retained because it is a genuinely different capability, not merely an older spelling: a resource server behind an mTLS listener with no DPoP support can check x5t#S256 and cannot check jkt. Calling this expresses exactly that, and — crucially — a jkt-bound token reaching it is refused, because a validator that cannot check a constraint must not honour a token that carries it. That refusal is the whole point of keeping the narrower entry point rather than quietly widening every caller to the new one.
