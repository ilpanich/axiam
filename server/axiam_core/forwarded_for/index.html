Which transport peers may speak for the client in X-Forwarded-For (T-212, R110-01, #711, #686).

Every per-address rate limit keys a request on the rightmost untrusted X-Forwarded-For hop (AXIAM__RATE_LIMIT__TRUSTED_HOPS). That is right behind an appending proxy, and wrong on a connection that reaches the listener with no proxy in front: there nothing appends to the header, the rightmost entry is whatever the caller wrote, and a caller who rotates it gets a fresh bucket per request.

TrustedProxies (AXIAM__RATE_LIMIT__TRUSTED_PROXIES, a comma-separated list of CIDR blocks) names the peers whose header is read at all. A request from a listed peer is keyed exactly as before, under TRUSTED_HOPS; a request from any other peer is keyed on the peer, whatever it wrote. With the list empty — the default — every peer’s header is read, which is what the server did before the list existed: the shipped topologies all put an appending proxy in front, and one of them (k8s/) re-encrypts to the server’s native TLS listener, so “native TLS on” does not mean “no proxy”. The boot WARN of TrustedProxies::boot_warning is the empty list’s other half.

The value none (case-insensitive, the whole value) says the opposite of the empty list: no proxy sits in front, so no peer’s header is read and every request is keyed on its own address (#758 (a)). It is a stated choice, so it draws no WARN; mixed with CIDR blocks it is refused.

The REST and gRPC extractors are siblings that may not depend on each other, so the variable and the rule live here, below both, and both read TrustedProxies::configured — one parse per process.
