Module limiter_sweep 

Source
Expand description

The registry of in-process rate-limiter maps that need sweeping (#673, R110W2-05).

A keyed governor limiter keeps one cell per key it has seen, and neither actix-governor nor tower_governor ever evicts one. The key is an address (which an IPv6 sender rotates at will) or, on the five federation routes, a verified principal, so every map grows with the number of distinct keys seen since start. A cell replenishes within a minute, after which it carries no information a fresh cell would not.

Each limiter’s owner registers one closure here when it builds the limiter; one interval task calls sweep_all. The REST and gRPC crates are siblings that may not depend on each other, so the registry lives below both, and it holds closures rather than limiters so that this crate needs no governor.

A closure holds its limiter by Weak, so the registry never keeps a map alive: when the server (or a test’s app) that built it is dropped, the closure reports itself dead and the next sweep forgets it.
