Write the tree and each segment’s envelope.

It also guards the tenant’s network policy, the Session-Timeout cap (network.session_timeout_max_secs): the write gate asks for it at the /network root when PUT /api/v1/network/policy is called, and there is no separate constant for the cap.

The maintainer’s correction of 2026-10-15 (plan section 13.6). The first reading guarded the cap with network:admin, which is administrative login to a segment’s NAS devices and is not grantable under option B (it is in NETWORK_ADMIN_CLASS_ACTIONS; the grant gate refuses an allow of it and the seeder withholds it), so the cap was writable by nobody. The cap is the Session-Timeout envelope every reply profile is clamped to, envelopes are this permission’s (“each segment’s envelope”), and H3 keeps envelope writers apart from profile writers (NETWORK_PROFILES_WRITE). A holder of the profile permission alone therefore cannot write the cap.

Unlike network:admin it can be held: it is grantable and delegable under the section 5.3 bound (“you delegate only what you hold”, it is in NETWORK_META_ACTIONS) and the seeded super-admin holds it (SEEDED_SUPER_ADMIN_NETWORK_ACTIONS). Only a grant at the /network root counts for the cap: one at a site below it does not, and a deny of it at the root refuses the write (deny-override).
