pub fn select_placement(
    segments: &[NetworkSegment],

Expand description

Choose the segment a device is placed on (design note §4.3 steps 2 to 5).

segments[i] is a candidate when it is enabled, joinable[i] (the subject’s check_access(network:join, segment) answered Allow, with deny-override in force) and usable[i] (its profile passed re-validation). Among access candidates the lowest rank wins (unique per site, so the choice is decided at write time, not by query order); a quarantine candidate is used only when no access candidate remains — which is what deny-override makes the case for a quarantined device (§4.4), so quarantine needs no precedence rule of its own. Two quarantine candidates at one site are ordered by name. None is “no candidate”: an Access-Reject, with no fallback segment.

The three slices are read in step; a length mismatch is no candidate.
