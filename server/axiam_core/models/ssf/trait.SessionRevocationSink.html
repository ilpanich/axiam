Expand description

The session-revocation port (D-52): the only way a CAEP session-revoked event is produced.

SessionRepository calls it from exactly the three paths that publish to the revocation feed — invalidate, invalidate_user_sessions and invalidate_user_sessions_except — after the revocation has committed, with the sessions that really were removed. It is never called from consume or consume_by_token_hash (a redemption is not a revocation), nor by expiry, and it does not depend on revocation_feed_enabled.

A sink must not fail the revocation it reports: it returns nothing, and logs what it cannot do.

Whether the sink will do anything with a revocation. A repository reads a session’s user (to name it) only when this is true, so a sink that is not wired costs the revocation path nothing.
