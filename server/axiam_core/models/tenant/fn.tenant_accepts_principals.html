Whether tenant admits its own principals: sign-in, token issuance, refresh and API requests (SA-13, N16, D-3).

The one predicate every authentication door asks — password, OPAQUE, WebAuthn, federation and social sign-in, the token endpoint for every grant, refresh, device mTLS, SCIM token resolution, the REST principal extractor, the gRPC listener and AMQP authorization requests — so the doors cannot come to disagree about what suspension means. A door that refuses answers crate::error::AxiamError::TenantSuspended (tenant_suspended).

A TenantStatus::Suspended tenant keeps its data, and organization principals — who live in the organization’s own tenant, not this one — keep reading it and can set it back to TenantStatus::Active. A tombstoned tenant is not this predicate’s to answer: every read filters it out, so a door never holds one.
