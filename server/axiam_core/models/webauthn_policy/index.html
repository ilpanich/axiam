Per-tenant WebAuthn attestation policy and the pure policy decision function (X3, D5/D6/D8).

This does not live inside SecuritySettings (crate::models::settings): that model’s org/tenant inheritance is validated “tenant override may only be more restrictive than the org baseline”, which requires a total order on every field. AAGUID allow/block lists have no such order — comparing two arbitrary lists for “more restrictive” has no obviously-correct semantics — so a bespoke comparator would have to be invented with no clear right answer. Org-level baselining of the attestation policy is deferred; this ships tenant-only for now (see the admin guide for the documented trade-off).
