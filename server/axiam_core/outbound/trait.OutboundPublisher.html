Expand description

Enqueue an outbound delivery. The producer side of the dispatcher.

Best-effort from the caller’s point of view: a producer is a side effect of some other operation (a revocation, a user update) and must not fail that operation because the broker is unavailable. Log the error and carry on, as WebhookDeliveryService::emit does.

Implementations route by OutboundMessage::kind and must enqueue the message with attempt as given (producers pass 0). The enqueue is durable: Ok(()) means the broker confirmed it.

§Bulk producers (R101W4-01, R101-01)

A producer that enqueues many messages in one run — a SCIM reconciliation (one reference per in-scope user), a provisioning fan-out, a linked user’s groups — stops at the first refusal of the run (of the step, for a reconciliation): every refusal costs the transport a row. It counts the messages it did not offer and hands that count to Self::record_not_offered once, at the end of the run. The refused message keeps its own row, written by enqueue; the run adds at most one more.

A bulk producer that runs off every request path — the reconciliation, which runs in the cleanup task or on a task of its own — offers through Self::enqueue_paced instead, which waits for room rather than refusing a queue that is only full for now. Its refusals are then the ones that end the run’s offers anyway: a closed queue, a passed deadline, a stop. A producer on a request path (the provisioning fan-out) or on the consumer’s own task (a linked user’s groups, enqueued by the deliverer — which would wait for itself) does not pace.

fn enqueue_paced<'a>( &'a self, msg: &'a OutboundMessage, deadline: Instant, should_stop: &'a (dyn Fn() -> bool + Send + Sync), ) -> OutboundFuture<'a, Result<(), OutboundError>>

Enqueue msg for a bulk producer that may wait (R101-01): where the transport’s queue is full for now, wait for room until deadline, and give up at once when should_stop says so (it is polled while waiting, so a stop ends the wait promptly) or the queue is closed.

An Err therefore means the transport will not take more of this run’s messages before its deadline: the producer stops offering. It writes the refused message’s row exactly as a refused Self::enqueue does.

Never call it on a request path, nor from a deliverer (the consumer that would make room is the caller). By default it is Self::enqueue: a transport whose enqueue does not refuse for being momentarily full (the broker’s, whose refusal is a lost connection or an unconfirmed publish) has nothing to wait for.

Source

fn record_not_offered<'a>( &'a self, kind: OutboundKind, tenant_id: Uuid, target_id: Uuid, not_offered: u64, ) -> OutboundFuture<'a, ()>

A bulk producer stopped offering messages of kind after one was refused: record the not_offered messages of that run it held back, as one row naming target_id of tenant_id (the target the run was for; for a fan-out over several targets, the target of the refused message).

Must not wait on the datastore on the caller’s path. Nothing, by default: a transport that writes no row for a refused enqueue (the broker’s: its refusal is the producer’s log line) writes none for these either. The minimal profile’s in-process dispatcher writes one <slug>.delivery_abandoned row carrying refused_count.
