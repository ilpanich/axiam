fn list_revoked_by_issuer( &self, issuer_ca_id: Uuid, expiring_after: DateTime<Utc>, ) -> impl Future<Output = AxiamResult<Vec<RevokedCertificate>>> + Send

The revoked leaves issuer_ca_id signed whose notAfter is later than expiring_after, in every tenant — the leaf half of that CA’s certificate revocation list (#565, T-102). The caller names the cut-off (#608), as for CaCertificateRepository::list_revoked_children.

Across tenants on purpose: a CRL belongs to its issuer, not to a tenant, and an organization CA’s leaves may be recorded under more than one.

fn list_unforwarded_revocations( &self, limit: u32, ) -> impl Future<Output = AxiamResult<Vec<Certificate>>> + Send

Revoked, not yet expired leaves of an active vault_pki CA whose revocation Vault has not yet been told of, in the order the sweep takes them (a row never attempted first, then by vault_next_attempt_at, then oldest revocation), at most limit (T-470) — whether or not a row’s backoff has run out: this is “what is pending”, and Self::list_due_vault_forwards is “what is due”.

Vault signs such a CA’s list, not AXIAM, so a revocation reaches it only by being forwarded; the cleanup sweep forwards the ones a revoke request could not, and the revocations that never went through one (a directory deprovisioning revokes in bulk). Across tenants: the sweep is deployment-wide. A revoked CA’s leaves are left out, since revoking the CA removed its issuer from Vault.

fn list_due_vault_forwards( &self, now: DateTime<Utc>, limit: u32, ) -> impl Future<Output = AxiamResult<Vec<VaultForwardCandidate>>> + Send

The rows Self::list_unforwarded_revocations names whose turn has come at now — never attempted, or vault_next_attempt_at not after now — in the order the sweep takes them, at most limit (#603).

A row Vault refused is out of this list until its backoff runs out, so a hundred permanently refused rows no longer hold every later one back, and a row another replica claimed is out of it for the length of the lease.

fn claim_vault_forward( &self, tenant_id: Uuid, id: Uuid, seen_next_attempt_at: Option<DateTime<Utc>>, lease_until: DateTime<Utc>, ) -> impl Future<Output = AxiamResult<bool>> + Send

Claim a pending revocation for one attempt (#603): a conditional write that sets vault_next_attempt_at to lease_until only if it still holds seen_next_attempt_at (the value Self::list_due_vault_forwards read, None for a row never attempted) and the row is still unforwarded. true for the one caller whose write matched; of two concurrent claims of one row exactly one gets true.

A claimant that dies leaves the lease to run out, after which the row is due again; nothing is counted against the row for that.

fn record_vault_forward_failure( &self, tenant_id: Uuid, id: Uuid, claimed_until: DateTime<Utc>, attempts: u32, next_attempt_at: DateTime<Utc>, error: &str, ) -> impl Future<Output = AxiamResult<bool>> + Send

Record that Vault refused a claimed row: its failed-attempt count (attempts, including this one), the sanitised error (stored truncated — a status and a short message, never a token or a response body) and when it is next due (#603). A row already forwarded is left alone.

Conditional on the claim it follows (R101W1-09 (d)): written only while the row’s vault_next_attempt_at is still claimed_until, the lease_until this caller’s Self::claim_vault_forward wrote. An attempt that outlived its lease, the row since claimed by another replica, writes nothing, so it can neither move the new holder’s lease nor overwrite the count and reason that holder records. true when the record was written.

fn revoke_all_for_tenant( &self, tenant_id: Uuid, ) -> impl Future<Output = AxiamResult<Vec<Certificate>>> + Send

Revoke every certificate of tenant_id that is not revoked and not yet expired, recording when, and return the certificates this revoked (R1W1-01).

What deleting a tenant does to its certificates: a deleted tenant’s leaves are disowned, so they go on their issuers’ revocation lists rather than staying valid to every relying party outside AXIAM until they expire. Returned so the caller can forward the vault_pki ones to Vault, as Self::revoke’s caller does; the cleanup job’s sweep forwards whatever it could not.

fn revoke_user_certificates( &self, tenant_id: Uuid, user_id: Uuid, username: &str, email: &str, user_created_at: DateTime<Utc>, ) -> impl Future<Output = AxiamResult<u64>> + Send

Revoke every active User-type certificate that belongs to user_id, recording when, and return how many were revoked (G-3, T23.3.3, D-28; #533).

“Belongs to” is, first, the binding: a certificate whose Certificate::user_id is user_id (set at issuance since schema v98). A row whose user_id is NONE — every certificate issued before v98, and a User certificate issued without one — falls back to the convention that was all there was before: its metadata.user_id naming the account, or its subject common name equal, ignoring case, to the account’s username or email. A row bound to another account is never matched by the convention, whatever its common name says. Only User-type, still-active certificates of the tenant are considered.

The common-name match is bounded twice (R101W1-01), because a folded name is evidence only when nobody else could own it — deletion and the self-service erasure revoke irreversibly, and usernames and emails are unique only case-sensitively:

  • only a row created at or after user_created_at (the account’s own created_at) matches by name: a certificate issued before the account existed was not issued for it;
  • a name that another account of the tenant also holds, ignoring case, in either column and in any status (the rule of UserRepository::find_identity_collision), is dropped: an ambiguous name matches nothing.

The binding and the metadata.user_id match (a random id the issuer wrote, which nobody can be named after) are not bounded.

What linking an account to its directory entry, an administrator’s deletion and the Art. 17 erasure call. Each revoked row carries revoked_at, so it is on its issuer’s revocation list, and vault_revoked_at NONE, so the cleanup job’s vault_revocation sweep forwards it when its issuer’s key is held by vault_pki (T-470). The caller passes the account’s names as they are before any erasure overwrites them, and its created_at.

Required, with no default, for the reason WebauthnCredentialRepository::delete_by_user gives: a default of “zero revoked” would make every double silently not revoke.

fn clear_user_certificates_metadata( &self, tenant_id: Uuid, user_id: Uuid, username: &str, email: &str, user_created_at: DateTime<Utc>, ) -> impl Future<Output = AxiamResult<u64>> + Send

Clear the free-form metadata (set it to {}) of every User-type certificate that belongs to user_id, in any status, and return how many rows it matched (R101W1-05, #618) — the Art. 17 purge’s scrub of what the revocation list does not need.

Matches exactly the rows Self::revoke_user_certificates matches — the binding, then the convention with its two bounds — except that it does not require the row to be active, so a certificate an operator had revoked before the erasure is scrubbed too. Rows are kept, with their PEM, subject, user_id and revoked_at: the revocation list is computed from them. A row whose metadata is already empty is not written (and not counted), which makes a retried purge a no-op.

Called after revoke_user_certificates and before the account’s names are overwritten, for the same reason that is: the convention reads them, and metadata.user_id is one of the things it reads, which this call removes.

Required, with no default, for the reason revoke_user_certificates is.

fn delete_past_retention( &self, limit: u32, ) -> impl Future<Output = AxiamResult<u64>> + Send

Delete up to limit certificate rows of live tenants whose notAfter passed more than eight days ago, in any status, and return how many this call removed (R101W1-05, #618).

The retention end of a certificate row. A revoked row is the evidence its issuer’s revocation list is computed from, and a list keeps an expired entry for at most seven days (axiam_pki::crl, #608); the eighth day is the margin for the datastore’s clock against the replicas’. Past it no list names the row and no relying party can need it, so the CRL is the same with the row as without. An expired certificate that was never revoked is on no list and goes with them. A row’s cert_bound_to edge goes with it.

“Live” is a tenant row without a deleted_at: a deleted tenant’s rows belong to the tenant purge, which keeps them for the same eight days and whose orphan scan then removes them. Touches no audit row.

Bounded by limit so one pass cannot hold a long write; the caller repeats while a full batch comes back. Safe for two replicas at once: deleting a row the other has just deleted removes nothing and counts nothing.

fn bound_service_accounts( &self, cert_ids: &[Uuid], ) -> impl Future<Output = AxiamResult<HashMap<Uuid, Uuid>>> + Send

The service account each of cert_ids is bound to, for those that are bound at all.

The bulk form of Self::get_bound_service_account, and the reason it exists is a list page: whether a certificate is bound is a graph edge, not a column, so a page of fifty certificates asking one at a time is fifty round trips. That cost is why the admin UI showed the binding nowhere at all, which in turn is why it was “almost impossible to understand if a certificate was bound to the service account or not”.

Certificates with no binding are simply absent from the map rather than present with a None, so a caller iterates what it got.
