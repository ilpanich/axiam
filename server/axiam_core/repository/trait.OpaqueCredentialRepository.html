Expand description

Repository for OPAQUE (RFC 9807) registration records.

One row per user at most. A record is written only where the plaintext password is legitimately in hand on the client (registration, an authenticated password change, reset completion), so upsert replaces rather than versions: keeping historical records would keep historical passwords attackable for no operational benefit.

fn get_by_user( &self, tenant_id: Uuid, user_id: Uuid, ) -> impl Future<Output = AxiamResult<OpaqueCredential>> + Send

Fetch a user’s record. NotFound means the user has never set a password under an OPAQUE-enabled policy — which is a normal state, not an error, and callers must treat it as “fall back to password login” rather than as a failure.

Note for callers on the login path: NotFound must not short-circuit into a distinguishable response. The protocol engine has a decoy path for exactly this case, and skipping it reintroduces the enumeration oracle the whole design avoids.
