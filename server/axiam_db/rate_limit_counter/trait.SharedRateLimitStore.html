Expand description

The single write primitive the write-behind flusher needs.

Object-safe on purpose (hence the boxed future rather than an async fn): SharedRateLimitCounter is deliberately NOT generic over the SurrealDB connection type, so one non-generic counter type can be held by axiam-api-rest’s AppState<C> and by axiam-api-grpc’s tower layer alike, and so tests can substitute a failing or call-counting store.

Implemented for SurrealRateLimitBucketRepository for every C: Connection.

Source

fn peek_bucket<'a>(&'a self, key: &'a str) -> StorePeekFuture<'a>

Reads the bucket key as stored, without writing: the start of the window its count belongs to and the count, or None when no bucket exists.

Self::increment_by with a delta of 0 is no substitute: that call upserts, so reading a bucket nobody had written creates a row, and reading one left from an older window rewrites it (#638). The stored window is returned as it is, so a caller can tell a bucket still holding the window it asks about from one an older window left and from one a newer window has already taken over (the CIBA hint cap refuses a call the next window has overtaken, #639).

Source

fn decrement<'a>( &'a self, key: &'a str, window_start: DateTime<Utc>, ) -> StoreDecrementFuture<'a>

Takes one back from the bucket key, atomically, when it still holds the window starting at window_start and its count is above zero; writes nothing (and creates no bucket) otherwise. Resolves to whether one was taken back.

The undo of an Self::increment_by of 1 for the same window, for a caller that counts first and decides afterwards: the CIBA hint cap counts every call and takes back the count of a call it refused, so a refused call does not consume the allowance (#639).
