pub async fn claim_purge( &self, id: Uuid, now: DateTime<Utc>, lease: TimeDelta, ) -> AxiamResult<bool>

Claim a tombstoned tenant’s purge for this replica (#610): true when this call won it, false when the tenant is not tombstoned (live, or already purged) or another replica’s claim, stamped after now - lease, still holds.

The cleanup job runs on every replica, so every replica’s tenant_purge sweep sees the same tombstoned tenant. The lease is the precondition of the write (the SCIM claim_reconciliation pattern): of two concurrent claimants, one write matches and stamps purge_claimed_at; the other either matches nothing or loses the optimistic write, retries, and then finds the winner’s stamp. A claim older than the lease is taken over, so a replica that claimed and died holds the tenant back for one lease at most. A purge still running when its lease runs out may then overlap another replica’s; every step of it is idempotent and only one of them removes the tenant row (see Self::purge_tombstoned), so that costs work, not correctness.

§Errors

A datastore failure.

Give up a claim Self::claim_purge stamped at claimed_at, so the next sweep — this replica’s or another’s — retries a purge that failed without waiting out the lease. A claim another replica has since taken over carries a different stamp and is left alone.

pub async fn purge_tombstoned(&self, id: Uuid) -> AxiamResult<TenantPurgeReport>

Remove every tenant-scoped row of a tombstoned tenant, then the tenant row. Of its audit trail, only the rows the export its deletion required holds go — those at or before the export time the tenants.deleted record names, never later than the receipt it names (R1W1-04, R101W3-03); the rest, or all of it when no export time can be read, stays for the retention sweep. The report says which.

Each table is one idempotent DELETE; a failure stops the purge with the tenant still tombstoned, and calling this again resumes it. A live tenant is refused before anything is touched — the purge never decides on its own that a tenant is gone.

Ok means this call removed the tenant row (#610): when two purges of one tenant overlap — a claim whose lease ran out mid-purge, taken over by another replica — both run the same idempotent steps, but only one of their final DELETEs finds the row, and the other answers NotFound, as for a tenant purged before the call. The caller records the purge on Ok only, so it is recorded once.

The row may be the claim marker of an orphan purge (Self::claim_orphan_purge) whose replica died holding it: the id is then purged as the orphan it is (its audit trail kept, as Self::purge_orphan keeps it) and the report says so (R101W1-09 (a)).

§Errors

NotFound for a tenant that is not tombstoned (live, or already purged — before this call or while it ran); a datastore failure otherwise.

pub async fn purge_tombstoned_rows( &self, id: Uuid, ) -> AxiamResult<TenantPurgeReport>

The first part of Self::purge_tombstoned: every tenant-scoped row of a tombstoned tenant, not its tenant row (#655).

The tenant stays tombstoned, so a purge stopped anywhere in here — a failure, or the cleanup task giving the purge up because the process is stopping — is resumed by the next call: every step is an idempotent DELETE. Nothing here is a point of no return.

The row may be the claim marker of an orphan purge (Self::claim_orphan_purge): the id is then purged as the orphan it is, its audit trail kept, and the report says so (R101W1-09 (a)).

§Errors

NotFound for a tenant that is not tombstoned (live, or already purged); a datastore failure otherwise.

pub async fn remove_purged_tenant(&self, id: Uuid) -> AxiamResult<()>

The last part of Self::purge_tombstoned: remove the tenant row, only while it is still tombstoned (#655). Call it only after Self::purge_tombstoned_rows has succeeded for the tenant; a tenant row removed before its rows leaves them for the orphan scan. For an orphaned id the row is its purge’s claim marker, removed after Self::purge_orphan_rows (R101W1-09 (a)).

This is the purge’s point of no return: once the row is gone, no later sweep finds the tenant, so whoever removed it is the only one that can write tenants.purged. Ok means this call removed it.

§Errors

NotFound when the row is not there or not tombstoned — an overlapping purge removed it first (#610); a datastore failure otherwise.

pub async fn claim_orphan_purge( &self, id: Uuid, now: DateTime<Utc>, ) -> AxiamResult<bool>

Claim an orphaned tenant id’s purge for this replica (R101W1-09 (a)): true when this call created the id’s claim marker, false when the id already has a tenant row — another replica’s marker, or a tenant of its own.

An orphan has no tenant row for Self::claim_purge to stamp, so the claim is a row: a tombstoned tenant row under the orphan’s own id, with metadata.orphan_purge = true and purge_claimed_at = now. A record id is unique, so of replicas whose orphan scans coincide exactly one CREATE succeeds (the bootstrap_lock and organization_scope pattern); the others fail on the existing id, or lose the optimistic write, retry, and then fail on it. While the marker exists the id is no orphan to any scan (the scan reads the tenant table), it is out of every tenant read (each filters deleted_at), and the tombstoned-tenant sweep leaves it alone for Self::claim_purge’s lease — then takes it over, as an orphan, if the claimant died. No has_tenant edge is written and the organization id is the nil id, so no organization’s listing reaches it.

§Errors

A datastore failure.

pub async fn purge_orphan( &self, id: Uuid, ) -> AxiamResult<Option<TenantPurgeReport>>

Remove an orphaned tenant id’s rows, as Self::purge_tombstoned does for a tombstoned tenant, except its audit trail, which no export receipt covers and which the audit retention sweep governs (the report counts it as kept).

Ok(Some(report)) means this call purged the id and the caller records it; Ok(None) that there is nothing for this call to record (R101W1-09 (a)). Every replica scans for orphans, so two scans may name one id. The purge is claimed first (Self::claim_orphan_purge): while one replica holds the id, another’s call answers None without touching a row. A scan that predates a finished purge of the id claims it afresh, finds no row left to remove, drops its marker and answers None. The purge’s last step deletes the marker, and only the call whose DELETE removed it answers Some — should a purge outlive the claim’s lease and the tombstoned-tenant sweep take the marker over, only one of the two records the purge.

The composition of Self::begin_orphan_purge, Self::purge_orphan_rows and Self::remove_purged_tenant (the point of no return), which the cleanup task runs step by step so that a stop gives the purge up before that point (#655).

§Errors

Conflict when a tenant row of its own exists for this id (live, or tombstoned by a deletion); a datastore failure otherwise, after which the marker is dropped so that the next scan finds the id again.

pub async fn begin_orphan_purge( &self, id: Uuid, ) -> AxiamResult<Option<DateTime<Utc>>>

The first part of Self::purge_orphan: claim the orphaned id (Self::claim_orphan_purge) and check, under the claim, that it still owns a row to purge (R101W1-09 (a)).

Ok(Some(claimed_at)) when this call holds the claim of an id with rows to purge: the caller goes on with Self::purge_orphan_rows, or, giving the purge up, releases the claim (Self::release_purge_claim with claimed_at), which leaves the marker to the tombstoned-tenant sweep to purge as the orphan it is. Ok(None) when another replica holds the id, or when a scan that predates a finished purge finds nothing left (its marker is dropped): nothing for this call to record.

§Errors

Conflict when a tenant row of its own exists for this id; a datastore failure otherwise, after which the marker is dropped.

Source

pub async fn purge_orphan_rows( &self, id: Uuid, claimed_at: DateTime<Utc>, ) -> AxiamResult<TenantPurgeReport>

The second part of Self::purge_orphan: the orphaned id’s rows, with [super::tenant_purge::PurgeScope::Orphan], under the claim Self::begin_orphan_purge stamped at claimed_at (#655).

Every step is an idempotent DELETE and the marker stays, so nothing here is a point of no return: a purge stopped in here is resumed by whoever purges the marker next. The point of no return is Self::remove_purged_tenant, and only the call that removed the marker records the purge.

§Errors

A datastore failure, after which the marker is dropped so that the next scan finds the id again.
