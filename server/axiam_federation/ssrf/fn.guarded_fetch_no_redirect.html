One guarded hop that never follows a redirect (G-5, T23.5.3, D-53 (9)).

The same resolve (A + AAAA, fresh), refusal of any non-global address, HTTPS requirement (waived only with allow_private, the test seam), IP pinning and Content-Length cap as guarded_fetch, on the one URL it is given. A 3xx is returned to the caller as a response — its Location is not resolved, not validated and not fetched — so a caller that must not send a body or a credential anywhere but the address it was given (an SSF push, whose Authorization header would otherwise follow a redirect) can refuse a redirect by construction instead of by inspecting a later hop.

guarded_fetch and guarded_fetch_with_cap are unchanged.
