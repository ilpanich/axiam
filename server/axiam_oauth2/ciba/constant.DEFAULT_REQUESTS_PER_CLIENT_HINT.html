The shipped allowance of bc-authorize calls one client may have admitted for one hint in any HINT_CAP_WINDOW_SECS (#599, T-424). The deployment sets its own with AXIAM__RATE_LIMIT__BC_AUTHORIZE_PER_HINT (#639, CibaHintCap::with_per_hint); a call past the allowance is refused before the hint is looked up, stored or mailed, with the slow_down the per-client limiter answers.

requested_expiry is the client’s to choose, so without a per-client bound a client that may address a user could keep the whole list full of short-lived requests of its own. Three is room for a retry or two while the first is still on the user’s phone; a client that needs more is waiting on a user who has not answered. A conformance suite or an SDK’s integration suite, which runs many flows for one test user from one client within minutes, needs more, and sets the knob for the deployment it tests.

What is counted is admitted calls, not open requests. The count is keyed on (tenant, client, a keyed digest of the hint) — never on the user the hint resolves to — so a hint that names nobody, a user who may not sign in and a real user are refused at the same call, and the refusal says nothing about the hint (D-63, T-422). A request that has been approved, denied or has expired therefore still counts until its window has passed. A refused call does not count (#639; until 1.1.0 it did, so a client that kept retrying stayed refused): a client that stops for the rest of the window after the one in which it used its allowance is admitted again. The hint is the one the request carried, as hint resolution normalises it (a login_hint trimmed and otherwise exact, as the username and e-mail lookups match it; an id_token_hint reduced to its verified subject), so one user named by username, by e-mail address and by ID token is three hints — three allowances a window from one client.

Admission requires the admitted calls in this window and the one before it, this call included, to come to at most the allowance, so any HINT_CAP_WINDOW_SECS-long stretch admits at most the allowance; as no request outlives that, one client never holds more open requests for one hint than the allowance. The price is coarseness: a client that has used the allowance in one window is refused for the whole of the next, so it waits between one and two windows. The count is the shared rate-limit table, written atomically in the datastore, so the bound holds across replicas and under concurrent calls (see CibaHintCap for the protocol and the argument).
