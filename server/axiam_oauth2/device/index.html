OAuth2 Device Authorization Grant (RFC 8628) — B2.

The grant for input-constrained devices: a TV, a CLI, a headless IoT sensor. The device shows a short code, the user types it on a phone or laptop, and the device polls until the user has approved.

§The two codes, and why they are shaped so differently

The device code is an ordinary bearer secret and is treated like one: CSPRNG, hashed at rest, never logged.

The user code cannot be. It has to be read off a screen and typed on a phone, so it is short, and short means guessable — which makes rate limiting the verification endpoint a security control, not a courtesy. See brute_force_attempts_required for the arithmetic that sizes it.
