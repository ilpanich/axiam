Expand description

RFC 9449 §5 — the DPoP key a refresh token minted beside cnf is bound to (#681), or None when it is bound to none.

Some(jkt) only for a public client registered for DPoP-bound tokens (token_endpoint_auth_method: none, dpop_bound_access_tokens): §5 binds “refresh tokens issued to public clients” to the key, because such a client has no credential and the key is all that ties a refresh token to it. A confidential client proves itself at every refresh by its credential, and §5 leaves its tokens unbound; a client not registered for DPoP sends no proof to bind to. For both this is None, and their refresh is unchanged.

cnf is the binding crate::token::TokenService::certificate_binding_for decided for this request, which for such a client always names the proof’s key: a request without a verified proof was refused before it got here.
