Expand description

Decide what a request from an externally registered client earns.

The argument order mirrors crate::sensitive::decide, and so does the order the inputs are consulted in: consent_leg — the request has already been through the consent screen once — before prompt_none, because it is the stronger statement. The user was asked, in person, and did not grant; redirecting again is the non-terminating case, so the chain is bounded at one consent hop.

prompt_none must be passed as true only when the relying party sent it and the client is on the honour lane, exactly as W7’s gate requires. A client registered ignore has its prompt dropped everywhere else in this server, and a dcr client is always ignore — the registration endpoint forces it — so in T21.4 this argument is always false. It is a parameter rather than a constant because T5’s CIMD clients will reach the same gate and the decision must not have to be rewritten then.
