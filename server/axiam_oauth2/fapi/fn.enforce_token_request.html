Request-time gate on the token endpoint (X5.1).

Defence in depth behind validate_registration. A FAPI client whose row was edited directly in the database — bypassing registration validation — must not be able to authenticate with a secret or receive an unbound token, so the invariants are re-checked at the moment they matter.

evidence is what the request actually carried: a verified client certificate on the connection, a verified DPoP proof, or neither. The FAPI profile requires whatever the client’s own registration says it requires, so the absence of the relevant evidence is refused here even though the authentication and binding paths would also refuse it — this way the refusal names the profile, which is what an operator needs to see.

A no-op for a standard client.
