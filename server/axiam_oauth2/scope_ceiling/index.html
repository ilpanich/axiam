#613 (T-289) — the tenant’s dcr_allowed_scopes as a ceiling on what an externally registered client may obtain, applied where scopes are read.

§The gap this closes

dcr_allowed_scopes bounds what a self-registered client (managed_by: dcr) or a client ID metadata document (managed_by: cimd) may register. It was checked at registration, at an RFC 7592 PUT and at a CIMD fetch — and nowhere else. A tenant that withdrew a scope from the list therefore narrowed nothing already registered: the client row kept the scope, every grant that reads client.scopes kept offering it, and the refresh grant’s stored.scopes ∩ client.scopes (#520) intersected against a row that still held it. The withdrawal took effect only when the client itself chose to re-register.

§Enforcement at the read points, not a rewrite of rows

The settings handler does not narrow client rows when the list changes. Rewriting rows would be a second writer on oauth2_client racing RFC 7592 PUTs and CIMD re-materialisations, and it would make the row say something the client never registered. Instead every point that decides what a token may carry reads the client’s scopes through apply_to_client, which intersects them with the tenant’s effective list (the organization baseline merged with the tenant override, exactly what registration validates against). A withdrawn scope is gone at the client’s next request, whatever the row says; a scope put back is back at the next request too, because nothing was deleted.

§Who pays for it

Only an external client. applies_to is answered from the client row the path already holds, so a client an administrator created — every client in most deployments — costs no read and sees byte-identical behaviour. An external client costs one effective-settings read per request on the paths above, which is the read materialise_if_cimd already makes for every URL-shaped client_id. Nothing is cached: a cache would be the staleness this module exists to remove.

§A read that fails refuses

For an external client a failed policy read is a server_error, never a fall-back to the row’s scopes: the row is exactly the value this module exists to distrust. An unwired policy (unwired) is the same refusal, so a composition root that forgets the port fails loudly on the first DCR request rather than silently restoring the gap.

§What it does not do

An access token already minted keeps its scope until it expires (15 minutes by default): it is a stateless JWT and nothing re-reads it. The refresh token behind it is narrowed at its next use. A device code pending when the list changes mints with the scopes recorded at /oauth2/device_authorization (its poll never reads the client), and the refresh token it yields is narrowed at its first use.
