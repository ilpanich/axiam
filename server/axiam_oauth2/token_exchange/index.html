OAuth2 Token Exchange (RFC 8693) — B3.

Design and rationale: claude_dev/token-exchange-design.md. The short version, because it governs every function below:

An exchange may only ever narrow. There is no input, no configuration and no client grant that causes the issued token to permit something the subject token did not already permit.

Each check here is that rule restated for one dimension — scopes, audience, lifetime, actor identity — and each has a test named after the thing it stops.

Like the device grant, this is a separate service rather than another arm of crate::token::TokenService: it needs different collaborators, and the REST layer keeps the seam at one match on grant_type.
