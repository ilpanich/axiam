custodians_from_env against an arbitrary lookup.

pub because it is also the honest entry point for an embedder whose configuration does not live in the process environment.

&dyn Fn rather than impl Fn: a generic seam is monomorphised once per closure type, and coverage instrumentation counts every instantiation’s lines separately. A test suite calling this with a dozen different closures would multiply this function’s line count by twelve and its uncovered lines with it — the tests would measurably worsen the very number they exist to improve. One instantiation, one count.

The same seam, and for the same reason, as [vault_endpoint_from]: this function decides which custodian a deployment gets, and that decision is the one the 1.0.0-beta01 report caught getting silently wrong. Driving it through the real environment would mean mutating process-global state from a multi-threaded harness, so the rules are tested as a function of their inputs instead.
