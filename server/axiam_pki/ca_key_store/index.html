Module ca_key_store 

Source
Expand description

Custodians for CA signing keys — the implementations behind [axiam_core::ca_keys::CaKeyStore].

Three of them today:

  • DatabaseCaKeyStore — AES-256-GCM ciphertext in the ca_certificate row, sealed under the process-wide pki_encryption_key. What AXIAM has always done, and still the default.
  • VaultCaKeyStore — a HashiCorp Vault KV v2 secret. The row holds a path and no key material.
  • VaultPkiCaKeyStore — Vault’s PKI secrets engine, where the key is generated and never leaves. Its own module, because it is the one custodian that also generates CAs and signs with them.

A KMS is the next one, and the port is shaped so it slots in beside these rather than replacing them: a deployment that adopts a new custodian keeps the CAs it already had, because each row records which custodian holds its key.
