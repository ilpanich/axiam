When a cimd row was last any use to anybody — T21.8 / MCP-04.

max(updated_at, last_authorized_at, created_at), and each of the three is load-bearing.

updated_at is the one that matters, and it is already the stamp #470 proposed adding a column for. materialise_if_cimd calls upsert_cimd_client after every successful resolve, and a resolve returns from the in-memory document cache on a hit — so the upsert runs whether or not a fetch happened, on authorize, on token and on PAR. The UPDATE arm sets updated_at = time::now(). A cimd row’s updated_at is therefore “last presented”, with a resolution of one request, and no migration is needed to read it.

last_authorized_at is read beside it because touch_last_authorized guards on managed_by != 'admin' rather than == 'dcr', so it is stamped on cimd rows too. Taking the maximum of the three cannot pick a stamp older than the row’s real last use, whichever of them the write path happened to move.
