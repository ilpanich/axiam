Expand description

An erasure through its point of no return to its record (#624): the erasure pipeline (run_erasure_pipeline_reporting: audit scrub, anonymization, proof), then the gdpr.user_pseudonymized audit row, then the account_deletion row marked completed (#689 (i): the record first). Run inside a unit of AuditedWork, so a cut of the cleanup task does not reach it.

The anonymization is the point of no return: it clears deletion_pending, so no later sweep selects the account again, and in the same transaction sets the account’s record marker (#689), which this call holds from there (released by a guard if it is cut) and clears with the completion once the audit row is written; a marker left set is recorded by the next sweep (record_owed_erasures). Until then — the audit scrub — the call gives up once work is stopping and answers Ok(false): the account stays due. Past it, it runs on to the audit row whatever the stop says, and answers Ok(true). A free function, and public, for the reason run_erasure_pipeline is one.

§Errors

Those of run_erasure_pipeline_reporting, before anything is recorded. The completion and the audit row are not fallible here: a failed completion is logged, and a failed audit write is dead-lettered (SECHRD-12).
