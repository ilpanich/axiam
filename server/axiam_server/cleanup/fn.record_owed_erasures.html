Expand description

Record the erasures whose record is still owed — a unit cut between the anonymization and the clearing of its marker (#689) — and settle each: the first step of every GDPR purge sweep; none starts once the process is stopping.

SurrealAccountDeletionRepository::claim_owed_erasure_records claims each owed erasure, conditionally on the marker read: a marker released by a cut unit or older than lease, and (#689 (i)) an anonymized account whose deletion request is still pending with no marker at all — an erasure cut before schema v108 between its anonymization and its completion. The gdpr.user_pseudonymized row is written unless the tenant’s trail already holds one for the account (a unit cut after its record and before the clearing): an account is erased once, so that row is this erasure’s. The row carries the pseudonym the anonymization wrote, certificates_revoked as null — the count lived only in the cut unit — and recovered: true. Then the marker is cleared and the request completed, in one transaction. The claim is held by the same guard the unit holds.

Ok(n) is the number of records this call wrote.

§Errors

The datastore error that kept the owed erasures from being read or claimed, or AxiamError::Internal naming how many could not be checked (each of those is released for the next sweep).
