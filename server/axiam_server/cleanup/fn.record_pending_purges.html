Expand description

Record the tenant purges whose tenant_purge_pending marker (#689) still stands — a unit cut between the removal of the tenant row and the clearing of its marker — and clear each marker. The first step of every sweep_tenant_purge pass; none starts once the process is stopping.

Each marker is claimed first (SurrealTenantRepository::claim_pending_purge_records): only one released or older than lease, and conditionally on the claim read, so a unit still recording and another replica’s sweep are never both its owner. The record is written unless the system log already holds a tenants.purged for the id written since the removal (a unit cut after its record and before the clearing), with what the removal stored: the record is the one the unit would have written. The claim is held by the same guard a unit holds, so a pass cut here releases it.

Ok(n) is the number of records this call wrote.

§Errors

The datastore error that kept the markers from being read or claimed, or AxiamError::Internal naming how many could not be checked (each of those is released for the next pass).
