Revoke the still-active User certificates of an account the Art. 17 purge is erasing, and clear the free-form metadata of all its User certificates, returning how many were revoked (#533, R101W1-05) — the purge’s step (b4).

Revoked, not deleted: each row carries revoked_at, so it stays on its issuer’s revocation list until it expires, and a vault_pki issuer’s list in Vault gets it from the cleanup job’s vault_revocation sweep. Deleting the row would make the certificate valid again to every relying party outside AXIAM — the retention docs/compliance/gdpr-compliance.md records for a deleted tenant’s certificates, here for one account’s.

What the list does not need is cleared, as the tenant purge clears it: metadata is set to {} on every row that is the account’s, in any status (R101W1-05). What stays is the PEM, subject, fingerprint, the dates and user_id; the first three are what the list is computed from and what a relying party matches an entry against, and user_id is an internal random id of an account that is anonymized in place by the next step, so it names nobody once this purge has run — and it is the key a retried purge finds the rows by. The rows go when a certificate retention sweep (CleanupTask’s certificate_retention) finds them more than eight days past notAfter.

Matches the binding (certificate.user_id, schema v98) and, for a row without one, the older convention on the account’s username and email — limited to certificates created since the account was and to names no other account of the tenant holds (R101W1-01), so a holder erasing their own account cannot revoke a namesake’s certificate — so it must run before anonymize_user overwrites them, which the purge does by calling it ahead of run_erasure_pipeline_reporting. The revocation comes first and the clearing second: metadata.user_id is one of the things the convention reads. Fatal there (?), like the credential deletions beside it: the account stays due and the next sweep retries, with its names in place; both writes are idempotent.

A free function, and public, for the reason run_erasure_pipeline is.
