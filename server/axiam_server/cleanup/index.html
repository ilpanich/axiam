Module cleanup 

Source
Expand description

Periodic cleanup task for expired federation rows, GDPR purges, and export jobs.

SurrealDB v3 does not support native TTL on rows (RESEARCH §7), so this task periodically sweeps various tables:

  • saml_assertion_replay and federation_login_state: expired rows
  • user: accounts past their scheduled purge date (D-05/D-06/D-08)
  • export_job: queued jobs waiting to have their encrypted blob generated (D-12)
  • every tenant-scoped table: the rows of a deleted (tombstoned) tenant, then its tenant row (#523, D-4)

The task shuts down cleanly when the caller sends true through the watch channel (D-09, D-24).

ERASURE_CLAIM_LEASE
How long a unit’s claim on an account’s erasure (#738) keeps the other replicas’ sweeps off the account: the tenant purge’s lease, for the same reasons. Every replica runs the GDPR sweep, and two that read one due account used to run its erasure twice — the record stayed single, but the SSF account_purged went out twice and the later unit failed its tick on the proof. Now the first claim is exclusive: a second claimant skips the account without an error. A unit holds the claim from before its first destructive step to the anonymization — its point of no return, which clears deletion_pending, so no sweep selects the account again — and releases it on every exit before (a failure, a stop, a cut or a panic, from a drop guard), so the next sweep takes the account at once. Only a process that ends before the release is written — a SIGKILL, or a unit cut at the stop’s bound, whose spawned release the process exit may cancel (#687) — leaves the account to this lease.
ORPHAN_TENANT_SCAN_INTERVAL
How often the tenant_purge sweep also looks for orphaned tenant ids.
PENDING_RECORD_LEASE
How long a unit’s claim on its pending-record marker (#689) keeps a sweep from recording the work itself: the tenant purge’s lease, for the same reasons. A unit holds the claim for the handful of statements between its point of no return and its record, which the teardown bounds at seconds; a unit that is cut releases it from a drop guard, so the next start records the work at once, and only a process that ends before the release is written — a SIGKILL, or a unit cut at the stop’s bound, whose spawned release the process exit may cancel (#687) — leaves the marker to this lease.
