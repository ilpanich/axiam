Where axiam-server healthcheck probes, and what it trusts (D-09, DF-016).

The probe was reqwest::blocking::get("http://127.0.0.1:8090/health") with AXIAM_HEALTHCHECK_URL as its only knob. On a deployment that terminates TLS in the server process — AXIAM__SERVER__TLS__ENABLED, which is how the shipped Kubernetes ConfigMap runs — that is a plaintext request to a TLS listener, so the container healthcheck fails forever and the operator’s only recourse was an AXIAM_HEALTHCHECK_URL pointing at an https:// address the probe then could not verify.

Two things were needed and one thing was not. The two: a default that follows the listener, and a way to name the trust anchor. The one that was not: an “insecure” switch. A probe that skips verification is a probe that answers “healthy” to anything listening on the port, which is worse than no probe, because a deployment stops looking.
