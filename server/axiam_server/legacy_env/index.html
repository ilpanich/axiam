Module legacy_env 

Source
Expand description

Environment variables that look like a secret’s name and are read by nothing.

Four variables were documented, set in two compose files and named in a dozen error messages, and none of them ever reached the server (DF-018/DF-022). AXIAM__EMAIL_ENCRYPTION_KEY and AXIAM__GDPR_PSEUDONYM_PEPPER map to AppConfig fields that are #[serde(skip)]; AXIAM__PKI__ENCRYPTION_KEY and AXIAM__FEDERATION_ENCRYPTION_KEY have no AppConfig field at all. All four are supplied by the secret provider instead, under the names axiam_core::secrets::env_var_name resolves.

The fix is the rename (decision D-1: one name per secret, no alias). This module is the other half — the deployment that is already wrong learns so at startup, in one line, naming both spellings.

The value is never read. legacy_secret_env_warnings is handed a predicate that answers is this variable set, not a lookup that returns what it holds, so there is no path by which a key could reach a log line.
