1//! Cross-replica authorization **decision-cache invalidation** over RabbitMQ
2//! (§4.2 — closes the multi-replica stale-allow residual / threat-model
3//! `T-88`).
4//!
5//! The `axiam-authz` decision cache invalidates process-locally. On a replica
6//! that did not handle the mutation, a revoked grant could stay `Allow` until
7//! its entry TTL-expired (default 5 s). This module is the transport that
8//! makes an invalidation reach **every** replica, built on the AMQP
9//! infrastructure and the §8 signed-message scheme this crate already has,
10//! rather than a parallel mechanism.
11//!
12//! # 1. Fan-out, not a work queue — the decision everything else rests on
13//!
14//! Invalidation must reach *every* replica. A work queue (many consumers on
15//! one shared queue) delivers each message to exactly **one** consumer, so all
16//! but one replica would stay stale — worse than no channel at all, because
17//! operators would believe the gap was closed. The topology is therefore:
18//!
19//! ```text
20//!                       ┌──────────────────────────────────────────┐
21//!   mutation on         │ exchange axiam.authz.cache.invalidate     │
22//!   replica A  ────────▶│ type: FANOUT, durable                     │
23//!                       └───┬──────────────┬───────────────┬────────┘
24//!                           │              │               │
25//!            queue …invalidate.<A>   …invalidate.<B>  …invalidate.<C>
26//!            exclusive, auto-delete, non-durable, one per replica
27//!                           │              │               │
28//!                     (self-echo:      apply to        apply to
29//!                      no-op)          B's cache       C's cache
30//! ```
31//!
32//! Every replica declares **its own** queue, named after its process-unique
33//! replica id, and binds it to the fanout exchange. `exclusive` means no other
34//! connection can steal from it; `auto_delete` means it disappears with the
35//! replica rather than accumulating messages for a pod that will never return.
36//! Nothing is durable on the queue side and messages are published transient:
37//! a replica that was down has an **empty** cache when it comes back, so
38//! invalidations it missed are meaningless to it.
39//!
40//! # 2. What happens when AMQP is unavailable — the crux
41//!
42//! Hard-failing every authorization check when the broker is down would be a
43//! catastrophic availability regression; silently continuing to serve a cache
44//! that can no longer be invalidated is the security hole this exists to
45//! close. The two sides are resolved **differently**, because their failures
46//! mean different things:
47//!
48//! * **Publish side → fail the mutation.** [`CacheInvalidationPublisher`]
49//!   publishes with publisher confirms and returns `Err` unless the broker
50//!   acked. `AuthorizationEngine::invalidate_*` propagates that, and the REST
51//!   mutation handler returns **503**. The operator asked for a revocation;
52//!   the database write is durable but the fan-out did not happen, and saying
53//!   "done" would be a lie. The local cache is always invalidated *before* the
54//!   publish is attempted, so the failure never leaves the mutating replica
55//!   itself stale, and every one of these mutations is idempotent in the
56//!   narrowing direction, so a retry is safe.
57//! * **Consume side → stop trusting the local cache.** When a replica's
58//!   consumer is not subscribed (startup, subscribe failure, stream end, task
59//!   cancellation), it calls `DecisionCache::set_trusted(false)`: the cache is
60//!   flushed and every check falls back to full database evaluation — correct,
61//!   just slower — instead of serving allows it can no longer invalidate.
62//!   Availability is preserved; only throughput degrades. The transition is
63//!   logged at ERROR and counted in `DecisionCacheStats::bypassed`, so the
64//!   degraded mode is loud rather than silent.
65//!
66//! **No inbound message can revoke trust** — not a stale one, not a replayed
67//! one. Otherwise an attacker holding a single captured, validly-signed
68//! broadcast could disable every replica's cache at will. A rejected message is
69//! logged and counted; it never moves the flag.
70//!
71//! ## 2a. Binding liveness — the heartbeat (§13.4 observation 1)
72//!
73//! Consumer liveness alone is not sufficient evidence, and this was a real gap.
74//! A party with broker **configure** rights can `queue.unbind` a replica's queue
75//! from the fanout exchange. Nothing visibly breaks: the consumer stays
76//! subscribed to a queue nothing routes to any more, so trust stays `true` and
77//! the replica keeps serving cached allows it will never be told to invalidate.
78//! The publisher cannot see it either — `mandatory` is off, so the broker acks
79//! an unroutable message. Invalidations are silently suppressed, bounded only by
80//! `decision_cache_ttl_secs`.
81//!
82//! Each replica therefore publishes a **self-addressed heartbeat** on an
83//! interval ([`build_signed_heartbeat`]) and watches for its own to come back.
84//! That round trip is the smallest thing that actually exercises the property in
85//! question — publish → exchange → binding → queue → consumer — so an unbound
86//! queue breaks it immediately. After
87//! [`HEARTBEAT_MISS_THRESHOLD`] consecutive missed intervals, the watchdog calls
88//! `set_trusted(false)` ([`InvalidationLiveness`]).
89//!
90//! Three properties make this safe rather than a new lever:
91//!
92//! * **The watchdog can only revoke, never grant.** Trust is granted in exactly
93//!   one place — the consumer, on a successful `basic_consume`. A watchdog able
94//!   to grant it could resurrect trust on a replica whose consumer had died.
95//! * **Only our OWN heartbeat counts.** Another replica's heartbeat proves that
96//!   replica can publish, which says nothing about *our* binding.
97//! * **Heartbeats never touch the cache and never enter the nonce guard.** They
98//!   are separated out before any [`InvalidationEvent`] is constructed, so a
99//!   heartbeat has no path to `apply`; and since they arrive on a fixed interval
100//!   from every replica, letting them consume the bounded nonce-guard capacity
101//!   would evict real invalidation nonces and weaken replay protection.
102//!
103//! * **A replayed heartbeat does not count** (§15.2). Bypassing the nonce guard
104//!   left a narrow path: a party with broker rights who captured one signed
105//!   heartbeat could replay it inside the freshness window to keep this
106//!   replica's watchdog satisfied while its queue was unbound. Acceptance is
107//!   therefore bound to nonces *this* replica published and has not yet seen
108//!   back ([`InvalidationLiveness::record_sent_heartbeat`]), which closes the
109//!   replay without spending the shared guard's bounded capacity.
110//!
111//! Heartbeats **cannot be disabled** while broadcast is on. An earlier revision
112//! accepted an interval of `0` as "off", which meant this whole mitigation could
113//! be removed with one environment variable and only a warning — leaving the TTL
114//! as the sole bound, which is the state it exists to escape. The TTL is itself
115//! now clamped (`MAX_DECISION_CACHE_TTL_SECS`), so neither half of the bound is
116//! operator-removable.
117//!
118//! # 3. Authenticity
119//!
120//! An invalidation is a control-plane instruction, so it carries the full §8
121//! envelope ([`CacheInvalidationMessage`]): per-tenant HKDF-SHA256 subkey,
122//! `key_version >= 2` hard floor, per-message `nonce`, and an `issued_at`
123//! freshness window. Broker ACLs are not the only thing standing between an
124//! attacker with publish rights and everyone's cache.
125//!
126//! The nonce is deduplicated **per replica, in memory** ([`NonceGuard`]) — see
127//! [`CacheInvalidationMessage::nonce`] for why the shared durable nonce store
128//! used by the authz consumer would be exactly wrong on a fanout.
129//!
130//! # 4. Self-echo
131//!
132//! A fanout delivers the message back to the publisher. The publisher stamps
133//! its own `origin_id`; a consumer seeing its own id treats the delivery as a
134//! **no-op** (it already invalidated locally, before publishing). It cannot
135//! loop: [`InvalidationEvent::apply`] talks to the `DecisionCache` directly and
136//! has no reachable path to a publish, so nothing a consumer does can emit a
137//! message.
138//!
139//! # 5. Opt-in, default-off
140//!
141//! Nothing here runs unless **both** `AXIAM__AUTHZ__DECISION_CACHE_ENABLED`
142//! and `AXIAM__AUTHZ__DECISION_CACHE_BROADCAST_ENABLED` are true. With the
143//! channel off, the decision cache behaves exactly as documented before §4.2:
144//! process-local invalidation, TTL-bounded cross-replica staleness, no AMQP
145//! dependency acquired by enabling the cache.

175/// Upper bound on nonces retained by a replica's [`NonceGuard`].
176///
177/// The guard only has to cover the freshness window (default 30 s), so this is
178/// generous: 20 000 invalidations in 30 s is ~660 mutations/second sustained,
179/// far beyond any realistic administrative mutation rate. If the bound is ever
180/// hit, the oldest nonces are dropped first — a replay older than the retained
181/// set is still bounded by the freshness gate, and the worst outcome remains a
182/// redundant cache flush.
183const NONCE_GUARD_CAPACITY: usize = 20_000;

189/// Exchange kind for [`exchanges::AUTHZ_CACHE_INVALIDATE`].
190///
191/// **Fanout, deliberately.** Exposed as a function rather than inlined so the
192/// choice is assertable by a test: this is the single most important decision
193/// in the module, and a future refactor that turned it into a direct/topic
194/// exchange with a shared queue would silently reintroduce the stale-allow
195/// residual on every replica but one.
196pub fn invalidation_exchange_kind() -> ExchangeKind {
197    ExchangeKind::Fanout
198}
199
200/// Per-replica queue name. One queue **per replica**, never a shared one.
201pub fn invalidation_queue_name(replica_id: Uuid) -> String {
202    format!("{}.{}", exchanges::AUTHZ_CACHE_INVALIDATE, replica_id)
203}
204
205/// Declaration options for a replica's own invalidation queue.
206///
207/// * `exclusive` — only this connection may consume it, so no other process
208///   can take deliveries meant for this replica.
209/// * `auto_delete` — it vanishes with the replica instead of accumulating
210///   messages for a pod that is never coming back.
211/// * not `durable` — a replica that was down has an empty cache when it
212///   returns, so invalidations it missed are meaningless to it.
213pub fn invalidation_queue_options() -> QueueDeclareOptions {
214    QueueDeclareOptions {
215        exclusive: true,
216        auto_delete: true,
217        durable: false,
218        ..QueueDeclareOptions::default()
219    }
220}
221
222/// Declare the fanout exchange, this replica's exclusive auto-delete queue, and
223/// the binding between them. Returns the queue name.
224pub async fn declare_cache_invalidation_topology(
225    channel: &Channel,
226    replica_id: Uuid,
227) -> Result<String, AmqpError> {
228    channel
229        .exchange_declare(
230            exchanges::AUTHZ_CACHE_INVALIDATE.into(),
231            invalidation_exchange_kind(),
232            ExchangeDeclareOptions {
233                durable: true,
234                ..ExchangeDeclareOptions::default()
235            },
236            FieldTable::default(),
237        )
238        .await
239        .map_err(AmqpError::Declaration)?;
240
241    let queue = invalidation_queue_name(replica_id);
242    channel
243        .queue_declare(
244            queue.as_str().into(),
245            invalidation_queue_options(),
246            FieldTable::default(),
247        )
248        .await
249        .map_err(AmqpError::Declaration)?;
250
251    // Fanout ignores the routing key; bind with the empty one.
252    channel
253        .queue_bind(
254            queue.as_str().into(),
255            exchanges::AUTHZ_CACHE_INVALIDATE.into(),
256            "".into(),
257            QueueBindOptions::default(),
258            FieldTable::default(),
259        )
260        .await
261        .map_err(AmqpError::Declaration)?;
262
263    info!(
264        exchange = exchanges::AUTHZ_CACHE_INVALIDATE,
265        queue = %queue,
266        "Declared authz decision-cache invalidation topology (fanout, per-replica queue)"
267    );
268    Ok(queue)
269}

275/// Build the signed wire bytes for one invalidation broadcast.
276///
277/// Broker-free seam so the whole envelope — canonical form, per-tenant subkey,
278/// nonce, `issued_at` — is unit-testable without RabbitMQ, mirroring
279/// `process_authz_request`'s separation of decode/verify from channel I/O.
280pub fn build_signed_invalidation(
281    master_key: &[u8],
282    origin_id: Uuid,
283    event: InvalidationEvent,
284    now: DateTime<Utc>,
285) -> Result<Vec<u8>, AmqpError> {
286    sign_message(
287        master_key,
288        CacheInvalidationMessage {
289            origin_id,
290            tenant_id: event.tenant_id(),
291            subject_id: event.subject_id(),
292            key_version: CURRENT_KEY_VERSION,
293            nonce: Uuid::new_v4(),
294            issued_at: now,
295            heartbeat: false,
296            hmac_signature: None,
297        },
298    )
299}
300
301/// Tenant id stamped on a liveness heartbeat.
302///
303/// Heartbeats are not tenant-scoped — they carry no cache effect at all — but
304/// the envelope derives its HMAC subkey from `tenant_id`, so the field must
305/// hold *something*. The nil UUID is used deliberately: it is not a real
306/// tenant, so even if a heartbeat were somehow mistaken for an invalidation it
307/// could only ever flush a tenant that does not exist. The consumer's heartbeat
308/// branch runs before any event is constructed, so that path is unreachable —
309/// this is the second line of defence, not the first.
310pub const HEARTBEAT_TENANT_ID: Uuid = Uuid::nil();
311
312/// Build the signed wire bytes for one liveness heartbeat (§13.4 observation 1).
313///
314/// Same envelope, same signing, same freshness and replay gates as an
315/// invalidation — a heartbeat is not a privileged message type, it simply
316/// carries no cache effect.
317/// Returns the wire bytes **and the nonce**; the caller registers the nonce as
318/// outstanding so the echo can be told apart from a replay (§15.2 gap 3).
319pub fn build_signed_heartbeat(
320    master_key: &[u8],
321    origin_id: Uuid,
322    now: DateTime<Utc>,
323) -> Result<(Vec<u8>, Uuid), AmqpError> {
324    let nonce = Uuid::new_v4();
325    let payload = sign_message(
326        master_key,
327        CacheInvalidationMessage {
328            origin_id,
329            tenant_id: HEARTBEAT_TENANT_ID,
330            subject_id: None,
331            key_version: CURRENT_KEY_VERSION,
332            nonce,
333            issued_at: now,
334            heartbeat: true,
335            hmac_signature: None,
336        },
337    )?;
338    Ok((payload, nonce))
339}

341/// Canonicalize, sign, and serialize one message. Shared by the invalidation and
342/// heartbeat builders so the two can never drift into signing different shapes.
343fn sign_message(
344    master_key: &[u8],
345    mut message: CacheInvalidationMessage,
346) -> Result<Vec<u8>, AmqpError> {
347    // Canonical body = the message with `hmac_signature` absent.
348    let canonical = serde_json::to_vec(&message)
349        .map_err(|e| AmqpError::Publish(format!("canonicalize invalidation: {e}")))?;
350    let subkey = derive_tenant_key(master_key, message.tenant_id, message.key_version);
351    message.hmac_signature = Some(sign_payload(&subkey, &canonical));
352
353    serde_json::to_vec(&message)
354        .map_err(|e| AmqpError::Publish(format!("serialize invalidation: {e}")))
355}

361/// Bounded in-memory nonce store for one replica's invalidation consumer.
362///
363/// Deliberately **not** the shared durable `AmqpNonceRepository` the authz
364/// consumer uses: on a fanout every replica receives the same nonce, so a
365/// shared store would let exactly one replica record it and make every other
366/// replica reject the invalidation as a replay — silently reintroducing the
367/// stale-allow hole on all but one replica. Per-replica memory is the correct
368/// scope for a broadcast.
369pub struct NonceGuard {
370    inner: Mutex<NonceGuardInner>,
371}
372
373#[derive(Default)]
374struct NonceGuardInner {
375    seen: HashSet<Uuid>,
376    /// `(expiry, nonce)` in insertion order; insertion order is expiry order
377    /// because every entry uses the same window.
378    order: VecDeque<(DateTime<Utc>, Uuid)>,
379}
380
381impl Default for NonceGuard {
382    fn default() -> Self {
383        Self::new()
384    }
385}
386
387impl NonceGuard {
388    pub fn new() -> Self {
389        Self {
390            inner: Mutex::new(NonceGuardInner::default()),
391        }
392    }
393
394    /// Record `nonce`, returning `true` when it is **new** (accept the message)
395    /// and `false` when it has already been seen within the window (replay).
396    ///
397    /// Entries are dropped once `expires_at` has passed — the freshness gate
398    /// already rejects anything that old — and the set is hard-capped at
399    /// [`NONCE_GUARD_CAPACITY`].
400    pub fn check_and_record(
401        &self,
402        nonce: Uuid,
403        expires_at: DateTime<Utc>,
404        now: DateTime<Utc>,
405    ) -> bool {
406        let mut inner = self.inner.lock().unwrap_or_else(|p| p.into_inner());
407        while let Some(&(expiry, old)) = inner.order.front() {
408            if expiry > now && inner.order.len() <= NONCE_GUARD_CAPACITY {
409                break;
410            }
411            inner.order.pop_front();
412            inner.seen.remove(&old);
413        }
414        if !inner.seen.insert(nonce) {
415            return false;
416        }
417        inner.order.push_back((expires_at, nonce));
418        true
419    }
420
421    /// Number of retained nonces (observability / tests).
422    pub fn len(&self) -> usize {
423        self.inner
424            .lock()
425            .unwrap_or_else(|p| p.into_inner())
426            .seen
427            .len()
428    }
429
430    pub fn is_empty(&self) -> bool {
431        self.len() == 0
432    }
433}

439/// Why a delivery was refused. Every variant is a *drop*, never a requeue: a
440/// broadcast has no second consumer to hand it to, and requeueing would
441/// hot-loop against ourselves.
442#[derive(Debug, Clone, Copy, PartialEq, Eq)]
443pub enum InvalidationReject {
444    /// Payload did not deserialize.
445    Malformed,
446    /// Unsigned, or the HMAC did not verify under the tenant's subkey.
447    BadSignature,
448    /// `key_version` below [`MIN_ACCEPTED_KEY_VERSION`] (pre-replay-protection).
449    KeyVersion,
450    /// `issued_at` outside the freshness window.
451    Stale,
452    /// This exact nonce was already applied on this replica.
453    Replay,
454}
455
456/// Outcome of processing one invalidation delivery.
457#[derive(Debug, Clone, Copy, PartialEq, Eq)]
458pub enum InvalidationOutcome {
459    /// Verified and fresh — the caller must apply this event to the cache.
460    Applied(InvalidationEvent),
461    /// The replica's own broadcast, echoed back by the fanout. **No-op**: the
462    /// publisher already invalidated locally before publishing, so re-applying
463    /// would be redundant work on the exact code path the cache exists to make
464    /// fast.
465    SelfEcho,
466    /// A liveness heartbeat (§13.4 observation 1). Never touches the cache.
467    /// `own` distinguishes this replica's own heartbeat — the only one that
468    /// carries information, since observing it proves *our* binding is intact —
469    /// from another replica's, which is simply ignored. `nonce` lets the caller
470    /// tell a genuine echo from a replay (§15.2 gap 3).
471    Heartbeat { own: bool, nonce: Uuid },
472    /// Refused; see [`InvalidationReject`].
473    Rejected(InvalidationReject),
474}
475
476/// Decode, verify, freshness-check, self-echo-check and replay-check one
477/// invalidation payload. **Pure** — no broker, no cache, `now` injected — so
478/// every branch is unit-testable, mirroring `process_authz_request`.
479///
480/// Order is deliberate: signature first (nothing unauthenticated influences
481/// any later step), then the version floor, then freshness, then self-echo
482/// (skipping before the nonce guard so our own broadcasts do not consume its
483/// capacity), then replay.
484pub fn process_invalidation(
485    raw: &[u8],
486    master_key: &[u8],
487    local_origin: Uuid,
488    guard: &NonceGuard,
489    skew: chrono::Duration,
490    now: DateTime<Utc>,
491) -> InvalidationOutcome {
492    let mut message: CacheInvalidationMessage = match serde_json::from_slice(raw) {
493        Ok(m) => m,
494        Err(e) => {
495            warn!(error = %e, "Invalid cache-invalidation payload — dropping");
496            return InvalidationOutcome::Rejected(InvalidationReject::Malformed);
497        }
498    };
499
500    // §8: verify the per-tenant derived HMAC over the canonical body
501    // (signature field absent). No fail-open path — an unsigned message is
502    // rejected exactly like a badly-signed one.
503    let received_sig = message.hmac_signature.take();
504    let tenant_id = message.tenant_id;
505    let key_version = message.key_version;
506    let canonical = match serde_json::to_vec(&message) {
507        Ok(c) => c,
508        Err(e) => {
509            warn!(error = %e, "Cache-invalidation canonicalization failed — dropping");
510            return InvalidationOutcome::Rejected(InvalidationReject::Malformed);
511        }
512    };
513    if !verify_tenant_signature(
514        master_key,
515        tenant_id,
516        key_version,
517        &canonical,
518        received_sig.as_deref(),
519    ) {
520        warn!(
521            tenant_id = %tenant_id,
522            "Cache-invalidation message unsigned or HMAC verification failed — rejecting"
523        );
524        return InvalidationOutcome::Rejected(InvalidationReject::BadSignature);
525    }
526
527    if key_version < MIN_ACCEPTED_KEY_VERSION {
528        warn!(
529            tenant_id = %tenant_id,
530            key_version,
531            "Cache-invalidation key_version below minimum — rejecting"
532        );
533        return InvalidationOutcome::Rejected(InvalidationReject::KeyVersion);
534    }
535
536    if !is_fresh(message.issued_at, now, skew) {
537        // Logged, counted — but deliberately NOT a reason to distrust the
538        // cache: see the module docs (trust follows connection liveness only,
539        // so a captured message cannot be used to disable every replica's
540        // cache).
541        warn!(
542            tenant_id = %tenant_id,
543            issued_at = %message.issued_at,
544            "Cache-invalidation issued_at outside freshness window — rejecting"
545        );
546        return InvalidationOutcome::Rejected(InvalidationReject::Stale);
547    }
548
549    // Heartbeats are separated out BEFORE the nonce guard and before any event
550    // is constructed. Two reasons, both deliberate: a heartbeat must never be
551    // able to reach `InvalidationEvent::apply` (so it cannot flush anything),
552    // and heartbeats arrive on a fixed interval from every replica, so letting
553    // them consume the bounded nonce-guard capacity would evict real
554    // invalidation nonces and weaken replay protection on a busy cluster.
555    if message.heartbeat {
556        let own = message.origin_id == local_origin;
557        debug!(own, "Cache-invalidation liveness heartbeat");
558        return InvalidationOutcome::Heartbeat {
559            own,
560            nonce: message.nonce,
561        };
562    }
563
564    if message.origin_id == local_origin {
565        debug!(tenant_id = %tenant_id, "Cache-invalidation self-echo — no-op");
566        return InvalidationOutcome::SelfEcho;
567    }
568
569    if !guard.check_and_record(message.nonce, message.issued_at + skew, now) {
570        warn!(
571            tenant_id = %tenant_id,
572            nonce = %message.nonce,
573            "Cache-invalidation nonce replay detected — rejecting"
574        );
575        return InvalidationOutcome::Rejected(InvalidationReject::Replay);
576    }
577
578    let event = match message.subject_id {
579        Some(subject_id) => InvalidationEvent::Subject {
580            tenant_id,
581            subject_id,
582        },
583        None => InvalidationEvent::Tenant { tenant_id },
584    };
585    InvalidationOutcome::Applied(event)
586}

588/// [`process_invalidation`] plus application to `cache`.
589///
590/// The only place a received message touches state. It calls
591/// [`InvalidationEvent::apply`], which talks to the `DecisionCache` directly —
592/// there is no path from here back to a publish, so an echo cannot loop.
593pub fn handle_invalidation(
594    raw: &[u8],
595    cache: &DecisionCache,
596    master_key: &[u8],
597    local_origin: Uuid,
598    guard: &NonceGuard,
599    skew: chrono::Duration,
600    now: DateTime<Utc>,
601) -> InvalidationOutcome {
602    let outcome = process_invalidation(raw, master_key, local_origin, guard, skew, now);
603    if let InvalidationOutcome::Applied(event) = outcome {
604        event.apply(cache);
605    }
606    outcome
607}

609// ---------------------------------------------------------------------------
610// Liveness (§13.4 observation 1)
611// ---------------------------------------------------------------------------
612
613/// How many heartbeat intervals may pass with no self-echo before this replica
614/// stops trusting its cache.
615///
616/// Three, not one: a single missed heartbeat is far more likely to be a broker
617/// hiccup or a scheduling delay than a broken binding, and revoking trust on it
618/// would make every transient blip a latency cliff. Three consecutive misses is
619/// long enough to be a real signal and still bounded well below any interval an
620/// operator would find acceptable for a stale allow.
621pub const HEARTBEAT_MISS_THRESHOLD: u32 = 3;
622
623/// Tracks whether this replica is still *receiving* its own broadcasts.
624///
625/// The gap this closes (§13.4 observation 1): the cache's trust flag follows
626/// **consumer liveness** — it is set when `basic_consume` succeeds and cleared
627/// when the consumer exits. But a party with broker *configure* rights can
628/// `queue.unbind` a replica's queue from the fanout exchange. The consumer stays
629/// happily subscribed to a queue nothing is routed to any more, trust stays
630/// `true`, and the replica keeps serving cached allows it will never be told to
631/// invalidate. The publisher sees nothing either: with `mandatory` off, the
632/// broker acks an unroutable message.
633///
634/// A self-addressed heartbeat is the smallest thing that actually tests the
635/// property in question, because it exercises the *entire* loop — publish →
636/// exchange → binding → queue → consumer. An unbound queue breaks it
637/// immediately.
638///
639/// **This type can only ever revoke trust, never grant it.** Trust is granted in
640/// exactly one place, by the consumer, on a successful `basic_consume`. A
641/// watchdog that could also grant it would be able to resurrect trust on a
642/// replica whose consumer had died — turning a fail-safe into a fail-open.
643pub struct InvalidationLiveness {
644    /// When we last saw our own broadcast come back. `None` = not subscribed.
645    last_own_echo: Mutex<Option<DateTime<Utc>>>,
646    /// Nonces of heartbeats this replica has published and not yet seen return
647    /// (§15.2 gap 3).
648    ///
649    /// Heartbeats deliberately bypass the [`NonceGuard`] — they arrive on a
650    /// fixed interval from every replica and would evict real invalidation
651    /// nonces from its bounded capacity. But that left a narrow suppression
652    /// path: a party with broker rights who captured one signed heartbeat could
653    /// replay it inside the freshness window to keep this replica's watchdog
654    /// satisfied while its queue was unbound — the exact adversary Obs 1 is
655    /// about.
656    ///
657    /// Binding acceptance to nonces *we* generated closes that without touching
658    /// the shared guard: a replayed heartbeat carries a nonce that was already
659    /// consumed (or never issued here), so it is ignored. This is strictly
660    /// cheaper than a general replay guard because the set only ever holds the
661    /// handful of heartbeats currently in flight.
662    outstanding: Mutex<VecDeque<Uuid>>,
663}
664
665/// Cap on [`InvalidationLiveness::outstanding`].
666///
667/// Only heartbeats still in flight matter, and a heartbeat that has not come
668/// back within a few intervals is already a miss. A small ring keeps this
669/// bounded regardless of broker behaviour — an unbound queue means every
670/// published nonce goes unanswered, and the set must not grow for as long as
671/// that lasts.
672const MAX_OUTSTANDING_HEARTBEATS: usize = 8;
673
674impl Default for InvalidationLiveness {
675    fn default() -> Self {
676        Self::new()
677    }
678}
679
680impl InvalidationLiveness {
681    pub fn new() -> Self {
682        Self {
683            last_own_echo: Mutex::new(None),
684            outstanding: Mutex::new(VecDeque::new()),
685        }
686    }
687
688    /// Record a heartbeat nonce this replica is about to publish (§15.2 gap 3).
689    pub fn record_sent_heartbeat(&self, nonce: Uuid) {
690        let mut q = self
691            .outstanding
692            .lock()
693            .unwrap_or_else(|poisoned| poisoned.into_inner());
694        if q.len() >= MAX_OUTSTANDING_HEARTBEATS {
695            q.pop_front();
696        }
697        q.push_back(nonce);
698    }
699
700    /// Consume `nonce` if this replica published it and has not seen it back.
701    ///
702    /// Returns `false` for a nonce we never issued or already consumed — i.e.
703    /// for a replayed heartbeat, which must not refresh the liveness clock.
704    fn consume_outstanding(&self, nonce: Uuid) -> bool {
705        let mut q = self
706            .outstanding
707            .lock()
708            .unwrap_or_else(|poisoned| poisoned.into_inner());
709        match q.iter().position(|n| *n == nonce) {
710            Some(i) => {
711                q.remove(i);
712                true
713            }
714            None => false,
715        }
716    }
717
718    /// Called by the consumer immediately after it subscribes. Starts the clock:
719    /// without this, a freshly-subscribed replica would look infinitely stale
720    /// and the watchdog would revoke trust before the first heartbeat round.
721    pub fn mark_subscribed(&self, now: DateTime<Utc>) {
722        *self.lock() = Some(now);
723    }
724
725    /// Called by the consumer when it observes its **own** heartbeat.
726    ///
727    /// Refreshes the liveness clock **only** for a nonce this replica actually
728    /// published and has not already seen back (§15.2 gap 3), so a replayed
729    /// heartbeat cannot hold the watchdog open. Returns whether it counted.
730    pub fn record_own_heartbeat(&self, nonce: Uuid, now: DateTime<Utc>) -> bool {
731        if !self.consume_outstanding(nonce) {
732            return false;
733        }
734        *self.lock() = Some(now);
735        true
736    }
737
738    /// Called when the consumer stops, so a reconnecting consumer cannot inherit
739    /// a stale "recently alive" timestamp from its predecessor.
740    pub fn mark_unsubscribed(&self) {
741        *self.lock() = None;
742        // A reconnecting consumer must not be able to satisfy its watchdog with
743        // a heartbeat its predecessor published.
744        self.outstanding
745            .lock()
746            .unwrap_or_else(|poisoned| poisoned.into_inner())
747            .clear();
748    }
749
750    /// The last observation, if any.
751    pub fn last_own_echo(&self) -> Option<DateTime<Utc>> {
752        *self.lock()
753    }
754
755    /// Has the loop been silent for longer than `interval * HEARTBEAT_MISS_THRESHOLD`?
756    ///
757    /// `None` (not subscribed) is **not** stale: the consumer's own exit path
758    /// already marked the cache untrusted, and reporting staleness here would
759    /// only produce a duplicate revocation and a misleading log line.
760    pub fn is_stale(&self, now: DateTime<Utc>, interval: chrono::Duration) -> bool {
761        match *self.lock() {
762            Some(last) => now - last > interval * (HEARTBEAT_MISS_THRESHOLD as i32),
763            None => false,
764        }
765    }
766
767    fn lock(&self) -> std::sync::MutexGuard<'_, Option<DateTime<Utc>>> {
768        self.last_own_echo
769            .lock()
770            .unwrap_or_else(|poisoned| poisoned.into_inner())
771    }
772}

777
778/// Publishes signed invalidation broadcasts to the fanout exchange.
779///
780/// Attached to every `AuthorizationEngine` as an
781/// [`InvalidationBroadcaster`] when the channel is enabled.
782pub struct CacheInvalidationPublisher {
783    /// Opens publisher-confirm channels on demand.
784    ///
785    /// Publisher confirms are mandatory: without them the broker returns
786    /// `Confirmation::NotRequested` and this publisher would report success for
787    /// a message the broker never accepted, which is precisely the silent
788    /// failure §4.2 exists to remove.
789    channels: Arc<dyn PublisherChannelFactory>,
790    /// The channel currently in use, if one is open and healthy.
791    ///
792    /// §13.4 observation 2: this used to be a single `Channel` created once at
793    /// startup and never replaced. A channel is closed by the broker on any
794    /// channel-level exception, and the consumer side is fully supervised with
795    /// backoff while this side was not — so one exception made **every**
796    /// access-narrowing mutation return 503 for the rest of the process
797    /// lifetime. Fail-closed, so not a security hole, but a permanent
798    /// availability defect that only a restart cleared.
799    ///
800    /// `tokio::sync::Mutex`, not `std::sync::Mutex`: the guard is held across
801    /// the `.await` on the broker's confirm.
802    ///
803    /// Paired with a **generation counter**, bumped every time the slot is
804    /// filled. §17.1 recorded that the compare-before-clear below originally
805    /// tested `Channel::id()`, which in lapin is the AMQP channel *number*
806    /// (`u16`) — the broker recycles it after a close, so it identifies a slot
807    /// on the connection rather than a particular handle. Two channels that
808    /// are genuinely different could therefore compare equal (a reopen that
809    /// happened to be assigned the same number), and the clear would discard a
810    /// healthy replacement. The generation is monotonic and process-local, so
811    /// the comparison is exact and does not rest on a lapin invariant.
812    channel: TokioMutex<Option<(u64, Channel)>>,
813    /// Source of the generation stamps above. Every increment happens while
814    /// the `channel` lock is held, which supplies all the ordering that
815    /// matters; the counter is atomic purely so the slot's type stays simple.
816    next_generation: AtomicU64,
817    master_key: Vec<u8>,
818    origin_id: Uuid,
819}
820
821/// Opens a publisher-confirm channel. Implemented by `AmqpManager`; a trait so
822/// this module stays testable without a broker and does not depend on the
823/// connection layer's concrete type.
824pub trait PublisherChannelFactory: Send + Sync {
825    fn open<'a>(&'a self) -> Pin<Box<dyn Future<Output = Result<Channel, AmqpError>> + Send + 'a>>;
826}
827
828impl CacheInvalidationPublisher {
829    pub fn new(
830        channels: Arc<dyn PublisherChannelFactory>,
831        master_key: Vec<u8>,
832        origin_id: Uuid,
833    ) -> Self {
834        Self {
835            channels,
836            channel: TokioMutex::new(None),
837            next_generation: AtomicU64::new(0),
838            master_key,
839            origin_id,
840        }
841    }
842
843    /// This replica's id, as stamped into every broadcast for self-echo
844    /// suppression. The consumer must be given the *same* value.
845    pub fn origin_id(&self) -> Uuid {
846        self.origin_id
847    }
848
849    /// Publish one invalidation and wait for the broker's confirm.
850    ///
851    /// # Errors
852    ///
853    /// Returns `Err` when the publish fails, is nacked, or is not confirmed —
854    /// i.e. whenever the fan-out demonstrably did not happen. An unroutable
855    /// message (no replica queues bound yet) is *not* an error: `mandatory` is
856    /// off, so the broker acks and drops it, which is correct — a replica with
857    /// no queue has no cache to invalidate.
858    pub async fn publish_event(&self, event: InvalidationEvent) -> Result<(), AmqpError> {
859        let payload =
860            build_signed_invalidation(&self.master_key, self.origin_id, event, Utc::now())?;
861        self.publish_payload(&payload).await
862    }
863
864    /// Publish one liveness heartbeat (§13.4 observation 1).
865    ///
866    /// Deliberately shares `publish_payload` with invalidations: the heartbeat
867    /// must traverse the exact same path it is meant to be evidence about. A
868    /// heartbeat sent over a different channel, exchange or routing key would
869    /// prove something other than what the invalidations depend on.
870    pub async fn publish_heartbeat(
871        &self,
872        liveness: &InvalidationLiveness,
873    ) -> Result<(), AmqpError> {
874        let (payload, nonce) =
875            build_signed_heartbeat(&self.master_key, self.origin_id, Utc::now())?;
876        // Registered BEFORE the publish: the fanout can deliver the echo before
877        // the confirm returns, and a nonce registered afterwards could lose that
878        // race and be discarded as a replay.
879        liveness.record_sent_heartbeat(nonce);
880        self.publish_payload(&payload).await
881    }
882
883    /// Acquire a healthy channel, publish, and await the confirm — reopening the
884    /// channel if the one we hold has been closed.
885    /// The lock covers only channel *acquisition*, never the broker round-trip
886    /// (§15.3.4).
887    ///
888    /// Holding it across the confirm serialised every access-narrowing mutation
889    /// in the process behind one network round-trip, with the heartbeat task
890    /// contending on the same lock — a throughput cliff under a slow broker,
891    /// and a regression against the pre-§13.4 code, which shared the channel
892    /// with no lock at all. `lapin::Channel` is a cheap handle over shared
893    /// state, so cloning it out of the slot and releasing the guard keeps the
894    /// reopen logic single-threaded while letting publishes proceed
895    /// concurrently — which is what the AMQP channel already supports.
896    async fn publish_payload(&self, payload: &[u8]) -> Result<(), AmqpError> {
897        let (generation, channel) = {
898            let mut slot = self.channel.lock().await;
899
900            // Drop a channel the broker has already closed, so the next block
901            // opens a fresh one instead of publishing into a dead handle.
902            if slot.as_ref().is_some_and(|(_, c)| !c.status().connected()) {
903                warn!("Cache-invalidation publisher channel is closed — reopening");
904                *slot = None;
905            }
906            if slot.is_none() {
907                let opened = self.channels.open().await?;
908                let generation = self.next_generation.fetch_add(1, Ordering::Relaxed);
909                *slot = Some((generation, opened));
910            }
911            let (generation, channel) = slot.as_ref().expect("channel opened above");
912            (*generation, channel.clone())
913            // Guard dropped here — the confirm below is awaited unlocked.
914        };
915
916        match Self::publish_on(&channel, payload).await {
917            Ok(()) => Ok(()),
918            Err(e) => {
919                // Any failure may have been the channel dying under us. Discard
920                // it so the *next* mutation reopens rather than inheriting a
921                // broken handle — the whole point of observation 2. The error is
922                // still returned: this mutation genuinely did not fan out, and
923                // silently retrying here would hide a broker refusing the
924                // message for a reason that will recur.
925                //
926                // Compare-before-clear: between releasing the guard and
927                // re-acquiring it, a concurrent publisher may already have
928                // replaced the slot with a healthy channel. Clearing
929                // unconditionally would discard that one too, and a burst of
930                // failures could then thrash the slot indefinitely.
931                //
932                // The comparison is on the generation stamp, not on
933                // `Channel::id()`: the latter is the broker's channel *number*
934                // and is recycled after a close, so a reopened channel could
935                // wear the same id as the dead one this call was holding and
936                // be cleared in its place (§17.1). Generations are monotonic
937                // and never reused, so `==` here means "still the very handle
938                // that failed" and nothing else.
939                let mut slot = self.channel.lock().await;
940                if slot.as_ref().is_some_and(|(g, _)| *g == generation) {
941                    *slot = None;
942                }
943                Err(e)
944            }
945        }
946    }
947
948    async fn publish_on(channel: &Channel, payload: &[u8]) -> Result<(), AmqpError> {
949        let confirm = channel
950            .basic_publish(
951                exchanges::AUTHZ_CACHE_INVALIDATE.into(),
952                // Fanout ignores the routing key.
953                "".into(),
954                BasicPublishOptions::default(),
955                payload,
956                BasicProperties::default()
957                    .with_content_type("application/json".into())
958                    // Transient (1), not persistent: an invalidation is only
959                    // meaningful to a live replica, and a replica that
960                    // restarts comes back with an empty cache.
961                    .with_delivery_mode(1),
962            )
963            .await
964            .map_err(|e| AmqpError::Publish(format!("cache invalidation publish failed: {e}")))?;
965
966        match confirm.await {
967            Ok(Confirmation::Ack(_)) | Ok(Confirmation::NotRequested) => Ok(()),
968            Ok(Confirmation::Nack(_)) => Err(AmqpError::Publish(
969                "cache invalidation broadcast was nacked by the broker".to_string(),
970            )),
971            Err(e) => Err(AmqpError::Publish(format!(
972                "cache invalidation broadcast not confirmed by the broker: {e}"
973            ))),
974        }
975    }
976}

998    }

1001// ---------------------------------------------------------------------------
1002// Consumer
1003// ---------------------------------------------------------------------------
1004
1005/// Marks the cache untrusted whenever the consumer is not running — on every
1006/// exit path including an error return, a panic, or the task being dropped
1007/// mid-await. Making this a `Drop` guard rather than a line at the end of the
1008/// function is what stops a future edit from introducing an early `return`
1009/// that leaves the cache trusted with no consumer behind it.
1010struct TrustGuard(Arc<DecisionCache>, Option<Arc<InvalidationLiveness>>);
1011
1012impl Drop for TrustGuard {
1013    fn drop(&mut self) {
1014        self.0.set_trusted(false);
1015        // Clear the liveness clock too, so a reconnecting consumer cannot
1016        // inherit its predecessor's "recently alive" timestamp and look healthy
1017        // before it has actually observed anything.
1018        if let Some(liveness) = &self.1 {
1019            liveness.mark_unsubscribed();
1020        }
1021    }
1022}
1023
1024/// Run this replica's invalidation consumer until the stream ends.
1025///
1026/// Declares the topology, subscribes, marks the cache **trusted**, then applies
1027/// every verified broadcast. On any exit — subscribe failure, stream end,
1028/// cancellation — the cache is marked **untrusted** again, so the replica falls
1029/// back to uncached (correct, slower) evaluation instead of serving allows it
1030/// can no longer invalidate.
1031///
1032/// Callers should supervise this in a reconnect loop with backoff; each call is
1033/// one connection's worth of consuming.
1034pub async fn run_cache_invalidation_consumer(
1035    channel: Channel,
1036    cache: Arc<DecisionCache>,
1037    master_key: Vec<u8>,
1038    replica_id: Uuid,
1039    skew: chrono::Duration,
1040    liveness: Option<Arc<InvalidationLiveness>>,
1041) -> Result<(), AmqpError> {
1042    // Armed before anything can fail: from here on, every exit path leaves the
1043    // cache untrusted.
1044    let _trust = TrustGuard(Arc::clone(&cache), liveness.clone());
1045
1046    let queue = declare_cache_invalidation_topology(&channel, replica_id).await?;
1047
1048    let mut consumer = channel
1049        .basic_consume(
1050            queue.as_str().into(),
1051            format!("axiam-cache-invalidation-{replica_id}")
1052                .as_str()
1053                .into(),
1054            BasicConsumeOptions::default(),
1055            FieldTable::default(),
1056        )
1057        .await
1058        .map_err(AmqpError::Channel)?;
1059
1060    // Only now — subscribed and receiving — may this replica serve from cache.
1061    // This is the ONLY place trust is granted; the liveness watchdog can revoke
1062    // it but never restore it, so a dead consumer can never be papered over.
1063    cache.set_trusted(true);
1064    if let Some(liveness) = &liveness {
1065        // Start the clock here rather than at the first heartbeat: otherwise a
1066        // freshly-subscribed replica looks infinitely stale and the watchdog
1067        // would revoke trust before the first heartbeat round completes.
1068        liveness.mark_subscribed(Utc::now());
1069    }
1070    info!(
1071        queue = %queue,
1072        replica_id = %replica_id,
1073        "AuthZ decision-cache invalidation consumer subscribed (cross-replica fan-out live)"
1074    );
1075
1076    let guard = NonceGuard::new();
1077
1078    while let Some(delivery_result) = consumer.next().await {
1079        let delivery = match delivery_result {
1080            Ok(d) => d,
1081            Err(e) => {
1082                error!(error = %e, "Error receiving cache-invalidation delivery");
1083                continue;
1084            }
1085        };
1086
1087        let outcome = handle_invalidation(
1088            &delivery.data,
1089            &cache,
1090            &master_key,
1091            replica_id,
1092            &guard,
1093            skew,
1094            Utc::now(),
1095        );
1096
1097        match outcome {
1098            InvalidationOutcome::Applied(event) => {
1099                debug!(
1100                    tenant_id = %event.tenant_id(),
1101                    subject_id = ?event.subject_id(),
1102                    "Applied cross-replica cache invalidation"
1103                );
1104                let _ = delivery.acker.ack(BasicAckOptions::default()).await;
1105            }
1106            InvalidationOutcome::SelfEcho => {
1107                let _ = delivery.acker.ack(BasicAckOptions::default()).await;
1108            }
1109            InvalidationOutcome::Heartbeat { own, nonce } => {
1110                // Only our OWN heartbeat is evidence: it is the one that proves
1111                // *this* replica's queue is still bound to the exchange. Another
1112                // replica's heartbeat proves only that the other replica can
1113                // publish, which says nothing about our binding.
1114                if let Some(liveness) = &liveness
1115                    && own
1116                    && !liveness.record_own_heartbeat(nonce, Utc::now())
1117                {
1118                    // A correctly-signed, fresh heartbeat carrying our origin id
1119                    // but a nonce we did not issue (or already saw) is a replay.
1120                    // It must not refresh the liveness clock — that is the
1121                    // suppression path §15.2 gap 3 names — and it is worth a log
1122                    // line, because in normal operation it cannot happen.
1123                    warn!(
1124                        %nonce,
1125                        "Replayed or unrecognised own-heartbeat nonce — ignoring; \
1126                         this does not refresh cache-invalidation liveness"
1127                    );
1128                }
1129                let _ = delivery.acker.ack(BasicAckOptions::default()).await;
1130            }
1131            InvalidationOutcome::Rejected(reason) => {
1132                // Drop, never requeue: a broadcast has no other consumer to
1133                // hand it to, so requeueing would hot-loop against ourselves.
1134                warn!(?reason, "Rejected cache-invalidation delivery");
1135                let _ = delivery
1136                    .acker
1137                    .nack(BasicNackOptions {
1138                        requeue: false,
1139                        ..BasicNackOptions::default()
1140                    })
1141                    .await;
1142            }
1143        }
1144    }
1145
1146    warn!("AuthZ decision-cache invalidation consumer stream ended");
1147    Ok(())
1148    // `_trust` drops here → cache marked untrusted.
1149}

1205        let later = t0 + chrono::Duration::seconds(31);
1206        assert!(guard.check_and_record(
1207            Uuid::new_v4(),
1208            later + chrono::Duration::seconds(30),
1209            later
1210        ));
1211        assert_eq!(guard.len(), 1, "expired nonce reaped");
1212
1213        for _ in 0..(NONCE_GUARD_CAPACITY + 500) {

1215        }

1217            guard.len() <= NONCE_GUARD_CAPACITY + 1,
1218            "guard must stay bounded, got {}",
