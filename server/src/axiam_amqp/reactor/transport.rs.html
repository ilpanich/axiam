1//! The production lapin [`ReactorTransport`] (X1 / R2.4).
2//!
3//! `dispatcher.rs` decides what a chain of reactors *means*; this module is the
4//! only part of X1 that knows a broker exists. It replaces
5//! [`super::dispatcher::UnavailableReactorTransport`], which every deployment
6//! composed while this file did not exist and which resolved every dispatch
7//! through the registration's failure policy.
8//!
9//! # Topology, and the one place it departs from a literal reading of §22.1
10//!
11//! `sdks/CONTRACT.md` §22.1 defines the topology this module declares:
12//!
13//! | Element | Value |
14//! |---|---|
15//! | Exchange | [`REACTOR_EXCHANGE`], type **topic**, durable |
16//! | Routing key | [`routing_key`] — `<tenant_id>.<event>` |
17//! | Per-reactor queue | [`queue_name`] — `axiam.reactor.q.<tenant>.<reactor>`, durable |
18//!
19//! **The server declares all three; an actor declares nothing.** That is the
20//! rule §22.1 states and the reason it states it: a reactor that can bind is a
21//! reactor that can bind itself to `*.token.pre_issue` and read another
22//! tenant's issuance events. [`LapinReactorTransport::declare_reactor_topology`]
23//! is where the server holds that capability, and it is called on the dispatch
24//! path so a queue that was deleted out from under a live registration repairs
25//! itself rather than silently swallowing every event.
26//!
27//! **An `intercept` round trip publishes to the reactor's queue directly (the
28//! default exchange), not through the topic exchange**, and this is deliberate
29//! rather than a shortcut. The routing key is per `(tenant, event)`, so a
30//! publish through the exchange reaches *every* reactor registered for that
31//! event at once. [`run_chain`](super::dispatcher::run_chain) dispatches
32//! sequentially in priority order, each reactor seeing what the previous ones
33//! patched, and it correlates exactly one reply per event. Fanning one
34//! `correlation_id` out to the whole chain would mean the first reply to arrive
35//! is consumed as the reply of whichever reactor the chain is currently
36//! waiting on — priority order decided by message timing, and a low-priority
37//! reactor able to answer in a high-priority reactor's place. Addressing the
38//! queue is what makes the dispatch 1:1 and the ordering the declared one.
39//!
40//! The exchange and the bindings are still declared, for every registration and
41//! every event it names, because §22.1 says the server owns them and because
42//! [`LapinReactorTransport::publish_listen`]'s fan-out and any operator
43//! inspecting the topology both depend on them existing.
44//!
45//! # Reply correlation
46//!
47//! One **exclusive, broker-named reply queue per process**, one consumer task,
48//! and a `correlation_id → oneshot::Sender` map. A round trip costs one publish
49//! and one map insert; it does not declare a queue. (A reply queue per round
50//! trip — what `tests/reactor_containerized_test.rs`'s test-only transport did
51//! before this module existed — is fine for five ignored tests and is a queue
52//! churn of one declare, one consume and one delete per login in production.)
53//!
54//! Replies are routed by the `correlation_id` **inside the body**, which is
55//! what §22.1 says the server authenticates, rather than by the AMQP property.
56//! Routing is not trust: the chain re-checks the correlation, the tenant, the
57//! event and the HMAC in [`ReactorReply::into_outcome`], so the worst a reactor
58//! can do by naming a correlation it was not given is fail a round trip that
59//! its own failure policy then resolves.
60//!
61//! # What a broker outage costs
62//!
63//! Nothing is retried at this layer and nothing is queued. A dispatch while the
64//! transport has no live session fails **immediately** as
65//! [`DispatchFailure::Transport`] rather than burning the reactor's whole
66//! `timeout_ms` waiting for a reply that cannot arrive — the registration's
67//! `failure_policy` then decides, which is the same closed set §22.8 puts a
68//! timeout in. A supervisor task re-establishes the session with backoff in the
69//! background.
70//!
71//! [`ReactorTransport::can_dispatch`] stays `true` throughout, including while
72//! disconnected. It reports the transport's *capability*, not its health; a
73//! `false` on a broker blip would refuse reactor registrations for the duration
74//! of the outage, turning a broker problem into an admin-API problem.
75

101/// How long a per-reactor queue survives with no consumer and no activity
102/// (`x-expires`), in milliseconds — seven days.
103///
104/// Reactor queues are durable and are **not** auto-delete: a registration's
105/// queue must outlive its actor's restarts, or every reconnect would race the
106/// server's next publish. That makes them the one piece of X1 topology that
107/// can accumulate, because deleting a registration through the admin API does
108/// not currently reach this transport to delete its queue.
109///
110/// `x-expires` bounds that without new plumbing: a queue nobody consumes and
111/// nothing touches for seven days is reclaimed by the broker, and a *live*
112/// registration is never affected because an attached consumer is "use". A
113/// registration whose actor really has been offline for a week loses a queue
114/// that only held expired events anyway (see [`Self::round_trip`]'s per-message
115/// expiration), and [`LapinReactorTransport::declare_reactor_topology`]
116/// recreates it on the next dispatch.
117const REACTOR_QUEUE_UNUSED_TTL_MS: i64 = 7 * 24 * 60 * 60 * 1_000;
118
119/// Bound on messages held for an offline reactor (`x-max-length`).
120///
121/// An interceptor's events carry a per-message expiration and drop themselves,
122/// so this is really a bound on `listen` fan-out to an actor that is not
123/// running. Overflow drops from the head (the oldest), which is the right end
124/// to lose: a listener that has fallen 10 000 events behind is not going to
125/// catch up, and the newest events are the ones with any remaining value.
126const REACTOR_QUEUE_MAX_LENGTH: i64 = 10_000;
127
128/// Backoff bounds for the reply-consumer supervisor.
129const RECONNECT_BACKOFF_START: Duration = Duration::from_secs(1);
130const RECONNECT_BACKOFF_MAX: Duration = Duration::from_secs(30);

132/// The failure text a dispatch carries when the transport has no live broker
133/// session. Named so an operator can grep for it, exactly as
134/// [`super::dispatcher::REACTOR_TRANSPORT_UNAVAILABLE`] is.
135pub const REACTOR_TRANSPORT_DISCONNECTED: &str =
136    "the AMQP reactor transport has no live broker session";

138/// One live broker session: the channel everything is published on and the
139/// reply queue replies come back to.
140///
141/// Held together because they are only ever valid together — a reply queue is
142/// exclusive to the connection that declared it, so a channel replacement that
143/// kept the old queue name would address a queue that no longer exists.
144#[derive(Clone)]
145struct Session {
146    channel: Channel,
147    reply_queue: String,
148}
149
150/// State shared between the transport and its supervisor task.
151struct Shared {
152    /// `None` until the supervisor establishes a session, and again after it
153    /// loses one.
154    session: RwLock<Option<Session>>,
155    /// In-flight round trips, keyed by the `correlation_id` the reply must
156    /// carry in its body.
157    pending: Mutex<HashMap<Uuid, oneshot::Sender<Vec<u8>>>>,
158    /// Which event bindings each reactor's queue currently has, as this
159    /// process declared them. Cleared whenever the session is lost, because
160    /// the next session must re-declare from scratch rather than trust a
161    /// cache written against a channel that is gone.
162    declared: Mutex<HashMap<Uuid, Vec<String>>>,
163}
164
165impl Shared {
166    fn new() -> Self {
167        Self {
168            session: RwLock::new(None),
169            pending: Mutex::new(HashMap::new()),
170            declared: Mutex::new(HashMap::new()),
171        }
172    }
173
174    /// Snapshot the current session, if any.
175    ///
176    /// Returns a clone rather than a guard: every caller needs it across an
177    /// `await`, and holding a lock across one is how a transport deadlocks
178    /// itself under load.
179    fn session(&self) -> Option<Session> {
180        match self.session.read() {
181            Ok(g) => g.clone(),
182            // A poisoned lock means a panic happened while the supervisor was
183            // swapping the session. Reading through it is safe — the value is
184            // either the old session or the new one, both valid — and refusing
185            // to dispatch would be strictly worse than dispatching on a
186            // session that may be one generation stale, which fails as a
187            // transport error and resolves through the failure policy anyway.
188            Err(poisoned) => poisoned.into_inner().clone(),
189        }
190    }
191
192    fn set_session(&self, session: Option<Session>) {
193        match self.session.write() {
194            Ok(mut g) => *g = session,
195            Err(poisoned) => *poisoned.into_inner() = session,
196        }
197    }
198
199    fn pending_map(&self) -> std::sync::MutexGuard<'_, HashMap<Uuid, oneshot::Sender<Vec<u8>>>> {
200        self.pending
201            .lock()
202            .unwrap_or_else(std::sync::PoisonError::into_inner)
203    }
204
205    fn declared_map(&self) -> std::sync::MutexGuard<'_, HashMap<Uuid, Vec<String>>> {
206        self.declared
207            .lock()
208            .unwrap_or_else(std::sync::PoisonError::into_inner)
209    }
210
211    /// Drop every waiting round trip. Each sender's `Drop` wakes its receiver
212    /// with an error, so an in-flight dispatch learns the session died at once
213    /// instead of waiting out its `timeout_ms` for a reply that can no longer
214    /// be delivered.
215    fn abandon_all_pending(&self) {
216        let abandoned = self.pending_map().drain().count();
217        if abandoned > 0 {
218            tracing::warn!(
219                target: "axiam::reactor",
220                abandoned,
221                "reactor reply session lost; in-flight dispatches fail now rather \
222                 than waiting out their timeouts"
223            );
224        }
225    }
226}

228/// The lapin [`ReactorTransport`] `axiam-server` composes.
229///
230/// Cheap to clone; every clone shares one session, one pending map and one
231/// topology cache.
232#[derive(Clone)]
233pub struct LapinReactorTransport {
234    shared: Arc<Shared>,
235    /// The AMQP master key. Events are signed with the tenant subkey derived
236    /// from it (§8 v2), the same derivation the chain uses to verify replies.
237    signing_key: Arc<Vec<u8>>,
238}
239
240impl LapinReactorTransport {
241    /// Build the transport and spawn the supervisor that keeps its broker
242    /// session alive.
243    ///
244    /// **Infallible on purpose.** The alternative — returning a `Result` that
245    /// `axiam-server` unwraps — would make a broker that happens to be slow at
246    /// boot into a server that refuses to start, and a reactor transport is
247    /// not a dependency worth refusing to serve logins over. Until the first
248    /// session is established every dispatch fails as
249    /// [`REACTOR_TRANSPORT_DISCONNECTED`] and the registration's
250    /// `failure_policy` decides, which is exactly what happens during any later
251    /// broker outage. A tenant with no registered reactor is unaffected either
252    /// way: the gate never reaches a transport for it.
253    pub fn start(amqp: Arc<AmqpManager>, signing_key: Vec<u8>) -> Self {
254        let shared = Arc::new(Shared::new());
255        tokio::spawn(supervise(Arc::clone(&amqp), Arc::clone(&shared)));
256        Self {
257            shared,
258            signing_key: Arc::new(signing_key),
259        }
260    }
261
262    /// Whether a broker session is currently established.
263    ///
264    /// This is *health*, and deliberately not what
265    /// [`ReactorTransport::can_dispatch`] answers — see the module docs.
266    /// Exposed for readiness reporting and for tests.
267    pub fn is_connected(&self) -> bool {
268        self.shared.session().is_some()
269    }
270
271    /// Declare the topology §22.1 makes the server responsible for: the topic
272    /// exchange, this reactor's durable queue, and one binding per event in
273    /// its registration.
274    ///
275    /// Idempotent, and self-correcting in both directions — an event removed
276    /// from a registration has its binding **unbound**, because leaving it
277    /// would keep delivering an event the operator un-subscribed from. The
278    /// per-process cache means the steady state costs one map lookup; the
279    /// declares themselves only happen on the first dispatch to a reactor,
280    /// after its `events` change, or after a reconnect.
281    ///
282    /// Public because this is also the operation the admin registration path
283    /// should perform at create/update time, so the queue exists before the
284    /// first event rather than at it.
285    pub async fn declare_reactor_topology(&self, reactor: &Reactor) -> Result<(), AmqpError> {
286        let Some(session) = self.shared.session() else {
287            return Err(AmqpError::Publish(
288                REACTOR_TRANSPORT_DISCONNECTED.to_string(),
289            ));
290        };
291        declare_reactor_topology_on(&session.channel, &self.shared, reactor).await
292    }
293
294    /// Serialize, publish, and map every failure onto [`DispatchFailure`].
295    ///
296    /// `expiration` is `Some(ms)` for an interception and `None` for a
297    /// listener: an interception the broker could not deliver inside the
298    /// reactor's window is worthless, because the chain has already resolved
299    /// the dispatch through the failure policy and will reject the late reply
300    /// as stale (§22.3). Letting the broker drop it is cheaper and safer than
301    /// handing an actor an event about a decision that was made minutes ago.
302    async fn publish(
303        &self,
304        session: &Session,
305        reactor: &Reactor,
306        msg: &ReactorEventMessage,
307        reply_to: Option<&str>,
308        expiration: Option<u32>,
309    ) -> Result<(), DispatchFailure> {
310        let body =
311            serde_json::to_vec(msg).map_err(|e| DispatchFailure::Transport(e.to_string()))?;
312
313        let mut props = BasicProperties::default()
314            .with_content_type("application/json".into())
315            // Echoed for the standard AMQP RPC convention's sake (§22.1). The
316            // server authenticates the copy inside the signed body, never
317            // this one.
318            .with_correlation_id(msg.correlation_id.to_string().into());
319        if let Some(reply_to) = reply_to {
320            props = props.with_reply_to(reply_to.into());
321        }
322        if let Some(ms) = expiration {
323            props = props.with_expiration(ms.to_string().into());
324        }
325
326        let confirm = session
327            .channel
328            .basic_publish(
329                // The default exchange, addressing the reactor's queue by
330                // name — see the module docs on why an interception is not
331                // fanned out through the topic exchange.
332                "".into(),
333                queue_name(reactor.tenant_id, reactor.id).into(),
334                BasicPublishOptions::default(),
335                &body,
336                props,
337            )
338            .await
339            .map_err(|e| DispatchFailure::Transport(e.to_string()))?;
340
341        // Publisher confirms are enabled on this channel, so awaiting the
342        // confirmation turns "the broker refused this" into a transport
343        // failure now rather than into a timeout `timeout_ms` from now. It is
344        // a broker-local acknowledgement, not a reactor round trip.
345        let confirmation = confirm
346            .await
347            .map_err(|e| DispatchFailure::Transport(e.to_string()))?;
348        if confirmation.is_nack() {
349            return Err(DispatchFailure::Transport(
350                "broker nacked the reactor event".into(),
351            ));
352        }
353        Ok(())
354    }
355}

357impl ReactorTransport for LapinReactorTransport {
358    async fn round_trip(
359        &self,
360        reactor: &Reactor,
361        event: &'static str,
362        correlation_id: Uuid,
363        payload: serde_json::Value,
364        timeout_ms: u32,
365    ) -> Result<ReactorReply, DispatchFailure> {
366        let Some(session) = self.shared.session() else {
367            // Fail now, not in `timeout_ms`. A reactor's budget is the caller's
368            // latency, and spending it waiting for a broker we know we are not
369            // connected to would make a broker outage look like every reactor
370            // in the deployment becoming slow.
371            return Err(DispatchFailure::Transport(
372                REACTOR_TRANSPORT_DISCONNECTED.to_string(),
373            ));
374        };
375
376        // `timeout_ms` bounds the WHOLE round trip, not just the wait for a
377        // reply.
378        //
379        // Everything below this line talks to the broker, and none of it is
380        // instantaneous: a declare is an RPC, and a publish on a confirm
381        // channel waits for the broker's ack. Since `AmqpManager` dials with
382        // `enable_auto_recover`, a channel whose connection is being recovered
383        // makes those calls *wait* for recovery rather than fail — which is
384        // the right behaviour for a background consumer and the wrong one on
385        // the login path. `run_chain` enforces `MAX_CHAIN_BUDGET_MS` only
386        // *between* reactors, so an unbounded await in here is an unbounded
387        // login, which is precisely the failure the whole timeout design
388        // exists to prevent. Each step therefore gets what is left of the
389        // budget, and running out is a `Timeout` like any other.
390        let budget = Duration::from_millis(u64::from(timeout_ms));
391        let started = std::time::Instant::now();
392        let remaining = || budget.saturating_sub(started.elapsed());
393
394        tokio::time::timeout(
395            remaining(),
396            declare_reactor_topology_on(&session.channel, &self.shared, reactor),
397        )
398        .await
399        .map_err(|_| DispatchFailure::Timeout)?
400        .map_err(|e| DispatchFailure::Transport(e.to_string()))?;
401
402        let msg = ReactorEventMessage::signed(
403            &self.signing_key,
404            reactor.tenant_id,
405            event,
406            correlation_id,
407            payload,
408            timeout_ms,
409            Utc::now(),
410        )
411        .map_err(|e| DispatchFailure::Transport(e.to_string()))?;
412
413        // Register before publishing: a reactor fast enough to answer between
414        // the publish and the registration would otherwise have its reply
415        // dropped as uncorrelated.
416        let (tx, rx) = oneshot::channel();
417        self.shared.pending_map().insert(correlation_id, tx);
418        // From here every exit path must deregister, or a timed-out dispatch
419        // leaks an entry for the process lifetime.
420        let _guard = PendingGuard {
421            shared: Arc::clone(&self.shared),
422            correlation_id,
423        };
424
425        tokio::time::timeout(
426            remaining(),
427            self.publish(
428                &session,
429                reactor,
430                &msg,
431                Some(&session.reply_queue),
432                Some(timeout_ms),
433            ),
434        )
435        .await
436        .map_err(|_| DispatchFailure::Timeout)??;
437
438        match tokio::time::timeout(remaining(), rx).await {
439            Ok(Ok(body)) => serde_json::from_slice::<ReactorReply>(&body)
440                .map_err(|e| DispatchFailure::Transport(e.to_string())),
441            // The sender was dropped: the session died under us (see
442            // `abandon_all_pending`).
443            Ok(Err(_)) => Err(DispatchFailure::Transport(
444                REACTOR_TRANSPORT_DISCONNECTED.to_string(),
445            )),
446            Err(_) => Err(DispatchFailure::Timeout),
447        }
448    }
449
450    async fn publish_listen(
451        &self,
452        reactor: &Reactor,
453        event: &'static str,
454        payload: serde_json::Value,
455    ) -> Result<(), DispatchFailure> {
456        let Some(session) = self.shared.session() else {
457            return Err(DispatchFailure::Transport(
458                REACTOR_TRANSPORT_DISCONNECTED.to_string(),
459            ));
460        };
461
462        // Bounded by the registration's own `timeout_ms` for the same reason
463        // `round_trip` is (see the comment there): nothing about being
464        // fire-and-forget makes a broker RPC instantaneous, and the fan-out
465        // this exists for would run at a hook site. A listener that cannot
466        // affect an outcome must also be unable to affect a latency.
467        let budget = Duration::from_millis(u64::from(reactor.timeout_ms));
468        let started = std::time::Instant::now();
469
470        tokio::time::timeout(
471            budget,
472            declare_reactor_topology_on(&session.channel, &self.shared, reactor),
473        )
474        .await
475        .map_err(|_| DispatchFailure::Timeout)?
476        .map_err(|e| DispatchFailure::Transport(e.to_string()))?;
477
478        // `timeout_ms` is carried so a listener sees the same body shape an
479        // interceptor does, but nothing waits on it and no `reply_to` is set:
480        // a reply to a listen event has nowhere to go, which is the wire-level
481        // statement of "a listener cannot affect an outcome".
482        let msg = ReactorEventMessage::signed(
483            &self.signing_key,
484            reactor.tenant_id,
485            event,
486            Uuid::new_v4(),
487            payload,
488            reactor.timeout_ms,
489            Utc::now(),
490        )
491        .map_err(|e| DispatchFailure::Transport(e.to_string()))?;
492
493        // Addressed to the reactor's queue, one message per registration —
494        // not fanned out through the exchange, which would deliver one copy
495        // per bound listener for every listener the caller iterates over.
496        tokio::time::timeout(
497            budget.saturating_sub(started.elapsed()),
498            self.publish(&session, reactor, &msg, None, None),
499        )
500        .await
501        .map_err(|_| DispatchFailure::Timeout)?
502    }
503}

505/// Deregisters an in-flight round trip however it ends — reply, timeout,
506/// cancellation, or the caller being dropped mid-`await`.
507///
508/// A `Drop` guard rather than removal at each exit because the interesting
509/// path is the one there is no code for: the whole login future being
510/// cancelled while a reactor round trip is outstanding.
511struct PendingGuard {
512    shared: Arc<Shared>,
513    correlation_id: Uuid,
514}
515
516impl Drop for PendingGuard {
517    fn drop(&mut self) {
518        self.shared.pending_map().remove(&self.correlation_id);
519    }
520}

522/// [`LapinReactorTransport::declare_reactor_topology`]'s body, taking the
523/// channel explicitly so the round-trip path can reuse a session it has
524/// already snapshotted.
525async fn declare_reactor_topology_on(
526    channel: &Channel,
527    shared: &Shared,
528    reactor: &Reactor,
529) -> Result<(), AmqpError> {
530    let wanted: Vec<String> = reactor.events.clone();
531
532    // Fast path: this process already declared exactly these bindings on this
533    // session. The steady state of a hot login path is this map lookup.
534    if shared
535        .declared_map()
536        .get(&reactor.id)
537        .is_some_and(|have| *have == wanted)
538    {
539        return Ok(());
540    }
541
542    let queue = queue_name(reactor.tenant_id, reactor.id);
543
544    // Durable and NOT auto-delete: the queue must outlive the actor's
545    // restarts. RabbitMQ 4 also refuses a transient non-exclusive declare
546    // outright, taking the connection down with it.
547    let mut args = FieldTable::default();
548    args.insert(
549        "x-expires".into(),
550        AMQPValue::LongLongInt(REACTOR_QUEUE_UNUSED_TTL_MS),
551    );
552    args.insert(
553        "x-max-length".into(),
554        AMQPValue::LongLongInt(REACTOR_QUEUE_MAX_LENGTH),
555    );
556
557    channel
558        .queue_declare(
559            queue.clone().into(),
560            QueueDeclareOptions {
561                durable: true,
562                ..QueueDeclareOptions::default()
563            },
564            args,
565        )
566        .await
567        .map_err(AmqpError::Declaration)?;
568
569    // Bind every event the registration names, and unbind the ones it no
570    // longer does. The second half matters: an operator who removes
571    // `login.post_auth` from a registration has un-subscribed from it, and a
572    // stale binding would keep delivering it.
573    let previous = shared
574        .declared_map()
575        .get(&reactor.id)
576        .cloned()
577        .unwrap_or_default();
578
579    for event in &wanted {
580        channel
581            .queue_bind(
582                queue.clone().into(),
583                REACTOR_EXCHANGE.into(),
584                routing_key(reactor.tenant_id, event).into(),
585                QueueBindOptions::default(),
586                FieldTable::default(),
587            )
588            .await
589            .map_err(AmqpError::Declaration)?;
590    }
591    for event in previous.iter().filter(|e| !wanted.contains(e)) {
592        channel
593            .queue_unbind(
594                queue.clone().into(),
595                REACTOR_EXCHANGE.into(),
596                routing_key(reactor.tenant_id, event).into(),
597                FieldTable::default(),
598            )
599            .await
600            .map_err(AmqpError::Declaration)?;
601    }
602
603    shared.declared_map().insert(reactor.id, wanted);
604    tracing::debug!(
605        target: "axiam::reactor",
606        tenant_id = %reactor.tenant_id,
607        reactor_id = %reactor.id,
608        queue = %queue,
609        events = ?reactor.events,
610        "declared reactor topology"
611    );
612    Ok(())
613}

615/// Declare the reactor exchange. Idempotent; called once per session.
616async fn declare_exchange(channel: &Channel) -> Result<(), AmqpError> {
617    channel
618        .exchange_declare(
619            REACTOR_EXCHANGE.into(),
620            // Topic, because the routing key is `<tenant>.<event>` and a
621            // listener fan-out selects on both halves.
622            ExchangeKind::Topic,
623            ExchangeDeclareOptions {
624                durable: true,
625                ..ExchangeDeclareOptions::default()
626            },
627            FieldTable::default(),
628        )
629        .await
630        .map_err(AmqpError::Declaration)
631}

633/// Establish one session and pump replies until it dies.
634///
635/// Returns `Ok(())` when the reply stream ended cleanly (the broker closed the
636/// consumer) and `Err` when it could not be established at all — the caller
637/// treats both as "reconnect", and only distinguishes them in the log.
638async fn run_reply_session(amqp: &AmqpManager, shared: &Shared) -> Result<(), AmqpError> {
639    // Confirms so a publish that the broker refuses fails at once rather than
640    // as a timeout one reactor budget later.
641    let channel = amqp.create_publisher_channel().await?;
642    declare_exchange(&channel).await?;
643
644    // Broker-named, exclusive, auto-delete: one reply queue for this process,
645    // gone the moment this connection is. Exclusive is also what keeps a
646    // transient declare legal on RabbitMQ 4, which refuses transient
647    // non-exclusive queues.
648    let reply_queue = channel
649        .queue_declare(
650            "".into(),
651            QueueDeclareOptions {
652                exclusive: true,
653                auto_delete: true,
654                ..QueueDeclareOptions::default()
655            },
656            FieldTable::default(),
657        )
658        .await
659        .map_err(AmqpError::Declaration)?;
660    let reply_queue_name = reply_queue.name().as_str().to_string();
661
662    let mut consumer = channel
663        .basic_consume(
664            reply_queue_name.clone().into(),
665            "axiam-reactor-replies".into(),
666            // No ack: a reply is only useful to the round trip that is waiting
667            // for it right now. Redelivering one after a crash would hand a
668            // decision to a request that no longer exists.
669            BasicConsumeOptions {
670                no_ack: true,
671                ..BasicConsumeOptions::default()
672            },
673            FieldTable::default(),
674        )
675        .await
676        .map_err(AmqpError::Channel)?;
677
678    shared.set_session(Some(Session {
679        channel,
680        reply_queue: reply_queue_name.clone(),
681    }));
682    tracing::info!(
683        target: "axiam::reactor",
684        reply_queue = %reply_queue_name,
685        "X1 reactor transport connected"
686    );
687
688    while let Some(delivery) = consumer.next().await {
689        let delivery = delivery.map_err(AmqpError::Channel)?;
690        route_reply(shared, delivery.data);
691    }
692    Ok(())
693}

695/// Hand one reply body to the round trip waiting on its `correlation_id`.
696///
697/// Routed by the body's field rather than the AMQP property because that is
698/// the one §22.1 makes normative — an SDK that copies the correlation only into
699/// the property produces a reply the server discards, and routing by the
700/// property would quietly accept it and then fail the chain's check instead,
701/// which is a much harder thing to debug from the SDK side.
702fn route_reply(shared: &Shared, body: Vec<u8>) {
703    #[derive(serde::Deserialize)]
704    struct CorrelationOnly {
705        correlation_id: Uuid,
706    }
707
708    let Ok(head) = serde_json::from_slice::<CorrelationOnly>(&body) else {
709        tracing::warn!(
710            target: "axiam::reactor",
711            "discarded a reactor reply with no readable correlation_id in its body"
712        );
713        return;
714    };
715
716    match shared.pending_map().remove(&head.correlation_id) {
717        Some(tx) => {
718            // The receiver being gone means the round trip already timed out;
719            // §22.3 says an SDK runtime SHOULD abandon a reply rather than
720            // send it late, and this is the server side of that — the late
721            // reply is dropped, not applied.
722            let _ = tx.send(body);
723        }
724        None => tracing::debug!(
725            target: "axiam::reactor",
726            correlation_id = %head.correlation_id,
727            "discarded a reactor reply nothing was waiting for (late, duplicate, or forged)"
728        ),
729    }
730}
731
732/// Keep a reply session alive for the process lifetime.
733///
734/// Never takes the process down and never gives up: the same discipline
735/// `axiam-server` applies to the cache-invalidation consumer. A reactor
736/// transport that exited on a broker blip would leave every dispatch resolving
737/// through `failure_policy` forever, with a restart as the only cure.
738async fn supervise(amqp: Arc<AmqpManager>, shared: Arc<Shared>) {
739    let mut backoff = RECONNECT_BACKOFF_START;
740    loop {
741        match run_reply_session(&amqp, &shared).await {
742            Ok(()) => tracing::error!(
743                target: "axiam::reactor",
744                "X1 reactor reply consumer exited; reconnecting"
745            ),
746            Err(e) => tracing::error!(
747                target: "axiam::reactor",
748                error = %e,
749                "X1 reactor transport session failed; reconnecting"
750            ),
751        }
752
753        // A session that actually came up resets the backoff, so a broker that
754        // restarts twice in a day does not leave the transport reconnecting on
755        // a 30-second cadence forever. Read before the teardown below clears
756        // it.
757        let was_established = shared.session().is_some();
758
759        // Order matters: stop advertising a session first, so no further
760        // dispatch publishes into a dead channel, then release the ones
761        // already waiting, then drop the topology cache so the next session
762        // re-declares rather than trusting declares made on a gone channel.
763        shared.set_session(None);
764        shared.abandon_all_pending();
765        shared.declared_map().clear();
766
767        if was_established {
768            backoff = RECONNECT_BACKOFF_START;
769        }
770        tokio::time::sleep(backoff).await;
771        backoff = (backoff * 2).min(RECONNECT_BACKOFF_MAX);
772    }
773}

914    /// Every lock in [`Shared`] recovers from poisoning rather than
915    /// propagating a panic.
916    ///
917    /// This matters more here than in most places: these locks sit on the
918    /// login path, and a `unwrap()` on a poisoned lock would turn one panicked
919    /// dispatch into every subsequent dispatch panicking — a single transient
920    /// fault escalated into a permanent, process-wide outage of exactly the
921    /// hook sites reactors guard.
922    #[test]
923    fn a_poisoned_lock_is_recovered_rather_than_propagated() {
924        let shared = Arc::new(Shared::new());
925
926        // The panic hook is silenced first so three *expected* panics do not
927        // print three backtraces into a passing test's output.
928        let hook = std::panic::take_hook();
929        std::panic::set_hook(Box::new(|_| {}));
930
931        let s = Arc::clone(&shared);
932        let _ = std::thread::spawn(move || {
933            let _held = s.pending.lock().unwrap();
934            panic!("poison `pending` while holding it");
935        })
936        .join();
937
938        let s = Arc::clone(&shared);
939        let _ = std::thread::spawn(move || {
940            let _held = s.declared.lock().unwrap();
941            panic!("poison `declared` while holding it");
942        })
943        .join();
944
945        let s = Arc::clone(&shared);
946        let _ = std::thread::spawn(move || {
947            let _held = s.session.write().unwrap();
948            panic!("poison `session` while holding it");
949        })
950        .join();
951
952        std::panic::set_hook(hook);
953
954        // The premise: all three really are poisoned, so the assertions below
955        // are exercising the recovery and not a no-op.
956        assert!(shared.pending.is_poisoned());
957        assert!(shared.declared.is_poisoned());
958        assert!(shared.session.is_poisoned());
959
960        // …and all three accessors still work.
961        shared
962            .pending_map()
963            .insert(Uuid::new_v4(), oneshot::channel().0);
964        assert_eq!(shared.pending_map().len(), 1);
965
966        shared
967            .declared_map()
968            .insert(Uuid::new_v4(), vec!["e".into()]);
969        assert_eq!(shared.declared_map().len(), 1);
970
971        assert!(shared.session().is_none());
972        shared.set_session(None);
973        assert!(shared.session().is_none());
974    }
