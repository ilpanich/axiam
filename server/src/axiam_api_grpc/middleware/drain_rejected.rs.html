1//! Drain the request body of a call that a layer above tonic rejected outright.
2//!
3//! # The bug this exists to prevent (h2 `GOAWAY: ENHANCE_YOUR_CALM`)
4//!
5//! The rate-limit layers on this listener reject by returning a
6//! `RESOURCE_EXHAUSTED` response and **dropping the request** — they never read
7//! its body, because they never need it. That is the natural way to write a
8//! short-circuiting `tower` layer, and on HTTP/1.1 it would be harmless.
9//!
10//! On HTTP/2 it is not, because of how `h2` defends itself against DATA-frame
11//! floods (the CVE-2019-9513 family). Every inbound DATA frame smaller than
12//! `DEFAULT_DATA_FRAME_OVERHEAD_THRESHOLD` (256 B) charges the difference
13//! against a per-connection budget of `256 * 100 = 25_600`, and that budget is
14//! replenished **only** when the application actually reads the frame
15//! (`h2::proto::streams::Streams::poll_data` → `Counts::release_data_frame`).
16//! A body that is dropped unread is never refunded.
17//!
18//! A unary gRPC request body is 5 bytes on the wire (one compression flag plus
19//! a four-byte length, with an empty message), so each rejected call costs
20//! `256 - 5 = 251` and the budget is gone after `25_600 / 251 = 102` of them.
21//! At that point `h2` concludes it is being flooded and kills the whole
22//! connection with `GOAWAY(ENHANCE_YOUR_CALM, "too_many_data_frames")`.
23//!
24//! The `grpc_infra` benchmark cell reproduces this exactly: rejected calls fail
25//! with `UNAVAILABLE` at iteration 101, 203, 305, 407, … — one dead connection
26//! every 102 rejections, like clockwork.
27//!
28//! # Why that is a real defect and not a benchmark artifact
29//!
30//! The listener is answering "you are over your quota" by destroying the
31//! caller's connection, which is worse than the rejection itself in three ways:
32//!
33//!   - **Collateral damage.** HTTP/2 multiplexes, so the `GOAWAY` also kills
34//!     every *unrelated* in-flight RPC on that connection. One throttled
35//!     method takes down calls that were within their quota.
36//!   - **It inverts the cost of rate limiting.** Each `GOAWAY` forces the
37//!     client to reconnect, and on this listener that means a fresh TLS
38//!     handshake — orders of magnitude more server CPU than the request that
39//!     was refused. A cheap client-side flood against the unauthenticated
40//!     infrastructure family (reflection / health, which carries the fixed
41//!     `INFRA_PER_SEC` ceiling precisely because it is unauthenticated) becomes
42//!     an amplified handshake load. The limiter turns into a DoS lever.
43//!   - **It is indistinguishable from a server fault.** The client sees
44//!     `UNAVAILABLE`, not `RESOURCE_EXHAUSTED`, so a correctly-throttled caller
45//!     cannot tell "back off" from "this server is broken".
46//!
47//! # What this layer does
48//!
49//! It hands the inner stack a body that reads through a slot it keeps a handle
50//! on. If the inner stack answers without consuming that body, the leftover is
51//! drained here — which is exactly the `poll_data` that refunds `h2`'s budget.
52//! On the admitted path the body has already been consumed by the time the
53//! response resolves, so the drain finds nothing and costs a lock and a branch.
54//!
55//! # Why the drain is gated on a trailers-only response
56//!
57//! Draining is only correct when nobody else still wants the body. A response
58//! that carries `grpc-status` in its **headers** is a trailers-only gRPC error,
59//! which is the wire shape produced by `tonic::Status::into_http()` — the one
60//! thing both rejection paths on this listener use (this crate's
61//! `too_many_requests_response`, and `tower_governor`'s own
62//! `From<GovernorError> for Response<tonic::body::Body>`). A request that tonic
63//! actually routed answers with `grpc-status` in its *trailers* instead, so the
64//! two cannot be confused.
65//!
66//! That distinction is what keeps this safe if a **streaming** method is ever
67//! added. Every RPC on this surface is unary today, but for a client-streaming
68//! or bidirectional call the handler goes on reading the request body *after*
69//! the response future resolves. Draining unconditionally would consume that
70//! stream out from under the handler and hang the call. Gating on the
71//! trailers-only shape means this layer only ever touches a request that never
72//! reached a handler at all.
73

84/// The request body, parked where [`DrainRejectedBody`] can reclaim whatever
85/// the inner stack did not read. `None` means fully consumed.
86type BodySlot = Arc<Mutex<Option<Body>>>;
87
88/// Locks `slot`, recovering the guard if a previous holder panicked.
89///
90/// A poisoned lock here would mean some other task panicked mid-body; that is
91/// not a reason to panic this task too, and the worst case is that a body is
92/// drained twice (a no-op) or not at all (the pre-existing behaviour).
93fn lock(slot: &BodySlot) -> std::sync::MutexGuard<'_, Option<Body>> {
94    slot.lock().unwrap_or_else(|poisoned| poisoned.into_inner())
95}
96
97/// A body that reads through a [`BodySlot`], so the layer keeps a handle on
98/// whatever is left when the inner stack drops the request.
99struct SlotBody {
100    slot: BodySlot,
101}
102
103impl HttpBody for SlotBody {
104    type Data = bytes::Bytes;
105    type Error = tonic::Status;
106
107    fn poll_frame(
108        self: Pin<&mut Self>,
109        cx: &mut Context<'_>,
110    ) -> Poll<Option<Result<Frame<Self::Data>, Self::Error>>> {
111        // `SlotBody` holds only an `Arc`, so it is `Unpin` and the inner body
112        // can be polled in place.
113        let mut guard = lock(&self.get_mut().slot);
114        let Some(inner) = guard.as_mut() else {
115            return Poll::Ready(None);
116        };
117        let polled = Pin::new(inner).poll_frame(cx);
118        // End of stream: empty the slot so the drain below knows there is
119        // nothing owing, and so a second poll cannot touch a finished body.
120        if matches!(polled, Poll::Ready(None)) {
121            *guard = None;
122        }
123        polled
124    }
125
126    fn is_end_stream(&self) -> bool {
127        lock(&self.slot)
128            .as_ref()
129            .is_none_or(HttpBody::is_end_stream)
130    }
131
132    fn size_hint(&self) -> SizeHint {
133        lock(&self.slot)
134            .as_ref()
135            .map_or_else(|| SizeHint::with_exact(0), HttpBody::size_hint)
136    }
137}

139/// Whether `res` is a trailers-only gRPC response — i.e. one produced without
140/// the request ever reaching a handler. See the module docs for why this is
141/// the gate.
142fn is_trailers_only(res: &Response<Body>) -> bool {
143    res.headers().contains_key("grpc-status")
144}

146/// [`Layer`] producing [`DrainRejectedBody`].
147#[derive(Clone, Copy, Debug, Default)]
148pub struct DrainRejectedBodyLayer;
149
150impl<S> Layer<S> for DrainRejectedBodyLayer {
151    type Service = DrainRejectedBody<S>;
152
153    fn layer(&self, inner: S) -> Self::Service {
154        DrainRejectedBody { inner }
155    }
156}

158/// Drains the request body of any call answered without reading it.
159///
160/// Wire this OUTSIDE the rate-limit layers — on `Server::builder()` that means
161/// adding it FIRST, since tonic runs the first-added layer first.
162#[derive(Clone, Debug)]
163pub struct DrainRejectedBody<S> {
164    inner: S,
165}
166
167impl<S> Service<Request<Body>> for DrainRejectedBody<S>
168where
169    S: Service<Request<Body>, Response = Response<Body>> + Clone + Send + 'static,
170    S::Future: Send + 'static,
171{
172    type Response = Response<Body>;
173    type Error = S::Error;
174    type Future = Pin<Box<dyn Future<Output = Result<Self::Response, Self::Error>> + Send>>;
175
176    fn poll_ready(&mut self, cx: &mut Context<'_>) -> Poll<Result<(), Self::Error>> {
177        self.inner.poll_ready(cx)
178    }
179
180    fn call(&mut self, req: Request<Body>) -> Self::Future {
181        // Standard clone-and-swap so the returned future owns a ready copy —
182        // same convention as the rate-limit services on this listener.
183        let clone = self.inner.clone();
184        let mut inner = std::mem::replace(&mut self.inner, clone);
185
186        let (parts, body) = req.into_parts();
187        let slot: BodySlot = Arc::new(Mutex::new(Some(body)));
188        let req = Request::from_parts(parts, Body::new(SlotBody { slot: slot.clone() }));
189
190        Box::pin(async move {
191            let res = inner.call(req).await?;
192            if is_trailers_only(&res) {
193                // Bound in its own statement so the `MutexGuard` is dropped
194                // here rather than living across the await below — holding it
195                // would make this future `!Send`, which tonic requires.
196                let unread = lock(&slot).take();
197                if let Some(unread) = unread {
198                    // Reading is the whole point: `poll_data` is what refunds
199                    // `h2`'s small-DATA-frame budget. The bytes are discarded,
200                    // and a body that errors mid-drain is ignored — the
201                    // response is already decided and a failed drain must not
202                    // change it.
203                    let _ = unread.collect().await;
204                }
205            }
206            Ok(res)
207        })
208    }
209}

211#[cfg(test)]
212mod tests {
213    use super::*;
214    use std::sync::atomic::{AtomicBool, Ordering};

216    /// A body that records whether it was ever polled to end-of-stream.
217    struct ProbeBody {
218        drained: Arc<AtomicBool>,
219        frames: usize,
220    }
221
222    impl HttpBody for ProbeBody {
223        type Data = bytes::Bytes;
224        type Error = tonic::Status;
225
226        fn poll_frame(
227            mut self: Pin<&mut Self>,
228            _cx: &mut Context<'_>,
229        ) -> Poll<Option<Result<Frame<Self::Data>, Self::Error>>> {
230            if self.frames == 0 {
231                self.drained.store(true, Ordering::SeqCst);
232                return Poll::Ready(None);
233            }
234            self.frames -= 1;
235            Poll::Ready(Some(Ok(Frame::data(bytes::Bytes::from_static(
236                b"\0\0\0\0\0",
237            )))))
238        }
239    }
240
241    fn probe() -> (Arc<AtomicBool>, Body) {
242        let drained = Arc::new(AtomicBool::new(false));
243        let body = Body::new(ProbeBody {
244            drained: drained.clone(),
245            frames: 1,
246        });
247        (drained, body)
248    }

250    /// The inner service ignores the request body entirely, exactly as the
251    /// rate-limit layers do when they reject.
252    #[derive(Clone)]
253    struct RejectUnread;
254
255    impl Service<Request<Body>> for RejectUnread {
256        type Response = Response<Body>;
257        type Error = std::convert::Infallible;
258        type Future = Pin<Box<dyn Future<Output = Result<Self::Response, Self::Error>> + Send>>;
259
260        fn poll_ready(&mut self, _cx: &mut Context<'_>) -> Poll<Result<(), Self::Error>> {
261            Poll::Ready(Ok(()))
262        }
263
264        fn call(&mut self, req: Request<Body>) -> Self::Future {
265            drop(req); // the body is never read — this is the bug being fixed
266            Box::pin(async {
267                Ok(tonic::Status::resource_exhausted("rate limit exceeded").into_http())
268            })
269        }
270    }
271
272    /// An inner service that answers like a routed RPC: no `grpc-status`
273    /// header, and it leaves the request body alone.
274    #[derive(Clone)]
275    struct RoutedUnread;
276
277    impl Service<Request<Body>> for RoutedUnread {
278        type Response = Response<Body>;
279        type Error = std::convert::Infallible;
280        type Future = Pin<Box<dyn Future<Output = Result<Self::Response, Self::Error>> + Send>>;
281
282        fn poll_ready(&mut self, _cx: &mut Context<'_>) -> Poll<Result<(), Self::Error>> {
283            Poll::Ready(Ok(()))
284        }
285
286        fn call(&mut self, req: Request<Body>) -> Self::Future {
287            drop(req);
288            Box::pin(async { Ok(Response::new(Body::empty())) })
289        }
290    }

292    #[tokio::test]
293    async fn drains_the_body_of_a_rejected_call() {
294        let (drained, body) = probe();
295        let mut svc = DrainRejectedBodyLayer.layer(RejectUnread);
296        let res = svc.call(Request::new(body)).await.unwrap();
297
298        assert_eq!(res.headers().get("grpc-status").unwrap(), "8");
299        assert!(
300            drained.load(Ordering::SeqCst),
301            "a rejected call's body must be read to end-of-stream, or h2's \
302             small-DATA-frame budget is never refunded and the connection dies \
303             after ~102 rejections"
304        );
305    }
306
307    #[tokio::test]
308    async fn leaves_a_routed_call_body_alone() {
309        let (drained, body) = probe();
310        let mut svc = DrainRejectedBodyLayer.layer(RoutedUnread);
311        let _res = svc.call(Request::new(body)).await.unwrap();
312
313        assert!(
314            !drained.load(Ordering::SeqCst),
315            "a response tonic actually routed carries grpc-status in its \
316             trailers, so this layer must not touch the request body — a \
317             streaming handler is still reading it"
318        );
319    }
320
321    #[tokio::test]
322    async fn a_body_the_inner_stack_consumed_is_not_drained_twice() {
323        let (drained, body) = probe();
324        let slot: BodySlot = Arc::new(Mutex::new(Some(body)));
325        let wrapped = Body::new(SlotBody { slot: slot.clone() });
326
327        // Consume it the way tonic would on an admitted unary call.
328        let _ = wrapped.collect().await;
329        assert!(drained.load(Ordering::SeqCst));
330        assert!(
331            lock(&slot).is_none(),
332            "reaching end-of-stream must empty the slot so the drain is a no-op"
333        );
334    }
