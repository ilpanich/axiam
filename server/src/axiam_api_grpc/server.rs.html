1//! Tonic gRPC server setup.
2//!
3//! CQ-B20: Server builder sets message-size limits, per-connection timeout,
4//! and concurrency limit to prevent resource exhaustion.
5//!
6//! # TLS (REQ-15 AC-1, R-1 / T-234)
7//!
8//! This listener does **not** ask tonic to terminate TLS. It takes the
9//! already-built rustls configuration as a value — [`GrpcTls`] — and does the
10//! handshake itself in [`crate::tls_incoming`], handing tonic an
11//! already-encrypted stream through `serve_with_incoming`.
12//!
13//! That indirection is the whole point of the change, and it buys two things
14//! `tonic::transport::ServerTlsConfig` cannot express, because it accepts
15//! neither a `rustls::ServerConfig` nor a certificate resolver:
16//!
17//! - **the leaf can be replaced while the listener runs.** The configuration
18//!   this crate is handed carries `axiam-server`'s `ReloadableCertResolver`,
19//!   the same instance the REST listener serves from when both listen on the
20//!   same leaf, so one `SIGHUP` (or one hourly poll) renews both. Before this,
21//!   the gRPC leaf was fixed at boot and a 90-day ACME certificate expired in
22//!   place unless an operator restarted the container — the failure T-214
23//!   fixed for REST and T-234 recorded as still open for gRPC.
24//! - **TLS 1.3 only.** The configuration is built with
25//!   `with_protocol_versions(&[&rustls::version::TLS13])`, matching the REST
26//!   posture (ASVS V9.1.2). Under `ServerTlsConfig` the crate default left
27//!   TLS 1.2 negotiable, which is the caveat T-233 recorded.
28//!
29//! Who builds that configuration is not a free choice: `ReloadableCertResolver`
30//! lives in `axiam-server` (layer 8) and this crate is layer 6, so the value
31//! has to arrive from above (`scripts/check-crate-layering.py` enforces it).
32//! The composition root reads `AXIAM__GRPC_TLS_CERT_PATH` /
33//! `AXIAM__GRPC_TLS_KEY_PATH` — unchanged flat names, unchanged
34//! panic-on-unreadable, so a typo is still a failed boot — and passes
35//! [`GrpcTls::Rustls`] or [`GrpcTls::Plaintext`]. The `INFO`/`WARN` lines the
36//! Pi runbook §14.4 greps for (`gRPC server TLS enabled`,
37//! `gRPC TLS is DISABLED`) are still emitted from here, so which mode a
38//! listener came up in is still readable from this listener's own log.
39//!
40//! D2 (benchmark plan — native gRPC TLS termination): this is the same
41//! mechanism the p2-tls13 native-TLS bench overlay
42//! (`benchmarks/targets/axiam/docker-compose.native-tls.yml`) turns on,
43//! pointed at the SAME server cert/key files the REST listener uses
44//! (`crates/axiam-server/src/tls.rs` / `AXIAM__SERVER__TLS__CERT_PATH`+
45//! `KEY_PATH`) so the two protocols present identical PKI material.
46

81/// How the gRPC listener terminates TLS, as decided by the composition root.
82///
83/// # Why a value rather than an env read
84///
85/// The certificate the listener serves must be replaceable while it runs, and
86/// the machinery that does that — `axiam_server::tls::ReloadableCertResolver`,
87/// the reload trigger it is registered with, and the `SIGHUP`/poll task that
88/// fires them — lives in `axiam-server`. That crate is layer 8; this one is
89/// layer 6, and `scripts/check-crate-layering.py` fails any build where an
90/// edge points the other way. So the configuration arrives already built, and
91/// the two listeners end up sharing one resolver instance instead of this
92/// crate growing its own second copy of the reload mechanism.
93///
94/// Reading the env vars stays with the composition root for the same reason:
95/// deciding TLS is on is a deployment fact, and the only place that can act on
96/// it — by building a config over the *same* leaf the REST listener resolved —
97/// is the place that already resolved it.
98///
99/// # Example
100///
101/// What `axiam-server`'s `main()` does. `grpc_tls_from_env` returns `None` when
102/// neither `AXIAM__GRPC_TLS_CERT_PATH` nor `AXIAM__GRPC_TLS_KEY_PATH` is set —
103/// the in-mesh posture, where a sidecar owns transport security — and panics
104/// when one is set but unreadable, because a listener that fell back to
105/// plaintext on a typo would serve cleartext on a port an operator believes is
106/// encrypted:
107///
108/// ```ignore
109/// // In axiam-server, which owns the reloadable certificate resolver:
110/// let tls = match axiam_server::tls::grpc_tls_from_env() {
111///     Some(config) => {
112///         // Idempotent — the REST bind calls this too, and either listener
113///         // can be the only one with TLS on.
114///         axiam_server::tls::spawn_leaf_reloader(reload_interval_secs);
115///         axiam_api_grpc::GrpcTls::Rustls(config)
116///     }
117///     None => axiam_api_grpc::GrpcTls::Plaintext,
118/// };
119///
120/// axiam_api_grpc::start_grpc_server(addr, /* ..., */ tls).await?;
121/// ```
122///
123/// A caller outside that crate — a test, or an embedding that manages its own
124/// PKI — can build the configuration itself; nothing here requires the
125/// resolver, only that whoever wants renewals without a restart uses one:
126///
127/// ```
128/// use std::sync::Arc;
129/// use axiam_api_grpc::GrpcTls;
130///
131/// # fn build(config: Arc<rustls::ServerConfig>) -> GrpcTls {
132/// let tls = GrpcTls::Rustls(config);
133/// # tls
134/// # }
135/// // ...or, for an in-mesh deployment behind a sidecar:
136/// let plaintext = GrpcTls::Plaintext;
137/// assert!(matches!(plaintext, GrpcTls::Plaintext));
138/// ```
139#[derive(Clone)]
140pub enum GrpcTls {
141    /// No transport security on this listener.
142    ///
143    /// The shipped default, and correct for an in-mesh deployment where a
144    /// sidecar terminates mutual TLS, or a loopback bind behind a terminating
145    /// reverse proxy. Emits the `gRPC TLS is DISABLED` warning the Pi runbook
146    /// §14.4 tells operators to grep for.
147    Plaintext,
148    /// Terminate TLS in-process with this rustls configuration.
149    ///
150    /// Expected to be TLS 1.3-only and to resolve its leaf through a reloadable
151    /// resolver; `axiam_server::tls::build_grpc_rustls_server_config` builds
152    /// exactly that. Nothing here enforces those properties — this crate cannot
153    /// see the resolver behind the config — which is why the builder that can
154    /// is the one the composition root calls.
155    Rustls(Arc<rustls::ServerConfig>),
156}

158/// Start the gRPC server with all registered services.
159///
160/// Applies two cooperating rate-limit layers (SECHRD-03, D-01a/b/c — gap
161/// closure for 24-07): the [`GrpcSharedRateLimitLayer`] cross-replica
162/// pre-check runs FIRST (outermost), failing OPEN to the per-replica in-memory
163/// governor stack (per D-10). Both layers derive their client-IP key from the
164/// SAME `trusted_hops` value so gRPC keying stays in lockstep across the
165/// shared counter and the in-memory fallback, and both are sized from the
166/// same per-second [`crate::middleware::rate_limit::GrpcRateLimits`] value.
167///
168/// Since I1/I2 the ceilings are **per method family**, not server-wide:
169/// `AXIAM__GRPC__GRPC_AUTHZ_PER_SEC` sizes `AuthorizationService`,
170/// `AXIAM__GRPC__GRPC_IDENTITY_PER_SEC` sizes `UserInfoService`/`TokenService`,
171/// `AXIAM__GRPC__GRPC_ADMIN_PER_SEC` sizes `UserService`, and gRPC
172/// reflection/health are never limited.
173///
174/// Since the H2 performance fix the shared pre-check performs NO synchronous
175/// datastore write: it is backed by the process-wide write-behind
176/// `axiam_db::SharedRateLimitCounter`, built ONCE here (this layer is
177/// server-wide, so every gRPC call used to pay one `UPSERT`). Knobs:
178/// `AXIAM__RATE_LIMIT__SHARED` (on|off, default on) and
179/// `AXIAM__RATE_LIMIT__SHARED_SYNC_MS` (default 1000, clamped 50..=60000) —
180/// the same two the REST listener reads.
181///
182/// Transport limits (CQ-B20):
183/// - Max message size: 4 MiB decode / 4 MiB encode
184/// - Per-connection timeout: 30 s
185/// - Concurrency limit: 256 streams per connection
186///
187/// TLS (REQ-15 AC-1): env-gated via `AXIAM__GRPC_TLS_CERT_PATH` /
188/// `AXIAM__GRPC_TLS_KEY_PATH`. When absent, TLS is disabled and a warning
189/// is logged (acceptable for in-mesh/loopback deployments).
190///
191/// # `strict_revocation_checker` (A4/J10)
192///
193/// `Some(..)` only when `AXIAM__GRPC__STRICT_REVOCATION=true`, and it MUST be
194/// the SAME session-repository instance the REST path holds. A second instance
195/// would carry a second validation cache, and a cache the REST invalidation
196/// hooks never reach is exactly the stale allow strict mode exists to prevent.
197/// `None` keeps the shipped posture: gRPC trusts JWT lifetime, so revocation
198/// takes effect at token expiry (up to 15 min) rather than immediately. See
199/// [`crate::middleware::strict_revocation`] for the full posture table.
200///
201/// # `reactor_engine`, `reactor_repo`, `reactor_audit_repo`, `reactor_routing_invalidator` (X1 / R2.3)
202///
203/// `reactor_engine` is a SECOND [`AuthorizationEngine`] instance, built from
204/// the same repositories as `engine`. `AuthorizationEngine` does not
205/// implement `Clone`, so `ReactorAdminServiceImpl` cannot share `engine`'s
206/// instance — it is given its own, mirroring `AuthorizationServiceImpl`'s.
207/// Two engines over the same repositories is correct, not wasteful: the
208/// decision cache and invalidation broadcaster (when configured) are handed
209/// to both by the caller, so the two stay coherent with each other exactly as
210/// `axiam-server`'s REST `AuthzChecker` and this gRPC listener already do.
211/// `reactor_routing_invalidator` MUST be the same closure over the same
212/// `ReactorRoutingTable` the REST admin handlers invalidate through, or a
213/// registration written over gRPC would not take effect on this replica
214/// until the routing table's TTL expired.
215#[allow(clippy::too_many_arguments)]
216pub async fn start_grpc_server<R, P, Res, S, G, U, C, Rr, A>(
217    addr: SocketAddr,
218    engine: AuthorizationEngine<R, P, Res, S, G>,
219    user_repo: U,
220    auth_config: AuthConfig,
221    grpc_config: &GrpcConfig,
222    db: impl Into<DbHandle<C>>,
223    batch_max_concurrency: usize,
224    strict_revocation_checker: Option<Arc<dyn SessionRevocationCheck>>,
225    reactor_engine: AuthorizationEngine<R, P, Res, S, G>,
226    reactor_repo: Rr,
227    reactor_audit_repo: A,
228    reactor_routing_invalidator: Arc<dyn Fn(Uuid) + Send + Sync>,
229    // SEC-101 — whether the composed reactor transport can deliver at all.
230    // MUST be read from the same gate `axiam-api-rest` holds, so the two
231    // admin surfaces refuse (or accept) the same registrations.
232    reactor_dispatch_available: bool,
233    // B1 — the process-wide Argon2id gate. MUST be a clone of the same
234    // `Arc<Semaphore>` `AppState::crypto_semaphore` holds: the permit count
235    // bounds peak concurrent ~19 MiB hash arenas for the WHOLE process, so a
236    // listener with its own instance would silently double the bound.
237    // `UserService/ValidateCredentials` is this listener's only consumer.
238    crypto_semaphore: Arc<Semaphore>,
239    // Where `UserService/ValidateCredentials` reads the tenant's
240    // `max_failed_login_attempts` and backoff. MUST resolve from the same
241    // settings store REST's login handler reads, or the same account locks
242    // after a different number of failures depending on which transport the
243    // attacker used. `axiam_auth::lockout::SettingsLockoutPolicy` is that
244    // resolver; `StaticLockoutPolicy` is the deployment-default fallback.
245    lockout_policy: Arc<dyn axiam_auth::lockout::LockoutPolicySource>,
246    // R-1 / T-234 — how this listener terminates TLS, decided and built by the
247    // composition root. See [`GrpcTls`] for why it is a value and not an env
248    // read, and the module docs for what changed.
249    tls: GrpcTls,
250) -> Result<(), Box<dyn std::error::Error + Send + Sync>>
251where
252    R: RoleRepository + 'static,
253    P: PermissionRepository + 'static,
254    Res: ResourceRepository + 'static,
255    S: ScopeRepository + 'static,
256    G: GroupRepository + 'static,
257    U: UserRepository + Clone + 'static,
258    C: Connection + 'static,
259    Rr: ReactorRepository + 'static,
260    A: AuditLogRepository + 'static,
261{
262    // I2: per-family ceilings (unset knobs derived from the authz ceiling).
263    let rate_limits = grpc_config.rate_limits();
264    tracing::info!(
265        bind = %addr,
266        grpc_authz_per_sec = rate_limits.authz_per_sec,
267        grpc_identity_per_sec = rate_limits.identity_per_sec,
268        grpc_admin_per_sec = rate_limits.admin_per_sec,
269        "Starting gRPC server",
270    );
271
272    // SECHRD-03 gap closure (24-07 follow-up): the shared-store pre-check
273    // MUST use the same trusted_hops value as the in-memory governor's key
274    // extractor (both ultimately key off GrpcTrustedHopsKeyExtractor logic)
275    // so a rotating XFF cannot mint a fresh bucket in one layer while being
276    // correctly collapsed in the other.
277    let trusted_hops = trusted_hops_from_env();
278    // Built exactly ONCE per process: this constructs the write-behind
279    // `SharedRateLimitCounter` (and spawns its single background flusher on
280    // this runtime). Cloning the LAYER is fine — the counter inside is an
281    // `Arc` handle, so every clone shares the same local counts. Building a
282    // second layer would create a second, independent counter.
283    //
284    // I1 (units) + I2 (scope): both layers are now built from the SAME
285    // per-second `GrpcRateLimits` value. `new_method_scoped` converts each
286    // per-second ceiling into the shared layer's 60-second window budget
287    // itself (`per_sec_to_window_limit`) — previously the per-second number
288    // was passed to a per-minute window verbatim, which made the effective
289    // gRPC ceiling 1/60th of the configured one.
290    let shared_rate_limit_layer =
291        GrpcSharedRateLimitLayer::new_method_scoped(db, rate_limits, trusted_hops);
292    let governor_layer = build_grpc_method_scoped_governor_layer(rate_limits);
293
294    // A4/J10: built before the interceptors take ownership of `auth_config`.
295    // The layer needs it to decode (not verify — see the module docs) the
296    // bearer token far enough to learn which session a request names.
297    let strict_revocation_layer = strict_revocation_checker.map(|checker| {
298        tracing::warn!(
299            "gRPC STRICT REVOCATION enabled — every gRPC request now re-checks \
300             session validity, matching REST. Expect the gRPC check profile to \
301             approach REST's revocation-checked one; with the session-validation \
302             cache disabled this is one datastore read per request."
303        );
304        GrpcStrictRevocationLayer::new(checker, auth_config.clone())
305    });
306
307    let authz_svc = AuthorizationServiceServer::with_interceptor(
308        AuthorizationServiceImpl::new(engine, batch_max_concurrency),
309        AuthInterceptor::new(auth_config.clone()),
310    );
311    // SECFIX-01: UserService and TokenService previously had zero auth —
312    // any unauthenticated mesh peer could call GetUser/ValidateCredentials/
313    // IntrospectToken. Wrap them with the same AuthInterceptor chokepoint
314    // as AuthorizationService so every gRPC call requires a verified bearer JWT.
315    let user_svc = UserServiceServer::with_interceptor(
316        UserServiceImpl::new(
317            user_repo.clone(),
318            auth_config.clone(),
319            crypto_semaphore,
320            lockout_policy,
321        ),
322        AuthInterceptor::new(auth_config.clone()),
323    );
324    // UserInfoService: OIDC-style self lookup — identity derived entirely from
325    // the interceptor-verified bearer token (no request body), mirroring the
326    // REST `/oauth2/userinfo` endpoint. Guarded by the same AuthInterceptor.
327    let user_info_svc = UserInfoServiceServer::with_interceptor(
328        UserInfoServiceImpl::new(user_repo),
329        AuthInterceptor::new(auth_config.clone()),
330    );
331    let token_svc = TokenServiceServer::with_interceptor(
332        TokenServiceImpl::new(auth_config.clone()),
333        AuthInterceptor::new(auth_config.clone()),
334    );
335    // X1 / R2.3 — reactor admin CRUD over gRPC, mirroring the REST
336    // `/api/v1/reactors*` surface. Same `AuthInterceptor` chokepoint as every
337    // other authenticated service here.
338    let reactor_svc = ReactorAdminServiceServer::with_interceptor(
339        ReactorAdminServiceImpl::new(
340            reactor_repo,
341            reactor_engine,
342            reactor_audit_repo,
343            reactor_routing_invalidator,
344            reactor_dispatch_available,
345        ),
346        AuthInterceptor::new(auth_config),
347    );
348
349    // CQ-B20: Apply transport limits to the gRPC server builder.
350    // Note: tonic 0.14 does not expose max_decoding_message_size / max_encoding_message_size
351    // at the Server level (added in tonic 0.12+ via the Router API). The HTTP/2 frame-size
352    // limit (max_frame_size) is the closest available per-connection cap in 0.14. Upgrade
353    // to tonic ≥0.12 to use per-service max_decoding_message_size / max_encoding_message_size.
354    // Tracked: max_decoding_message_size (CQ-B20, pending tonic upgrade in Phase 19).
355    // SECHRD-03 (D-01a/b/c) + run-5 J1: layer ORDER is load-bearing here.
356    // Tower's `Server::builder()` runs the FIRST-added layer with the request
357    // FIRST (the opposite of actix's last-`.wrap()`-is-outermost rule), so
358    // the layer named first below is the OUTERMOST one.
359    //
360    // Until run 5 the shared-store pre-check was outermost. That inverted the
361    // two layers' natural roles and starved every gRPC family: the pre-check
362    // charges its whole 60-second window budget the moment it admits a
363    // request, but the per-second `governor` behind it then rejected almost
364    // all of those requests. A flood therefore burned all 6 000 authz
365    // admissions of a window on traffic that was never served, in well under
366    // a second, and the window stayed exhausted for its remaining ~59 —
367    // measured at 181 admissions/min against a configured 6 000/min, i.e.
368    // 1/33 of the ceiling (`claude_dev/improvement-after-run5-benchmark.md`
369    // A1/J1).
370    //
371    // The governor is therefore now OUTERMOST and owns the admission
372    // decision, and the shared cross-replica counter sits behind it, counting
373    // only traffic that was actually admitted. Both roles are preserved:
374    //
375    // - single replica — the governor's per-second quota is the binding
376    //   constraint and the shared counter (sized `per_sec × 60`) never trips,
377    //   so the effective ceiling equals the configured one;
378    // - N replicas — each admits its own per-second quota, their sum reaches
379    //   the shared window budget, and the shared counter cuts in. That is
380    //   exactly the `replicas × limit` multiplication SECHRD-03 exists to
381    //   stop, and it is still stopped.
382    //
383    // Fail-open is unchanged: on a missing key, a disabled shared layer, or a
384    // SurrealDB blip the inner layer forwards the request and the governor's
385    // decision (already taken, outside it) stands.
386    //
387    // The REST listener cannot use this ordering — its shared middleware is
388    // also what parses `client_id` out of the form body for the client-aware
389    // key modes, so it must stay outermost there. It solves the same problem
390    // with `SharedRateLimitCounter::refund` instead; see that method's docs.
391    // A4/J10: strict revocation, when enabled, sits INSIDE the rate limiters
392    // (so a flood of revoked-session calls is throttled before it can touch
393    // the session cache) and OUTSIDE the services (so it applies uniformly to
394    // every RPC, including any added later). `option_layer` makes the disabled
395    // case a genuine no-op rather than a branch in the request path.
396    let mut builder = Server::builder()
397        .max_frame_size(4 * 1024 * 1024) // CQ-B20: 4 MiB frame cap (tonic-0.14 equivalent of max_decoding_message_size)
398        .timeout(Duration::from_secs(30))
399        .concurrency_limit_per_connection(256)
400        // OUTERMOST (added first = runs first): refunds h2's small-DATA-frame
401        // budget for any call the rate limiters below answer without reading
402        // its body. Without it the listener GOAWAYs the connection every ~102
403        // rejections — see `middleware::drain_rejected`.
404        .layer(DrainRejectedBodyLayer)
405        .layer(governor_layer)
406        .layer(shared_rate_limit_layer)
407        .layer(tower::util::option_layer(strict_revocation_layer));
408
409    // R-1 / T-234: the services are registered once, and only *how the bytes
410    // arrive* differs between the two modes below. Before this change the whole
411    // `add_service` chain was written out twice, once per branch, which is how
412    // a service added to one arm and not the other becomes possible.
413    let router = builder
414        .add_service(authz_svc)
415        .add_service(user_svc)
416        .add_service(user_info_svc)
417        .add_service(token_svc)
418        .add_service(reactor_svc);
419
420    match tls {
421        GrpcTls::Rustls(tls_config) => {
422            // Bound here rather than by `serve()` so the accept loop can be
423            // ours: tonic's `serve_with_incoming` consumes a stream of
424            // already-connected IO and never binds anything itself.
425            let listener = tokio::net::TcpListener::bind(addr).await?;
426            // The runbook greps for this exact line (§14.4), and the env-var
427            // name in it is the one whose typo is the usual cause of a
428            // plaintext listener an operator expected to be encrypted.
429            tracing::info!(
430                bind = %listener.local_addr().unwrap_or(addr),
431                tls_versions = "1.3",
432                reloadable_leaf = true,
433                max_concurrent_handshakes = crate::tls_incoming::MAX_CONCURRENT_HANDSHAKES,
434                "gRPC server TLS enabled (AXIAM__GRPC_TLS_CERT_PATH)"
435            );
436
437            // A listener that stops accepting must fail the server task, not
438            // return `Ok(())`. `serve_with_incoming` cannot tell us that
439            // itself — it treats an exhausted stream as a clean shutdown — so
440            // the accept loop reports an unrecoverable error out of band and
441            // this select turns it back into the error the caller expects.
442            let (fatal_tx, fatal_rx) = tokio::sync::oneshot::channel();
443            let incoming = tls_incoming(listener, tls_config, fatal_tx);
444            tokio::select! {
445                served = router.serve_with_incoming(incoming) => {
446                    served.map_err(Into::into)
447                }
448                Ok(accept_error) = fatal_rx => {
449                    Err(Box::new(accept_error) as Box<dyn std::error::Error + Send + Sync>)
450                }
451            }
452        }
453        GrpcTls::Plaintext => {
454            tracing::warn!(
455                "gRPC TLS is DISABLED — set AXIAM__GRPC_TLS_CERT_PATH + \
456                 AXIAM__GRPC_TLS_KEY_PATH to enable (acceptable for in-mesh deployments)"
457            );
458            // Unchanged from before R-1, deliberately: tonic binds, sets
459            // TCP_NODELAY, and serves exactly as it always has. The E2E suite
460            // and every benchmark that is not the native-TLS overlay run
461            // through this arm.
462            router.serve(addr).await.map_err(Into::into)
463        }
464    }
