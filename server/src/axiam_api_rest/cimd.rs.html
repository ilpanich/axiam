1//! Materialising a client from a Client ID Metadata Document (T21.5).
2//!
3//! `axiam_oauth2::cimd` decides *whether* a URL-shaped `client_id` is a client
4//! and *what* it becomes. This module is the half that needs state: the
5//! tenant's settings, the document cache, the client table and the audit log.
6//!
7//! # Where it runs, and why nowhere else
8//!
9//! [`materialise_if_cimd`] is called at the top of the authorize, PAR and
10//! token paths — the three places a `client_id` arrives — **before** the
11//! existing client lookup. It is not a lookup itself and it returns nothing:
12//! its whole effect is that, by the time the ordinary
13//! `get_by_client_id` runs, a row either exists or does not, and everything
14//! downstream (client authentication, the T21.2 loopback matcher, the D4
15//! consent gate, the D3 resource allow-list, the FAPI refusals) is the code
16//! that was already there, acting on a row like any other.
17//!
18//! That is the design decision worth stating plainly: **CIMD adds no branch to
19//! any flow.** It adds one step in front of three of them, and that step's
20//! only outputs are "a row now exists" or "nothing happened".
21//!
22//! # Every failure is "nothing happened"
23//!
24//! A `client_id` that is not a URL, a tenant with CIMD off, a URL the rules
25//! refuse, a publisher that is down, a document that is malformed, a row that
26//! belongs to somebody else, a settings read that failed — all of them return
27//! without writing. The request then meets the client lookup it would have met
28//! anyway and is refused as an unknown client, which is **byte for byte
29//! today's answer** (I1). Nothing here can turn a request that used to succeed
30//! into one that fails, because the only thing it can do is add a row that did
31//! not exist.
32//!
33//! # The row it will not touch
34//!
35//! A client whose `managed_by` is not `cimd` is left exactly as it is, and the
36//! request proceeds against the administrator's registration. An operator who
37//! registered a client whose `client_id` happens to be a URL keeps that
38//! client, its secret, its profile and its audiences, whatever any document at
39//! that address says. The repository enforces this too — the refresh carries
40//! `AND managed_by = 'cimd'` in its `WHERE` — so it is refused twice, once
41//! where it can be explained and once where it cannot be bypassed.
42

54/// Resolve a URL-shaped `client_id` into a shadow client row, if this tenant
55/// admits one.
56///
57/// Returns nothing on purpose: see the module header. The caller's next step
58/// is the client lookup it was always going to make.
59///
60/// # Cost on the path that is not CIMD
61///
62/// Two `starts_with` calls. Every `client_id` AXIAM has ever issued is
63/// `oa_` followed by hex, so the overwhelming majority of requests leave this
64/// function having read no setting, taken no lock and touched no socket. The
65/// settings read happens only for a `client_id` that is literally an
66/// `http`/`https` URL — which, on a deployment that has not enabled CIMD, is a
67/// request that was going to be refused anyway.
68pub async fn materialise_if_cimd<C: Connection + Clone>(
69    state: &AppState<C>,
70    http_req: &actix_web::HttpRequest,
71    tenant_id: Uuid,
72    client_id: &str,
73) {
74    // 1. The I1 fast path.
75    if !cimd::looks_like_url(client_id) {
76        return;
77    }
78
79    // 2. The tenant's policy. A tenant that cannot be read, or whose
80    //    organization cannot be resolved, is treated as having CIMD off: a
81    //    settings read that failed must never be what opens an outbound fetch.
82    let Ok(tenant) = state.tenant_repo.get_by_id(tenant_id).await else {
83        return;
84    };
85    let Ok(settings) = SettingsRepository::get_effective_settings(
86        &state.settings_repo,
87        tenant.organization_id,
88        tenant_id,
89    )
90    .await
91    else {
92        tracing::warn!(
93            %tenant_id,
94            "could not read a tenant's effective settings while resolving a URL-shaped \
95             client_id; treating client ID metadata documents as disabled"
96        );
97        return;
98    };
99    if !settings.oidc.cimd.enabled {
100        return;
101    }
102
103    // 3. The per-tenant ceiling, **before any fetch** — T21.8 / MCP-04.
104    //
105    // Asked here rather than after the resolve for two reasons. A tenant at
106    // quota should not be an outbound amplifier either: refusing after the
107    // fetch would mean a stranger at the ceiling still gets one outbound
108    // request per distinct URL they can name. And the row lookup this needs is
109    // one the function made anyway, a few lines down, to decide whether the
110    // materialisation is a first appearance or a refresh — so moving it up
111    // costs nothing and the count query runs only when there is no row.
112    //
113    // **A refresh never counts and never costs the query.** The quota bounds
114    // how many distinct documents a tenant holds, not how often they are
115    // presented.
116    //
117    // The ceiling is `dcr_max_clients`, counted separately for `cimd`, which
118    // is what the repository's own comment on `count_by_managed_by` asks for:
119    // "the quota is per mechanism, so … a CIMD shadow row materialised by a
120    // legitimate client cannot exhaust the allowance for self-registration".
121    // Two counts against one number honours that. Not a tenth CIMD field: the
122    // precedent is T21.5 amendment 4, where `dcr_allowed_scopes` governs both
123    // mechanisms and keeps its `dcr_` name because DCR defined it.
124    let existing = state
125        .oauth2_client_repo
126        .get_by_client_id(tenant_id, client_id)
127        .await
128        .ok();
129    if let Some(row) = &existing
130        && row.managed_by != ManagedBy::Cimd
131    {
132        tracing::warn!(
133            %tenant_id,
134            client_id,
135            managed_by = %row.managed_by,
136            "a client ID metadata document names a client_id this tenant already registered by \
137             another means; the existing registration stands and the document is ignored"
138        );
139        return;
140    }
141    if existing.is_none() {
142        let limit = u64::from(settings.oidc.dcr_max_clients);
143        let held = match state
144            .oauth2_client_repo
145            .count_by_managed_by(tenant_id, ManagedBy::Cimd)
146            .await
147        {
148            Ok(held) => held,
149            Err(e) => {
150                // Fail closed: an unreadable count must not be read as room,
151                // exactly as the DCR endpoint reads it.
152                tracing::error!(
153                    error = %e,
154                    %tenant_id,
155                    "could not count client ID metadata document rows; treating the tenant as \
156                     at quota"
157                );
158                limit
159            }
160        };
161        if held >= limit {
162            // `debug`, not `warn`, for the reason the resolve failure below
163            // gives: the input is chosen by an unauthenticated caller, so
164            // anything louder is a log-flooding primitive handed to a
165            // stranger. The audit row is the record an operator acts on.
166            tracing::debug!(
167                %tenant_id,
168                client_id,
169                held,
170                limit,
171                "a tenant is at its client ID metadata document ceiling; not fetching"
172            );
173            audit_quota_refusal(state, http_req, tenant_id).await;
174            return;
175        }
176    }
177
178    // 4-6. Validate the URL, fetch (cached, guarded, bounded) and validate the
179    //      document.
180    let validated = match cimd::resolve(
181        &state.oauth2.cimd_cache,
182        tenant_id,
183        client_id,
184        &settings.oidc,
185    )
186    .await
187    {
188        Ok(validated) => validated,
189        Err(e) => {
190            // `debug`, not `warn`: the input is chosen by an unauthenticated
191            // caller, so anything louder is a log-flooding primitive handed to
192            // a stranger. The audit event below records the refusals that
193            // reached a fetch; this line is for the operator debugging their
194            // own client.
195            tracing::debug!(
196                %tenant_id,
197                client_id,
198                error = %e,
199                "a URL-shaped client_id did not resolve to a client ID metadata document"
200            );
201            return;
202        }
203    };
204
205    // `existing` was read above, before the fetch, because the quota needed
206    // it. It also decides whether anything is audited — a client materialising
207    // for the first time is an event an operator wants to see, and a refresh
208    // every five minutes for as long as the client is in use is not.
209    match state
210        .oauth2_client_repo
211        .upsert_cimd_client(client_id, validated.create)
212        .await
213    {
214        Ok(_) if existing.is_some() => {}
215        Ok(_) => audit_materialisation(state, http_req, tenant_id, client_id).await,
216        Err(e) => {
217            tracing::error!(
218                %tenant_id,
219                client_id,
220                error = %e,
221                "a client ID metadata document validated but its shadow client could not be \
222                 written; the request will be refused as an unknown client"
223            );
224        }
225    }
226}

228/// Record a refusal because the tenant is at its CIMD ceiling (T21.8 / MCP-04).
229///
230/// The same shape as T21.4a's registration refusal — the action, the
231/// `managed_by`, the error code, the caller's IP — so one audit filter shows
232/// both mechanisms' refusals side by side. And the same discipline about what
233/// it carries: **no client-supplied string**, not even the `client_id`, which
234/// on this path is a URL a stranger chose and an audit viewer is a place where
235/// attacker-controlled strings are read by people. The count and the ceiling
236/// are AXIAM's own numbers and are what an operator needs to act on.
237async fn audit_quota_refusal<C: Connection + Clone>(
238    state: &AppState<C>,
239    http_req: &actix_web::HttpRequest,
240    tenant_id: Uuid,
241) {
242    if let Err(e) = state
243        .audit_repo
244        .append(CreateAuditLogEntry {
245            tenant_id,
246            actor_id: Uuid::nil(),
247            actor_type: ActorType::System,
248            action: "oauth2.client_registration_refused".into(),
249            resource_id: None,
250            outcome: AuditOutcome::Failure,
251            ip_address: crate::extractors::client_info::client_ip(http_req),
252            metadata: Some(serde_json::json!({
253                "managed_by": ManagedBy::Cimd.as_str(),
254                "error": "client_quota_exhausted",
255            })),
256        })
257        .await
258    {
259        tracing::error!(
260            error = %e,
261            %tenant_id,
262            "could not record a refused client ID metadata document materialisation; the \
263             request is unaffected"
264        );
265    }
266}

268/// Record the first time a document becomes a client in this tenant.
269///
270/// The same shape as T21.4's registration event, with `managed_by: cimd`, so
271/// the audit viewer's existing filter shows both mechanisms side by side. A
272/// failure to write it never fails the authorization: the client exists either
273/// way, and refusing a sign-in because an audit row could not be appended
274/// would make the log a single point of failure for the login page.
275async fn audit_materialisation<C: Connection + Clone>(
276    state: &AppState<C>,
277    http_req: &actix_web::HttpRequest,
278    tenant_id: Uuid,
279    client_id: &str,
280) {
281    if let Err(e) = state
282        .audit_repo
283        .append(CreateAuditLogEntry {
284            tenant_id,
285            actor_id: Uuid::nil(),
286            actor_type: ActorType::System,
287            action: "oauth2.client_registered".into(),
288            resource_id: None,
289            outcome: AuditOutcome::Success,
290            ip_address: crate::extractors::client_info::client_ip(http_req),
291            metadata: Some(serde_json::json!({
292                "managed_by": ManagedBy::Cimd.as_str(),
293                "client_id": client_id,
294            })),
295        })
296        .await
297    {
298        tracing::error!(
299            error = %e,
300            %tenant_id,
301            "could not record a client ID metadata document materialisation; the request is \
302             unaffected"
303        );
304    }
