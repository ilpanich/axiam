1//! Rate-limit key extractor using X-Forwarded-For header (per D-02, SEC-048).
2//!
3//! SEC-048: The extractor selects the *rightmost untrusted* hop from the
4//! X-Forwarded-For header to prevent IP-spoofing based rate-limit evasion.
5//!
6//! # Deriving `trusted_hops`
7//!
8//! The value follows from one fact about how proxies write the header: a proxy
9//! appends **the address it received the request from**, not its own. nginx's
10//! `proxy_add_x_forwarded_for` is `$http_x_forwarded_for, $remote_addr`; Caddy's
11//! `reverse_proxy` and ingress-nginx do the same. So the *nearest* proxy never
12//! appears in the header the server reads — it is the socket peer. Therefore:
13//!
14//! > **`trusted_hops` = (number of reverse proxies between the client and this
15//! > server) − 1** — equivalently, the number of *proxy* addresses that appear
16//! > in the X-Forwarded-For header this server receives.
17//!
18//! | Proxies in front | Header the server sees | `trusted_hops` |
19//! | --- | --- | --- |
20//! | 1 (Caddy, or an ingress) | `<client>` | **0** |
21//! | 2 (Caddy → nginx) | `<client>, <caddy>` | **1** |
22//! | 3 (LB → ingress → mesh) | `<client>, <lb>, <ingress>` | **2** |
23//!
24//! Example, with a client that spoofs a header of its own behind two proxies:
25//!   X-Forwarded-For: <attacker-ip>, <real-client-ip>, <trusted-proxy-ip>
26//!   trusted_hops = 1 → selects <real-client-ip> (skip 1 from right)
27//!
28//! Behind a *single* appending proxy, `0` selects the real client whether or not
29//! the client lies: with no spoof the header is `<client>` and index 0 is the
30//! client; with a spoof it is `<attacker>, <client>` and index 1 is the client.
31//!
32//! **This corrected an off-by-one in the previous text**, which said the value
33//! "should equal the number of trusted reverse-proxy hops (e.g. 1 for a single
34//! nginx/ingress in front of the server)". Setting 1 behind one proxy makes
35//! `trusted_hops >= hops.len()`, so the header is discarded and the key becomes
36//! `peer_addr()` — the proxy's own address — collapsing every client on the
37//! internet into a single bucket. The advice produced exactly the failure this
38//! extractor exists to prevent. See `claude_dev/public-backend-tls-design.md` §4.
39//!
40//! Falls back to the direct peer address when the header is absent, unparseable,
41//! or has fewer hops than `trusted_hops` (a client cannot manufacture extra
42//! trusted hops to force a fallback to an attacker-controlled entry: when there
43//! are not enough hops to trust, the XFF header is ignored entirely and the key
44//! is derived from `peer_addr()`).
45//!
46//! **nginx/ingress requirement**: The upstream proxy MUST append the real client
47//! IP to the RIGHT of X-Forwarded-For (not inject it at position 0) for this to
48//! be effective. With `proxy_add_x_forwarded_for` in nginx this is the default
49//! behaviour — the real client is the RIGHTMOST trusted entry, not the leftmost.
50

62/// Extracts client IP from X-Forwarded-For header, falls back to peer address.
63///
64/// `trusted_hops` controls how many rightmost entries in the XFF header to skip
65/// (they come from trusted proxies). The selected entry is the **rightmost
66/// untrusted** hop — `idx = len - 1 - trusted_hops` — which is correct for a
67/// chain of proxies that right-append the address they received from (nginx
68/// `proxy_add_x_forwarded_for`, Caddy, ingress-nginx). `trusted_hops = 0`
69/// selects the rightmost entry, which is the real client behind exactly one
70/// such proxy; `trusted_hops = 1` skips one appended proxy address, which is
71/// what two proxies produce — see the module docs for the derivation. (SEC-070: earlier doc text wrongly described this as using the
72/// *leftmost* entry — the leftmost is the most attacker-controllable position
73/// and is never used.)
74#[derive(Debug, Clone, Default)]
75pub struct XForwardedForKeyExtractor {
76    /// Number of trusted reverse-proxy hops to skip from the right of
77    /// the X-Forwarded-For list. Set to the number of load-balancers/
78    /// ingress proxies between the client and this server.
79    ///
80    /// Default: 0 (rightmost entry), which is **correct** behind exactly one
81    /// appending proxy — the shape of both shipped topologies
82    /// (`k8s/ingress.yml` and the Compose/Pi deployment). NOTE: when the server
83    /// is exposed with no proxy at all, a client can set XFF freely; the
84    /// `peer_addr()` fallback is what keeps that safe, and such a server should
85    /// stay on 0 rather than trusting anything the client sent.
86    pub trusted_hops: usize,
87}
88
89impl XForwardedForKeyExtractor {
90    /// Create an extractor that uses the rightmost-untrusted hop.
91    /// `trusted_hops` = number of trusted proxy entries from the right.
92    pub fn with_trusted_hops(trusted_hops: usize) -> Self {
93        Self { trusted_hops }
94    }
95}

97impl KeyExtractor for XForwardedForKeyExtractor {
98    type Key = IpAddr;
99    type KeyExtractionError = SimpleKeyExtractionError<&'static str>;
100
101    fn extract(&self, req: &ServiceRequest) -> Result<Self::Key, Self::KeyExtractionError> {
102        if let Some(forwarded_for) = req.headers().get("X-Forwarded-For")
103            && let Ok(val) = forwarded_for.to_str()
104        {
105            let hops: Vec<&str> = val.split(',').map(str::trim).collect();
106            // Select the rightmost-untrusted hop.
107            // hops = [client, proxy1, ..., trusted_proxy]
108            // trusted_hops=1 → index = len - 1 - 1 = len - 2
109            if self.trusted_hops < hops.len() {
110                let idx = hops.len() - 1 - self.trusted_hops;
111                if let Ok(ip) = hops[idx].parse::<IpAddr>() {
112                    return Ok(ip);
113                }
114            }
115            // Fewer hops than trusted_hops requires: the header cannot be
116            // trusted at all (an attacker could otherwise rotate it to get a
117            // fresh bucket per request via the old `hops[0]` fallback — SECHRD-03).
118            // Fall through to peer_addr() below instead of indexing into XFF.
119        }
120        req.peer_addr()
121            .map(|addr| addr.ip())
122            .ok_or_else(|| SimpleKeyExtractionError::new("no peer address"))
123    }
124
125    /// Returns a JSON 429 response with Retry-After header per D-03.
126    ///
127    /// Body: `{"error":"rate_limit_exceeded","retry_after":<seconds>}`
128    fn exceed_rate_limit_response(
129        &self,
130        negative: &NotUntil<QuantaInstant>,
131        mut response: actix_web::HttpResponseBuilder,
132    ) -> HttpResponse {
133        let wait_secs = negative
134            .wait_time_from(DefaultClock::default().now())
135            .as_secs();
136        response
137            .content_type(ContentType::json())
138            .insert_header((RETRY_AFTER, wait_secs.to_string()))
139            .body(format!(
140                r#"{{"error":"rate_limit_exceeded","retry_after":{}}}"#,
141                wait_secs
142            ))
143    }
144}

147// D8 — client-identity-aware keying (token/introspect/revoke only)

149
150/// Request-extension carrying the `client_id` (if any) parsed from the
151/// request body by
152/// [`crate::middleware::rate_limit_shared::RateLimitShared`]'s
153/// client-identity-aware constructor, so [`ClientAwareKeyExtractor`] (used
154/// by the in-memory `Governor` on the SAME resource) doesn't need to peek
155/// the body a second time.
156///
157/// Ordering guarantee this relies on: in `server.rs`, `RateLimitShared` is
158/// always the OUTER `.wrap()` (last one added — see the module docs on
159/// `RateLimitShared`), so it always runs BEFORE the `Governor` middleware
160/// and always inserts this extension (`None` when no `client_id` could be
161/// parsed, or when the configured key mode is `ip`) before delegating.
162/// `Governor`'s [`ClientAwareKeyExtractor`] treats a *missing* extension
163/// (e.g. if the two middlewares were ever mis-ordered) identically to
164/// `None` — it falls back to the IP key, never panics.
165#[derive(Debug, Clone, Default)]
166pub struct RateLimitClientId(pub Option<String>);
167
168/// Parses the `client_id` field out of an `application/x-www-form-urlencoded`
169/// body — the ONLY client-authentication style AXIAM's `/oauth2/token`,
170/// `/oauth2/revoke`, and `/oauth2/introspect` handlers accept
171/// (`client_secret_post`, RFC 6749 §2.3.1; see `handlers::oauth2` and
172/// `axiam_oauth2::token::{TokenRequest, RevokeRequest, IntrospectRequest}`,
173/// all form-decoded via `web::Form<..>`).
174///
175/// Returns `None` for a missing/empty/unparseable `client_id` — the caller
176/// (the rate limiter) must fail SAFE by falling back to the IP key rather
177/// than reject the request outright; rejecting a malformed body is the
178/// handler's job (it returns a proper RFC 6749 `invalid_request` error),
179/// not the rate limiter's.
180pub fn extract_form_client_id(body: &[u8]) -> Option<String> {
181    url::form_urlencoded::parse(body)
182        .find(|(k, _)| k == "client_id")
183        .map(|(_, v)| v.into_owned())
184        .filter(|v| !v.is_empty())
185}

187/// D8 key extractor for the token/introspect/revoke endpoints: honors
188/// `AXIAM__RATE_LIMIT__KEY` (`ip` | `client_id` | `ip_client_id`) to key the
189/// in-memory `Governor` bucket on the OAuth2 `client_id`, the `(ip,
190/// client_id)` pair, or (default, unchanged behavior) IP alone.
191///
192/// **Never wire this onto `/auth/login` or any other endpoint without a
193/// client identity** — see [`crate::config::rate_limit::RateLimitKeyMode`]
194/// for why login is structurally excluded (it authenticates a user, not an
195/// OAuth2 client; there is no `client_id` to key on at that point).
196#[derive(Debug, Clone)]
197pub struct ClientAwareKeyExtractor {
198    /// Always computed alongside the client_id — used verbatim in `Ip`
199    /// mode, and as a namespace-safety prefix in `IpClientId` mode.
200    pub ip_extractor: XForwardedForKeyExtractor,
201    pub key_mode: RateLimitKeyMode,
202}
203
204impl ClientAwareKeyExtractor {
205    pub fn new(ip_extractor: XForwardedForKeyExtractor, key_mode: RateLimitKeyMode) -> Self {
206        Self {
207            ip_extractor,
208            key_mode,
209        }
210    }
211}
212
213impl KeyExtractor for ClientAwareKeyExtractor {
214    type Key = String;
215    type KeyExtractionError = SimpleKeyExtractionError<&'static str>;
216
217    fn extract(&self, req: &ServiceRequest) -> Result<Self::Key, Self::KeyExtractionError> {
218        let ip = self.ip_extractor.extract(req)?;
219
220        let client_id = req
221            .extensions()
222            .get::<RateLimitClientId>()
223            .and_then(|c| c.0.clone());
224
225        Ok(match (self.key_mode, client_id) {
226            // `ip` mode, or no client_id available (fail-safe fallback):
227            // identical to the pre-D8 IP-only key.
228            (RateLimitKeyMode::Ip, _) | (_, None) => ip.to_string(),
229            (RateLimitKeyMode::ClientId, Some(cid)) => format!("client:{cid}"),
230            (RateLimitKeyMode::IpClientId, Some(cid)) => format!("{ip}:client:{cid}"),
231        })
232    }
233
234    /// Same 429 contract as [`XForwardedForKeyExtractor`] — clients must
235    /// see one consistent rate-limit response shape regardless of which key
236    /// mode rejected the request.
237    fn exceed_rate_limit_response(
238        &self,
239        negative: &NotUntil<QuantaInstant>,
240        mut response: actix_web::HttpResponseBuilder,
241    ) -> HttpResponse {
242        let wait_secs = negative
243            .wait_time_from(DefaultClock::default().now())
244            .as_secs();
245        response
246            .content_type(ContentType::json())
247            .insert_header((RETRY_AFTER, wait_secs.to_string()))
248            .body(format!(
249                r#"{{"error":"rate_limit_exceeded","retry_after":{}}}"#,
250                wait_secs
251            ))
252    }
253}

377    /// Builds a `NotUntil` "rate limited" outcome directly from a real
378    /// `governor::RateLimiter`, without going through a full `actix_governor`
379    /// `Governor` middleware/request cycle: consume a 1-per-hour direct quota
380    /// once (succeeds), then again (fails) — the failure is exactly the
381    /// `NotUntil<QuantaInstant>` both `exceed_rate_limit_response` impls
382    /// take. Neither impl is reached by any HTTP-round-trip test in this
383    /// crate: those exercise `RateLimitShared`'s own 429 body
384    /// (`middleware::rate_limit_shared::too_many_requests_response`), never
385    /// the in-memory `Governor`'s per-`KeyExtractor` override.
386    fn rate_limited_not_until() -> NotUntil<QuantaInstant> {
387        use actix_governor::governor::{Quota, RateLimiter};
388        use std::num::NonZeroU32;
389
390        let quota = Quota::per_hour(NonZeroU32::new(1).unwrap());
391        let limiter = RateLimiter::direct(quota);
392        limiter.check().expect("first request must be allowed");
393        limiter
394            .check()
395            .expect_err("second request within the same window must be rate-limited")
396    }
