1//! Rate-limit key extractor using X-Forwarded-For header (per D-02, SEC-048).
2//!
3//! SEC-048: The extractor selects the *rightmost untrusted* hop from the
4//! X-Forwarded-For header to prevent IP-spoofing based rate-limit evasion.
5//!
6//! # Deriving `trusted_hops`
7//!
8//! The value follows from one fact about how proxies write the header: a proxy
9//! appends **the address it received the request from**, not its own. nginx's
10//! `proxy_add_x_forwarded_for` is `$http_x_forwarded_for, $remote_addr`; Caddy's
11//! `reverse_proxy` and ingress-nginx do the same. So the *nearest* proxy never
12//! appears in the header the server reads — it is the socket peer. Therefore:
13//!
14//! > **`trusted_hops` = (number of reverse proxies between the client and this
15//! > server) − 1** — equivalently, the number of *proxy* addresses that appear
16//! > in the X-Forwarded-For header this server receives.
17//!
18//! | Proxies in front | Header the server sees | `trusted_hops` |
19//! | --- | --- | --- |
20//! | 1 (Caddy, or an ingress) | `<client>` | **0** |
21//! | 2 (Caddy → nginx) | `<client>, <caddy>` | **1** |
22//! | 3 (LB → ingress → mesh) | `<client>, <lb>, <ingress>` | **2** |
23//!
24//! Example, with a client that spoofs a header of its own behind two proxies:
25//!   X-Forwarded-For: <attacker-ip>, <real-client-ip>, <trusted-proxy-ip>
26//!   trusted_hops = 1 → selects <real-client-ip> (skip 1 from right)
27//!
28//! Behind a *single* appending proxy, `0` selects the real client whether or not
29//! the client lies: with no spoof the header is `<client>` and index 0 is the
30//! client; with a spoof it is `<attacker>, <client>` and index 1 is the client.
31//!
32//! **This corrected an off-by-one in the previous text**, which said the value
33//! "should equal the number of trusted reverse-proxy hops (e.g. 1 for a single
34//! nginx/ingress in front of the server)". Setting 1 behind one proxy makes
35//! `trusted_hops >= hops.len()`, so the header is discarded and the key becomes
36//! `peer_addr()` — the proxy's own address — collapsing every client on the
37//! internet into a single bucket. The advice produced exactly the failure this
38//! extractor exists to prevent. See `claude_dev/public-backend-tls-design.md` §4.
39//!
40//! Falls back to the direct peer address when the header is absent, unparseable,
41//! or has fewer hops than `trusted_hops` (a client cannot manufacture extra
42//! trusted hops to force a fallback to an attacker-controlled entry: when there
43//! are not enough hops to trust, the XFF header is ignored entirely and the key
44//! is derived from `peer_addr()`).
45//!
46//! **nginx/ingress requirement**: The upstream proxy MUST append the real client
47//! IP to the RIGHT of X-Forwarded-For (not inject it at position 0) for this to
48//! be effective. With `proxy_add_x_forwarded_for` in nginx this is the default
49//! behaviour — the real client is the RIGHTMOST trusted entry, not the leftmost.
50//!
51//! # Which peers may write the header (`TRUSTED_PROXIES`, #711)
52//!
53//! No value of `trusted_hops` helps a connection with no appending proxy in
54//! front: the rightmost entry is then the caller's own. When
55//! `AXIAM__RATE_LIMIT__TRUSTED_PROXIES` names the proxies (CIDR blocks), the
56//! header is read only on a request whose transport peer is inside one of
57//! them; every other request is keyed on its peer, whatever it wrote. With the
58//! list empty (the default) every peer's header is read, as before the list
59//! existed. The rule is [`axiam_core::forwarded_for::TrustedProxies`], shared
60//! with the gRPC extractor.
61

78/// Extracts client IP from X-Forwarded-For header, falls back to peer address.
79///
80/// `trusted_hops` controls how many rightmost entries in the XFF header to skip
81/// (they come from trusted proxies). The selected entry is the **rightmost
82/// untrusted** hop — `idx = len - 1 - trusted_hops` — which is correct for a
83/// chain of proxies that right-append the address they received from (nginx
84/// `proxy_add_x_forwarded_for`, Caddy, ingress-nginx). `trusted_hops = 0`
85/// selects the rightmost entry, which is the real client behind exactly one
86/// such proxy; `trusted_hops = 1` skips one appended proxy address, which is
87/// what two proxies produce — see the module docs for the derivation. (SEC-070: earlier doc text wrongly described this as using the
88/// *leftmost* entry — the leftmost is the most attacker-controllable position
89/// and is never used.)
90#[derive(Debug, Clone, Default)]
91pub struct XForwardedForKeyExtractor {
92    /// Number of trusted reverse-proxy hops to skip from the right of
93    /// the X-Forwarded-For list. Set to the number of load-balancers/
94    /// ingress proxies between the client and this server.
95    ///
96    /// Default: 0 (rightmost entry), which is **correct** behind exactly one
97    /// appending proxy — the shape of both shipped topologies
98    /// (`k8s/ingress.yml` and the Compose/Pi deployment). NOTE: when the server
99    /// is exposed with no proxy at all, a client can set XFF freely and no
100    /// value of this field helps: that is what [`Self::trusted_proxies`] is
101    /// for. *(Corrected 2026-10-19, #686: this note said the `peer_addr()`
102    /// fallback kept that case safe, which holds only for a caller that sends
103    /// no header.)*
104    pub trusted_hops: usize,
105    /// The peers whose X-Forwarded-For is read at all
106    /// (`AXIAM__RATE_LIMIT__TRUSTED_PROXIES`, #711). A request from any other
107    /// peer is keyed on the peer. Empty (the default): every peer's.
108    pub trusted_proxies: TrustedProxies,
109}

111impl XForwardedForKeyExtractor {
112    /// Create an extractor that uses the rightmost-untrusted hop.
113    /// `trusted_hops` = number of trusted proxy entries from the right.
114    /// The proxy list is empty: every peer's header is read.
115    pub fn with_trusted_hops(trusted_hops: usize) -> Self {
116        Self {
117            trusted_hops,
118            trusted_proxies: TrustedProxies::default(),
119        }
120    }
121
122    /// This extractor, reading the header only from a peer in `trusted_proxies`.
123    #[must_use]
124    pub fn with_trusted_proxies(mut self, trusted_proxies: TrustedProxies) -> Self {
125        self.trusted_proxies = trusted_proxies;
126        self
127    }
128
129    /// The extractor the deployment configures: `AXIAM__RATE_LIMIT__TRUSTED_HOPS`
130    /// ([`configured_trusted_hops`]) and `AXIAM__RATE_LIMIT__TRUSTED_PROXIES`
131    /// ([`TrustedProxies::configured`]). Every REST limiter keyed on the
132    /// client's address is built from this, so they cannot disagree about
133    /// which address a request is.
134    pub fn configured() -> Self {
135        Self::with_trusted_hops(configured_trusted_hops())
136            .with_trusted_proxies(TrustedProxies::configured())
137    }
138}

140/// `AXIAM__RATE_LIMIT__TRUSTED_HOPS`, or `0` when it is unset or unparseable.
141///
142/// The one reading of the variable every REST limiter keyed on the client's
143/// address uses: the route governors (`server.rs`), the shared counter
144/// (`middleware::rate_limit_shared`). Read per call, as the shared counter has
145/// always read it, so they cannot disagree about which address a request is.
146pub fn configured_trusted_hops() -> usize {
147    std::env::var("AXIAM__RATE_LIMIT__TRUSTED_HOPS")
148        .ok()
149        .and_then(|v| v.parse().ok())
150        .unwrap_or(0)
151}

153/// The address a per-address rate limit keys a request on (SEC-048, T-212).
154///
155/// `peer`, the transport peer, when `trusted_proxies` does not honour its
156/// header (#711). Otherwise the **rightmost untrusted** `X-Forwarded-For`
157/// hop — `hops[len - 1 - trusted_hops]` — when the header has more hops than
158/// `trusted_hops` and that entry parses as an address; otherwise `peer`.
159/// Behind `trusted_hops + 1` appending proxies a client cannot choose the
160/// result by writing the header: the entries it writes sit to the LEFT of the
161/// ones the proxies append, and the index counts from the right; and a header
162/// too short to reach past the trusted hops is ignored entirely rather than
163/// indexed from the left (SECHRD-03). A server exposed with no proxy at all
164/// reads whatever the caller wrote unless `trusted_proxies` names the proxies
165/// — the deployment guide's T-212 caveat, shared by every limiter that calls
166/// this.
167///
168/// The second value is `Some(hops seen)` when the header was discarded
169/// because `trusted_hops >= hops` — the R-4 misconfiguration signal, which
170/// only [`XForwardedForKeyExtractor`] records, once per request.
171fn select_rate_limit_ip(
172    headers: &HeaderMap,
173    peer: Option<SocketAddr>,
174    trusted_hops: usize,
175    trusted_proxies: &TrustedProxies,
176) -> (Option<IpAddr>, Option<usize>) {
177    let peer = peer.map(|addr| addr.ip());
178    // #711: a peer the list does not name is not a proxy, so whatever it wrote
179    // is its own choice. Not an R-4 discard: `trusted_hops` is not wrong.
180    if !trusted_proxies.honours_forwarded_for(peer) {
181        return (peer, None);
182    }
183    let mut discarded_hops = None;
184    if let Some(forwarded_for) = headers.get("X-Forwarded-For")
185        && let Ok(val) = forwarded_for.to_str()
186    {
187        let hops: Vec<&str> = val.split(',').map(str::trim).collect();
188        // Select the rightmost-untrusted hop.
189        // hops = [client, proxy1, ..., trusted_proxy]
190        // trusted_hops=1 → index = len - 1 - 1 = len - 2
191        if trusted_hops < hops.len() {
192            let idx = hops.len() - 1 - trusted_hops;
193            if let Ok(ip) = hops[idx].parse::<IpAddr>() {
194                return (Some(ip), None);
195            }
196        } else {
197            // Fewer hops than trusted_hops requires: the header cannot be
198            // trusted at all (an attacker could otherwise rotate it to get a
199            // fresh bucket per request via the old `hops[0]` fallback —
200            // SECHRD-03). Fall through to the peer instead of indexing into it.
201            discarded_hops = Some(hops.len());
202        }
203    }
204    (peer, discarded_hops)
205}

207impl KeyExtractor for XForwardedForKeyExtractor {
208    type Key = IpAddr;
209    type KeyExtractionError = SimpleKeyExtractionError<&'static str>;
210
211    fn extract(&self, req: &ServiceRequest) -> Result<Self::Key, Self::KeyExtractionError> {
212        let (ip, discarded_hops) = select_rate_limit_ip(
213            req.headers(),
214            req.peer_addr(),
215            self.trusted_hops,
216            &self.trusted_proxies,
217        );
218        // R-4: a header with fewer hops than `trusted_hops` requires is no
219        // longer discarded silently. Under a `trusted_hops` one too high this
220        // fires on every request and every client shares one bucket keyed on
221        // the proxy — the failure T-212 describes, which went unnoticed
222        // precisely because nothing said so. One WARN per process plus a
223        // counter; see `super::xff_metrics`.
224        if let Some(hops_seen) = discarded_hops {
225            super::xff_metrics::record_discarded_xff(hops_seen, self.trusted_hops);
226        }
227        ip.ok_or_else(|| SimpleKeyExtractionError::new("no peer address"))
228    }
229
230    /// Returns a JSON 429 response with Retry-After header per D-03.
231    ///
232    /// Body: `{"error":"rate_limit_exceeded","retry_after":<seconds>}`
233    fn exceed_rate_limit_response(
234        &self,
235        negative: &NotUntil<QuantaInstant>,
236        mut response: actix_web::HttpResponseBuilder,
237    ) -> HttpResponse {
238        let wait_secs = negative
239            .wait_time_from(DefaultClock::default().now())
240            .as_secs();
241        response
242            .content_type(ContentType::json())
243            .insert_header((RETRY_AFTER, wait_secs.to_string()))
244            .body(format!(
245                r#"{{"error":"rate_limit_exceeded","retry_after":{}}}"#,
246                wait_secs
247            ))
248    }
249}

255/// Request-extension carrying the `client_id` (if any) parsed from the
256/// request body by
257/// [`crate::middleware::rate_limit_shared::RateLimitShared`]'s
258/// client-identity-aware constructor, so [`ClientAwareKeyExtractor`] (used
259/// by the in-memory `Governor` on the SAME resource) doesn't need to peek
260/// the body a second time.
261///
262/// Ordering guarantee this relies on: in `server.rs`, `RateLimitShared` is
263/// always the OUTER `.wrap()` (last one added — see the module docs on
264/// `RateLimitShared`), so it always runs BEFORE the `Governor` middleware
265/// and always inserts this extension (`None` when no `client_id` could be
266/// parsed, or when the configured key mode is `ip`) before delegating.
267/// `Governor`'s [`ClientAwareKeyExtractor`] treats a *missing* extension
268/// (e.g. if the two middlewares were ever mis-ordered) identically to
269/// `None` — it falls back to the IP key, never panics.
270#[derive(Debug, Clone, Default)]
271pub struct RateLimitClientId(pub Option<String>);
272
273/// Parses the `client_id` field out of an `application/x-www-form-urlencoded`
274/// body — where a `client_secret_post` client (RFC 6749 §2.3.1, see
275/// `handlers::oauth2` and `axiam_oauth2::token::{TokenRequest, RevokeRequest,
276/// IntrospectRequest}`, all form-decoded via `web::Form<..>`) names itself.
277/// A `client_secret_basic` client may name itself in the `Authorization`
278/// header alone; see [`extract_basic_client_id`] and [`extract_client_id`].
279///
280/// Returns `None` for a missing/empty/unparseable `client_id` — the caller
281/// (the rate limiter) must fail SAFE by falling back to the IP key rather
282/// than reject the request outright; rejecting a malformed body is the
283/// handler's job (it returns a proper RFC 6749 `invalid_request` error),
284/// not the rate limiter's.
285pub fn extract_form_client_id(body: &[u8]) -> Option<String> {
286    url::form_urlencoded::parse(body)
287        .find(|(k, _)| k == "client_id")
288        .map(|(_, v)| v.into_owned())
289        .filter(|v| !v.is_empty())
290}
291
292/// The `client_id` an `Authorization: Basic` header names (RFC 6749 §2.3.1,
293/// decoded by `axiam_oauth2::client_secret_basic` exactly as the handlers
294/// decode it), or `None` for no header, another scheme, or a header that does
295/// not decode.
296///
297/// T23.1.5. RFC 6749 §2.3.1 makes the body's `client_id` optional for a client
298/// authenticating through the header, and 37 of the Basic OP suite's 38
299/// modules send it there alone. A rate limiter that read the form only keyed
300/// such a request on the source address whatever `AXIAM__RATE_LIMIT__KEY` said,
301/// so a `client_secret_basic` client had no per-client bucket and its secret
302/// could be guessed from as many addresses as the guesser owned. The secret
303/// half of the credential is dropped on the floor here: only the id selects a
304/// bucket, and the header is never logged.
305pub fn extract_basic_client_id(authorization: &str) -> Option<String> {
306    axiam_oauth2::client_secret_basic::parse_authorization_header(authorization)?
307        .ok()
308        .map(|credentials| credentials.client_id().to_owned())
309}
310
311/// The `client_id` a request names itself by: the form body's when present,
312/// otherwise the `Authorization: Basic` header's.
313///
314/// The body wins because that is the order the handlers resolve it in
315/// (`resolve_client_id`), and a request naming two different ids is refused
316/// there before any secret is checked, so a caller cannot use the disagreement
317/// to guess a secret under a bucket other than the one it is charged to.
318pub fn extract_client_id(body: &[u8], authorization: Option<&str>) -> Option<String> {
319    extract_form_client_id(body).or_else(|| authorization.and_then(extract_basic_client_id))
320}

323// #633 — principal keying (the authenticated federation flow routes only)
324// ---------------------------------------------------------------------------

326/// The principal a [`RateLimitKeyMode::Principal`] bucket is keyed on: the
327/// `(tenant, sub)` of an access token whose signature, expiry and issuer were
328/// **verified** for this request.
329///
330/// Built only by [`verified_principal`], from the
331/// [`CachedUserIdentity`] that `axiam_audit::middleware::AuditMiddleware`
332/// leaves on every request whose token verifies. That middleware wraps the
333/// whole application (`axiam-server`'s `boot.rs`), so it has run before any
334/// limiter here, and reusing its result is what keeps the principal key free:
335/// no limiter verifies a signature, so a refused credential still costs the
336/// verifications it cost before (§10, "one verify per refusal").
337#[derive(Debug, Clone, PartialEq, Eq)]
338pub struct RateLimitPrincipal {
339    /// The tenant the token was issued in (its `tenant_id` claim).
340    pub tenant_id: Uuid,
341    /// The token's subject (its `sub` claim).
342    pub subject: Uuid,
343    /// Whether the token is sender-constrained (`cnf`, RFC 8705 / RFC 9449).
344    /// Its proof of possession is checked by the extractor, after the limiter,
345    /// so here the token alone does not yet show its holder is the principal.
346    pub sender_constrained: bool,
347}
348
349/// The verified principal of this request, or `None` when no token verified.
350///
351/// **Reads, never verifies.** `None` covers "no token", "a token that did not
352/// verify" (forged, expired, another issuer's) and "no audit middleware in this
353/// composition" alike, and every one of them keys on the address — the
354/// pre-authentication fallback, which is what every route keyed on before
355/// #633. A caller cannot reach this with a claim it wrote itself: request
356/// extensions are written by server code only, and the one writer of this
357/// extension inserts it after `validate_access_token` succeeded.
358pub fn verified_principal(req: &ServiceRequest) -> Option<RateLimitPrincipal> {
359    let extensions = req.extensions();
360    let cached = extensions.get::<Arc<CachedUserIdentity>>()?;
361    Some(RateLimitPrincipal {
362        tenant_id: cached.tenant_id,
363        subject: cached.user_id,
364        sender_constrained: cached.claims.0.cnf.is_some(),
365    })
366}
367
368/// The identity part of a bucket key — `{endpoint}:{this}` in the shared
369/// counter, the whole key in the in-memory governor — for every key mode.
370///
371/// One function for both layers, so the shared counter
372/// ([`crate::middleware::rate_limit_shared::RateLimitShared`]) and the
373/// in-process governor ([`ClientAwareKeyExtractor`]) can never disagree about
374/// which bucket a request belongs to: with `AXIAM__RATE_LIMIT__SHARED` on or
375/// off, a route keys the same way.
376///
377/// `None` only when the key needs the address and there is none; the caller
378/// then fails open (shared layer) or refuses the key (governor), as before.
379pub fn bucket_key_part(
380    key_mode: RateLimitKeyMode,
381    ip: Option<IpAddr>,
382    client_id: Option<&str>,
383    principal: Option<&RateLimitPrincipal>,
384) -> Option<String> {
385    match (key_mode, client_id, principal) {
386        // #633. A verified bearer token: the principal alone, from whichever
387        // address it comes — one token used from many addresses is one
388        // bucket, and one address relaying many users is many.
389        (RateLimitKeyMode::Principal, _, Some(p)) if !p.sender_constrained => {
390            Some(format!("principal:{}:{}", p.tenant_id, p.subject))
391        }
392        // A sender-constrained token, whose possession is not yet proved: the
393        // address and the principal together, so a copy replayed from
394        // elsewhere spends a bucket of its own and never its principal's.
395        (RateLimitKeyMode::Principal, _, Some(p)) => {
396            ip.map(|ip| format!("{ip}:principal:{}:{}", p.tenant_id, p.subject))
397        }
398        // No verified token (pre-authentication fallback), `ip` mode, or no
399        // client_id available (fail-safe fallback): the address alone.
400        (RateLimitKeyMode::Principal, _, None)
401        | (RateLimitKeyMode::Ip, _, _)
402        | (RateLimitKeyMode::ClientId | RateLimitKeyMode::IpClientId, None, _) => {
403            ip.map(|ip| ip.to_string())
404        }
405        (RateLimitKeyMode::ClientId, Some(cid), _) => Some(format!("client:{cid}")),
406        (RateLimitKeyMode::IpClientId, Some(cid), _) => ip.map(|ip| format!("{ip}:client:{cid}")),
407    }
408}

410/// D8 key extractor for the token/introspect/revoke endpoints: honors
411/// `AXIAM__RATE_LIMIT__KEY` (`ip` | `client_id` | `ip_client_id`) to key the
412/// in-memory `Governor` bucket on the OAuth2 `client_id`, the `(ip,
413/// client_id)` pair, or (default, unchanged behavior) IP alone.
414///
415/// **Never wire this onto `/auth/login` or any other endpoint without a
416/// client identity** — see [`crate::config::rate_limit::RateLimitKeyMode`]
417/// for why login is structurally excluded (it authenticates a user, not an
418/// OAuth2 client; there is no `client_id` to key on at that point).
419///
420/// The same extractor in [`RateLimitKeyMode::Principal`] keys the five
421/// authenticated federation flow routes on their verified principal (#633);
422/// see [`verified_principal`]. It never reads a body in that mode.
423#[derive(Debug, Clone)]
424pub struct ClientAwareKeyExtractor {
425    /// Always computed alongside the client_id — used verbatim in `Ip`
426    /// mode, and as a namespace-safety prefix in `IpClientId` mode.
427    pub ip_extractor: XForwardedForKeyExtractor,
428    pub key_mode: RateLimitKeyMode,
429}
430
431impl ClientAwareKeyExtractor {
432    pub fn new(ip_extractor: XForwardedForKeyExtractor, key_mode: RateLimitKeyMode) -> Self {
433        Self {
434            ip_extractor,
435            key_mode,
436        }
437    }
438}
439
440impl KeyExtractor for ClientAwareKeyExtractor {
441    type Key = String;
442    type KeyExtractionError = SimpleKeyExtractionError<&'static str>;
443
444    fn extract(&self, req: &ServiceRequest) -> Result<Self::Key, Self::KeyExtractionError> {
445        let ip = self.ip_extractor.extract(req)?;
446
447        let client_id = req
448            .extensions()
449            .get::<RateLimitClientId>()
450            .and_then(|c| c.0.clone());
451        let principal = match self.key_mode {
452            RateLimitKeyMode::Principal => verified_principal(req),
453            _ => None,
454        };
455
456        // With an address in hand every mode yields a key; `ok_or` is for the
457        // type, not a reachable branch.
458        bucket_key_part(
459            self.key_mode,
460            Some(ip),
461            client_id.as_deref(),
462            principal.as_ref(),
463        )
464        .ok_or_else(|| SimpleKeyExtractionError::new("no bucket key"))
465    }
466
467    /// Same 429 contract as [`XForwardedForKeyExtractor`] — clients must
468    /// see one consistent rate-limit response shape regardless of which key
469    /// mode rejected the request.
470    fn exceed_rate_limit_response(
471        &self,
472        negative: &NotUntil<QuantaInstant>,
473        mut response: actix_web::HttpResponseBuilder,
474    ) -> HttpResponse {
475        let wait_secs = negative
476            .wait_time_from(DefaultClock::default().now())
477            .as_secs();
478        response
479            .content_type(ContentType::json())
480            .insert_header((RETRY_AFTER, wait_secs.to_string()))
481            .body(format!(
482                r#"{{"error":"rate_limit_exceeded","retry_after":{}}}"#,
483                wait_secs
484            ))
485    }
486}

662    /// Builds a `NotUntil` "rate limited" outcome directly from a real
663    /// `governor::RateLimiter`, without going through a full `actix_governor`
664    /// `Governor` middleware/request cycle: consume a 1-per-hour direct quota
665    /// once (succeeds), then again (fails) — the failure is exactly the
666    /// `NotUntil<QuantaInstant>` both `exceed_rate_limit_response` impls
667    /// take. Neither impl is reached by any HTTP-round-trip test in this
668    /// crate: those exercise `RateLimitShared`'s own 429 body
669    /// (`middleware::rate_limit_shared::too_many_requests_response`), never
670    /// the in-memory `Governor`'s per-`KeyExtractor` override.
671    fn rate_limited_not_until() -> NotUntil<QuantaInstant> {
672        use actix_governor::governor::{Quota, RateLimiter};
673        use std::num::NonZeroU32;
674
675        let quota = Quota::per_hour(NonZeroU32::new(1).unwrap());
676        let limiter = RateLimiter::direct(quota);
677        limiter.check().expect("first request must be allowed");
678        limiter
679            .check()
680            .expect_err("second request within the same window must be rate-limited")
681    }

839    fn headers(xff: Option<&str>) -> HeaderMap {
840        let mut req = TestRequest::get();
841        if let Some(value) = xff {
842            req = req.insert_header(("X-Forwarded-For", value));
843        }
844        req.to_http_request().headers().clone()
845    }

847    fn select(xff: Option<&str>, trusted_hops: usize) -> (Option<IpAddr>, Option<usize>) {
848        select_rate_limit_ip(
849            &headers(xff),
850            Some(PROXY.parse().unwrap()),
851            trusted_hops,
852            &TrustedProxies::default(),
853        )
854    }
855
856    fn ip(s: &str) -> Option<IpAddr> {
857        Some(s.parse().unwrap())
858    }

860    fn proxy() -> Option<IpAddr> {
861        Some(PROXY.parse::<SocketAddr>().unwrap().ip())
862    }

864    #[test]
865    fn behind_one_proxy_the_key_is_the_address_the_proxy_appended() {
866        assert_eq!(select(Some(A), 0), (ip(A), None));
867        // An untrusted entry the client wrote itself sits to the LEFT of the
868        // one the proxy appends, so it does not change the key: a caller at A
869        // cannot charge its requests to B's bucket.
870        assert_eq!(select(Some(&format!("{B}, {A}")), 0), (ip(A), None));
871        assert_eq!(select(Some(&format!("{B},{B}, {A}")), 0), (ip(A), None));
872    }
873
874    #[test]
875    fn trusted_hops_at_or_above_the_hop_count_falls_back_to_the_peer() {
876        // The T-212 off-by-one (`1` behind one proxy): the header cannot be
877        // trusted, so the key is the peer, and the discard is reported for
878        // R-4's signal.
879        assert_eq!(select(Some(A), 1), (proxy(), Some(1)));
880        assert_eq!(select(Some(&format!("{B}, {A}")), 2), (proxy(), Some(2)));
881        assert_eq!(select(Some(&format!("{B}, {A}")), 5), (proxy(), Some(2)));
882        // One hop more than trusted reaches the client again.
883        assert_eq!(select(Some(&format!("{B}, {A}")), 1), (ip(B), None));
884    }

886    #[test]
887    fn no_header_or_an_unparseable_entry_falls_back_to_the_peer() {
888        assert_eq!(select(None, 0), (proxy(), None));
889        assert_eq!(select(Some("not-an-address"), 0), (proxy(), None));
890        assert_eq!(
891            select_rate_limit_ip(&headers(Some(A)), None, 1, &TrustedProxies::default()),
892            (None, Some(1)),

897    #[test]
898    fn a_peer_outside_the_proxy_list_is_keyed_on_itself() {
899        let listed = TrustedProxies::parse("10.0.0.0/24").unwrap();
900        let elsewhere = TrustedProxies::parse("192.0.2.0/24").unwrap();
901        let peer = Some(PROXY.parse().unwrap());
902        // The peer is a listed proxy: its header is read under `trusted_hops`.
903        assert_eq!(
904            select_rate_limit_ip(&headers(Some(A)), peer, 0, &listed),

917        assert_eq!(
918            select_rate_limit_ip(&headers(Some(A)), None, 0, &listed),
919            (None, None)
920        );
