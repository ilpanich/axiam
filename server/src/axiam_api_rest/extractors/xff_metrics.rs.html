1//! Visibility for a `TRUSTED_HOPS` misconfiguration (R-4, narrows T-212/T-233).
2//!
3//! # Why this exists
4//!
5//! Both rate-limit key extractors fall through to the peer address when
6//! `trusted_hops >= hops.len()` — an `X-Forwarded-For` header that cannot be
7//! trusted is ignored entirely, rather than indexed into. That fallback is
8//! **correct** and must stay: it is what stops a client rotating a single-hop
9//! XFF to mint a fresh bucket per request (SECHRD-03 / D-01d).
10//!
11//! What was wrong is that it happened **silently**. That silence is exactly how
12//! the off-by-one T-212 describes went unnoticed: with `trusted_hops` one too
13//! high, every client keyed to the proxy's address, the whole deployment shared
14//! one bucket, and nothing in any log said so. The failure looks like "the rate
15//! limit is mysteriously strict", which is the kind of thing an operator raises
16//! the limit to fix.
17//!
18//! So the fallback now leaves two traces:
19//!
20//! - a **once-per-process** `WARN` naming the hop count seen, the `trusted_hops`
21//!   in force and the rule (`proxies − 1`), so the first request that hits it
22//!   explains itself in the log an operator is already reading;
23//! - a counter, so a dashboard can show that every request is keying on the
24//!   peer rather than on the client.
25//!
26//! The `WARN` is once per process on purpose. The condition fires on *every*
27//! request under a misconfiguration, so one line per request would be a log
28//! flood proportional to traffic — and the second line adds nothing the first
29//! did not say.
30//!
31//! # Why a counter and not a metrics crate
32//!
33//! This workspace has no metrics facade. `axiam_db::metrics` and
34//! `axiam_amqp::reactor::metrics` are the pattern: a process-wide relaxed
35//! atomic, readable from tests and from a future `/metrics` endpoint, with the
36//! Prometheus name it will be exported under written down beside it. A second
37//! convention here would leave this boundary measurable by different means than
38//! everything around it.
39//!
40//! The metric is one series with a `protocol` label:
41//! `axiam_rate_limit_xff_discarded_total{protocol="rest"}` here, and
42//! `{protocol="grpc"}` from the identical counter in
43//! `axiam_api_grpc::middleware::rate_limit`. The two crates are siblings —
44//! neither may depend on the other — so the label is expressed as two counters
45//! that an exporter renders as one labelled series.
46
47use std::sync::atomic::{AtomicBool, AtomicU64, Ordering};
48
49/// `axiam_rate_limit_xff_discarded_total{protocol="rest"}`.
50static XFF_DISCARDED: AtomicU64 = AtomicU64::new(0);
51
52/// Whether the explanatory `WARN` has already been emitted this process.
53static WARNED: AtomicBool = AtomicBool::new(false);
54
55/// How many REST requests arrived with an `X-Forwarded-For` header that
56/// `trusted_hops` discarded, so the key came from the peer address instead.
57///
58/// Metric name: `axiam_rate_limit_xff_discarded_total{protocol="rest"}`.
59///
60/// **A non-zero value is not automatically a fault.** It is a fault when it
61/// tracks total request volume: that means the header is present on every
62/// request and trusted on none, i.e. `trusted_hops` is too high for this
63/// deployment's proxy count and every client shares one bucket. A handful,
64/// against a much larger request count, is a few clients sending their own XFF
65/// to a server that correctly ignores it.
66pub fn xff_discarded() -> u64 {
67    XFF_DISCARDED.load(Ordering::Relaxed)
68}
69
70/// Record that a present `X-Forwarded-For` header was discarded because
71/// `trusted_hops` exceeded the hops available, and explain it once.
72///
73/// Called only on that path — a request with **no** header does not come
74/// through here, because a client with no proxy in front of it is not a
75/// misconfiguration and counting it would bury the signal.
76pub(crate) fn record_discarded_xff(hops_seen: usize, trusted_hops: usize) {
77    XFF_DISCARDED.fetch_add(1, Ordering::Relaxed);
78
79    if !WARNED.swap(true, Ordering::Relaxed) {
80        tracing::warn!(
81            protocol = "rest",
82            hops_seen,
83            trusted_hops,
84            "X-Forwarded-For was DISCARDED and the rate-limit key fell back to the \
85             connection peer: the header carried {hops_seen} hop(s) but \
86             AXIAM__RATE_LIMIT__TRUSTED_HOPS is {trusted_hops}, which trusts them all. \
87             If this fires on every request, every client is sharing ONE bucket keyed \
88             on the proxy's address. The rule is trusted_hops = proxies - 1 \
89             (one proxy in front of the server means 0). Counted as \
90             axiam_rate_limit_xff_discarded_total{{protocol=\"rest\"}}; logged once per \
91             process."
92        );
93    }
94}

96#[cfg(test)]
97mod tests {
98    use super::*;
99
100    /// Serializes the tests below.
101    ///
102    /// Both statics are process-global and `cargo test` runs these on threads
103    /// of one process, so a test that resets them races any test reading them.
104    /// The bug that produces is intermittent and looks like a real regression,
105    /// which is the worst kind to leave in a suite that guards an observability
106    /// signal.
107    fn lock() -> std::sync::MutexGuard<'static, ()> {
108        static LOCK: std::sync::Mutex<()> = std::sync::Mutex::new(());
109        LOCK.lock().unwrap_or_else(|poisoned| poisoned.into_inner())
110    }
111
112    /// Reset both statics so a test can assert from a known point.
113    fn reset() {
114        XFF_DISCARDED.store(0, Ordering::Relaxed);
115        WARNED.store(false, Ordering::Relaxed);
116    }
117
118    /// The counter counts every discard; the `WARN` latch fires once.
119    ///
120    /// Both halves matter and they fail differently. A counter that only
121    /// incremented on the first discard would show `1` under a misconfiguration
122    /// that is dropping the header on every request — the exact opposite of the
123    /// signal R-4 exists to give, which is "this number tracks request volume".
124    /// A `WARN` that fired every time would be a log flood proportional to
125    /// traffic, which is how an operator learns to filter the line out.
126    #[test]
127    fn every_discard_is_counted_and_only_the_first_is_warned_about() {
128        let _guard = lock();
129        reset();
130
131        for _ in 0..5 {
132            record_discarded_xff(1, 3);
133        }
134        assert_eq!(
135            xff_discarded(),
136            5,
137            "the counter must track every discard, not only the first"
138        );
139        assert!(
140            WARNED.load(Ordering::Relaxed),
141            "the first discard must arm the once-per-process latch"
142        );
143    }
144
145    /// A fresh process warns again — the latch is per-process, not permanent
146    /// state on disk, so a restart re-explains the misconfiguration.
147    #[test]
148    fn the_warning_latch_is_per_process() {
149        let _guard = lock();
150        reset();
151        assert!(!WARNED.load(Ordering::Relaxed));
152        record_discarded_xff(2, 4);
153        assert!(WARNED.load(Ordering::Relaxed));
154        reset();
155        assert!(
156            !WARNED.load(Ordering::Relaxed),
157            "a new process must be able to explain itself again"
158        );
159    }
160}
