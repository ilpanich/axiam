1//! Shared (cross-replica) rate-limit pre-check middleware
2//! (SECHRD-03 / D-01a, D-01b, D-01d).
3//!
4//! [`RateLimitShared`] consults the process-wide write-behind
5//! [`SharedRateLimitCounter`] (`axiam-db::rate_limit_counter`) BEFORE the
6//! existing per-replica in-memory `Governor`/`GovernorLayer`
7//! (`server.rs::build_governor`, kept byte-for-byte unchanged as the
8//! fail-open fallback). This closes the multi-replica HPA gap where
9//! per-replica in-memory buckets otherwise multiply the effective rate
10//! limit by the replica count.
11//!
12//! # No synchronous datastore write on the request path (H2 fix)
13//!
14//! This middleware used to `await` ONE SurrealDB `UPSERT`
15//! (`SurrealRateLimitBucketRepository::increment`) per request, before the
16//! handler ran. That single write capped every wrapped endpoint at **16–21
17//! ops/s at any concurrency from 1 to 40 VUs** (p50 ≈ 55–65 ms at 1 VU,
18//! ≈ 1 s at 20 VUs) while structurally identical unwrapped endpoints ran at
19//! 68–4 248 ops/s — the datastore attributed ~39–46 ms of each request to
20//! that one RPC, and the same UPSERT issued directly ran in 6–9 ms and
21//! scaled fine, so the ordering (not the datastore) was the ceiling. Full
22//! measurements: `claude_dev/postseed-transient-investigation.md` §2, §3, §7.
23//!
24//! The counting mechanism — and ONLY the counting mechanism — changed: the
25//! key derivation (`{endpoint}:{key_part}`, the D8 `client_id` modes, the
26//! body peek/restore), the 429 response shape and every fail-open branch
27//! behave exactly as before. [`SharedRateLimitCounter::check`] is fully
28//! synchronous (one sharded-map increment, no datastore round trip, no task
29//! spawn) and a single background flusher coalesces the accumulated
30//! increments into one datastore write per bucket per
31//! `AXIAM__RATE_LIMIT__SHARED_SYNC_MS`. Cross-replica enforcement is
32//! therefore *eventual*, with the overshoot bound stated precisely in the
33//! [`axiam_db::rate_limit_counter`] module docs; the in-memory governor still
34//! makes a full per-replica decision on the very same endpoints.
35//!
36//! **Fail-open (D-01b, T-24-42 accepted risk):** when no client-IP key can be
37//! derived, no [`AppState`] (hence no counter) is registered, or the shared
38//! layer is disabled via `AXIAM__RATE_LIMIT__SHARED=off`, this middleware
39//! forwards the request unchanged so the existing in-memory governor makes
40//! the decision instead. Store outages are now surfaced by the counter's
41//! flusher (a `warn` alarm that never includes the raw key — T-24-43) while
42//! decisions keep being served from local counts. A counter-store outage must
43//! never hard-block auth traffic — this is the ONE deliberate fail-open
44//! exception; every other control fails closed.
45//!
46//! **CRITICAL (RESEARCH Pitfall 1):** `governor::StateStore::measure_and_replace`
47//! is a *synchronous* trait method. This middleware is deliberately NOT a
48//! `StateStore` implementation and never calls `block_on`/`futures::executor::
49//! block_on` — it is a separate Actix `Transform`/`Service` (mirroring
50//! [`crate::middleware::authz::AuthzMiddleware`]'s scaffold). It stays async
51//! only because the D8 body peek (`req.extract::<web::Bytes>()`) is async;
52//! the rate-limit decision itself no longer awaits anything.

72/// Fixed-window duration (seconds) for the shared bucket. A simple
73/// fixed-window counter is acceptable here (unlike the in-memory GCRA
74/// governor) because this layer only needs to be *approximately* right —
75/// it fails open by design (RESEARCH.md "Don't Hand-Roll").
76const WINDOW_SECS: i64 = 60;
77
78/// Reads the SAME `AXIAM__RATE_LIMIT__TRUSTED_HOPS` env var
79/// `server.rs::build_governor` uses, so the shared-store bucket key and the
80/// in-memory governor's key are derived from the identical client IP
81/// (D-01d parity — a rotating XFF must not yield a fresh bucket in either
82/// layer).
83fn trusted_hops() -> usize {
84    std::env::var("AXIAM__RATE_LIMIT__TRUSTED_HOPS")
85        .ok()
86        .and_then(|v| v.parse().ok())
87        .unwrap_or(0)
88}
89
90/// Truncates `now` down to the start of the current fixed
91/// [`WINDOW_SECS`]-second window.
92fn window_start(now: DateTime<Utc>) -> DateTime<Utc> {
93    let epoch = now.timestamp();
94    let start_epoch = epoch - epoch.rem_euclid(WINDOW_SECS);
95    DateTime::<Utc>::from_timestamp(start_epoch, 0).unwrap_or(now)
96}
97
98/// Builds the same-shaped 429 response the in-memory governor returns
99/// (`extractors::rate_limit::XForwardedForKeyExtractor::exceed_rate_limit_response`),
100/// so clients see one consistent rate-limit contract regardless of which
101/// layer rejected the request.
102fn too_many_requests_response() -> HttpResponse {
103    HttpResponse::TooManyRequests()
104        .content_type(ContentType::json())
105        .insert_header((RETRY_AFTER, WINDOW_SECS.to_string()))
106        .body(r#"{"error":"rate_limit_exceeded"}"#)
107}

113/// Shared SurrealDB-backed rate-limit pre-check middleware.
114///
115/// Generic over the SurrealDB connection type `C` so it can be wired
116/// against both the production `DbClient` and the in-memory `Mem` engine
117/// used in tests. `endpoint` MUST be unique per rate-limited resource so
118/// the shared bucket key (`"{endpoint}:{ip}"`) preserves per-endpoint
119/// granularity — never collapse distinct endpoints into one global bucket.
120///
121/// Wire this BEFORE (i.e. `.wrap()` AFTER, since the last `.wrap()` call is
122/// the outermost layer and therefore executes first) `build_governor(...)`
123/// on the same resource, e.g.:
124///
125/// ```ignore
126/// web::resource("/login")
127///     .wrap(build_governor(rate_limit_cfg.login_per_min))
128///     .wrap(RateLimitShared::<C>::new("login", rate_limit_cfg.login_per_min))
129///     .route(web::post().to(handlers::auth::login::<C>))
130/// ```
131pub struct RateLimitShared<C: Connection + Clone> {
132    endpoint: &'static str,
133    limit: u32,
134    /// D8: bucket-key derivation mode. Always [`RateLimitKeyMode::Ip`] for
135    /// instances built via [`RateLimitShared::new`] — only
136    /// [`RateLimitShared::new_client_identity_aware`] ever sets this to
137    /// something else.
138    key_mode: RateLimitKeyMode,
139    /// D8: whether this resource has a form-encoded OAuth2 `client_id` to
140    /// peek at (`/oauth2/token`, `/oauth2/revoke`, `/oauth2/introspect`
141    /// ONLY — see [`RateLimitShared::new_client_identity_aware`]). `false`
142    /// for every other resource (including `/auth/login`), which never
143    /// touches the request body and always keys per-IP.
144    client_identity_aware: bool,
145    _marker: PhantomData<C>,
146}
147
148impl<C: Connection + Clone> RateLimitShared<C> {
149    /// Plain IP-keyed constructor — unchanged since before D8. Use this for
150    /// every endpoint EXCEPT `/oauth2/token`, `/oauth2/revoke`, and
151    /// `/oauth2/introspect`. In particular, `/auth/login` MUST keep using
152    /// this constructor: it authenticates a user via username/password, so
153    /// there is no OAuth2 `client_id` in the request to key on, and this
154    /// type never reads `AXIAM__RATE_LIMIT__KEY` for it.
155    pub fn new(endpoint: &'static str, limit: u32) -> Self {
156        Self {
157            endpoint,
158            limit,
159            key_mode: RateLimitKeyMode::Ip,
160            client_identity_aware: false,
161            _marker: PhantomData,
162        }
163    }
164
165    /// D8 constructor for the three endpoints where an OAuth2 client
166    /// authenticates itself via a form-encoded `client_id`
167    /// (`client_secret_post`, RFC 6749 §2.3.1): `/oauth2/token`,
168    /// `/oauth2/revoke`, `/oauth2/introspect`.
169    ///
170    /// When `key_mode` is [`RateLimitKeyMode::ClientId`] or
171    /// [`RateLimitKeyMode::IpClientId`], this middleware peeks (and
172    /// restores) the request body to read `client_id`, and stashes it into
173    /// the request extensions (as [`RateLimitClientId`]) so the downstream
174    /// in-memory `Governor`'s `ClientAwareKeyExtractor` on the SAME
175    /// resource can reuse it without a second body read. When `key_mode` is
176    /// [`RateLimitKeyMode::Ip`] this is exactly as if `new()` had been
177    /// called — the body is never touched.
178    ///
179    /// **Do not use this constructor for `/auth/login` or any other
180    /// endpoint without a client identity** — see
181    /// [`crate::config::rate_limit::RateLimitKeyMode`] docs.
182    pub fn new_client_identity_aware(
183        endpoint: &'static str,
184        limit: u32,
185        key_mode: RateLimitKeyMode,
186    ) -> Self {
187        Self {
188            endpoint,
189            limit,
190            key_mode,
191            client_identity_aware: true,
192            _marker: PhantomData,
193        }
194    }
195}

237pub struct RateLimitSharedService<S, C: Connection + Clone> {
238    inner: Rc<S>,
239    endpoint: &'static str,
240    limit: u32,
241    key_mode: RateLimitKeyMode,
242    client_identity_aware: bool,
243    _marker: PhantomData<C>,
244}
245
246impl<S, B, C> Service<ServiceRequest> for RateLimitSharedService<S, C>
247where
248    S: Service<ServiceRequest, Response = ServiceResponse<B>, Error = Error> + 'static,
249    B: 'static,
250    C: Connection + Clone + 'static,
251{
252    type Response = ServiceResponse<EitherBody<B>>;
253    type Error = Error;
254    type Future = std::pin::Pin<Box<dyn Future<Output = Result<Self::Response, Self::Error>>>>;
255
256    fn poll_ready(
257        &self,
258        cx: &mut std::task::Context<'_>,
259    ) -> std::task::Poll<Result<(), Self::Error>> {
260        self.inner.poll_ready(cx)
261    }
262
263    fn call(&self, mut req: ServiceRequest) -> Self::Future {
264        let endpoint = self.endpoint;
265        let limit = self.limit;
266        let key_mode = self.key_mode;
267        let client_identity_aware = self.client_identity_aware;
268        let inner = Rc::clone(&self.inner);
269
270        // Reuse the EXACT fixed IP-key extraction logic (D-01d) so the
271        // shared bucket key and the in-memory governor's key agree.
272        let extractor = XForwardedForKeyExtractor::with_trusted_hops(trusted_hops());
273        let ip = extractor.extract(&req).ok();
274
275        // The process-wide write-behind counter is read from
276        // `web::Data<AppState<C>>` (QUAL-01 — was a standalone
277        // `web::Data<Surreal<C>>` registration used to build a repository per
278        // request). Its absence is treated exactly like the old missing-DB-
279        // handle case below — fail open to the in-memory governor.
280        //
281        // This is a cheap `Arc` clone of the ONE counter registered in
282        // `main.rs`, never a new counter: a per-request (or per-worker)
283        // instance would fragment the local count.
284        let counter = req
285            .app_data::<web::Data<AppState<C>>>()
286            .map(|d| d.shared_rate_limit.clone());
287
288        Box::pin(async move {
289            // D8: for the client-identity-aware endpoints only
290            // (`/oauth2/token`, `/oauth2/revoke`, `/oauth2/introspect` —
291            // never `/auth/login`), peek the form-encoded body for
292            // `client_id` and restore the payload so the handler's
293            // `web::Form<..>` extractor still sees the full body
294            // untouched. This ALSO stashes the result into request
295            // extensions for the downstream in-memory `Governor`'s
296            // `ClientAwareKeyExtractor` to reuse (see
297            // `extractors::rate_limit::RateLimitClientId`).
298            //
299            // Skipped entirely in `ip` mode (the default) — no body read,
300            // byte-for-byte the pre-D8 code path.
301            let client_id = if client_identity_aware {
302                let client_id = if key_mode != RateLimitKeyMode::Ip {
303                    let bytes = req.extract::<web::Bytes>().await.unwrap_or_default();
304                    let client_id = extract_form_client_id(&bytes);
305                    // Restore the body EXACTLY as read so the handler's
306                    // `web::Form<..>` extraction downstream is unaffected —
307                    // this middleware must be transparent to the request.
308                    req.set_payload(Payload::from(bytes));
309                    client_id
310                } else {
311                    None
312                };
313                req.extensions_mut()
314                    .insert(RateLimitClientId(client_id.clone()));
315                client_id
316            } else {
317                None
318            };
319
320            // The bucket-key "identity" part: IP alone (`ip` mode, or
321            // fail-safe fallback when no client_id was found), the
322            // client_id alone, or the `(ip, client_id)` pair. Mirrors
323            // `extractors::rate_limit::ClientAwareKeyExtractor` exactly so
324            // this shared-store pre-check and the in-memory governor never
325            // disagree about which bucket a request belongs to.
326            let key_part = match (key_mode, &client_id) {
327                (RateLimitKeyMode::Ip, _) | (_, None) => ip.map(|ip| ip.to_string()),
328                (RateLimitKeyMode::ClientId, Some(cid)) => Some(format!("client:{cid}")),
329                (RateLimitKeyMode::IpClientId, Some(cid)) => {
330                    ip.map(|ip| format!("{ip}:client:{cid}"))
331                }
332            };
333
334            let allow = match (key_part, counter) {
335                (Some(key_part), Some(counter)) => {
336                    // Same bucket key as before — `{endpoint}:{key_part}` —
337                    // so an in-flight upgrade keeps counting against the same
338                    // `rate_limit_bucket` records.
339                    let key = format!("{endpoint}:{key_part}");
340                    let window = window_start(Utc::now());
341                    // Fully synchronous: no datastore round trip on the
342                    // request path (H2 fix). Store outages are reported by
343                    // the counter's background flusher, which keeps serving
344                    // decisions from local counts (fail open, D-01b).
345                    counter.check(&key, window, limit)
346                }
347                // No key part (IP unavailable) or no counter registered —
348                // fail open; the in-memory governor still makes the real
349                // decision. (A counter built with
350                // `AXIAM__RATE_LIMIT__SHARED=off` also always allows, from
351                // inside `check`.)
352                _ => true,
353            };
354
355            if allow {
356                let res = inner.call(req).await?;
357                Ok(res.map_into_left_body())
358            } else {
359                let res = req.into_response(too_many_requests_response());
360                Ok(res.map_into_right_body())
361            }
362        })
363    }
