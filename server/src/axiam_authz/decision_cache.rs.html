1//! Per-tenant cache of effective-permission evaluations (D7).
2//!
3//! # What this caches
4//!
5//! A [`DecisionCache`] memoizes the full [`AccessDecision`] (Allow, or Deny
6//! *with its exact reason*) for a `(tenant_id, subject, resource, action,
7//! scope)` tuple, so a repeated check can skip the 3–4 sequential SurrealDB
8//! round-trips the engine would otherwise issue (see the D6 tuning report).
9//!
10//! The cache is **opt-in** and feature-flagged: [`AuthorizationEngine`] only
11//! consults it when one has been attached via
12//! [`AuthorizationEngine::with_decision_cache`], which `axiam-server` does only
13//! when `AXIAM__AUTHZ__DECISION_CACHE_ENABLED=true`. When absent, the engine's
14//! code path is byte-for-byte identical to today (zero behaviour change).
15//!
16//! [`AuthorizationEngine`]: crate::engine::AuthorizationEngine
17//! [`AuthorizationEngine::with_decision_cache`]: crate::engine::AuthorizationEngine::with_decision_cache
18//!
19//! # Security property (CRITICAL — read before changing invalidation)
20//!
21//! AXIAM's RBAC is **default-deny with deny-override**: an absent grant
22//! refuses, an `effect: Allow` grant permits, and an `effect: Deny` grant
23//! refuses and **beats every allow**, at any depth of the hierarchy (CLAUDE.md;
24//! SEC-040 closed by B1; precedence table in
25//! `claude_dev/deny-override-design.md`).
26//!
27//! The two staleness directions are still NOT equally dangerous, but note *why*
28//! — the reason changed when B1 landed and the distinction matters below:
29//!
30//! - A **stale DENY** is *safe* because a deny is the restrictive outcome: the
31//!   subject is momentarily under-privileged, never over-privileged. (Before
32//!   B1 this was phrased as a consequence of the engine being allow-wins. It is
33//!   not — it follows from deny being restrictive, which is why it survived
34//!   the change.)
35//! - A **stale ALLOW** is *dangerous*: a subject keeps access they no longer
36//!   have. This is the direction we must protect against, and TTL alone is not
37//!   enough.
38//!
39//! ## What B1 changed about which mutations need a hook
40//!
41//! Under the pre-B1 additive model, "narrowing" and "removing" were the same
42//! set: **adding** a grant could only ever widen, so an addition was safe to
43//! leave stale. That is no longer true. Granting a role an `effect: Deny`
44//! permission is an *addition* that **narrows**, and a cached allow that
45//! outlives it is a subject exercising access an administrator has explicitly
46//! forbidden.
47//!
48//! **Do not reintroduce the "additions are safe, skip the flush" optimisation.**
49//! It was sound under allow-wins and is a privilege bug under deny-override.
50//! `permissions::grant_to_role` flushes the tenant for exactly this reason and
51//! says so at the call site.
52//!
53//! Every mutation that can narrow access — role unassignment, grant removal,
54//! role/permission deletion, group membership removal, resource
55//! reparent/delete, **and any grant whose effect is `Deny`** — MUST invalidate
56//! the affected entries **immediately** via
57//! [`DecisionCache::invalidate_subject`] or [`DecisionCache::invalidate_tenant`]
58//! — wired to the mutation path, not left to TTL. The REST handlers in
59//! `axiam-api-rest` do exactly this through the `AuthzChecker` trait, and in
60//! practice they invalidate on widening mutations too, which is what keeps the
61//! deny case covered rather than depending on every author classifying their
62//! mutation correctly.
63//!
64//! # Bounded staleness fallback
65//!
66//! Even if an invalidation event were somehow missed (a bug, a mutation path
67//! that forgot to call invalidate, an out-of-band DB write), the damage is
68//! **bounded by the TTL**: a stale allow can persist at most
69//! `decision_cache_ttl_secs` (default 5 s) before TTL eviction forces a fresh
70//! evaluation. The short default TTL is the belt to the invalidation hooks'
71//! braces.
72//!
73//! # SCOPE OF "IMMEDIATE": process-local by default, cross-replica when enabled
74//!
75//! `axiam-server` builds **one in-process** `Arc<DecisionCache>` and shares it
76//! across the REST, gRPC and AMQP engines of *that process*. Whether an
77//! invalidation reaches the *other* replicas depends on one switch:
78//!
79//! ## (a) `decision_cache_broadcast_enabled = false` — the default
80//!
81//! There is no cross-replica invalidation channel. Consequently:
82//!
83//! - **Single replica:** the invalidation hooks above make revocation
84//!   *immediate*; the TTL is only the fallback for a missed event.
85//! - **Two or more replicas** (the Kubernetes deployment AXIAM targets): a
86//!   revocation handled by replica A invalidates **only replica A**. Replicas
87//!   B…N keep serving the pre-revocation decision from their own caches until
88//!   their entry TTL-expires. The **worst-case revocation latency for the
89//!   deployment is therefore `decision_cache_ttl_secs` (default 5 s)**, not
90//!   zero — and it applies uniformly to `/api/v1/authz/check`, the gRPC
91//!   `CheckAccess`, AMQP async authz *and* the internal `RequirePermission`
92//!   guard on every admin endpoint, so an administrator's own privileges can
93//!   also outlive their revocation by up to the TTL on other replicas.
94//! - The failure is **silent**: a hit is byte-identical to a miss (same
95//!   decision, same deny reason) and the audit log records the decision, not
96//!   its provenance. Post-incident it is not possible to tell from the logs
97//!   whether a given allow was served from cache.
98//!
99//! Operators running more than one replica must either enable the broadcast
100//! channel below, accept a ≤ TTL revocation window, or leave the cache off.
101//!
102//! ## (b) `decision_cache_broadcast_enabled = true` — cross-replica fan-out
103//!
104//! Every [`DecisionCache::invalidate_tenant`] /
105//! [`DecisionCache::invalidate_subject`] triggered by a mutation is *also*
106//! published, HMAC-signed, to a **RabbitMQ fanout exchange**; every replica
107//! binds its own exclusive auto-delete queue to that exchange and applies what
108//! it receives. Revocation then propagates in broker-latency time on **every**
109//! replica, not just the one that handled the mutation. See
110//! [`crate::invalidation`] for the contract and
111//! `axiam-amqp::cache_invalidation` for the shipped transport.
112//!
113//! Two properties of that mode are load-bearing and live in *this* type:
114//!
115//! 1. **The trust gate** ([`DecisionCache::set_trusted`]). A replica may only
116//!    serve from this cache while it is actually receiving invalidations. If
117//!    its consumer is not subscribed — at startup, or after the broker
118//!    connection drops — the cache is marked **untrusted**: it is flushed,
119//!    every read returns a miss and every write is discarded, so the replica
120//!    silently falls back to full (correct, slower) DB evaluation instead of
121//!    serving allows it can no longer invalidate. This is a deliberate
122//!    availability/correctness trade: throughput degrades, decisions do not.
123//!    The transition is logged at ERROR and counted in
124//!    [`DecisionCacheStats::bypassed`] — the degraded mode is loud.
125//! 2. **Trust follows connection liveness only.** Nothing an inbound *message*
126//!    says can revoke trust (a stale or replayed but validly-signed capture
127//!    must not become a lever for disabling every replica's cache). Only the
128//!    consumer's own subscribe/stream state moves the flag.
129//!
130//! The publish side fails the other way: if the broadcast cannot be confirmed
131//! by the broker, the mutation handler returns 503 rather than reporting a
132//! revocation that only took effect on one replica.
133//!
134//! This split is stated next to the default in `docs/deployment/README.md`,
135//! `docs/admin/README.md`, the [`crate::config::AuthzConfig`] docstrings and
136//! `benchmarks/PUBLIC_BENCH_ANALYSIS.md`.
137//!
138//! # Internal structure (and why)
139//!
140//! ```text
141//! stripes: [Mutex<HashMap<TenantId, TenantShard>>; STRIPE_COUNT]   // lock striping
142//!                                     │
143//!                                     ├── entries:    HashMap<Arc<SubKey>, Entry>
144//!                                     ├── order:      VecDeque<(seq, Arc<SubKey>)>  // FIFO cap
145//!                                     └── by_subject: HashMap<SubjectId, HashSet<Arc<SubKey>>>
146//! ```
147//!
148//! Three properties this layout buys, each fixing a defect found in the G5
149//! decision review (`claude_dev/decision-cache-decision.md` §2.5):
150//!
151//! 1. **`order` is bounded** (§2.5 finding *a*). A TTL-expired key is removed
152//!    from `entries` on read but its `order` slot cannot be found and removed
153//!    in O(1); the pre-fix code therefore appended a *second* slot when the key
154//!    was re-inserted, and only ever popped slots when `entries.len()` exceeded
155//!    the per-tenant cap — so a working set *below* the cap grew `order`
156//!    without limit at the miss rate. Each slot now carries the entry's
157//!    monotonic `seq`, which makes a superseded slot recognisable, and
158//!    [`TenantShard::compact_if_needed`] rebuilds the queue whenever it exceeds
159//!    `max(2 × entries.len(), COMPACT_FLOOR)`. That bounds `order` at ~2× the
160//!    live set (and ≤ ~2× `max_entries_per_tenant`) while staying O(1)
161//!    amortised: each compaction halves the queue, so the O(n) pass is paid at
162//!    most once per n inserts.
163//! 2. **`invalidate_subject` is O(entries for that subject)** (§2.5 finding
164//!    *c*), not O(shard). The `by_subject` index gives the affected keys
165//!    directly, so a role unassignment no longer scans up to
166//!    `max_entries_per_tenant` entries while holding a lock the authz hot path
167//!    needs. The index shares its keys with `entries` via `Arc<SubKey>`, so it
168//!    costs one pointer per entry, not a second copy of the key.
169//! 3. **Lock striping**: the map of tenants is split over `STRIPE_COUNT`
170//!    independent mutexes keyed by `tenant_id`, so one tenant's invalidation or
171//!    eviction no longer blocks *every* other tenant's checks — the pre-fix
172//!    code took a single global mutex on every `get`/`insert`. A tenant's shard
173//!    lives entirely within one stripe, which keeps the per-tenant FIFO cap
174//!    exact (an intra-tenant striping would only be able to enforce the cap
175//!    approximately). Contention *within* one tenant is therefore unchanged and
176//!    remains the honest limit of this design: a single-tenant deployment still
177//!    serialises its cache accesses, which is why the K-sweep in the decision
178//!    note measures cache-ON/OFF rather than assuming a win.

190/// Number of independent tenant-map mutexes. Fixed (not CPU-derived) so the
191/// structure is deterministic across hosts and reproducible in benchmarks.
192const STRIPE_COUNT: usize = 16;
193
194/// Minimum queue length below which compaction is not worth its O(n) pass.
195/// Keeps tiny tenants from compacting on every other insert.
196const COMPACT_FLOOR: usize = 64;
197
198/// Runtime configuration for the decision cache.
199#[derive(Debug, Clone)]
200pub struct DecisionCacheConfig {
201    /// Time-to-live for a cached decision. After this elapses the entry is
202    /// treated as a miss and re-evaluated. Bounds worst-case revocation
203    /// latency if an invalidation event is ever missed — and, in a
204    /// multi-replica deployment, bounds it on every replica that did not
205    /// handle the mutation (see the module docs).
206    pub ttl: Duration,
207    /// Maximum number of live entries retained **per tenant**. When exceeded,
208    /// the oldest entry (FIFO) for that tenant is evicted. Bounds memory so a
209    /// hot tenant cannot grow the map without limit.
210    pub max_entries_per_tenant: usize,
211}
212
213impl Default for DecisionCacheConfig {
214    fn default() -> Self {
215        Self {
216            ttl: Duration::from_secs(5),
217            max_entries_per_tenant: 10_000,
218        }
219    }
220}

222/// The intra-tenant portion of the cache key: everything except `tenant_id`
223/// (which selects the shard). Ordering mirrors the design-doc key
224/// `(subject, resource, action, scope)`.
225#[derive(Clone, PartialEq, Eq, Hash, Debug)]
226struct SubKey {
227    subject_id: Uuid,
228    /// Whose grants answered, and how far they reached.
229    ///
230    /// Part of the key because it is part of the question. The same subject
231    /// asking about the same resource gets a different answer depending on
232    /// whether its grants came from this tenant or from the organization
233    /// tenant, since only global grants cross that boundary. A subject's home
234    /// tenant is in practice a fixed property of the subject, so this rarely
235    /// distinguishes two live keys — it is here so that correctness does not
236    /// *depend* on that being true, which is the sort of invariant that holds
237    /// until someone adds a feature.
238    subject_scope: SubjectScope,
239    resource_id: Uuid,
240    action: String,
241    scope: Option<String>,
242}
243
244impl SubKey {
245    fn from_request(request: &AccessRequest) -> Self {
246        Self {
247            subject_id: request.subject_id,
248            subject_scope: request.subject_scope,
249            resource_id: request.resource_id,
250            action: request.action.clone(),
251            scope: request.scope.clone(),
252        }
253    }
254}

256/// A cached decision plus the metadata needed for TTL and FIFO bookkeeping.
257struct Entry {
258    decision: AccessDecision,
259    inserted_at: Instant,
260    /// Monotonic per-tenant insertion sequence. A queue slot is *live* only if
261    /// its `seq` still matches the entry's; anything else is a superseded slot
262    /// left behind by TTL expiry or invalidation and is dropped on compaction.
263    seq: u64,
264}
265
266/// Observable counters for one point in time. Cheap to produce; intended for a
267/// periodic log line or a metrics gauge, and used by the tests that assert the
268/// cache really holds `max_entries_per_tenant` entries rather than silently
269/// evicting.
270#[derive(Debug, Clone, Copy, PartialEq, Eq)]
271pub struct DecisionCacheStats {
272    /// Cumulative hits since construction.
273    pub hits: u64,
274    /// Cumulative misses since construction (includes TTL-expired reads).
275    pub misses: u64,
276    /// Live entries across every tenant (counts expired-but-not-yet-reaped
277    /// entries, which are never *returned*).
278    pub entries: usize,
279    /// Tenants with at least one shard allocated.
280    pub tenants: usize,
281    /// Total FIFO queue slots across every tenant — the quantity that used to
282    /// grow without bound. Expect ≤ ~2× `entries` (or `COMPACT_FLOOR`).
283    pub queue_slots: usize,
284    /// Cumulative reads short-circuited because the cache was **untrusted**
285    /// (cross-replica invalidation enabled but this replica's consumer is not
286    /// subscribed — see [`DecisionCache::set_trusted`]). These are also counted
287    /// in `misses`, so `hits + misses` still equals total reads; `bypassed` is
288    /// the subset that was refused rather than looked up. A non-zero and
289    /// *rising* value means this replica is evaluating everything against the
290    /// database because it cannot hear invalidations — the degraded mode is
291    /// correct but slow, and this is the counter that says so.
292    pub bypassed: u64,
293    /// Whether the cache is currently trusted (i.e. actually serving). Always
294    /// `true` when cross-replica invalidation is disabled.
295    pub trusted: bool,
296}

298/// Per-tenant shard: the entry map, the FIFO order queue used for the size-cap
299/// eviction, and the subject index used for targeted invalidation. Keeping
300/// tenants in separate shards makes a per-tenant flush O(1) (drop the shard)
301/// and keeps one tenant's churn from evicting another tenant's entries.
302#[derive(Default)]
303struct TenantShard {
304    entries: HashMap<Arc<SubKey>, Entry>,
305    /// Insertion order of *new* keys, for the bounded-size FIFO eviction. May
306    /// hold superseded slots (TTL-expired or invalidated keys); those are
307    /// recognised by a `seq` mismatch and dropped when popping or compacting.
308    order: VecDeque<(u64, Arc<SubKey>)>,
309    /// subject_id → its keys. Makes `invalidate_subject` proportional to the
310    /// subject's own entries instead of the whole shard.
311    by_subject: HashMap<Uuid, HashSet<Arc<SubKey>>>,
312    next_seq: u64,
313}
314
315impl TenantShard {
316    /// Read, honouring TTL. An expired entry is reaped in passing so it cannot
317    /// be returned again.
318    fn get(&mut self, key: &SubKey, now: Instant, ttl: Duration) -> Option<AccessDecision> {
319        match self.entries.get(key) {
320            Some(entry) if now.duration_since(entry.inserted_at) < ttl => {
321                Some(entry.decision.clone())
322            }
323            Some(_) => {
324                self.remove_entry(key);
325                None
326            }
327            None => None,
328        }
329    }
330
331    /// Remove a key from `entries` and the subject index. Its FIFO slot is left
332    /// behind (it cannot be located in O(1)) and is reclaimed by compaction.
333    fn remove_entry(&mut self, key: &SubKey) {
334        if let Some((arc, _)) = self.entries.remove_entry(key) {
335            self.unindex(&arc);
336        }
337    }
338
339    fn unindex(&mut self, key: &Arc<SubKey>) {
340        if let Some(set) = self.by_subject.get_mut(&key.subject_id) {
341            set.remove(key);
342            if set.is_empty() {
343                self.by_subject.remove(&key.subject_id);
344            }
345        }
346    }
347
348    fn insert(
349        &mut self,
350        key: &SubKey,
351        decision: AccessDecision,
352        now: Instant,
353        cfg: &DecisionCacheConfig,
354    ) {
355        // Re-insert of a still-present key: refresh value and timestamp in
356        // place. It keeps its FIFO slot and `seq`, so no new slot is pushed —
357        // this is the case the pre-fix code already handled correctly.
358        if let Some(entry) = self.entries.get_mut(key) {
359            entry.decision = decision;
360            entry.inserted_at = now;
361            return;
362        }
363
364        let seq = self.next_seq;
365        self.next_seq = self.next_seq.wrapping_add(1);
366        let arc: Arc<SubKey> = Arc::new(key.clone());
367        self.entries.insert(
368            Arc::clone(&arc),
369            Entry {
370                decision,
371                inserted_at: now,
372                seq,
373            },
374        );
375        self.by_subject
376            .entry(arc.subject_id)
377            .or_default()
378            .insert(Arc::clone(&arc));
379        self.order.push_back((seq, arc));
380
381        // Enforce the per-tenant size cap: pop FIFO, skipping superseded slots,
382        // until one *live* entry has been dropped or the queue drains.
383        while self.entries.len() > cfg.max_entries_per_tenant {
384            match self.order.pop_front() {
385                Some((slot_seq, victim)) => {
386                    if self.entries.get(&*victim).map(|e| e.seq) == Some(slot_seq) {
387                        self.entries.remove(&*victim);
388                        self.unindex(&victim);
389                        break;
390                    }
391                    // else: superseded slot, keep popping.
392                }
393                None => break,
394            }
395        }
396
397        self.compact_if_needed(now, cfg);
398    }
399
400    /// Reclaim superseded FIFO slots (and TTL-expired entries) once the queue
401    /// has grown past ~2× the live set. Amortised O(1) per insert: a compaction
402    /// leaves `order.len() == entries.len()`, so the next one cannot trigger
403    /// until roughly `entries.len()` further inserts.
404    ///
405    /// This is the fix for the unbounded-`order` growth described in the module
406    /// docs; without it a working set below `max_entries_per_tenant` never runs
407    /// the cap loop and the queue grows at the miss rate, forever.
408    fn compact_if_needed(&mut self, now: Instant, cfg: &DecisionCacheConfig) {
409        let threshold = COMPACT_FLOOR.max(self.entries.len().saturating_mul(2));
410        if self.order.len() <= threshold {
411            return;
412        }
413
414        // Expired entries are already logically absent (a read would reap
415        // them); drop them here so the live set — and therefore the queue
416        // bound — reflects reality even for keys never read again.
417        let expired: Vec<Arc<SubKey>> = self
418            .entries
419            .iter()
420            .filter(|(_, e)| now.duration_since(e.inserted_at) >= cfg.ttl)
421            .map(|(k, _)| Arc::clone(k))
422            .collect();
423        for key in expired {
424            self.entries.remove(&*key);
425            self.unindex(&key);
426        }
427
428        let Self { entries, order, .. } = self;
429        order.retain(|(slot_seq, key)| entries.get(&**key).map(|e| e.seq) == Some(*slot_seq));
430    }
431
432    /// Drop every entry for one subject. O(that subject's entries).
433    fn invalidate_subject(&mut self, subject_id: Uuid) {
434        if let Some(keys) = self.by_subject.remove(&subject_id) {
435            for key in keys {
436                self.entries.remove(&*key);
437                // FIFO slots become superseded; compaction reclaims them.
438            }
439        }
440    }
441}

443/// A concurrent, per-tenant, TTL + size-bounded cache of authorization
444/// decisions. Cheap to clone-share behind an `Arc`.
445///
446/// See the [module docs](self) for the security rationale, the multi-replica
447/// caveat and the internal structure.
448pub struct DecisionCache {
449    config: DecisionCacheConfig,
450    /// Tenants split over independent mutexes; a tenant always lives in
451    /// `stripes[stripe_index(tenant_id)]`.
452    stripes: Vec<Mutex<HashMap<Uuid, TenantShard>>>,
453    hits: AtomicU64,
454    misses: AtomicU64,
455    bypassed: AtomicU64,
456    /// Whether this replica may serve from the cache at all. See
457    /// [`Self::set_trusted`]; always `true` unless cross-replica invalidation
458    /// is enabled and its consumer is disconnected.
459    trusted: AtomicBool,
460}
461
462impl DecisionCache {
463    /// Build a cache with the given configuration, **trusted** (the
464    /// single-process behaviour: nothing else has to happen for it to serve).
465    ///
466    /// When cross-replica invalidation is enabled, `axiam-server` immediately
467    /// calls `set_trusted(false)` on the fresh cache so it stays inert until
468    /// the invalidation consumer has actually subscribed — see
469    /// [`crate::config::AuthzConfig::build_decision_cache`].
470    pub fn new(config: DecisionCacheConfig) -> Self {
471        Self {
472            config,
473            stripes: (0..STRIPE_COUNT)
474                .map(|_| Mutex::new(HashMap::new()))
475                .collect(),
476            hits: AtomicU64::new(0),
477            misses: AtomicU64::new(0),
478            bypassed: AtomicU64::new(0),
479            trusted: AtomicBool::new(true),
480        }
481    }
482
483    /// Whether the cache is currently allowed to serve.
484    pub fn is_trusted(&self) -> bool {
485        self.trusted.load(Ordering::Acquire)
486    }
487
488    /// Mark the cache trusted / untrusted, returning the **previous** value.
489    ///
490    /// This is the cross-replica degraded-mode switch (see the module docs).
491    /// Only the invalidation consumer's own connection state may call it:
492    /// `true` once it is subscribed and receiving, `false` the moment it is
493    /// not (startup, subscribe failure, stream end, task drop).
494    ///
495    /// While untrusted:
496    /// * [`Self::get`] returns `None` for every request and counts a
497    ///   [`DecisionCacheStats::bypassed`] read, so the engine falls back to a
498    ///   full database evaluation — correct, just slower. It never serves an
499    ///   allow it can no longer invalidate.
500    /// * [`Self::insert`] discards, so nothing accumulates during the outage
501    ///   that would have to be reasoned about on recovery.
502    ///
503    /// **Every transition flushes the cache**, in both directions: entering
504    /// the untrusted state drops decisions that may already be stale, and
505    /// leaving it drops anything that could have been invalidated by a
506    /// broadcast we were not there to receive. Recovery therefore starts from
507    /// an empty, provably-fresh cache rather than from whatever survived.
508    ///
509    /// Transitions are logged (ERROR on losing trust, INFO on regaining it) —
510    /// a silently-degraded cache would be exactly the failure this whole
511    /// mechanism exists to prevent.
512    pub fn set_trusted(&self, trusted: bool) -> bool {
513        let previous = self.trusted.swap(trusted, Ordering::AcqRel);
514        if previous == trusted {
515            return previous;
516        }
517        // Flush on BOTH edges — see the doc comment.
518        self.invalidate_all();
519        if trusted {
520            tracing::info!(
521                "AuthZ decision cache TRUSTED again — cross-replica invalidation stream is live; \
522                 cache flushed and re-enabled"
523            );
524        } else {
525            tracing::error!(
526                "AuthZ decision cache UNTRUSTED — cross-replica invalidation stream is NOT live; \
527                 cache flushed and every check now falls back to full database evaluation \
528                 (correct but slower) until the stream recovers"
529            );
530        }
531        previous
532    }
533
534    /// Which mutex owns a tenant. UUIDv4 bytes are already uniformly
535    /// distributed, so folding the halves is sufficient dispersion and costs
536    /// nothing on the hot path.
537    fn stripe_index(&self, tenant_id: Uuid) -> usize {
538        let bits = tenant_id.as_u128();
539        let folded = (bits as u64) ^ ((bits >> 64) as u64);
540        (folded % STRIPE_COUNT as u64) as usize
541    }
542
543    fn stripe(&self, tenant_id: Uuid) -> std::sync::MutexGuard<'_, HashMap<Uuid, TenantShard>> {
544        self.stripes[self.stripe_index(tenant_id)]
545            .lock()
546            .unwrap_or_else(|p| p.into_inner())
547    }
548
549    /// Look up a cached decision for `request`. Returns `None` on a miss or an
550    /// expired entry (which is evicted in passing). Records a hit/miss.
551    ///
552    /// Returns `None` unconditionally while the cache is **untrusted** (see
553    /// [`Self::set_trusted`]), counting the read as both a miss and a
554    /// [`DecisionCacheStats::bypassed`].
555    pub fn get(&self, request: &AccessRequest) -> Option<AccessDecision> {
556        if !self.is_trusted() {
557            self.bypassed.fetch_add(1, Ordering::Relaxed);
558            self.misses.fetch_add(1, Ordering::Relaxed);
559            return None;
560        }
561        let key = SubKey::from_request(request);
562        let now = Instant::now();
563        let decision = {
564            let mut stripe = self.stripe(request.tenant_id);
565            stripe
566                .get_mut(&request.tenant_id)
567                .and_then(|shard| shard.get(&key, now, self.config.ttl))
568        };
569        if decision.is_some() {
570            self.hits.fetch_add(1, Ordering::Relaxed);
571        } else {
572            self.misses.fetch_add(1, Ordering::Relaxed);
573        }
574        decision
575    }
576
577    /// Insert (or refresh) the decision for `request`, stamping it `now`.
578    ///
579    /// Discarded while the cache is **untrusted** (see [`Self::set_trusted`]),
580    /// so an outage cannot accumulate entries whose freshness nobody can
581    /// vouch for.
582    pub fn insert(&self, request: &AccessRequest, decision: AccessDecision) {
583        if !self.is_trusted() {
584            return;
585        }
586        let key = SubKey::from_request(request);
587        let now = Instant::now();
588        let mut stripe = self.stripe(request.tenant_id);
589        stripe
590            .entry(request.tenant_id)
591            .or_default()
592            .insert(&key, decision, now, &self.config);
593    }
594
595    /// Drop **every** cached decision for a tenant. The conservative,
596    /// always-correct invalidation: after this, no decision for `tenant_id`
597    /// can be served stale. Used for coarse mutations whose affected-subject
598    /// set is not known without a DB query (grant revoke, role/permission
599    /// delete, role/permission update, group-role unassignment, resource
600    /// reparent/delete).
601    pub fn invalidate_tenant(&self, tenant_id: Uuid) {
602        let mut stripe = self.stripe(tenant_id);
603        stripe.remove(&tenant_id);
604    }
605
606    /// Drop every cached decision for a single subject within a tenant. The
607    /// targeted invalidation used when a mutation changes exactly one
608    /// subject's effective permissions (user role unassignment, group
609    /// membership removal) — see the module security note.
610    ///
611    /// Cost is proportional to **that subject's** cached entries (via the
612    /// `by_subject` index), not to the tenant shard, and it holds only the
613    /// stripe that owns `tenant_id` — other tenants' checks are unaffected.
614    pub fn invalidate_subject(&self, _tenant_id: Uuid, subject_id: Uuid) {
615        // Every shard, not the one named.
616        //
617        // Shards are keyed by the tenant a decision was *about*, and an
618        // organization-level principal accumulates decisions in every tenant it
619        // touches while its roles live in exactly one — the organization
620        // tenant. A handler revoking such a role calls this with the tenant the
621        // mutation happened in, so clearing only that shard would leave a
622        // freshly revoked administrator holding cached allows in every other
623        // tenant until the TTL expired. Revocation that is correct for
624        // ordinary principals and silently late for privileged ones is the
625        // wrong way round.
626        //
627        // Sweeping is not over-invalidation: a subject id is unique across the
628        // deployment, so this removes exactly that subject's entries wherever
629        // they are. Cost is bounded by the `by_subject` index in each shard,
630        // and role mutations are not a hot path.
631        //
632        // `_tenant_id` is kept in the signature because ~20 call sites pass it
633        // and it still says which tenant the mutation happened in, which is
634        // worth keeping legible at those call sites even though the sweep no
635        // longer needs it.
636        for stripe in &self.stripes {
637            let mut guard = stripe.lock().unwrap_or_else(|p| p.into_inner());
638            for shard in guard.values_mut() {
639                shard.invalidate_subject(subject_id);
640            }
641        }
642    }
643
644    /// Drop the entire cache (all tenants). Provided for completeness /
645    /// administrative flush; not on any hot path.
646    pub fn invalidate_all(&self) {
647        for stripe in &self.stripes {
648            stripe.lock().unwrap_or_else(|p| p.into_inner()).clear();
649        }
650    }

652    /// Cumulative (hits, misses) since construction — for observability/tests.
653    pub fn stats(&self) -> (u64, u64) {
654        (
655            self.hits.load(Ordering::Relaxed),
656            self.misses.load(Ordering::Relaxed),
657        )
658    }

660    /// A full counter snapshot, including the live entry count and the FIFO
661    /// queue length. `axiam-server` logs this periodically when the cache is
662    /// enabled so an operator (or a benchmark) can verify how many entries the
663    /// cache actually holds — the pre-fix code exposed no way to tell a full
664    /// cache from one that was silently evicting.
665    pub fn snapshot(&self) -> DecisionCacheStats {
666        let (hits, misses) = self.stats();
667        let mut entries = 0usize;
668        let mut tenants = 0usize;
669        let mut queue_slots = 0usize;
670        for stripe in &self.stripes {
671            let guard = stripe.lock().unwrap_or_else(|p| p.into_inner());
672            tenants += guard.len();
673            for shard in guard.values() {
674                entries += shard.entries.len();
675                queue_slots += shard.order.len();
676            }
677        }
678        DecisionCacheStats {
679            hits,
680            misses,
681            entries,
682            tenants,
683            queue_slots,
684            bypassed: self.bypassed.load(Ordering::Relaxed),
685            trusted: self.is_trusted(),
686        }
687    }
688
689    /// Total live entries across all tenants (test/observability helper; also
690    /// counts not-yet-reaped expired entries).
691    pub fn len(&self) -> usize {
692        self.snapshot().entries
693    }
694
695    /// Live entries for one tenant.
696    pub fn tenant_len(&self, tenant_id: Uuid) -> usize {
697        self.stripe(tenant_id)
698            .get(&tenant_id)
699            .map(|s| s.entries.len())
700            .unwrap_or(0)
701    }
702
703    /// Whether the cache holds no entries.
704    pub fn is_empty(&self) -> bool {
705        self.len() == 0
706    }

1022        // steady state at all. This measures the cache alone: RSS delta across

1028            let resident_pages: u64 = statm.split_whitespace().nth(1)?.parse().ok()?;
1029            Some(resident_pages * 4) // 4 KiB pages on every supported target
1030        }

1032            eprintln!("skipping: /proc/self/statm unavailable on this platform");
1033            return;
1034        };
1035
1036        let cfg = DecisionCacheConfig::default();
1037        let cap = cfg.max_entries_per_tenant;
1038        let cache = DecisionCache::new(DecisionCacheConfig {
1039            ttl: Duration::from_secs(600),
1040            ..cfg
1041        });

1043        let s = Uuid::new_v4();
1044        for i in 0..cap {
1045            cache.insert(

1048            );
1049        }
1050        let after = rss_kib().expect("statm readable a second time");
1051        let snap = cache.snapshot();
1052        // Order-independent invariants — these are what the K=10 000 memory
1053        // column was supposed to establish and could not: the cache really
1054        // holds its full cap (no silent eviction), and the FIFO queue carries
1055        // no duplicate slots.
1056        assert_eq!(snap.entries, cap, "the cap must be genuinely held");
1057        assert_eq!(

1059            "one queue slot per live entry, no duplicates"

1063        eprintln!(

1072        // has to refute "10 000 cached decisions cost hundreds of MiB". The

1074        assert!(

1076            "10 000 cached decisions must not cost 32 MiB (measured {delta_kib} KiB)"
1077        );
1078    }

1151    /// Concurrency smoke test: the striped structure must stay consistent under
1152    /// simultaneous readers, writers and invalidators.
1153    #[test]
1154    fn concurrent_access_is_consistent() {
1155        let cache = Arc::new(DecisionCache::new(DecisionCacheConfig {
1156            ttl: Duration::from_millis(20),
1157            max_entries_per_tenant: 500,
1158        }));
1159        let tenants: Vec<Uuid> = (0..4).map(|_| Uuid::new_v4()).collect();
1160        let subjects: Vec<Uuid> = (0..8).map(|_| Uuid::new_v4()).collect();
1161
1162        let handles: Vec<_> = (0..8)
1163            .map(|worker| {
1164                let cache = Arc::clone(&cache);
1165                let tenants = tenants.clone();
1166                let subjects = subjects.clone();
1167                std::thread::spawn(move || {
1168                    for i in 0..500 {
1169                        let t = tenants[i % tenants.len()];
1170                        let s = subjects[(i + worker) % subjects.len()];
1171                        let r = req(t, s, Uuid::new_v4(), "read");
1172                        cache.insert(&r, AccessDecision::Allow);
1173                        let _ = cache.get(&r);
1174                        if i % 97 == 0 {
1175                            cache.invalidate_subject(t, s);
1176                        }
1177                        if i % 251 == 0 {
1178                            cache.invalidate_tenant(t);
1179                        }
1180                    }
1181                })
1182            })
1183            .collect();
1184        for h in handles {
1185            h.join().expect("worker panicked");
1186        }
1187
1188        let snap = cache.snapshot();
1189        for t in &tenants {
1190            assert!(cache.tenant_len(*t) <= 500, "per-tenant cap must hold");
1191        }
1192        // Per tenant the queue is bounded by ~2x the cap (plus the floor);
1193        // 8 workers x 500 iterations = 4 000 inserts would otherwise pile up.
1194        assert!(
1195            snap.queue_slots <= tenants.len() * (2 * 500 + COMPACT_FLOOR),
1196            "queue slots {} unbounded relative to {} entries",
1197            snap.queue_slots,
1198            snap.entries
1199        );
