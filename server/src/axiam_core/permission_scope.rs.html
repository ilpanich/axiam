1//! Which permission actions act on the **organization** rather than on a
2//! tenant.
3//!
4//! # Why this list exists
5//!
6//! AXIAM's tenants are isolation boundaries; an organization contains them.
7//! A handful of actions operate on the organization itself — minting the CA
8//! material every tenant's certificates chain to, deciding what may
9//! authenticate against the whole deployment, creating and destroying the
10//! tenants themselves. Those are not a tenant administrator's to perform, and
11//! [`Tenant::is_organization_scope`](crate::models::tenant::Tenant::is_organization_scope)
12//! is the property that says who may.
13//!
14//! Two independent layers enforce that, and this list is what keeps them
15//! talking about the same set of actions:
16//!
17//! 1. **The scope guard** (`axiam-api-rest`'s `require_organization_principal`)
18//!    refuses a caller whose own record does not live in the organization
19//!    scope. It is the load-bearing half: it holds whatever permissions a role
20//!    happens to carry, because where a principal lives is a row it cannot
21//!    edit.
22//! 2. **The seeder** (`axiam-db`'s `seed_default_roles` /
23//!    `reconcile_default_role_grants`) withholds these actions from an ordinary
24//!    tenant's seeded roles, so the grant is not there to be relied on in the
25//!    first place.
26//!
27//! Layer 2 alone would be insufficient — a permission is a value in a registry,
28//! and the very route that seeds roles could grant it again. Layer 1 alone was
29//! what shipped, and it works; this list adds the second so the two agree
30//! rather than one quietly contradicting the other.
31//!
32//! # Adding an action here
33//!
34//! Adding an action to this list **withholds it from every ordinary tenant's
35//! seeded roles**, and `reconcile_default_role_grants` will revoke it from
36//! tenants that already hold it. Add one only together with the
37//! `require_organization_principal` guard on the handler it names — the two are
38//! asserted to agree by `organization_level_actions_match_the_guarded_handlers`
39//! in `axiam-api-rest`, which reads the handler sources rather than trusting
40//! this comment.
41//!
42//! # What is deliberately *not* here
43//!
44//! `email_config:write` guards both `/organizations/{id}/email-config` and
45//! `/tenants/{id}/email-config`. A tenant administrator configuring its own
46//! tenant's mail is exactly the thing a tenant administrator should do, so the
47//! action stays grantable and the organization half is protected by the scope
48//! guard alone. An action shared between the two levels cannot be withheld
49//! without taking the tenant-level capability with it.
50//!
51//! Read actions (`organizations:list`, `organizations:get`, `tenants:list`,
52//! `ca_certificates:list`, …) are absent for the same reason they are absent
53//! from the scope guard: the tenant switcher needs them and they leak nothing
54//! across the boundary.
55
56/// Every permission action that may only be exercised by an organization-level
57/// principal.
58///
59/// Withheld from the seeded `super-admin` and `admin` roles of an ordinary
60/// (`TenantKind::Standard`) tenant. The organization's own scope keeps them.
61///
62/// The `viewer` role is unaffected by construction: it is seeded only with
63/// actions ending in `:list` or `:get`, and every action here is a mutation.
64pub const ORGANIZATION_LEVEL_ACTIONS: &[&str] = &[
65    // The organization itself. `POST /api/v1/organizations` has no
66    // organization in its path to bind against at all, which is why the scope
67    // of the *caller* is the only thing that can gate it.
68    "organizations:create",
69    "organizations:update",
70    "organizations:delete",
71    // The tenants an organization contains. A tenant administrator creating
72    // sibling tenants — or deleting one — is acting outside its own boundary
73    // by definition.
74    "tenants:create",
75    "tenants:update",
76    "tenants:delete",
77    // Organization CA material. `ca_certificates:manage` covers the mTLS
78    // trust-anchor flag, which decides what client certificates authenticate
79    // against the entire deployment; a tenant administrator holding both that
80    // flag and the CA's private key could mint certificates authenticating as
81    // principals in sibling tenants. This is the row that made B-04 a
82    // high-severity finding rather than an untidiness.
83    "ca_certificates:generate",
84    "ca_certificates:revoke",
85    "ca_certificates:manage",
86];
87
88/// Whether `action` may only be exercised by an organization-level principal.
89///
90/// A linear scan over a list this short is cheaper than any structure that
91/// would need building first, and the seeder calls it once per permission per
92/// tenant at startup.
93pub fn is_organization_level_action(action: &str) -> bool {
94    ORGANIZATION_LEVEL_ACTIONS.contains(&action)
95}

97#[cfg(test)]
98mod tests {
99    use super::*;
100
101    #[test]
102    fn the_list_holds_no_read_action() {
103        // The `viewer` role is seeded with `:list`/`:get` actions and is
104        // deliberately not filtered against this list. If a read action ever
105        // lands here, viewer would silently keep a grant the other two roles
106        // lost — so the assumption is pinned rather than commented.
107        for action in ORGANIZATION_LEVEL_ACTIONS {
108            assert!(
109                !action.ends_with(":list") && !action.ends_with(":get"),
110                "{action} is a read action; the viewer role is not filtered \
111                 against this list, so adding one here would make the roles \
112                 disagree"
113            );
114        }
115    }
116
117    #[test]
118    fn the_list_has_no_duplicates() {
119        let mut sorted = ORGANIZATION_LEVEL_ACTIONS.to_vec();
120        sorted.sort_unstable();
121        let before = sorted.len();
122        sorted.dedup();
123        assert_eq!(before, sorted.len(), "duplicate action in the list");
124    }
125
126    #[test]
127    fn membership_is_exact_not_prefixed() {
128        assert!(is_organization_level_action("tenants:create"));
129        // A near miss must not match: the seeder withholds on this answer.
130        assert!(!is_organization_level_action("tenants:list"));
131        assert!(!is_organization_level_action("tenants"));
132        assert!(!is_organization_level_action("email_config:write"));
133    }
134}
