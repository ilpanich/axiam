1//! Where AXIAM's long-lived symmetric keys come from.
2//!
3//! This is a **port**: layer 0 declares what the rest of the system needs from
4//! a key source, and layer 1 supplies the implementations. Nothing here knows
5//! about environment variables, files or HTTP.
6//!
7//! # Why this exists
8//!
9//! AXIAM's OPAQUE setup key encrypts every tenant's OPRF seed at rest. Losing
10//! it makes every registration record in every tenant unopenable; leaking it
11//! turns a stolen credential database back into an offline-crackable one, which
12//! is the single property the migration from SRP was for.
13//!
14//! A key that important should not be limited to one delivery mechanism.
15//! Environment variables are convenient and also appear in container specs,
16//! `/proc/<pid>/environ`, crash dumps and orchestrator APIs. A mounted file is
17//! what Docker secrets and Kubernetes `Secret` volumes actually hand you. A KMS
18//! is what an operator who cares reaches for, because access there is
19//! authenticated, audited and revocable rather than being a string that was
20//! copied somewhere once.
21//!
22//! Inverting the dependency lets a deployment choose, and lets a new source be
23//! added without touching a line of authentication code.
24//!
25//! # Why this trait is synchronous
26//!
27//! Keys are resolved **once, during composition** — never on a request path.
28//! A provider that needs to talk to the network does so while it is being
29//! *built* (see `axiam_auth::secrets::VaultSecretProvider::fetch`) and then
30//! answers from memory.
31//!
32//! That is not a shortcut, it is the behaviour worth having: it keeps a KMS off
33//! the login hot path entirely, and it makes a KMS outage fail at startup —
34//! loudly, before any traffic — rather than turning into intermittent login
35//! failures an hour later. It also keeps the trait object-safe without a
36//! proc-macro, which matters because the composition root picks an
37//! implementation at runtime.
38//!
39//! # What a provider is not responsible for
40//!
41//! Deciding whether a missing key is fatal. A provider reports `Ok(None)` for
42//! "this key is not configured" and reserves `Err` for "it is configured and I
43//! could not get it" — a distinction the caller needs, because the first means
44//! *fall back to password login* and the second means *fail closed*. Collapsing
45//! them would let a Vault outage look like a deliberate decision to run without
46//! OPAQUE.
47

76/// HMAC-SHA256 master key authenticating AMQP message payloads.
77///
78/// Signing is mandatory and there is no unsigned code path, so an absent key is
79/// a startup failure in a release build. It is a 256-bit key here and a hex
80/// string in `AmqpConfig::signing_key`; the composition root encodes it, which
81/// is the right place for that adaptation — the port describes what the secret
82/// *is*, not how one consumer spells it.

103/// The password pepper, prepended before Argon2id hashing.

123/// A source of 256-bit symmetric keys, addressed by a stable logical name.
124///
125/// Names are logical (`opaque_setup_key`), not physical: translating one into
126/// an environment variable, a path or a KMS secret is the provider's job. That
127/// is what lets a deployment change where its keys live without any caller
128/// learning about it.
129pub trait SecretProvider: Send + Sync {
130    /// Fetch the 256-bit key registered under `name`.
131    ///
132    /// Returns `Ok(None)` when the key is genuinely not configured, and `Err`
133    /// when it is configured but could not be retrieved or is malformed. See
134    /// the module docs for why those must not be collapsed.
135    fn get_key(&self, name: &str) -> AxiamResult<Option<[u8; 32]>>;
136
137    /// Fetch the text secret registered under `name`.
138    ///
139    /// Separate from [`Self::get_key`] because not every secret is 32 bytes:
140    /// the password pepper is concatenated with a password rather than used as
141    /// a key, and the token signing key is a PEM document. Forcing them through
142    /// a `[u8; 32]` would mean hex-encoding a PEM, which is the kind of
143    /// indirection that gets an operator's key rejected for a reason no error
144    /// message explains.
145    ///
146    /// The value is returned in a [`Zeroizing`] wrapper so a caller that drops
147    /// it does not leave it in a freed heap page. That is a small control, not
148    /// a strong one — the secret is about to live in the process anyway.
149    fn get_secret(&self, name: &str) -> AxiamResult<Option<Zeroizing<String>>>;
150
151    /// A short label for logs and startup diagnostics, e.g. `"env"`.
152    ///
153    /// Present so an operator reading a log line can tell *which* source
154    /// answered — the commonest OPAQUE misconfiguration is believing a key came
155    /// from somewhere it did not.
156    fn describe(&self) -> &'static str;
157}
