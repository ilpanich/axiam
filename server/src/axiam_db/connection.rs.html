1//! SurrealDB connection management.
2//!
3//! Uses the **HTTP engine** (`surrealdb::engine::remote::http`) rather than the
4//! WebSocket engine. The HTTP engine is stateless per request — namespace,
5//! database, and auth are sent on every request — so there is no long-lived
6//! session that can be silently lost on an idle reconnect. This sidesteps
7//! SurrealDB Rust SDK issue #5750 (Ws reconnect drops `use_ns`/`use_db`),
8//! which caused a running server to return "not found" on records that exist
9//! after the connection idled. AXIAM uses no live queries, so the WebSocket
10//! engine bought us nothing but that failure mode.
11//!
12//! ## Root-token renewal (CORR-02)
13//!
14//! SurrealDB mints root signin JWTs with a fixed `DURATION FOR TOKEN`. Left
15//! at the SDK default (`1h`), the HTTP engine's cached token expires mid-process
16//! and every subsequent request 401s until the process restarts.
17//! [`DbManager::connect`] spawns a background task that re-`signin`s the SAME
18//! still-authenticated session at a fraction of the TTL (D-04,
19//! [`re_signin_interval`]) — this succeeds because the cached token is still
20//! valid when the request is sent (see [`DbManager::spawn_proactive_resignin`]
21//! doc comment for why this must NOT call `invalidate()` first).
22//!
23//! [`DbManager::reconnect`] is the reactive "missed window" safety net for
24//! when the proactive task didn't run in time. Per the SDK's HTTP transport,
25//! a request on an ALREADY-expired handle — including `Signin`/`Invalidate`
26//! themselves — is rejected before the RPC dispatcher ever runs, so recovery
27//! there means building a brand-new connection, not resuscitating the stale
28//! one in place. `health_check` classifies auth failures distinctly
29//! ([`DbError::Unhealthy`], D-05) so the readiness probe alarms rather than
30//! treating expired/invalid root credentials as an ordinary, possibly
31//! transient query error.
32//!
33//! ## Session lifecycle (CQ-B48 closed by the DbPool, F2)
34//!
35//! Repositories no longer hold frozen `client_cloned()` snapshots. They bind a
36//! LIVE [`crate::DbHandle`] over a slot of [`crate::DbPool`], which holds N
37//! INDEPENDENT `Surreal<Client>` handles (not clones), each with its OWN
38//! proactive re-signin and reconnect loop — the same D-04/PERF-04 machinery
39//! this module implements, now spawned once per pooled handle instead of only
40//! for the manager's single handle.
41//! Every session a request can reach therefore belongs to a pooled handle that
42//! is kept authenticated inside the root-token TTL and rebuilt on
43//! expiry/poison, so the former restart-only ~4-week outage is gone. Binding a
44//! live handle rather than a clone is what makes that rebuild actually reach
45//! the repositories: a clone would keep them on the connection the reconnect
46//! loop just evicted (see `handle.rs`). The
47//! deliberately-un-renewed startup-snapshot `health_probe` that used to alarm
48//! on that gap is removed; readiness is now established by [`crate::DbPool`]
49//! probing its pooled handles (see [`DbManager::connect_handle`], the shared
50//! per-handle connect+spawn path both [`DbManager`] and the pool build through).
51//!
52//! ## Reconnect loop, full-jitter backoff, poisoned-handle eviction (PERF-04)
53//!
54//! [`DbManager`]'s own handle is held behind a swappable
55//! [`crate::DbHandle`] slot — an `Arc<ArcSwap<Surreal<Client>>>` (D-12), read
56//! lock-free on the query hot path. A background task
57//! ([`DbManager::spawn_reconnect_loop`]) polls health through the current
58//! handle and, on [`DbError::Unhealthy`], runs a bounded retry loop using
59//! [`reconnect_backoff_delay`]'s full-jitter exponential backoff (D-10/D-13 —
60//! `uniform(0, min(base_ms * 2^n, ceiling_ms))`, the AWS-documented fix for
61//! thundering-herd reconnect storms across replicas after a shared DB blip).
62//! On a successful [`DbManager::reconnect`], the old (possibly poisoned)
63//! handle is replaced under the write guard and dropped — never recycled or
64//! returned to any caller again. On `reconnect_max_retries` exhaustion the
65//! manager stays `Unhealthy` and keeps probing at the ceiling interval
66//! forever; it never exits the process or crash-loops (D-11).
67

90/// Token lifetime applied to the SurrealDB root user at startup. Represented
91/// as a real `Duration` (not just a SurrealQL string literal) so the
92/// `DEFINE USER ... DURATION FOR TOKEN` statement AND the proactive
93/// re-signin cadence ([`re_signin_interval`]) derive from ONE source of

99/// Configuration for connecting to SurrealDB.
100///
101/// `Debug` is hand-written and redacts `password` (T-132's follow-up, R-5).
102/// The credential is read-write access to every tenant's data, and a derived
103/// `Debug` puts it into any log line, panic message or error chain that
104/// renders a configuration — the shape of the three CodeQL findings T-260
105/// closed. `username` is kept: a connection failure is the commonest reason to
106/// print this, and "which account" is the fact that answers it.
107#[derive(Clone, Deserialize)]
108#[serde(default)]
109pub struct DbConfig {
110    /// Server address (e.g., `127.0.0.1:8000`).
111    pub url: String,
112    /// SurrealDB namespace.
113    pub namespace: String,
114    /// SurrealDB database name.
115    pub database: String,
116    /// Root username for authentication.
117    pub username: String,
118    /// Root password for authentication.
119    pub password: String,
120    /// Fraction of [`ROOT_TOKEN_DURATION`] at which the proactive re-signin
121    /// task fires (D-04). Clamped to `0.05..=0.95` at use (see
122    /// [`re_signin_interval`]) — never trusted un-clamped from config.
123    /// Overridable via `AXIAM__DB__TOKEN_REFRESH_FRACTION` (D-20); default
124    /// ~0.6 leaves a wide safety margin before the token actually expires
125    /// while avoiding excessive re-signin traffic.
126    pub token_refresh_fraction: f64,
127    /// Base delay (milliseconds) for the reconnect loop's full-jitter
128    /// exponential backoff (D-10/D-13, PERF-04): `capped = base_ms * 2^n`.
129    /// Overridable via `AXIAM__DB__RECONNECT_BASE_MS`; default 250ms.
130    pub reconnect_base_ms: u64,
131    /// Ceiling (milliseconds) the exponential backoff never exceeds, and the
132    /// interval the reconnect loop keeps probing at forever once
133    /// `reconnect_max_retries` is exhausted (D-11). Overridable via
134    /// `AXIAM__DB__RECONNECT_CEILING_MS`; default 30_000ms (30s).
135    pub reconnect_ceiling_ms: u64,
136    /// Number of exponential-backoff attempts before the reconnect loop
137    /// gives up escalating and falls back to probing at the flat ceiling
138    /// interval forever (D-11) — it never exits the process. Overridable via
139    /// `AXIAM__DB__RECONNECT_MAX_RETRIES`; default 10.
140    pub reconnect_max_retries: u32,
141    /// Number of INDEPENDENT `Surreal<Client>` handles the [`crate::DbPool`]
142    /// builds — each with its OWN router task, `reqwest` client (hence its own
143    /// implicit TCP pool) and renewable signin session (NOT `.clone()`s of one
144    /// handle). Overridable via `AXIAM__DB__POOL_SIZE`. DEFAULT `1` —
145    /// byte-for-byte today's behavior (one handle, one funnel, one session):
146    /// the safe-rollout default. `>1` is opt-in until F3 laptop data justifies
147    /// a new default. A value of `0` is treated as `1`.
148    pub pool_size: usize,
149    /// Process-wide cap on concurrent in-flight DB ops across ALL pooled
150    /// handles — the stampede bound, analogous to B1's `MAX_CONCURRENT_HASHES`
151    /// Argon2id gate. Overridable via `AXIAM__DB__POOL_MAX_IN_FLIGHT`.
152    /// DEFAULT `0` = **disabled/unbounded** (no semaphore is built and the
153    /// checkout acquire-timeout path can never fire) — this preserves today's
154    /// unbounded DB concurrency so the default config is a no-op behavior
155    /// change. Set a positive value to enable the bound; F3 tunes it against
156    /// real load. It must never be set below expected steady-state concurrency
157    /// or it becomes a latency source.
158    pub pool_max_in_flight: usize,
159    /// How long [`crate::DbPool::checkout`] waits for a semaphore permit before
160    /// returning the existing overload error (`AxiamError::ServiceUnavailable`
161    /// → HTTP 503, B1's taxonomy). Only consulted when `pool_max_in_flight > 0`.
162    /// Overridable via `AXIAM__DB__POOL_ACQUIRE_TIMEOUT_SECS`. DEFAULT `5`
163    /// (matches B1's `hash_acquire_timeout_secs` so backpressure feels the same
164    /// across the Argon2id gate and the DB pool).
165    pub pool_acquire_timeout_secs: u64,
166    /// TTL, in seconds, of the tenant / OAuth2 client / user record caches
167    /// ([`crate::record_cache`]): the hot, read-only lookups of the token
168    /// endpoints, UserInfo and session refresh. Default **5** — the same bound
169    /// as the session-validation and decision caches. `0` disables them; every
170    /// such lookup then reads the datastore. Overridable via
171    /// `AXIAM__DB__RECORD_CACHE_TTL_SECS`.
172    pub record_cache_ttl_secs: u64,
173    /// Bound on the entries of each record cache. Overridable via
174    /// `AXIAM__DB__RECORD_CACHE_MAX_ENTRIES`; default 10 000.
175    pub record_cache_max_entries: usize,
176    /// Which SDK protocol carries the queries ([`DbEngine`]). Overridable via
177    /// `AXIAM__DB__ENGINE` (`http` or `ws`); default `http`.
178    pub engine: DbEngine,
179    /// With [`DbEngine::Ws`], the most time a REST request may take before it
180    /// is answered `503` (`AXIAM__DB__WS_REQUEST_DEADLINE_SECS`, default 60;
181    /// `0` = none).
182    ///
183    /// The WebSocket engine does not fail a query while it reconnects: the
184    /// query waits for the connection to come back. The SDK offers no
185    /// per-query timeout on its remote engines, so the bound is applied to the
186    /// request instead — above the 30 s an SSF long poll may legitimately wait,
187    /// and above the gRPC listener's own 30 s request timeout, so a healthy
188    /// request never meets it. Ignored with [`DbEngine::Http`], which fails a
189    /// query at once when the server is unreachable.
190    pub ws_request_deadline_secs: u64,
191}

193/// The SDK protocol AXIAM's handles use.
194///
195/// `Http` (the default) is stateless per request — namespace, database and
196/// token travel with every query — and fails fast when the server is down.
197/// `Ws` keeps one connection per pooled handle, saving the per-request
198/// authentication and parsing the HTTP engine pays (≈ 240–290 µs of server CPU
199/// per round trip on SurrealDB 4.0.1); since SDK 4.0 it replays `use`/`signin`
200/// on every reconnect, which is what AXIAM moved to HTTP to avoid (#5750).
201/// Opt-in: see `claude_dev/db-query-optimization.md` §8.4.
202#[derive(Debug, Clone, Copy, Default, PartialEq, Eq, Deserialize)]
203#[serde(rename_all = "lowercase")]
204pub enum DbEngine {
205    /// The HTTP engine (default).
206    #[default]
207    Http,
208    /// The WebSocket engine (opt-in).
209    Ws,
210}
211
212impl DbConfig {
213    /// The SDK endpoint for [`Self::url`]: the URL itself when it names a
214    /// scheme, otherwise `http://` or `ws://` in front of it per [`Self::engine`].
215    #[must_use]
216    pub fn endpoint(&self) -> String {
217        if self.url.contains("://") {
218            return self.url.clone();
219        }
220        let scheme = match self.engine {
221            DbEngine::Http => "http",
222            DbEngine::Ws => "ws",
223        };
224        format!("{scheme}://{}", self.url)
225    }
226}

272/// Computes a full-jitter exponential backoff delay for reconnect attempt
273/// `attempt` (1-indexed): `capped = min(base_ms * 2^(attempt-1), ceiling_ms)`,
274/// then the returned delay is `uniform(0, capped)` — full jitter, the
275/// AWS-documented fix for thundering-herd reconnect storms across replicas
276/// after a shared DB blip (D-10/D-13, PERF-04). Mirrors CORR-03's
277/// `webhook_consumer.rs` `base_ms`/`ceiling_ms` naming and `*2^n`
278/// clamp-to-ceiling shape, but that backoff has NO jitter (27-RESEARCH.md
279/// Pitfall 5) — this adds it.
280///
281/// Side-effect-free apart from RNG draw, so it's unit-testable without a
282/// live server: assert the result is always in `[0, capped]`, never an exact
283/// value (the delay is non-deterministic by design).
284pub fn reconnect_backoff_delay(attempt: u32, base_ms: u64, ceiling_ms: u64) -> Duration {
285    let exponent = attempt.saturating_sub(1);
286    let capped = (base_ms as f64 * 2f64.powi(exponent as i32)).min(ceiling_ms as f64);
287    let jittered_ms = rand::rng().random::<f64>() * capped;
288    Duration::from_millis(jittered_ms as u64)
289}

291/// Returns the SurrealQL `DURATION FOR TOKEN` literal for the given TTL
292/// (e.g. `Duration::from_secs(60)` -> `"60s"`). SurrealQL accepts a bare
293/// `<n>s` duration literal, so no duration-string parser is needed — the
294/// literal is derived FROM the `Duration`, never the reverse.
295fn root_token_duration_surql_literal(ttl: Duration) -> String {
296    format!("{}s", ttl.as_secs())
297}

299/// Parse a SurrealQL duration literal (`4w`, `1h30m`, `2419200s`) into a
300/// [`Duration`].
301///
302/// `root_token_duration_surql_literal` deliberately only ever *emits* `<n>s`,
303/// and its doc note that "no duration-string parser is needed" was true while
304/// nothing read the value back. [`DbManager::extend_root_token_duration`] now
305/// does — it asks what the TTL already is before overwriting the user — and
306/// SurrealDB does not answer in the units it was given: a TTL written as
307/// `2419200s` comes back from `INFO FOR ROOT` as `4w`.
308///
309/// Returns `None` for anything it does not fully understand, and the one caller
310/// treats `None` as "redefine", so an unparsed literal costs a redefine rather
311/// than a silently-wrong TTL.
312fn parse_surql_duration(literal: &str) -> Option<Duration> {
313    const UNITS: &[(&str, u64)] = &[
314        // Longest first: `ms` must not be read as `m` followed by junk.
315        ("ns", 0),
316        ("us", 0),
317        ("ms", 0),
318        ("w", 7 * 24 * 3600),
319        ("d", 24 * 3600),
320        ("h", 3600),
321        ("m", 60),
322        ("s", 1),
323    ];
324
325    let mut rest = literal.trim();
326    if rest.is_empty() {
327        return None;
328    }
329    let mut total = Duration::ZERO;
330
331    while !rest.is_empty() {
332        let digits_end = rest.find(|c: char| !c.is_ascii_digit())?;
333        if digits_end == 0 {
334            return None;
335        }
336        let value: u64 = rest[..digits_end].parse().ok()?;
337        rest = &rest[digits_end..];
338
339        let (unit, secs) = UNITS.iter().find(|(u, _)| rest.starts_with(u))?;
340        rest = &rest[unit.len()..];
341        // Sub-second units contribute nothing to a token TTL measured in
342        // seconds, and rounding them up would overstate it. They are accepted
343        // (so `1h500ms` still parses) and ignored.
344        total += Duration::from_secs(value.saturating_mul(*secs));
345    }
346
347    Some(total)
348}

350/// The `DURATION FOR TOKEN` currently defined for `username` on ROOT, or
351/// `None` if it cannot be established.
352///
353/// `INFO FOR ROOT` answers with the *statements* that would recreate the root
354/// definitions — `{ users: { axiam: "DEFINE USER axiam ON ROOT PASSHASH '...'
355/// ROLES OWNER DURATION FOR TOKEN 4w, FOR SESSION NONE" } }` — so the value is
356/// read back out of that text. Debug-formatted because `Value` does not
357/// implement `Display`.
358///
359/// Every failure path returns `None`, and the caller reads `None` as "go ahead
360/// and redefine". This function must never be the reason a TTL is left short.
361async fn current_root_token_duration<C: surrealdb::Connection>(
362    db: &Surreal<C>,
363    username: &str,
364) -> Option<Duration> {
365    let mut resp = db.query("INFO FOR ROOT").await.ok()?;
366    let info: surrealdb::types::Value = resp.take(0).ok()?;
367    let rendered = format!("{info:?}");
368
369    // Narrow to this user's statement before looking for the clause: a root
370    // with several users would otherwise hand back whichever duration happened
371    // to appear first.
372    let start = rendered.find(&format!("DEFINE USER {username} ON ROOT"))?;
373    let stmt = &rendered[start..];
374    let stmt = &stmt[..stmt.find("FOR SESSION").unwrap_or(stmt.len())];
375
376    let clause = "DURATION FOR TOKEN ";
377    let at = stmt.find(clause)? + clause.len();
378    let literal: String = stmt[at..]
379        .chars()
380        .take_while(|c| c.is_ascii_alphanumeric())
381        .collect();
382
383    parse_surql_duration(&literal)
384}

386/// Interval between proactive re-signin attempts, computed against the
387/// given TTL: `ttl * fraction`, with `fraction` clamped to a safe
388/// `0.05..=0.95` band (D-04) regardless of what a misconfigured env var
389/// supplies.
390fn re_signin_interval_for(ttl: Duration, fraction: f64) -> Duration {
391    Duration::from_secs_f64(ttl.as_secs_f64() * fraction.clamp(0.05, 0.95))
392}

394/// Manages a connection to SurrealDB over the stateless HTTP engine.
395pub struct DbManager {
396    /// SurrealDB client handle (HTTP engine), behind a swappable
397    /// [`DbSlot`] (PERF-04, D-12) so the reconnect loop can atomically replace
398    /// a poisoned/broken handle with a freshly-authenticated one — the old
399    /// handle is dropped on swap and never recycled or returned to any
400    /// caller again. `Arc`-shared (not cloned) with the proactive re-signin
401    /// and reconnect-loop tasks — and with every [`crate::DbHandle`] bound to
402    /// it — so all sides observe/refresh the SAME current handle (see module
403    /// docs, Pitfall 2).
404    db: DbSlot<Client>,
405    /// Handle to the background proactive re-signin task (D-03/D-04),
406    /// owned so it is explicitly droppable/abortable rather than a
407    /// fire-and-forget detached task.
408    refresh_handle: JoinHandle<()>,
409    /// Handle to the background reconnect-loop task (D-10/D-11/D-12/D-13,
410    /// PERF-04), owned for the same explicit-drop reason as
411    /// `refresh_handle`.
412    reconnect_handle: JoinHandle<()>,
413}
414
415impl DbManager {
416    /// Connect to SurrealDB using the provided configuration.
417    ///
418    /// Authenticates as root and selects the configured namespace and database.
419    /// With the HTTP engine these are stored on the client and re-sent on every
420    /// request, so the selection cannot be silently lost on reconnect.
421    ///
422    /// Also spawns the proactive re-signin background task (D-03/D-04) that
423    /// keeps this session authenticated well inside the root token's TTL.
424    pub async fn connect(config: &DbConfig) -> Result<Self, surrealdb::Error> {
425        Self::connect_with_ttl(config, ROOT_TOKEN_DURATION).await
426    }
427
428    /// Test-only entry point: identical to [`connect`](Self::connect) but
429    /// with an explicit root-token TTL override, so an integration test can
430    /// prove recovery from a REAL, short-lived token expiry without waiting
431    /// four weeks. Production code should always use [`connect`](Self::connect),
432    /// which always passes the fixed [`ROOT_TOKEN_DURATION`].
433    pub async fn connect_with_ttl(
434        config: &DbConfig,
435        ttl: Duration,
436    ) -> Result<Self, surrealdb::Error> {
437        info!(
438            url = %config.url,
439            namespace = %config.namespace,
440            database = %config.database,
441            "Connecting to SurrealDB (HTTP engine)"
442        );
443
444        // SurrealDB mints root signin JWTs with a default `DURATION FOR TOKEN 1h`.
445        // The HTTP engine caches that JWT and, once it expires, EVERY request 401s
446        // (login → "invalid credentials"; audit/cleanup writes fail) until the
447        // process restarts. Re-`signin` on an already-authenticated handle is itself
448        // rejected with 401, so a background re-auth loop does NOT recover it.
449        //
450        // Fix: on a short-lived setup handle, extend the root user's token duration,
451        // then open the real connection whose FRESH signin mints a long-lived token.
452        // The proactive re-signin task spawned below then keeps that token from
453        // ever actually reaching this extended TTL.
454        Self::extend_root_token_duration(config, ttl).await;
455
456        let (db, refresh_handle, reconnect_handle) = Self::connect_handle(config, ttl).await?;
457
458        info!("Successfully connected to SurrealDB");
459
460        Ok(Self {
461            db,
462            refresh_handle,
463            reconnect_handle,
464        })
465    }
466
467    /// Build ONE fully-independent, authenticated HTTP handle and spawn its
468    /// per-handle proactive re-signin ([`spawn_proactive_resignin`]) and
469    /// reconnect ([`spawn_reconnect_loop`]) tasks. This is the single shared
470    /// "one live handle + its own D-04/PERF-04 lifecycle" path that both
471    /// [`connect_with_ttl`](Self::connect_with_ttl) (the single-handle manager)
472    /// and [`crate::DbPool`] (N handles) construct through — so a pooled handle
473    /// is genuinely an independent connection with its own router task,
474    /// `reqwest` client and renewable session, never a `.clone()` that shares
475    /// one `Arc<inner>`.
476    ///
477    /// `pub(crate)` because the pool lives in a sibling module; the caller is
478    /// responsible for running [`extend_root_token_duration`](Self::extend_root_token_duration)
479    /// beforehand (idempotent, so once per process is enough even for N handles).
480    pub(crate) async fn connect_handle(
481        config: &DbConfig,
482        ttl: Duration,
483    ) -> Result<(DbSlot<Client>, JoinHandle<()>, JoinHandle<()>), surrealdb::Error> {
484        let db = connect_any(config.endpoint()).await?;
485        db.signin(Root {
486            username: config.username.clone(),
487            password: config.password.clone(),
488        })
489        .await?;
490        db.use_ns(&config.namespace)
491            .use_db(&config.database)
492            .await?;
493
494        let db = new_slot(db);

500    /// Best-effort: redefine the root user with a long token duration so the
501    /// connection's cached JWT does not expire mid-process. Failures are logged
502    /// and ignored (the server still starts; it just reverts to the ~1h window).
503    /// Idempotent — safe to run on every startup (and once per process is
504    /// enough even when [`crate::DbPool`] builds N handles). `pub(crate)` so the
505    /// pool module can run it once before constructing its handles.
506    pub(crate) async fn extend_root_token_duration(config: &DbConfig, ttl: Duration) {
507        let setup = match connect_any(config.endpoint()).await {
508            Ok(s) => s,
509            Err(e) => {
510                warn!(error = %e, "token-duration setup: connect failed (continuing)");
511                return;
512            }
513        };
514        if let Err(e) = setup
515            .signin(Root {
516                username: config.username.clone(),
517                password: config.password.clone(),
518            })
519            .await
520        {
521            warn!(error = %e, "token-duration setup: signin failed (continuing)");
522            return;
523        }
524        // Ask before overwriting.
525        //
526        // `DEFINE USER OVERWRITE ... PASSWORD '...'` re-hashes the password with
527        // a FRESH SALT, and SurrealDB signs root tokens against that hash — so
528        // the statement invalidates every token already issued for this user.
529        // Run unconditionally at every boot (which the doc comment above used to
530        // call "idempotent"), it logs out every AXIAM process already connected
531        // to the same datastore: start a second replica, or roll a deployment,
532        // and the running ones 401 on every query from that moment.
533        //
534        // Measured, not theorised: a second server container against this
535        // datastore took the first one from healthy to a 401 on every request
536        // within five seconds, and it never recovered on its own.
537        //
538        // So do it only when it would actually change something. Anything this
539        // cannot read — a query that fails, a shape it does not recognise, a
540        // duration literal it cannot parse — falls through to the redefine,
541        // which is the previous behaviour. Being wrong in that direction costs
542        // a redefine; being wrong in the other direction would leave the TTL at
543        // SurrealDB's ~1h default while the re-signin task waits weeks, which is
544        // the original expiry bug.
545        if let Some(existing) = current_root_token_duration(&setup, &config.username).await
546            && existing >= ttl
547        {
548            info!(
549                duration_secs = existing.as_secs(),
550                "SurrealDB root token duration is already at least the configured TTL — \
551                 not redefining the user (a redefine would invalidate every other \
552                 replica's token)"
553            );
554            return;
555        }
556
557        // SurrealQL string-escape the password (single-quoted literal).
558        let escaped_pass = config.password.replace('\\', "\\\\").replace('\'', "\\'");
559        let define_user = format!(
560            "DEFINE USER OVERWRITE {} ON ROOT PASSWORD '{}' ROLES OWNER \
561             DURATION FOR TOKEN {}, FOR SESSION NONE",
562            config.username,
563            escaped_pass,
564            root_token_duration_surql_literal(ttl)
565        );
566        match setup.query(define_user).await.and_then(|r| r.check()) {
567            Ok(_) => info!(
568                duration_secs = ttl.as_secs(),
569                "Extended SurrealDB root token duration"
570            ),
571            Err(e) => warn!(error = %e, "token-duration setup: DEFINE USER failed (continuing)"),
572        }
573    }

575    /// Spawn the proactive periodic re-signin task (D-03/D-04) that keeps
576    /// this `DbManager`'s own SurrealDB session authenticated well inside
577    /// the root token's TTL, so the cached JWT never actually reaches its
578    /// expiry under normal operation.
579    ///
580    /// Re-signs the SAME `Arc`-shared session `db` refers to (not a
581    /// `.clone()`d one) at each interval — this succeeds because the
582    /// currently-cached token is still valid when the request is sent.
583    /// Deliberately does NOT call `invalidate()` first: that request would
584    /// itself carry the (still valid) auth header, so it buys nothing on
585    /// this path, and calling it on an ALREADY-expired handle would itself
586    /// 401 before clearing anything — see `26-RESEARCH.md` Pitfall 3
587    /// (the reactive "missed window" safety net, [`DbManager::reconnect`],
588    /// is a separate mechanism).
589    fn spawn_proactive_resignin(
590        db: DbSlot<Client>,
591        config: &DbConfig,
592        ttl: Duration,
593    ) -> JoinHandle<()> {
594        let interval = re_signin_interval_for(ttl, config.token_refresh_fraction);
595        let username = config.username.clone();
596        let password = config.password.clone();
597
598        tokio::spawn(async move {
599            loop {
600                tokio::time::sleep(interval).await;
601                // Re-signin only mutates the SAME handle's server-side auth
602                // state via a request (`&self`) — it does not need to swap
603                // the handle itself, so loading the current handle is enough
604                // here. The reconnect loop (spawn_reconnect_loop) is the ONLY
605                // task that ever stores a replacement handle (D-12).
606                let current = db.load_full();
607                match current
608                    .signin(Root {
609                        username: username.clone(),
610                        password: password.clone(),
611                    })
612                    .await
613                {
614                    // T-26-02-01: never log the token/JWT/password — only the
615                    // outcome (ok/err) and non-secret context.
616                    Ok(_) => info!("Proactive SurrealDB root re-signin succeeded"),
617                    Err(e) => warn!(
618                        error = %e,
619                        "Proactive SurrealDB root re-signin failed (a reactive \
620                         reconnect path is the safety net for a fully-missed window)"
621                    ),
622                }
623            }
624        })
625    }

627    /// Reactive reconnect seam (D-03) — the "missed window" safety net for
628    /// when the proactive re-signin task above did not run in time and the
629    /// cached token has ALREADY expired.
630    ///
631    /// Builds a BRAND-NEW `connect_any(config.endpoint())` connection with its own
632    /// fresh session and signs in on it, rather than attempting
633    /// `invalidate()`+`signin()` on the stale handle: every request on an
634    /// already-401ing handle — including `Signin`/`Invalidate` themselves —
635    /// carries the stale cached auth header and is rejected by the HTTP
636    /// engine's transport-level status check before the RPC dispatcher ever
637    /// runs (see module docs).
638    ///
639    /// This is intentionally a single-attempt primitive — [`spawn_reconnect_loop`]
640    /// (PERF-04) wraps a full jittered-backoff reconnect loop and
641    /// poisoned-connection eviction around this.
642    pub async fn reconnect(config: &DbConfig) -> Result<Surreal<Client>, surrealdb::Error> {
643        let db = connect_any(config.endpoint()).await?;
644        db.signin(Root {
645            username: config.username.clone(),
646            password: config.password.clone(),
647        })
648        .await?;
649        db.use_ns(&config.namespace)
650            .use_db(&config.database)
651            .await?;
652        Ok(db)
653    }

655    /// Background reconnect loop (D-10/D-11/D-12/D-13, PERF-04): polls
656    /// health through the current handle, and on
657    /// `DbError::Unhealthy` runs a bounded, full-jitter exponential-backoff
658    /// retry loop calling [`DbManager::reconnect`]. On success, the old
659    /// handle is atomically stored into the slot (D-12 —
660    /// the poisoned handle is dropped right there and never recycled or
661    /// returned to any caller again) and health polling resumes at the
662    /// normal cadence.
663    ///
664    /// On `reconnect_max_retries` exhaustion, the manager stays `Unhealthy`
665    /// (so `/ready` sheds traffic) and this task falls back to probing at
666    /// the flat `reconnect_ceiling_ms` interval FOREVER — it never
667    /// `break`s/`return`s out of the outer loop and never exits the process
668    /// or crash-loops (D-11). A later successful reconnect at that cadence
669    /// still swaps the handle and flips health back to `Ok` with no process
670    /// restart.
671    fn spawn_reconnect_loop(db: DbSlot<Client>, config: DbConfig) -> JoinHandle<()> {
672        tokio::spawn(async move {
673            loop {
674                tokio::time::sleep(HEALTH_POLL_INTERVAL).await;
675
676                let is_unhealthy = {
677                    let current = db.load_full();
678                    let outcome = current
679                        .query("RETURN 1")
680                        .await
681                        .map_err(Self::classify_query_error)
682                        .and_then(|r| r.check().map_err(Self::classify_query_error));
683                    matches!(outcome, Err(DbError::Unhealthy(_)))
684                };
685
686                if !is_unhealthy {
687                    continue;
688                }
689
690                warn!(
691                    "DbManager: connection detected Unhealthy — entering bounded \
692                     full-jitter reconnect retry loop"
693                );
694
695                let mut reconnected = false;
696                let mut attempt: u32 = 1;
697                while attempt <= config.reconnect_max_retries {
698                    let delay = reconnect_backoff_delay(
699                        attempt,
700                        config.reconnect_base_ms,
701                        config.reconnect_ceiling_ms,
702                    );
703                    tokio::time::sleep(delay).await;
704
705                    match Self::reconnect(&config).await {
706                        Ok(fresh) => {
707                            db.store(Arc::new(fresh));
708                            info!(attempt, "DbManager reconnect succeeded — handle swapped");
709                            reconnected = true;
710                            break;
711                        }
712                        Err(e) => {
713                            warn!(error = %e, attempt, "DbManager reconnect attempt failed");
714                            attempt += 1;
715                        }
716                    }
717                }
718
719                if reconnected {
720                    continue;
721                }
722
723                warn!(
724                    max_retries = config.reconnect_max_retries,
725                    "DbManager: reconnect retries exhausted — staying Unhealthy and \
726                     probing at the ceiling interval forever (never exiting)"
727                );
728                loop {
729                    tokio::time::sleep(Duration::from_millis(config.reconnect_ceiling_ms)).await;
730                    match Self::reconnect(&config).await {
731                        Ok(fresh) => {
732                            db.store(Arc::new(fresh));
733                            info!(
734                                "DbManager reconnect succeeded after exhaustion — handle \
735                                 swapped, resuming normal health polling"
736                            );
737                            break;
738                        }
739                        Err(e) => {
740                            warn!(
741                                error = %e,
742                                "DbManager: ceiling-interval reconnect probe still failing"
743                            );
744                        }
745                    }
746                }
747            }
748        })
749    }

804    /// Classify a query/check failure into a [`DbError`], distinguishing an
805    /// authentication problem — expired token, invalidated session, or a
806    /// genuinely revoked/invalid root credential (ANY `NotAllowed(Auth(..))`
807    /// variant, not just token expiry, per T-26-02-02/D-05) — from an
808    /// ordinary query error.
809    ///
810    /// Side-effect-free and public so it can be unit-tested directly against
811    /// a synthetic `surrealdb::Error` without a live server.
812    pub fn classify_query_error(err: surrealdb::Error) -> DbError {
813        if matches!(err.not_allowed_details(), Some(NotAllowedError::Auth(_))) {
814            return DbError::Unhealthy(err.to_string());
815        }
816        if is_transport_auth_rejection(&err) {
817            return DbError::Unhealthy(err.to_string());
818        }
819        DbError::Surreal(err)
820    }

832/// Whether a SurrealDB error is the HTTP engine's way of saying "this handle's
833/// credentials are no longer accepted".
834///
835/// The statement-level `NotAllowed(Auth(..))` shape that
836/// [`DbManager::classify_query_error`] checks first is what the **WebSocket**
837/// engine produces. AXIAM runs the **HTTP** engine (Phase 13), and there the
838/// server answers `401` at the transport, before any SurrealQL response exists.
839/// So on the engine actually deployed, the one error that must reach the
840/// reconnect loop arrived looking like an ordinary query failure. The loop never
841/// ran, and a process whose root token had been invalidated served 401s until
842/// somebody restarted it. That is not hypothetical: **every AXIAM boot used to
843/// run `DEFINE USER OVERWRITE … ON ROOT`** (see
844/// [`DbManager::extend_root_token_duration`], which now asks first), which
845/// re-salts the password hash and invalidates every token already issued for
846/// that user — so starting a second replica, or a rolling deploy, wedged the
847/// replicas already running.
848///
849/// **Matched on the message, and only on the message.** The obvious structured
850/// predicate is wrong: the SDK's `From<reqwest::Error>` builds
851/// `ErrorDetails::Connection(ConnectionFailed)`, but the error that actually
852/// arrives here does not come through it. Reproduced against a live server
853/// (`a_redefined_root_user_classifies_as_unhealthy_on_the_http_engine`), it is:
854///
855/// ```text
856/// Error { code: -32000,
857///         message: "HTTP status client error (401 Unauthorized) for url (…/rpc)",
858///         details: Internal, cause: None }
859/// ```
860///
861/// `Internal` is the enum's forward-compatibility catch-all, so it says nothing
862/// and `connection_details()` returns `None`. A first version of this fix keyed
863/// on `Connection`, passed a unit test built from that assumption, and changed
864/// nothing at all on the running stack. The status code is genuinely
865/// unreachable through this conversion; the message is the only signal there is.
866///
867/// The full reqwest phrase is matched rather than a bare `"401"`, so a query
868/// error that happens to mention the number cannot be mistaken for one — and
869/// only `401`/`403`, because those mean this handle's bearer token will never be
870/// accepted again, which a reconnect fixes. A timeout or a refused connection
871/// says nothing about the handle's credentials and is left to ordinary retry,
872/// so that a network blip does not tear down and rebuild every pooled
873/// connection.
874fn is_transport_auth_rejection(err: &surrealdb::Error) -> bool {
875    let msg = err.to_string();
876    msg.contains("HTTP status client error (401 Unauthorized)")
877        || msg.contains("HTTP status client error (403 Forbidden)")
878}

884        // lifetime so this rarely runs, but it keeps tests (which may
885        // construct several `DbManager`s) from leaking background tasks.
886        self.refresh_handle.abort();
887        self.reconnect_handle.abort();
888    }

1048            Some(Duration::from_secs(2 * 86400 + 12 * 3600))
1049        );
1050        // Sub-second units contribute nothing to a TTL in seconds, but must not
1051        // make the whole literal unparseable.
1052        assert_eq!(
1053            parse_surql_duration("1h500ms"),
1054            Some(Duration::from_secs(3600))
1055        );
1056    }
