1//! Write-behind shared rate-limit counter (SECHRD-03 / D-01a, D-01b —
2//! performance fix for the H2 finding).
3//!
4//! # What this replaces, and why
5//!
6//! Until this module existed, both shared-store rate-limit layers
7//! (`axiam-api-rest::middleware::rate_limit_shared::RateLimitShared` and
8//! `axiam-api-grpc::middleware::rate_limit::GrpcSharedRateLimitLayer`)
9//! performed ONE synchronous
10//! [`SurrealRateLimitBucketRepository::increment`] UPSERT against a single
11//! `rate_limit_bucket:<endpoint>:<ip>` record **before** the handler ran, on
12//! the request's critical path.
13//!
14//! That write is a deliberate global hot spot: one record per
15//! `(endpoint, key)` pair, written by every request. Measured on
16//! 2026-07-28 (`server:1.0.0-alpha19` + SurrealDB 3.2.3, 2 CPU / 1 GiB each,
17//! rate limits neutralized — full data in
18//! `claude_dev/postseed-transient-investigation.md` §2, §3, §7):
19//!
20//! - The six wrapped endpoints (`POST /api/v1/authz/check`,
21//!   `POST /oauth2/token`, `POST /oauth2/introspect`, `POST /oauth2/revoke`,
22//!   `POST /api/v1/auth/login`, and — unintentionally, see §7 ask 1 —
23//!   `GET /api/v1/users`) were pinned at **16–21 ops/s at any concurrency
24//!   from 1 to 40 VUs**, with p50 ≈ 55–65 ms at 1 VU and ≈ 1 s at 20 VUs.
25//! - Structurally identical endpoints WITHOUT the wrap ran at
26//!   **68–4 248 ops/s**. The cleanest pair: `GET /api/v1/users` at 60–65 ms
27//!   vs `GET /api/v1/resources` at 11–12 ms — same handler shape, same
28//!   session, same datastore; the only difference was the wrap.
29//! - The datastore's own tracer attributed ~39–46 ms of each such request to
30//!   a **single** RPC that only the wrapped endpoints issue; every other RPC
31//!   in the same request was 0–6 ms. The same UPSERT issued directly
32//!   (`surreal sql` / raw HTTP `/sql`) ran at 6–9 ms and scaled to 487 ops/s
33//!   at 20 concurrent writers on the same hot key — so the *ordering*, not
34//!   the datastore, was the ceiling. The ceiling is set by the slowest
35//!   datastore write in the deployment and does not improve with
36//!   concurrency, app replicas, or connection pooling.
37//!
38//! [`SharedRateLimitCounter`] keeps the security purpose of the layer while
39//! removing that synchronous write: the per-request path is now a single
40//! in-process sharded-map increment (no datastore round trip, no task spawn,
41//! no `await`), and a background flusher coalesces the accumulated
42//! increments into **one** [`SurrealRateLimitBucketRepository::increment_by`]
43//! write per `(key, window)` per sync interval.
44//!
45//! # What the layer is for (do not remove it)
46//!
47//! The per-replica in-memory `governor`/`GovernorLayer` still runs on exactly
48//! the same endpoints and still makes a full per-replica decision — it is
49//! untouched by this module. The shared store exists for a different reason:
50//! with N replicas behind an HPA, N independent in-memory buckets multiply
51//! the effective rate limit by N. The shared counter is what makes the
52//! configured limit hold *across* replicas. Deleting it would silently
53//! restore that N× multiplication.
54//!
55//! # Staleness / overshoot bound (quotable in the security docs)
56//!
57//! With write-behind, cross-replica enforcement becomes **eventual** rather
58//! than immediate. Precisely:
59//!
60//! > A replica's local view of a bucket is `shared_count + pending`, where
61//! > `shared_count` is the authoritative store count as of that replica's
62//! > last successful flush and `pending` is its own unflushed increments.
63//! > A replica therefore always counts **all** of its own traffic
64//! > immediately, and *other* replicas' traffic only as of its last flush —
65//! > which is at most `sync_interval` old (`AXIAM__RATE_LIMIT__SHARED_SYNC_MS`,
66//! > default 1000 ms). Consequently, for a bucket receiving aggregate
67//! > arrival rate `R` spread over `replicas` replicas, the worst-case
68//! > overshoot beyond the configured limit before the counts converge is
69//! > bounded by approximately
70//! >
71//! > ```text
72//! > (replicas - 1) × (R / replicas) × sync_interval
73//! > ```
74//! >
75//! > i.e. at most `(replicas − 1) × arrival_rate_per_replica × sync_interval`
76//! > extra admitted requests, and **zero** on a single replica (where
77//! > `replicas - 1 = 0`, so local counting is exact and this layer is as
78//! > strict as the previous synchronous implementation). With the previous
79//! > per-request-synchronous write the bound was zero for any replica count,
80//! > at the cost of the ~20 ops/s per-endpoint ceiling documented above.
81//! > Overshoot is also capped by the in-memory `governor` on the same
82//! > endpoint, which independently enforces the limit per replica; the
83//! > shared layer's job is to stop the aggregate from reaching
84//! > `replicas × limit`, and after one `sync_interval` it does.
85//!
86//! Example: limit 100/min, 4 replicas, `sync_interval` 1 s, aggregate
87//! arrival 40 req/s ⇒ worst case ≈ `3 × 10 × 1 s` = ~30 requests of
88//! overshoot inside a 60 s window before convergence (≈ 30 % of the limit,
89//! and shrinking linearly with `sync_interval`).
90//!
91//! # Fail-open posture (D-01b, T-24-42 accepted risk)
92//!
93//! This layer keeps the ONE deliberate fail-open exception in the codebase;
94//! every other control fails closed. It allows the request and logs a
95//! `warn`-level alarm WITHOUT the raw bucket key (T-24-43 — the key embeds a
96//! client IP / `client_id`) when:
97//!
98//! - the shared layer is disabled (`AXIAM__RATE_LIMIT__SHARED=off`),
99//! - the caller has no key part (no client IP could be derived),
100//! - no datastore handle / no counter is registered,
101//! - the flusher's wake channel is full or closed,
102//! - the store errors during a flush.
103//!
104//! In the last three cases the counter **keeps serving decisions from local
105//! counts** — a store outage degrades cross-replica strictness to
106//! per-replica strictness (exactly the in-memory `governor`'s posture), it
107//! never hard-blocks auth traffic and never surfaces a 5xx.
108//!
109//! Note the one behavioral difference from the pre-write-behind layer: a
110//! store outage is now discovered by the *flusher*, not by the request, so a
111//! request is no longer blanket-allowed just because the store is down — it
112//! is still evaluated against the (perfectly valid) local count. A limit of
113//! `0` therefore denies locally even with an unreachable store, where the
114//! old code would have allowed. That is strictly a correctness improvement:
115//! "the store is unreachable" must not become "the limit is disabled".
116//!
117//! # Concurrency rules obeyed here
118//!
119//! - State is a fixed [`SHARD_COUNT`]-way sharded map of `std::sync::Mutex`
120//!   (NOT a tokio mutex): critical sections are a few field updates and are
121//!   **never** held across an `await`. The flusher collects work under the
122//!   lock, drops it, awaits the store, then re-locks to write back.
123//! - [`SharedRateLimitCounter::check`] is fully synchronous and allocation-
124//!   free on the hot path apart from the map probe, so it can be called from
125//!   any executor (actix worker, tonic/tower task) without `block_on`.
126//! - Poisoned mutexes are recovered from (`into_inner`) rather than
127//!   panicking: a panic elsewhere must not take the rate limiter down.

144/// Number of independent shards in the in-process bucket map. Sized so that
145/// unrelated hot keys (one per rate-limited endpoint per client IP) rarely
146/// contend on the same `Mutex`, while keeping a flush pass to 16 cheap lock
147/// acquisitions.
148pub const SHARD_COUNT: usize = 16;

150/// Default write-behind flush interval, in milliseconds
151/// (`AXIAM__RATE_LIMIT__SHARED_SYNC_MS`).
152pub const DEFAULT_SYNC_INTERVAL_MS: u64 = 1_000;

154/// Lower clamp for `AXIAM__RATE_LIMIT__SHARED_SYNC_MS`. Below this the
155/// flusher would approach the per-request write storm this module exists to
156/// remove.
157pub const MIN_SYNC_INTERVAL_MS: u64 = 50;
158
159/// Upper clamp for `AXIAM__RATE_LIMIT__SHARED_SYNC_MS`. Above this the
160/// cross-replica overshoot bound (see module docs) grows past anything
161/// defensible for a security control.
162pub const MAX_SYNC_INTERVAL_MS: u64 = 60_000;

164/// Fixed-window length assumed by both callers' `window_start()` helpers
165/// (`axiam-api-rest::middleware::rate_limit_shared::WINDOW_SECS` and
166/// `axiam-api-grpc::middleware::rate_limit::WINDOW_SECS`). Used ONLY to
167/// decide when an idle bucket is stale enough to prune — the window itself is
168/// always supplied by the caller, never computed here.
169pub const DEFAULT_WINDOW_SECS: u64 = 60;
170
171/// A bucket whose window is older than `STALE_WINDOW_MULTIPLE` windows and
172/// which has nothing pending is dropped by the flusher, bounding memory to
173/// "keys seen in the last two windows".
174const STALE_WINDOW_MULTIPLE: u32 = 2;
175
176/// Capacity of the bounded wake channel feeding the flusher. Notifications
177/// are pure hints (the shard maps are the source of truth), so a full
178/// channel only ever delays a flush to the next interval tick — it can never
179/// lose a pending delta.
180const WAKE_CHANNEL_CAPACITY: usize = 1_024;
181
182/// A bucket with pending work that has not been flushed for this many sync
183/// intervals means the flusher is starved (blocked store, saturated runtime).
184/// The stated overshoot bound scales with the ACTUAL flush period, so this is
185/// worth exactly one `warn` to an operator.
186const OVERDUE_SYNC_MULTIPLE: i32 = 5;

192/// Evaluation interval for the machine-traffic throttling advisory, in
193/// seconds. "Sustained" has to mean more than a burst, and 5 minutes is long
194/// enough that a deploy-time thundering herd or a single retry storm cannot
195/// trip it.
196pub const ADVISORY_WINDOW_SECS: i64 = 300;
197
198/// Deny ratio, over one [`ADVISORY_WINDOW_SECS`] interval, above which the
199/// shipped `internet` limits are more likely mis-sized than under attack.
200pub const ADVISORY_DENIED_RATIO: f64 = 0.5;
201
202/// Minimum machine-endpoint requests in an interval before the ratio is
203/// meaningful at all — 3 denials out of 4 requests is noise, not a signal.
204pub const ADVISORY_MIN_SAMPLES: u64 = 100;
205
206/// Bucket-name prefixes counted as **machine** traffic by the advisory.
207///
208/// Human endpoints (`login`, `register`, `password_reset`, `mfa`) are
209/// deliberately absent: a `429` storm there is a credential-stuffing signal,
210/// not a sizing signal, and must never be answered by raising a limit.
211/// These are the `endpoint` halves of the `"{endpoint}:{key_part}"` bucket
212/// keys wired in `axiam-api-rest::server`.
213pub const MACHINE_ENDPOINTS: &[&str] = &[
214    "oauth2_token",
215    "oauth2_introspect",
216    "oauth2_revoke",
217    "authz_check",
218    "authz_check_batch",
219];
220
221/// `true` when `key` (`"{endpoint}:{key_part}"`) belongs to a machine
222/// endpoint.
223fn is_machine_key(key: &str) -> bool {
224    let endpoint = key.split(':').next().unwrap_or(key);
225    MACHINE_ENDPOINTS.contains(&endpoint)
226}

228/// Rolling allow/deny tally over the machine endpoints, evaluated once per
229/// [`ADVISORY_WINDOW_SECS`] interval (I3).
230///
231/// **Why it lives here.** The write-behind counter already sees every
232/// rate-limit decision and already runs exactly one background task. Putting
233/// the tally on the same atomics `check` touches, and the evaluation on the
234/// flusher's existing pass, adds no task, no timer and no lock — a separate
235/// watcher for this would cost more than the advice is worth.
236///
237/// Inert until [`SharedRateLimitCounter::arm_machine_traffic_advisory`] is
238/// called, which the composition root does only when the shipped `internet`
239/// defaults are the active posture: an operator who deliberately picked
240/// `gateway`/`mesh`, or who pinned the limits by hand, has already made this
241/// decision and does not need to be told about it.
242#[derive(Debug, Default)]
243struct MachineTrafficAdvisory {
244    armed: AtomicBool,
245    allowed: AtomicU64,
246    denied: AtomicU64,
247    /// Start of the current evaluation interval, epoch seconds. `0` = not
248    /// started yet (set on the first flush after arming).
249    window_start_epoch: AtomicI64,
250}
251
252impl MachineTrafficAdvisory {
253    fn arm(&self) {
254        self.armed.store(true, Ordering::Relaxed);
255    }
256
257    /// Records one decision. Cheap enough for the request path: an armed
258    /// check is one relaxed load, and only machine keys pay the increment.
259    fn record(&self, key: &str, allowed: bool) {
260        if !self.armed.load(Ordering::Relaxed) || !is_machine_key(key) {
261            return;
262        }
263        let counter = if allowed { &self.allowed } else { &self.denied };
264        counter.fetch_add(1, Ordering::Relaxed);
265    }
266
267    /// Closes the interval if it is due, emitting the advisory when the
268    /// sustained deny ratio says the shipped limits are throttling what looks
269    /// like legitimate machine traffic. Called from the flusher's existing
270    /// pass — never from the request path.
271    fn maybe_report(&self, now: DateTime<Utc>) {
272        if !self.armed.load(Ordering::Relaxed) {
273            return;
274        }
275        let now_epoch = now.timestamp();
276        let started = self.window_start_epoch.load(Ordering::Relaxed);
277        if started == 0 {
278            self.window_start_epoch.store(now_epoch, Ordering::Relaxed);
279            return;
280        }
281        if now_epoch - started < ADVISORY_WINDOW_SECS {
282            return;
283        }
284
285        // Interval closed: take the tallies and start the next one. The two
286        // `swap`es are not atomic together, so a decision landing between
287        // them is counted in the next interval — irrelevant at this
288        // resolution, and cheaper than a lock on the request path.
289        let allowed = self.allowed.swap(0, Ordering::Relaxed);
290        let denied = self.denied.swap(0, Ordering::Relaxed);
291        self.window_start_epoch.store(now_epoch, Ordering::Relaxed);
292
293        let total = allowed + denied;
294        if total < ADVISORY_MIN_SAMPLES {
295            return;
296        }
297        let ratio = denied as f64 / total as f64;
298        if ratio <= ADVISORY_DENIED_RATIO {
299            return;
300        }
301        // No key, no IP, no client_id — only aggregate counts (T-24-43).
302        tracing::warn!(
303            machine_denied_ratio = format!("{ratio:.2}"),
304            machine_denied = denied,
305            machine_allowed = allowed,
306            window_secs = ADVISORY_WINDOW_SECS,
307            "your limits are throttling what looks like legitimate machine traffic; \
308             see rate-limit-sizing"
309        );
310    }
311}

317/// Boxed future returned by [`SharedRateLimitStore::increment_by`].
318pub type StoreIncrementFuture<'a> = Pin<Box<dyn Future<Output = Result<u64, DbError>> + Send + 'a>>;
319
320/// The single write primitive the write-behind flusher needs.
321///
322/// Object-safe on purpose (hence the boxed future rather than an
323/// `async fn`): [`SharedRateLimitCounter`] is deliberately NOT generic over
324/// the SurrealDB connection type, so one non-generic counter type can be held
325/// by `axiam-api-rest`'s `AppState<C>` and by `axiam-api-grpc`'s tower layer
326/// alike, and so tests can substitute a failing or call-counting store.
327///
328/// Implemented for [`SurrealRateLimitBucketRepository`] for every
329/// `C: Connection`.
330pub trait SharedRateLimitStore: Send + Sync + 'static {
331    /// Adds `delta` to the bucket `key` for the fixed window starting at
332    /// `window_start`, returning the authoritative POST-update count.
333    fn increment_by<'a>(
334        &'a self,
335        key: &'a str,
336        window_start: DateTime<Utc>,
337        delta: u64,
338    ) -> StoreIncrementFuture<'a>;
339}
340
341impl<C: Connection> SharedRateLimitStore for SurrealRateLimitBucketRepository<C> {
342    fn increment_by<'a>(
343        &'a self,
344        key: &'a str,
345        window_start: DateTime<Utc>,
346        delta: u64,
347    ) -> StoreIncrementFuture<'a> {
348        Box::pin(SurrealRateLimitBucketRepository::increment_by(
349            self,
350            key,
351            window_start,
352            delta,
353        ))
354    }
355}

361/// Configuration for [`SharedRateLimitCounter`], read once via
362/// [`SharedRateLimitConfig::from_env`] so the REST and gRPC layers always
363/// behave identically.
364#[derive(Debug, Clone, PartialEq, Eq)]
365pub struct SharedRateLimitConfig {
366    /// `AXIAM__RATE_LIMIT__SHARED` — `on` (default) or `off`.
367    ///
368    /// `off` skips the shared layer *entirely* (no state, no store call, no
369    /// flusher) for single-replica deployments, leaving the per-replica
370    /// in-memory `governor` as the sole limiter. It does NOT change any
371    /// configured limit.
372    pub enabled: bool,
373    /// `AXIAM__RATE_LIMIT__SHARED_SYNC_MS` — write-behind flush interval,
374    /// clamped to [`MIN_SYNC_INTERVAL_MS`]..=[`MAX_SYNC_INTERVAL_MS`].
375    /// Directly scales the cross-replica overshoot bound (module docs).
376    pub sync_interval: Duration,
377    /// Fixed-window length used only for staleness pruning; must match the
378    /// callers' `window_start()` truncation (60 s in both).
379    pub window: Duration,
380}
381
382impl Default for SharedRateLimitConfig {
383    fn default() -> Self {
384        Self {
385            enabled: true,
386            sync_interval: Duration::from_millis(DEFAULT_SYNC_INTERVAL_MS),
387            window: Duration::from_secs(DEFAULT_WINDOW_SECS),
388        }
389    }
390}
391
392impl SharedRateLimitConfig {
393    /// Reads `AXIAM__RATE_LIMIT__SHARED` and
394    /// `AXIAM__RATE_LIMIT__SHARED_SYNC_MS`.
395    ///
396    /// - `AXIAM__RATE_LIMIT__SHARED`: `off`/`false`/`0`/`no` disable the
397    ///   shared layer; anything else (including unset) leaves it **on** —
398    ///   the secure default, since disabling it re-opens the multi-replica
399    ///   limit multiplication.
400    /// - `AXIAM__RATE_LIMIT__SHARED_SYNC_MS`: parsed as `u64` milliseconds,
401    ///   clamped to [`MIN_SYNC_INTERVAL_MS`]..=[`MAX_SYNC_INTERVAL_MS`];
402    ///   unparseable or absent falls back to [`DEFAULT_SYNC_INTERVAL_MS`].
403    pub fn from_env() -> Self {
404        let enabled = match std::env::var("AXIAM__RATE_LIMIT__SHARED") {
405            Ok(raw) => !matches!(
406                raw.trim().to_ascii_lowercase().as_str(),
407                "off" | "false" | "0" | "no"
408            ),
409            Err(_) => true,
410        };
411
412        let sync_interval_ms = std::env::var("AXIAM__RATE_LIMIT__SHARED_SYNC_MS")
413            .ok()
414            .and_then(|raw| raw.trim().parse::<u64>().ok())
415            .unwrap_or(DEFAULT_SYNC_INTERVAL_MS)
416            .clamp(MIN_SYNC_INTERVAL_MS, MAX_SYNC_INTERVAL_MS);
417
418        Self {
419            enabled,
420            sync_interval: Duration::from_millis(sync_interval_ms),
421            window: Duration::from_secs(DEFAULT_WINDOW_SECS),
422        }
423    }
424}

430/// One in-process fixed-window bucket.
431///
432/// The effective count a decision is made on is `shared_count + pending`:
433/// the authoritative cross-replica count as of the last successful flush,
434/// plus this replica's own not-yet-flushed increments.
435#[derive(Debug, Clone)]
436struct Bucket {
437    /// Start of the fixed window this bucket's counts belong to. A `check`
438    /// for a different window rolls the bucket over (both counts reset).
439    window_start: DateTime<Utc>,
440    /// Authoritative store count as of the last successful flush of this
441    /// bucket in this window (already includes this replica's flushed
442    /// increments).
443    shared_count: u64,
444    /// Local increments accepted since the last successful flush and not yet
445    /// written to the store.
446    pending: u64,
447    /// When this bucket was last successfully flushed (`None` = never in this
448    /// window). Read by the flusher purely for starvation detection: if a
449    /// bucket with pending work has not been flushed for
450    /// [`OVERDUE_SYNC_MULTIPLE`] sync intervals, the write-behind loop is not
451    /// keeping up and the cross-replica overshoot bound documented in the
452    /// module docs no longer holds, which is worth one `warn`.
453    last_flush: Option<DateTime<Utc>>,
454}
455
456impl Bucket {
457    fn new(window_start: DateTime<Utc>) -> Self {
458        Self {
459            window_start,
460            shared_count: 0,
461            pending: 0,
462            last_flush: None,
463        }
464    }
465}

471/// Shared, write-behind rate-limit counter used by BOTH the REST
472/// (`RateLimitShared`) and gRPC (`GrpcSharedRateLimitLayer`) shared-store
473/// layers.
474///
475/// Cheap to clone (`Arc` inside) and MUST be shared process-wide: one
476/// instance per process, cloned into every worker. Per-worker instances would
477/// fragment the local count and weaken the limit by the worker count — this
478/// is why `axiam-api-rest` holds it in `AppState` (registered once as
479/// `web::Data`) rather than constructing one per resource.
480///
481/// See the module docs for the overshoot bound and the fail-open posture.
482#[derive(Clone)]
483pub struct SharedRateLimitCounter {
484    inner: Arc<Inner>,
485    /// Wake hint for the flusher. `None` when the counter is disabled or no
486    /// tokio runtime was available at construction (local-only mode). Held
487    /// here rather than in [`Inner`] so that dropping every clone of the
488    /// counter closes the channel and lets the flusher task exit instead of
489    /// leaking.
490    wake: Option<tokio::sync::mpsc::Sender<()>>,
491}
492
493struct Inner {
494    config: SharedRateLimitConfig,
495    /// `None` when the shared layer is disabled — no store is ever touched.
496    store: Option<Arc<dyn SharedRateLimitStore>>,
497    shards: Vec<Mutex<HashMap<String, Bucket>>>,
498    /// Latch so a persistent wake-channel problem logs once instead of once
499    /// per request (a warn per request would itself be a performance bug).
500    wake_warned: AtomicBool,
501    /// Latch for the "flusher is starved" alarm (see
502    /// [`OVERDUE_SYNC_MULTIPLE`]), for the same reason.
503    starvation_warned: AtomicBool,
504    /// I3 machine-traffic throttling advisory. Inert unless armed by
505    /// [`SharedRateLimitCounter::arm_machine_traffic_advisory`].
506    advisory: MachineTrafficAdvisory,
507}
508
509impl SharedRateLimitCounter {
510    /// Builds a counter over `store` and starts its single background
511    /// flusher task.
512    ///
513    /// Must be called from within a tokio runtime (it is: both callers
514    /// construct it during async server startup). If no runtime handle is
515    /// available, construction still succeeds but logs a `warn` and the
516    /// counter runs **local-only** — decisions keep working from local
517    /// counts, they just never converge across replicas. That is the same
518    /// fail-open degradation as a store outage, never a hard failure.
519    ///
520    /// When `config.enabled` is `false` the store is dropped on the spot, no
521    /// task is spawned, and [`Self::check`] short-circuits to "allow".
522    pub fn new(config: SharedRateLimitConfig, store: Arc<dyn SharedRateLimitStore>) -> Self {
523        if !config.enabled {
524            tracing::info!(
525                "shared rate-limit counter DISABLED (AXIAM__RATE_LIMIT__SHARED=off); \
526                 the per-replica in-memory governor is the sole rate limiter"
527            );
528            return Self::disabled(config);
529        }
530
531        let inner = Arc::new(Inner::new(config, Some(store)));
532
533        // A bounded channel of increment notifications: `check` hints that
534        // work exists, the flusher coalesces every `sync_interval`.
535        let (tx, rx) = tokio::sync::mpsc::channel(WAKE_CHANNEL_CAPACITY);
536
537        let wake = match tokio::runtime::Handle::try_current() {
538            Ok(handle) => {
539                let flusher_inner = Arc::clone(&inner);
540                handle.spawn(flusher_loop(flusher_inner, rx));
541                tracing::info!(
542                    sync_interval_ms = inner.config.sync_interval.as_millis() as u64,
543                    shards = SHARD_COUNT,
544                    "shared rate-limit counter ACTIVE (write-behind); one datastore write \
545                     per bucket per sync interval instead of one per request"
546                );
547                Some(tx)
548            }
549            Err(_) => {
550                tracing::warn!(
551                    "shared rate-limit counter started outside a tokio runtime; running \

608    /// The per-request decision: `true` = allow, `false` = deny (HTTP 429 /
609    /// gRPC `RESOURCE_EXHAUSTED`).
610    ///
611    /// Fully synchronous: one hash, one `Mutex` acquisition, a few field
612    /// updates, and a non-blocking wake hint. No datastore round trip, no
613    /// `await`, no task spawn — this is the whole point of the module.
614    ///
615    /// Semantics:
616    /// - The bucket rolls over (both counts reset to zero) whenever
617    ///   `window_start` differs from the stored one, so a caller that
618    ///   truncates `now` to its fixed window gets exact fixed-window
619    ///   behavior.
620    /// - `pending` is incremented for every call, including denied ones, so
621    ///   sustained over-limit traffic is reported to the store and thus to
622    ///   the other replicas (mirrors the previous behavior, where the
623    ///   UPSERT also ran before the limit test).
624    /// - Denies when `shared_count + pending > limit`.
625    ///
626    /// Always allows (and never touches any state) when the counter is
627    /// disabled.
628    pub fn check(&self, key: &str, window_start: DateTime<Utc>, limit: u32) -> bool {
629        if !self.inner.config.enabled {
630            return true;
631        }
632
633        let allow = {
634            let shard = self.inner.shard_for(key);
635            let mut guard = lock_shard(shard);
636            let bucket = guard
637                .entry(key.to_string())
638                .or_insert_with(|| Bucket::new(window_start));
639
640            // Window rollover: a new fixed window is a brand-new bucket.
641            // Any `pending` from the previous window is intentionally
642            // discarded — that window is closed, so its count can no longer
643            // influence a decision, and re-sending it would corrupt the new
644            // window's count.
645            if bucket.window_start != window_start {
646                *bucket = Bucket::new(window_start);
647            }
648
649            bucket.pending = bucket.pending.saturating_add(1);
650            bucket.shared_count.saturating_add(bucket.pending) <= u64::from(limit)
651        };
652
653        // I3: aggregate tally only (no key, no IP), inert unless armed.
654        self.inner.advisory.record(key, allow);
655        self.notify_flusher();
656        allow
657    }

679    /// Non-blocking wake hint for the flusher.
680    ///
681    /// A full channel is benign — a flush is already queued and the shard
682    /// maps (not the messages) carry the pending deltas, so the worst case is
683    /// that this delta waits for the flusher's next interval tick. A closed
684    /// channel means the flusher is gone; both are logged once at `warn`
685    /// (never per request, and never with the key — T-24-43) and the decision
686    /// already returned above stands.
687    fn notify_flusher(&self) {
688        let Some(tx) = &self.wake else { return };
689        if let Err(err) = tx.try_send(())
690            && !self.inner.wake_warned.swap(true, Ordering::Relaxed)
691        {
692            tracing::warn!(
693                reason = %match err {
694                    tokio::sync::mpsc::error::TrySendError::Full(_) => "wake channel full",
695                    tokio::sync::mpsc::error::TrySendError::Closed(_) => "flusher stopped",
696                },
697                "shared rate-limit flusher could not be woken; continuing to serve \
698                 decisions from local counts (logged once)"
699            );
700        }
701    }

704    /// `pending` into a single store write, adopt the returned authoritative

708    /// convergence deterministically instead of sleeping. Idempotent and
709    /// safe to call concurrently with `check`.
710    pub async fn flush_once(&self) {
711        self.inner.flush_once().await;

738impl Inner {
739    fn new(config: SharedRateLimitConfig, store: Option<Arc<dyn SharedRateLimitStore>>) -> Self {
740        let mut shards = Vec::with_capacity(SHARD_COUNT);
741        for _ in 0..SHARD_COUNT {
742            shards.push(Mutex::new(HashMap::new()));
743        }
744        // A disabled counter drops the store here, so there is no way for any
745        // later code path to reach the datastore.
746        let store = if config.enabled { store } else { None };
747        Self {
748            config,
749            store,
750            shards,
751            wake_warned: AtomicBool::new(false),
752            starvation_warned: AtomicBool::new(false),
753            advisory: MachineTrafficAdvisory::default(),
754        }
755    }
756
757    fn shard_for(&self, key: &str) -> &Mutex<HashMap<String, Bucket>> {
758        let mut hasher = DefaultHasher::new();
759        key.hash(&mut hasher);
760        &self.shards[(hasher.finish() as usize) % SHARD_COUNT]
761    }
762
763    /// See [`SharedRateLimitCounter::flush_once`].
764    ///
765    /// Three phases, so that the `std::sync::Mutex` is NEVER held across the
766    /// store `await`:
767    /// 1. Under each shard lock: prune stale buckets and collect
768    ///    `(shard, key, window, delta)` for every bucket with pending work
769    ///    that has not already been flushed within this `sync_interval`.
770    /// 2. Lock-free: one [`SharedRateLimitStore::increment_by`] per key.
771    /// 3. Re-lock briefly: adopt the authoritative count and subtract the
772    ///    flushed delta from `pending` (increments that arrived during the
773    ///    await stay pending for the next pass).
774    async fn flush_once(&self) {
775        let now = Utc::now();
776        // I3: piggy-backs on the flusher's existing cadence — no extra task,
777        // no extra timer. Runs before the store check so the advisory does
778        // not depend on store reachability.
779        self.advisory.maybe_report(now);
780
781        let Some(store) = self.store.as_ref() else {
782            return;
783        };
784
785        let work = self.collect_pending(now);
786
787        for (shard_idx, key, window, delta) in work {
788            match store.increment_by(&key, window, delta).await {
789                Ok(authoritative) => {
790                    let mut guard = lock_shard(&self.shards[shard_idx]);
791                    if let Some(bucket) = guard.get_mut(&key) {
792                        // Ignore the result if the bucket rolled over into a
793                        // new window while the write was in flight — that
794                        // count belongs to the window we just left.
795                        if bucket.window_start == window {
796                            bucket.shared_count = authoritative;
797                            bucket.pending = bucket.pending.saturating_sub(delta);
798                            bucket.last_flush = Some(now);
799                        }
800                    }
801                }
802                Err(err) => {
803                    // Fail OPEN (D-01b): a counter-store outage must never
804                    // hard-block auth traffic. `pending` is deliberately left
805                    // in place so the delta is retried on the next pass; a
806                    // retry that double-counts an UPSERT which actually
807                    // landed errs toward *stricter* limiting, which is the
808                    // safe direction for a security control.
809                    // T-24-43: never log the raw key (it embeds a client IP /
810                    // client_id).
811                    tracing::warn!(
812                        delta,
813                        error = %err,
814                        "shared rate-limit store unreachable during write-behind flush; \
815                         cross-replica convergence paused, still enforcing local counts"
816                    );
817                }
818            }
819        }
820    }
821
822    /// Phase 1 of [`Self::flush_once`]: prune + collect, one short lock per
823    /// shard, nothing awaited.
824    ///
825    /// Only buckets with `pending > 0` are collected, so an idle bucket costs
826    /// zero store writes no matter how many passes run. Since the flusher
827    /// loop itself runs at most once per `sync_interval`, "one write per
828    /// bucket per interval" follows from the loop, not from any per-bucket
829    /// suppression here — a bucket must never be skipped while it has
830    /// unflushed increments, or its replica's contribution would stay
831    /// invisible to the other replicas for an unbounded time.
832    fn collect_pending(&self, now: DateTime<Utc>) -> Vec<(usize, String, DateTime<Utc>, u64)> {
833        let stale_after = self.config.window * STALE_WINDOW_MULTIPLE;
834        let stale_cutoff = chrono::Duration::from_std(stale_after)
835            .ok()
836            .and_then(|d| now.checked_sub_signed(d));
837        let overdue_after = chrono::Duration::from_std(self.config.sync_interval)
838            .ok()
839            .map(|gap| gap * OVERDUE_SYNC_MULTIPLE);
840
841        let mut work = Vec::new();
842        let mut overdue = false;
843        for (shard_idx, shard) in self.shards.iter().enumerate() {
844            let mut guard = lock_shard(shard);
845
846            // Pruning (bounded memory): drop buckets older than
847            // STALE_WINDOW_MULTIPLE windows that have nothing left to flush.
848            if let Some(cutoff) = stale_cutoff {
849                guard.retain(|_, bucket| bucket.pending > 0 || bucket.window_start >= cutoff);
850            }
851
852            for (key, bucket) in guard.iter() {
853                if bucket.pending == 0 {
854                    continue;
855                }
856                // Starvation detection only — never suppresses a write.
857                if let (Some(last), Some(threshold)) = (bucket.last_flush, overdue_after)
858                    && now.signed_duration_since(last) > threshold
859                {
860                    overdue = true;
861                }
862                work.push((shard_idx, key.clone(), bucket.window_start, bucket.pending));
863            }
864        }
865
866        if overdue && !self.starvation_warned.swap(true, Ordering::Relaxed) {
867            // T-24-43: no raw key in the alarm.
868            tracing::warn!(
869                sync_interval_ms = self.config.sync_interval.as_millis() as u64,
870                overdue_multiple = OVERDUE_SYNC_MULTIPLE,
871                "shared rate-limit write-behind flusher is falling behind its sync \
872                 interval; cross-replica overshoot may exceed the documented bound \
873                 (logged once)"
874            );
875        }
876
877        work
878    }
879}

881/// Acquires a shard lock, recovering from poisoning instead of panicking: a
882/// panic in an unrelated task must not disable the rate limiter.
883fn lock_shard(shard: &Mutex<HashMap<String, Bucket>>) -> MutexGuard<'_, HashMap<String, Bucket>> {
884    shard
885        .lock()
886        .unwrap_or_else(|poisoned| poisoned.into_inner())
887}
888
889/// The single background flusher task.
890///
891/// Wakes on an increment notification OR on a `sync_interval` backstop tick
892/// (so a delta whose wake hint was dropped by a full channel is still
893/// flushed), drains any further queued hints, then runs one coalesced pass.
894/// Exits when every [`SharedRateLimitCounter`] clone has been dropped, so it
895/// never outlives the counter it serves.
896async fn flusher_loop(inner: Arc<Inner>, mut rx: tokio::sync::mpsc::Receiver<()>) {
897    let interval = inner.config.sync_interval;
898    loop {
899        tokio::select! {
900            hint = rx.recv() => {
901                if hint.is_none() {
902                    // All senders dropped: the counter is gone.
903                    break;
904                }
905                // Coalescing window: let further increments accumulate
906                // before paying for a store round trip.
907                tokio::time::sleep(interval).await;
908            }
909            _ = tokio::time::sleep(interval) => {}
910        }
911
912        // Drain queued hints so they don't each trigger a redundant pass.
913        while rx.try_recv().is_ok() {}
914
915        inner.flush_once().await;
916    }
917}
