1//! SurrealDB implementation of [`PermissionTicketRepository`] (UMA 2.0 / X2).
2//!
3//! # Why `consume` layers a transaction under a nonce
4//!
5//! UMA 2.0 §3.3 makes a permission ticket single-use, so a read-then-write
6//! would let two concurrent redemptions both spend one ticket. Putting the
7//! precondition — unconsumed, unexpired, right tenant, right client — in the
8//! `WHERE` clause of a single `UPDATE` is necessary but **not sufficient**: on
9//! its own, without an explicit transaction around it, eight concurrent
10//! redemptions of one ticket all succeed.
11//!
12//! Single-use **is** guaranteed here, conditional on running an attested
13//! persistent storage engine (X6, #302). It is not one mechanism but two, and
14//! a double redemption needs both to fail on the same ticket:
15//!
16//!   1. **The engine arbitrates.** The guarded `UPDATE` runs inside an explicit
17//!      `BEGIN`/`COMMIT`, so two concurrent redemptions are a write-write
18//!      conflict on one key and the loser is aborted. Measured with
19//!      `tools/surreal-race-probe` on the engines AXIAM deploys: 0 double
20//!      redemptions in 5000 rounds of 8 racers on `surrealkv` (what compose and
21//!      the k8s StatefulSet run) and 0 in 1200 on `rocksdb`, with the engine
22//!      aborting 54% of contended attempts. `kv-mem` aborts at the same rate
23//!      and then silently misses 23 times in 1200 — which is what "conditional
24//!      on a persistent engine" means, and why `axiam-server` attests the
25//!      engine at startup (`axiam_db::engine_attestation`).
26//!   2. **The nonce audits it.** Each attempt stamps its own `redemption_id`,
27//!      and after the transaction commits a separate query reads the row back;
28//!      only the caller whose nonce survived reports a redemption. This asks
29//!      the engine for nothing, so a conflict the engine misses is caught here
30//!      **unless the two commits interleave around the read-back** — if A
31//!      commits, A reads back and sees its own nonce, and only then B's
32//!      concurrent transaction commits, B's later read-back sees B's nonce and
33//!      both callers report a redemption (SEC-105). So what this layer buys is
34//!      precisely what §X6.2 promises and no more: a double redemption needs
35//!      **two independent failures**, not one. It is not "the nonce catches
36//!      any conflict the engine misses" — the project's own measurement agrees,
37//!      recording the nonce-with-read-back shape at 1/640 on `kv-mem`
38//!      (`claude_dev/extra-B-track-features.md` §X6.1).
39//!
40//! The read-back **must** stay outside the transaction, in a query of its own
41//! after the commit. Inside it, snapshot isolation shows every racer its own
42//! write and every racer believes it won — the occasional double redemption
43//! becomes a guaranteed one. `SCHEMA_V31` records that trap and the layering.
44//!
45//! On `kv-mem` single-use is explicitly **not** guaranteed: the nonce leaks
46//! there too (6 rounds in 1200). Running it is now an operator's deliberate,
47//! logged choice rather than an accident — see `ALLOW_MEMORY_ENGINE_ENV`.
48//!
49//! Neither is a uniqueness constraint an alternative: a claim keyed on a record
50//! ID is far worse (30/1200), and a `UNIQUE` index tripled the failure rate in
51//! this path (3/320 against 1/320) because the extra write lengthens the window
52//! without reliably being enforced. `SCHEMA_V31` carries the full comparison,
53//! and #302 records why no fifth query-layer mechanism was sought.
54//!
55//! `concurrent_redemptions_yield_exactly_one_winner` is the regression test. It
56//! runs on `surrealkv` and over many rounds as of 2026-08; before that it ran
57//! one unsynchronised round against `kv-mem`, which is why the residual it was
58//! meant to guard went unobserved in CI for as long as it did. The test that
59//! fails the OLD mechanism reliably — #302's acceptance bar — is the probe
60//! itself, `surreal-race-probe mem tx 1200 8`; see its README.
61//!
62//! # Why `client_id` is in that clause and not checked afterwards
63//!
64//! A ticket is bound to the resource server that minted it. If the binding
65//! were checked on the returned row, a ticket leaked to another client would
66//! be *burned* by that client's failed attempt — the rightful holder's ticket
67//! destroyed by someone who was never entitled to it. Matching it in the
68//! statement means a wrong-client redemption changes nothing.

83/// Projected explicitly rather than `SELECT *` so that `meta::id(id)` lands in
84/// `record_id`; a bare `*` yields SurrealDB's `Thing`, which does not
85/// deserialize into a `String`.
86const SELECT_FIELDS: &str = "meta::id(id) AS record_id, tenant_id, client_id, \
87     ticket_hash, permissions, consumed, expires_at, created_at";

89#[derive(Debug, SurrealValue)]
90struct PermissionTicketRow {
91    record_id: String,
92    tenant_id: String,
93    client_id: String,
94    ticket_hash: String,
95    permissions: Vec<RequestedPermissionRow>,
96    consumed: bool,
97    expires_at: DateTime<Utc>,
98    created_at: DateTime<Utc>,
99}
100
101/// One stored `(resource, scopes)` tuple.
102///
103/// A row type of its own rather than reusing [`RequestedPermission`] directly
104/// because the domain type is `serde`-shaped and this one is
105/// `SurrealValue`-shaped — the same split every other repository here uses.
106/// `resource_id` is stored as a string for the same reason `tenant_id` is.
107#[derive(Debug, SurrealValue)]
108struct RequestedPermissionRow {
109    resource_id: String,
110    resource_scopes: Vec<String>,
111}
112
113impl From<RequestedPermission> for RequestedPermissionRow {
114    fn from(p: RequestedPermission) -> Self {
115        Self {
116            resource_id: p.resource_id.to_string(),
117            resource_scopes: p.resource_scopes,
118        }
119    }
120}
121
122impl RequestedPermissionRow {
123    fn try_into_permission(self) -> Result<RequestedPermission, DbError> {
124        Ok(RequestedPermission {
125            resource_id: Uuid::parse_str(&self.resource_id)
126                .map_err(|e| DbError::Migration(format!("invalid resource UUID: {e}")))?,
127            resource_scopes: self.resource_scopes,
128        })
129    }
130}
131
132impl PermissionTicketRow {
133    fn try_into_ticket(self) -> Result<PermissionTicket, DbError> {
134        let id = Uuid::parse_str(&self.record_id)
135            .map_err(|e| DbError::Migration(format!("invalid permission ticket UUID: {e}")))?;
136        let tenant_id = Uuid::parse_str(&self.tenant_id)
137            .map_err(|e| DbError::Migration(format!("invalid tenant UUID: {e}")))?;
138        let permissions = self
139            .permissions
140            .into_iter()
141            .map(RequestedPermissionRow::try_into_permission)
142            .collect::<Result<Vec<_>, _>>()?;
143        Ok(PermissionTicket {
144            id,
145            tenant_id,
146            ticket_hash: self.ticket_hash,
147            client_id: self.client_id,
148            permissions,
149            consumed: self.consumed,
150            expires_at: self.expires_at,
151            created_at: self.created_at,
152        })
153    }
154}

156/// SurrealDB implementation of the permission-ticket repository.
157#[derive(Clone)]
158pub struct SurrealPermissionTicketRepository<C: Connection> {
159    db: DbHandle<C>,
160}

162impl<C: Connection> SurrealPermissionTicketRepository<C> {
163    pub fn new(db: impl Into<DbHandle<C>>) -> Self {
164        Self { db: db.into() }
165    }
166}

168impl<C: Connection> PermissionTicketRepository for SurrealPermissionTicketRepository<C> {
169    async fn create(&self, input: CreatePermissionTicket) -> AxiamResult<PermissionTicket> {
170        let id = new_id();
171        let permissions: Vec<RequestedPermissionRow> = input
172            .permissions
173            .into_iter()
174            .map(RequestedPermissionRow::from)
175            .collect();
176
177        let mut result = self
178            .db
179            .current()
180            .query(format!(
181                "LET $created = (CREATE type::record('permission_ticket', $id) SET \
182                     tenant_id = $tenant_id, \
183                     client_id = $client_id, \
184                     ticket_hash = $hash, \
185                     permissions = $permissions, \
186                     consumed = false, \
187                     expires_at = $expires_at); \
188                 SELECT {SELECT_FIELDS} FROM $created"
189            ))
190            .bind(("id", id.to_string()))
191            .bind(("tenant_id", input.tenant_id.to_string()))
192            .bind(("client_id", input.client_id))
193            .bind(("hash", input.ticket_hash))
194            .bind(("permissions", permissions))
195            .bind(("expires_at", input.expires_at))
196            .await
197            .map_err(DbError::from)?;
198
199        let rows: Vec<PermissionTicketRow> = result.take(1).map_err(DbError::from)?;
200        rows.into_iter()
201            .next()
202            .ok_or_else(|| DbError::Migration("permission_ticket insert returned no row".into()))?
203            .try_into_ticket()
204            .map_err(Into::into)
205    }
206
207    async fn consume(
208        &self,
209        tenant_id: Uuid,
210        ticket_hash: &str,
211        client_id: &str,
212    ) -> AxiamResult<Option<PermissionTicket>> {
213        // `RETURN BEFORE` yields the pre-transition row. Marking `consumed`
214        // rather than deleting keeps "already used" distinguishable from
215        // "never existed" for the audit trail, even though both answer
216        // `invalid_grant` on the wire.
217        //
218        // Two layers, in two queries (X6/#302 — see the module header).
219        //
220        // Layer 1, here: the guarded `UPDATE` inside an explicit transaction,
221        // so two concurrent redemptions conflict on one key and the deployed
222        // engine aborts the loser. `WHERE consumed = false` is still required
223        // — it is what makes a later, non-concurrent replay match nothing and
224        // leave the first winner's nonce undisturbed.
225        //
226        // Layer 2, in the SEPARATE query below: read the nonce back after this
227        // transaction has committed. It must not be folded into the statements
228        // here. Under snapshot isolation a racer inside the transaction sees
229        // its own write, so every racer would read back its own nonce and
230        // believe it won — an occasional double redemption would become a
231        // certain one (`SCHEMA_V31`).
232        let nonce = new_id().to_string();
233        let result = self
234            .db
235            .current()
236            .query(format!(
237                "BEGIN TRANSACTION; \
238                 LET $before = (UPDATE permission_ticket \
239                     SET consumed = true, redemption_id = $nonce \
240                     WHERE tenant_id = $tenant_id AND ticket_hash = $hash \
241                     AND client_id = $client_id \
242                     AND consumed = false AND expires_at > time::now() \
243                     RETURN BEFORE); \
244                 SELECT {SELECT_FIELDS} FROM $before; \
245                 COMMIT TRANSACTION"
246            ))
247            .bind(("tenant_id", tenant_id.to_string()))
248            .bind(("hash", ticket_hash.to_string()))
249            .bind(("client_id", client_id.to_string()))
250            .bind(("nonce", nonce.clone()))
251            .await;
252
253        // A loser's abort is this method's "someone else redeemed first"
254        // answer, not a server fault; propagating it would turn a
255        // correctly-refused replay into a 500.
256        let mut result = match result {
257            Ok(r) => r,
258            Err(e) if is_transaction_conflict(&e) => return Ok(None),
259            Err(e) => return Err(DbError::from(e).into()),
260        };
261
262        // BEGIN=0, LET=1, SELECT=2, COMMIT=3.
263        let rows: Vec<PermissionTicketRow> = match result.take::<Vec<PermissionTicketRow>>(2) {
264            Ok(rows) => rows,
265            Err(e) if is_transaction_conflict(&e) => return Ok(None),
266            Err(e) => return Err(DbError::from(e).into()),
267        };
268        if rows.is_empty() {
269            // Nothing matched: unknown, already consumed, expired, or the
270            // wrong client. No write happened, so nothing was burned.
271            return Ok(None);
272        }
273
274        // Layer 2: outside, and after, the transaction above.
275        let stored = self
276            .db
277            .current()
278            .query(
279                "SELECT VALUE redemption_id FROM permission_ticket \
280                 WHERE tenant_id = $tenant_id AND ticket_hash = $hash LIMIT 1",
281            )
282            .bind(("tenant_id", tenant_id.to_string()))
283            .bind(("hash", ticket_hash.to_string()))
284            .await;
285        let mut stored = match stored {
286            Ok(r) => r,
287            Err(e) if is_transaction_conflict(&e) => return Ok(None),
288            Err(e) => return Err(DbError::from(e).into()),
289        };
290        let stored: Vec<Option<String>> = match stored.take::<Vec<Option<String>>>(0) {
291            Ok(v) => v,
292            Err(e) if is_transaction_conflict(&e) => return Ok(None),
293            Err(e) => return Err(DbError::from(e).into()),
294        };
295        if stored.into_iter().flatten().next().as_deref() != Some(nonce.as_str()) {
296            // Our write landed but someone else's landed after it. They hold
297            // the redemption; this caller must not also report one. The ticket
298            // is spent either way, so `consumed` staying true is correct.
299            return Ok(None);
300        }
301
302        rows.into_iter()
303            .next()
304            .map(PermissionTicketRow::try_into_ticket)
305            .transpose()
306            .map_err(Into::into)
307    }

309    async fn find_by_hash(
310        &self,
311        tenant_id: Uuid,
312        ticket_hash: &str,
313    ) -> AxiamResult<Option<PermissionTicket>> {
314        let mut result = self
315            .db
316            .current()
317            .query(format!(
318                "SELECT {SELECT_FIELDS} FROM permission_ticket \
319                 WHERE tenant_id = $tenant_id AND ticket_hash = $hash LIMIT 1"
320            ))
321            .bind(("tenant_id", tenant_id.to_string()))
322            .bind(("hash", ticket_hash.to_string()))
323            .await
324            .map_err(DbError::from)?;
325
326        let rows: Vec<PermissionTicketRow> = result.take(0).map_err(DbError::from)?;
327        rows.into_iter()
328            .next()
329            .map(PermissionTicketRow::try_into_ticket)
330            .transpose()
331            .map_err(Into::into)
332    }

334    async fn cleanup_expired(&self, tenant_id: Uuid) -> AxiamResult<u64> {
335        let mut result = self
336            .db
337            .current()
338            .query(
339                "SELECT count() AS c FROM (DELETE permission_ticket \
340                 WHERE tenant_id = $tenant_id AND expires_at <= time::now() \
341                 RETURN BEFORE) GROUP ALL",
342            )
343            .bind(("tenant_id", tenant_id.to_string()))
344            .await
345            .map_err(DbError::from)?;
346
347        #[derive(Debug, SurrealValue)]
348        struct CountRow {
349            c: i64,
350        }
351        let rows: Vec<CountRow> = result.take(0).map_err(DbError::from)?;
352        Ok(rows.into_iter().next().map(|r| r.c as u64).unwrap_or(0))
353    }
