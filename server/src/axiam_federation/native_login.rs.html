1//! G-A — a provider-issued **ID token**, presented by a native app, verified
2//! as a sign-in.
3//!
4//! Design: `claude_dev/social-login-gap-plan-2026-10-30.md` §3.1. The rule
5//! every function here applies:
6//!
7//! > **An ID token is accepted as a sign-in only when it was issued to us.**
8//!
9//! "Us" is one of the client IDs an operator listed in the provider's
10//! `native_login.client_ids` for exactly this purpose — not the provider's web
11//! `client_id` unless it is listed, and never "any audience". The party a
12//! token was issued to is its `azp` when it carries one, otherwise its single
13//! `aud` (D-N17, see [`issued_to`]).
14//!
15//! This module answers one question: *which AXIAM user does this ID token
16//! prove signed in, through which provider?* The grant that turns the answer
17//! into a token set lives in `axiam-oauth2` (W2.3).
18//!
19//! # The order is the design
20//!
21//! [`OidcFederationService::verify_native_id_token`] runs these steps in this
22//! order, each before the next (step 1, client authentication and the grant
23//! gate, is the token endpoint's):
24//!
25//! 2. **Provider**: the request's `provider` (UUID or `provider_slug`) names
26//!    an *effective* provider of the requesting tenant — its own, or inherited
27//!    from its organization, exactly as the browser login's provider listing
28//!    resolves it ([`crate::provider_resolution`]) — that is enabled, speaks
29//!    OIDC and has `native_login.enabled`. A provider of another tenant is not
30//!    found.
31//! 3. **Header**: `alg=none` refused on the raw header, `alg` within the
32//!    provider's `allowed_algorithms`, `kid` resolved through the JWKS cache
33//!    with its rate-limited rollover refetch — no new fetch surface.
34//! 4. **Signature and claims**, through the browser login's own verification
35//!    core: `iss` exactly the discovered issuer; the token issued to a listed
36//!    client ID, **azp-first** (D-N17): a listed `azp`, with `aud` (string or
37//!    array) containing a listed ID or the provider's web `client_id` — the
38//!    shape of Google's Android tokens — or, with no `azp`, a single listed
39//!    `aud` (several audiences need an `azp`, OIDC Core §3.1.3.7); `exp` in
40//!    the future within the 60 s leeway (D-05); `iat` neither older than
41//!    `max_token_age_secs` nor in the future beyond the leeway.
42//! 5. **Shape**: an ID token and nothing else — `nonce` present and equal, in
43//!    constant time, to the SHA-256 hex of the request's nonce, the claim's
44//!    hex letters compared without regard to case (D-N16, D-N21; the app gives
45//!    the provider SDK the hash and AXIAM the raw value); an access-token
46//!    `typ` (`at+jwt`) refused. The marker list is [`crate::token_shape`]'s,
47//!    the same one X4 refuses by.
48//! 6. **Replay**: the SHA-256 of the token's JWS signing input (the bytes
49//!    before its second `.`) recorded in the replay store under its issuer,
50//!    deployment-wide (D-N19), until `exp` plus twice the leeway; a second
51//!    presentation through any tenant or configuration is refused, and a store
52//!    that cannot record refuses too.
53//! 7. **Subject**: the browser login's resolution, unchanged —
54//!    `map_identity(provider_kind, attribute_map, claims)` and then
55//!    `provision_or_link_identity`, provisioning on first sign-in, adopting no
56//!    email as verified; then `account_may_act`. A first sign-in whose mapped
57//!    username or email another account holds is the generic refusal
58//!    (`provisioning_conflict`), not a server error (F4-W2-10).
59//!
60//! # Why the replay guard sits where it does
61//!
62//! The store is keyed on the SHA-256 of the token's **signing input** —
63//! `base64url(header) "." base64url(payload)`, the exact bytes before the
64//! second `.`, which the signature covers — and a row is written only once
65//! steps 2–5 have all passed.
66//!
67//! The signature part is left out of the key on purpose (F4-W2-11). An
68//! ECDSA signature has a second valid encoding (`s` → `n − s`), so an
69//! ES256/ES384 token has two compact strings that both verify; hashing the
70//! whole string recorded them as two tokens and let one be spent twice. The
71//! signing input has one spelling per token: changing a byte of it breaks the
72//! signature. That covers any malleable algorithm, not only ECDSA.
73//!
74//! * **Not before the signature (step 4).** Then anyone could write rows: a
75//!   stream of garbage tokens would fill the table. A forged token can never
76//!   take a genuine token's slot either way — its signed bytes, and so its
77//!   hash, differ — but only a verified token, one the provider really issued to a
78//!   listed client ID, is ever recorded.
79//! * **Not before the nonce (step 5).** Then someone who obtained a victim's
80//!   genuine token without the nonce it is bound to (from a log, a proxy, a
81//!   crash report) could present it, fail the nonce check *after* burning its
82//!   hash, and turn the victim's own sign-in into a "replay". Recorded after
83//!   step 5, only a presenter holding both the token and its raw nonce — the
84//!   app that started the sign-in — can spend it. That holds because the
85//!   token carries only the nonce's SHA-256 (D-N16): the claim a token holder
86//!   can read from the payload is not the value the request must carry. When
87//!   the claim itself was accepted too, copying it passed (F4-W2-02).
88//! * **Not after subject resolution (step 7).** Then two concurrent
89//!   presentations would both resolve, and both sign in, before either
90//!   recorded. The insert is the one atomic decision (a UNIQUE index), placed
91//!   after everything that proves the presentation genuine and before anything
92//!   that acts on it.
93//!
94//! # What the caller learns
95//!
96//! Every refusal past step 2 is one generic answer on the wire (the X4 rule:
97//! a wrong token and a wrong configuration are told apart only in the server
98//! log); [`NativeLoginError`] keeps the distinctions for logs, audit and tests.
99//! The raw token is never logged, never stored, never returned.

130/// A native sign-in request, as the token endpoint received it.
131///
132/// Holds the token by reference only; nothing here is retained.
133#[derive(Clone, Copy)]
134pub struct NativeIdTokenRequest<'a> {
135    /// The provider: its UUID, or its `provider_slug`.
136    pub provider: &'a str,
137    /// The ID token the provider issued to the app.
138    pub id_token: &'a str,
139    /// The raw nonce the app generated. The provider's SDK was given its

202/// Why a native sign-in was refused.
203///
204/// The variants are for the server log, the audit record and the tests; the
205/// wire sees only [`NativeLoginError::refusal`]. No variant carries the token.
206#[derive(Debug, Clone, PartialEq, Eq)]
207pub enum NativeLoginError {
208    /// Step 2: no effective, enabled, OIDC, native-login-enabled provider of
209    /// this tenant is named by the request (unknown, another tenant's,
210    /// disabled, SAML, OAuth2, native login off, or an unusable block).
211    ProviderNotFound,
212    /// Step 2: the provider's discovery document could not be read.
213    ProviderUnavailable(String),
214    /// Step 3: `alg` is `none` or not in the provider's `allowed_algorithms`.
215    AlgorithmRefused,
216    /// Step 3: no JWKS key matches the `kid`, after one rollover refetch.
217    UnknownKey,
218    /// Step 3: the provider's JWKS could not be fetched.
219    KeysUnavailable(String),
220    /// Step 4: the signature does not verify, or the token is not a JWS.
221    BadSignature,
222    /// Step 4: `iss` is not the provider's discovered issuer.
223    WrongIssuer,
224    /// Step 4: with no `azp`, the single `aud` is not listed; with a listed
225    /// `azp`, `aud` names neither a listed ID nor the provider's web
226    /// `client_id`.
227    WrongAudience,
228    /// Step 4: the `azp` is present and not listed (or not a string), or `aud`
229    /// has several members and there is no `azp`.
230    AuthorizedPartyRefused,
231    /// Step 4: `exp` has passed, beyond the leeway.
232    Expired,
233    /// Step 4: `iat` is older than the provider's `max_token_age_secs`.
234    TooOld,
235    /// Step 4: `iat` is in the future beyond the leeway.
236    IssuedInFuture,
237    /// Step 4: another claim was refused (missing, malformed, empty `sub`).
238    ClaimRejected(String),
239    /// Step 5: the token has an access-token or refresh/logout `typ`.
240    WrongTokenShape(String),
241    /// Step 5: the token has no `nonce` — it is not an ID token from a flow
242    /// the app bound to a nonce.
243    NonceMissing,
244    /// Step 5: the `nonce` is not the SHA-256 hex (in either case) of the
245    /// request's nonce (a claim equal to the request's value unhashed
246    /// included), or the request carried none.
247    NonceMismatch,
248    /// Step 6: this token was presented before.
249    Replayed,
250    /// Step 6: the replay store could not record the token, so it is refused.
251    ReplayGuardUnavailable(String),
252    /// Step 7: the provider's attribute map yields no external subject.
253    SubjectUnmapped,
254    /// Step 7: provisioning a first-time user collided with an existing
255    /// account's username or email. Refused with the same generic answer as
256    /// every other token problem, not as a server error (F4-W2-10), so it
257    /// cannot be told apart from those refusals.
258    ///
259    /// It *can* be told apart from success: a caller who controls a provider
260    /// identity whose email it chooses learns from refusal versus sign-in
261    /// whether the mapped email or username is taken. That oracle is intrinsic
262    /// to first-sign-in provisioning and is shared with the browser login; it
263    /// is a recorded residual (F4-W2-12, D-N20, T-491), which a later release
264    /// may remove by changing provisioning.
265    ProvisioningConflict,
266    /// Step 7: the account may not act (locked, inactive, anonymized,
267    /// deleted); the text is `account_may_act`'s.
268    AccountRefused(String),
269    /// A datastore failure outside the replay store.
270    Server(String),
271}

365    /// Map a refusal of the shared verification core (steps 3 and 4).
366    fn from_check(e: IdTokenCheckError) -> Self {
367        use jsonwebtoken::errors::ErrorKind;
368        match e {
369            IdTokenCheckError::Federation(f) => match f {
370                FederationError::AlgorithmNotAllowed(_) => Self::AlgorithmRefused,
371                FederationError::JwtSignatureInvalid => Self::BadSignature,
372                FederationError::JwksKidUnknown => Self::UnknownKey,
373                FederationError::JwksFetchFailed(m) => Self::KeysUnavailable(m),
374                other => Self::ClaimRejected(other.to_string()),
375            },
376            IdTokenCheckError::Claims(e) => match e.kind() {
377                ErrorKind::InvalidIssuer => Self::WrongIssuer,
378                ErrorKind::InvalidAudience => Self::WrongAudience,
379                ErrorKind::ExpiredSignature => Self::Expired,
380                other => Self::ClaimRejected(format!("{other:?}")),
381            },
382        }
383    }

390/// Lowercase hex SHA-256 — the nonce form the token carries (D-N16), and
391/// the replay key over a token's signing input ([`replay_key`]).
392fn sha256_hex(input: &str) -> String {
393    hex::encode(Sha256::digest(input.as_bytes()))
394}
395
396/// Step 6's replay key: the lowercase hex SHA-256 of the token's JWS signing
397/// input, `base64url(header) "." base64url(payload)` — the exact bytes before
398/// the second `.` — never of the whole compact token (F4-W2-11).
399///
400/// The signature is outside what it signs, and for ECDSA it has a second
401/// valid encoding (`s` → `n − s`): hashing it too would key one token under
402/// two strings. `None` for a string with fewer than two dots, which cannot
403/// have passed verification.
404fn replay_key(token: &str) -> Option<String> {
405    let mut dots = token.match_indices('.').map(|(i, _)| i);
406    dots.next()?;
407    let second = dots.next()?;
408    Some(sha256_hex(&token[..second]))
409}
410
411/// The token's `nonce` claim with its ASCII hex letters `A`–`F` folded to
412/// lower case and every other byte left as it is (D-N21, F4-W2-14). Only hex
413/// case is forgiven: a claim with any non-hex character still differs from
414/// every SHA-256 hex and is refused.
415fn fold_hex_case(claim: &str) -> Vec<u8> {
416    claim
417        .bytes()
418        .map(|b| match b {
419            b'A'..=b'F' => b.to_ascii_lowercase(),
420            other => other,
421        })
422        .collect()
423}

445/// Step 4's audience rule beyond the decoder's: which listed client ID the
446/// token was issued to — **azp-first** (D-N17, F4-W2-03).
447///
448/// * With an `azp`, the `azp` is the party the token was issued to (OIDC Core
449///   §2), so it must be listed. `aud` must then contain a listed ID or the
450///   provider's own web `client_id`: Google issues an Android app's token
451///   for the *server* client it asks for, so `aud` is the web client and
452///   `azp` the Android client. A token for some third party that merely
453///   carries one of our IDs in `aud` has a foreign `azp`, and is refused.
454/// * Without an `azp`, `aud` must be one listed value (an iOS token without a
455///   server client). Several audiences need an `azp` (OIDC Core §3.1.3.7).
456///
457/// So a browser-flow token — `aud` the web client, `azp` the web client or
458/// absent — is refused unless the operator lists the web client, which
459/// admits exactly those tokens and which the docs advise against.
460///
461/// `web_client_id` is the provider's configured `client_id`; empty means
462/// none, and matches nothing.
463fn issued_to(
464    client_ids: &[String],
465    web_client_id: &str,
466    aud: Option<&serde_json::Value>,
467    azp: Option<&serde_json::Value>,
468) -> Result<String, NativeLoginError> {
469    let audiences = flatten_audience(aud);
470    let listed = |v: &str| client_ids.iter().any(|c| c == v);
471    if audiences.is_empty() {
472        return Err(NativeLoginError::WrongAudience);
473    }
474    match azp {
475        Some(azp) => {
476            let azp = azp
477                .as_str()
478                .filter(|azp| listed(azp))
479                .ok_or(NativeLoginError::AuthorizedPartyRefused)?;
480            let addressed = audiences
481                .iter()
482                .any(|a| listed(a) || (!web_client_id.is_empty() && a == web_client_id));
483            if addressed {
484                Ok(azp.to_owned())
485            } else {
486                Err(NativeLoginError::WrongAudience)
487            }
488        }
489        None => match audiences.as_slice() {
490            [one] if listed(one) => Ok(one.clone()),
491            [_] => Err(NativeLoginError::WrongAudience),
492            _ => Err(NativeLoginError::AuthorizedPartyRefused),
493        },
494    }
495}

497/// Step 4's age rule: `iat` neither in the future beyond the leeway nor older
498/// than the provider allows. The bound is inclusive.
499fn check_iat(iat: Option<u64>, now: i64, max_age_secs: i64) -> Result<(), NativeLoginError> {
500    let iat = iat
501        .and_then(|v| i64::try_from(v).ok())
502        .ok_or_else(|| NativeLoginError::ClaimRejected("no usable 'iat'".into()))?;
503    if iat > now + CLOCK_SKEW_LEEWAY_SECS as i64 {
504        return Err(NativeLoginError::IssuedInFuture);
505    }
506    if now - iat > max_age_secs {
507        return Err(NativeLoginError::TooOld);
508    }
509    Ok(())
510}

512/// Step 5: the token is an ID token bound to this request's nonce.
513///
514/// `typ` (header or claim) must not name an access, refresh or logout token;
515/// `nonce` must be present and equal, in constant time, to the lower-case
516/// SHA-256 hex of the request nonce (D-N16, F4-W2-02), after the claim's hex
517/// letters are folded to lower case, so an app whose hex helper emits upper
518/// case is not refused (D-N21, F4-W2-14). The raw form — a claim
519/// equal to the request's value — is **not** accepted: a JWT payload is
520/// readable by whoever holds the token, so accepting the claim itself would
521/// let a token's holder copy it into the request. With the hashed form the
522/// value to present is a SHA-256 preimage of what the token carries.
523fn check_shape(
524    header_typ: Option<&str>,
525    raw: &serde_json::Value,
526    request_nonce: &str,
527) -> Result<(), NativeLoginError> {
528    let claim_typ = raw.get("typ").and_then(serde_json::Value::as_str);
529    for typ in [header_typ, claim_typ].into_iter().flatten() {
530        let normalized = token_shape::normalize_typ(typ);
531        if token_shape::refused_as_native_id_token(&normalized) {
532            return Err(NativeLoginError::WrongTokenShape(normalized));
533        }
534    }
535
536    let Some(token_nonce) = raw.get(REQUIRED_MARKER).and_then(serde_json::Value::as_str) else {
537        return Err(NativeLoginError::NonceMissing);
538    };
539    if request_nonce.is_empty() || token_nonce.is_empty() {
540        return Err(NativeLoginError::NonceMismatch);
541    }
542    let hashed = sha256_hex(request_nonce);
543    if bool::from(
544        fold_hex_case(token_nonce)
545            .as_slice()
546            .ct_eq(hashed.as_bytes()),
547    ) {
548        Ok(())
549    } else {
550        Err(NativeLoginError::NonceMismatch)
551    }
552}

557
558impl<FC, FL, UR> OidcFederationService<FC, FL, UR>
559where
560    FC: FederationConfigRepository,
561    FL: FederationLinkRepository,
562    UR: UserRepository,
563{
564    /// Verify a provider-issued ID token presented for native sign-in into
565    /// `tenant_id`, and resolve the AXIAM user it signs in.
566    ///
567    /// Runs §3.1 steps 2–7 in order (see the module documentation). `now` is
568    /// the caller's clock in seconds since the epoch, used for the `iat`
569    /// rules; `exp` is checked by the decoder against the system clock with
570    /// the same 60 s leeway the browser login uses.
571    ///
572    /// The caller (W2.3) has authenticated the client and checked that it may
573    /// use the grant; it maps every error through
574    /// [`NativeLoginError::refusal`] and records
575    /// [`NativeLoginError::reason_code`] in the audit trail.
576    ///
577    /// # Errors
578    ///
579    /// [`NativeLoginError`], one variant per refused check.
580    pub async fn verify_native_id_token<TR, RR>(
581        &self,
582        tenants: &TR,
583        replay: &RR,
584        tenant_id: Uuid,
585        request: &NativeIdTokenRequest<'_>,
586        now: i64,
587    ) -> Result<NativeSubject, NativeLoginError>
588    where
589        TR: TenantRepository,
590        RR: ProviderIdTokenReplayRepository,
591    {
592        let result = self
593            .verify_native_id_token_inner(tenants, replay, tenant_id, request, now)
594            .await;
595        if let Err(ref e) = result {
596            // The reason, never the token. Configuration problems at warn so an
597            // operator sees them; token problems at debug, because a stream of
598            // bad tokens is a client's bug or an attack and not actionable here.
599            match e {
600                NativeLoginError::ProviderUnavailable(_)
601                | NativeLoginError::KeysUnavailable(_)
602                | NativeLoginError::ReplayGuardUnavailable(_)
603                | NativeLoginError::Server(_) => warn!(
604                    tenant_id = %tenant_id,
605                    reason = e.reason_code(),
606                    detail = %e,
607                    "native sign-in refused"
608                ),
609                _ => debug!(
610                    tenant_id = %tenant_id,
611                    reason = e.reason_code(),
612                    detail = %e,
613                    "native sign-in refused"
614                ),
615            }
616        }
617        result
618    }
619
620    async fn verify_native_id_token_inner<TR, RR>(
621        &self,
622        tenants: &TR,
623        replay: &RR,
624        tenant_id: Uuid,
625        request: &NativeIdTokenRequest<'_>,
626        now: i64,
627    ) -> Result<NativeSubject, NativeLoginError>
628    where
629        TR: TenantRepository,
630        RR: ProviderIdTokenReplayRepository,
631    {
632        // --- 2. Which provider? ---------------------------------------------
633        let (config, inherited) = self
634            .resolve_native_provider(tenants, tenant_id, request.provider)
635            .await?;
636        let trust = &config.native_login;
637        let metadata_url = config.metadata_url.as_deref().ok_or_else(|| {
638            NativeLoginError::ProviderUnavailable("no metadata URL configured".into())
639        })?;
640        let discovery = self
641            .discover(metadata_url)
642            .await
643            .map_err(|e| NativeLoginError::ProviderUnavailable(e.to_string()))?;
644
645        // --- 3 and 4. Header, key, signature, iss, aud, exp ------------------
646        // The browser login's verification core, with the native client IDs
647        // and the provider's web `client_id` as the audiences the decoder
648        // admits, and the same JWKS cache key, so the two share one rollover
649        // state for this provider. The web client is admitted here only so a
650        // token addressed to it can reach `issued_to`, which accepts it solely
651        // as the `aud` of a token whose `azp` is listed (D-N17).
652        let mut audiences: Vec<&str> = trust.client_ids.iter().map(String::as_str).collect();
653        if !config.client_id.is_empty() && !audiences.contains(&config.client_id.as_str()) {
654            audiences.push(config.client_id.as_str());
655        }
656        let checked = self
657            .verify_id_token_core(
658                request.id_token,
659                &discovery,
660                &audiences,
661                &config.allowed_algorithms,
662                &config.allowed_issuer_tenants,
663                (config.tenant_id, config.id),
664            )
665            .await
666            .map_err(NativeLoginError::from_check)?;
667        let claims = &checked.verified.claims;
668        let raw = &checked.verified.raw;
669
670        let audience = issued_to(
671            &trust.client_ids,
672            &config.client_id,
673            claims.aud.as_ref(),
674            raw.get("azp"),
675        )?;
676        check_iat(claims.iat, now, trust.max_token_age_secs)?;
677        let id_token_exp = claims
678            .exp
679            .and_then(|v| i64::try_from(v).ok())
680            .ok_or_else(|| NativeLoginError::ClaimRejected("no usable 'exp'".into()))?;
681        if claims.sub.trim().is_empty() {
682            return Err(NativeLoginError::ClaimRejected("empty 'sub'".into()));
683        }
684        let issuer = claims
685            .iss
686            .clone()
687            .ok_or_else(|| NativeLoginError::ClaimRejected("no 'iss'".into()))?;
688
689        // --- 5. Shape: an ID token, bound to this request's nonce ------------
690        check_shape(checked.header.typ.as_deref(), raw, request.nonce)?;
691
692        // --- 6. Replay: spend the token, once --------------------------------
693        // After the signature (a forged token records nothing) and before the
694        // subject (two concurrent presentations cannot both resolve). Keyed on
695        // the issuer and the hash only (D-N19): a token is spent once across
696        // the deployment, whichever tenant or provider configuration lists the
697        // app it was issued to. The hash is over the signing input, not the
698        // whole token, so an ECDSA signature's second encoding is the same
699        // token (F4-W2-11).
700        //
701        // The row is kept to `exp` plus *twice* the leeway. `exp` is checked
702        // here against this node's clock with one leeway; the sweep deletes by
703        // the database's clock. The second leeway keeps a row alive while any
704        // node within 60 s of the database would still accept the token.
705        let expires_at = chrono::DateTime::<chrono::Utc>::from_timestamp(
706            id_token_exp.saturating_add(2 * CLOCK_SKEW_LEEWAY_SECS as i64),
707            0,
708        )
709        .ok_or_else(|| NativeLoginError::ClaimRejected("'exp' is not a date".into()))?;
710        let token_hash = replay_key(request.id_token)
711            .ok_or_else(|| NativeLoginError::ClaimRejected("not a compact JWS".into()))?;
712        match replay
713            .insert_id_token(&issuer, &token_hash, expires_at)
714            .await
715        {
716            Ok(()) => {}
717            Err(AxiamError::ReplayDetected) => return Err(NativeLoginError::Replayed),
718            // A guard that cannot record must not accept: the token would be
719            // single-use only while the datastore is up (the CIBA rule).
720            Err(e) => return Err(NativeLoginError::ReplayGuardUnavailable(e.to_string())),
721        }
722
723        // --- 7. Which AXIAM user? --------------------------------------------
724        // Exactly the browser login's resolution (D-N11): the provider's
725        // attribute map over the verified claims, then the same link-or-
726        // provision function. A native sign-in and a browser login with the
727        // same claims are the same user.
728        let identity = map_identity(config.provider_kind, &config.attribute_map, raw)
729            .ok_or(NativeLoginError::SubjectUnmapped)?;
730        let resolved = self
731            .provision_or_link_identity(tenant_id, config.id, &identity)
732            .await
733            .map_err(|e| match e {
734                FederationError::ProvisioningConflict(_) => NativeLoginError::ProvisioningConflict,
735                other => NativeLoginError::Server(other.to_string()),
736            })?;
737        axiam_auth::service::account_may_act(&resolved.user)
738            .map_err(|e| NativeLoginError::AccountRefused(e.to_string()))?;
739
740        if resolved.newly_provisioned {
741            info!(
742                target: "axiam::audit",
743                event = "federation.jit_provision",
744                tenant_id = %tenant_id,
745                provider = %config.provider,
746                user_id = %resolved.user.id,
747                source = "native_login",
748                "JIT-provisioned an AXIAM user from a native sign-in"
749            );
750        }
751
752        Ok(NativeSubject {
753            user_id: resolved.user.id,
754            tenant_id,
755            provider_id: config.id,
756            provider_tenant_id: config.tenant_id,
757            inherited,
758            provider_name: config.provider.clone(),
759            provider_kind: config.provider_kind,
760            issuer,
761            external_subject: identity.external_subject,
762            audience,
763            newly_provisioned: resolved.newly_provisioned,
764            upstream_auth_time: upstream_instant(claims.auth_time),
765            id_token_exp,
766        })
767    }
768
769    /// Step 2: the effective provider the request names, re-read in full from
770    /// the tenant that owns it, as the browser login does.
771    async fn resolve_native_provider<TR: TenantRepository>(
772        &self,
773        tenants: &TR,
774        tenant_id: Uuid,
775        provider: &str,
776    ) -> Result<(FederationConfig, bool), NativeLoginError> {
777        let provider = provider.trim();
778        if provider.is_empty() {
779            return Err(NativeLoginError::ProviderNotFound);
780        }
781        let tenant = tenants.get_by_id(tenant_id).await.map_err(|e| match e {
782            AxiamError::NotFound { .. } => NativeLoginError::ProviderNotFound,
783            other => NativeLoginError::Server(other.to_string()),
784        })?;
785        let effective = effective_providers(
786            self.federation_config_repo_ref(),
787            tenants,
788            tenant.organization_id,
789            tenant_id,
790        )
791        .await
792        .map_err(|e| NativeLoginError::Server(e.to_string()))?;
793
794        let mut matching = effective
795            .into_iter()
796            .filter(|p| accepts_native_login(&p.config) && names(&p.config, provider));
797        let found = matching.next().ok_or(NativeLoginError::ProviderNotFound)?;
798        // Two effective providers sharing a slug (an OIDC and an OAuth2
799        // generic one, say, of which only one could match here — or a
800        // misconfiguration) must not be resolved by list order.
801        if matching.next().is_some() {
802            return Err(NativeLoginError::ProviderNotFound);
803        }
804
805        let full = self
806            .federation_config_repo_ref()
807            .get_by_id(found.config.tenant_id, found.config.id)
808            .await
809            .map_err(|e| match e {
810                AxiamError::NotFound { .. } => NativeLoginError::ProviderNotFound,
811                other => NativeLoginError::Server(other.to_string()),
812            })?;
813        // The listing and the row are read apart; the row decides.
814        if !accepts_native_login(&full) {
815            return Err(NativeLoginError::ProviderNotFound);
816        }
817        Ok((full, found.inherited))
818    }
819}
