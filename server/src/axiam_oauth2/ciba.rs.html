1//! OpenID Connect Client-Initiated Backchannel Authentication — G-7.
2//!
3//! CIBA Core 1.0, poll and ping modes. This module owns everything about the
4//! grant that is not the token endpoint's issuance (that is
5//! `TokenService::exchange_ciba`, beside the other grants, so the CIBA grant
6//! cannot mint differently from them):
7//!
8//! * what a CIBA **client registration** must say ([`validate_client_registration`]),
9//! * what a `POST /oauth2/bc-authorize` **request** may carry and how its hint
10//!   resolves to a user ([`CibaService::initiate`]),
11//! * the **approval service API** the identity pages call
12//!   ([`CibaService::lookup_for_approval`], [`CibaService::approve`],
13//!   [`CibaService::deny`]),
14//! * the **poll back-off** ([`poll_backoff`]).
15//!
16//! # What AXIAM requires of a CIBA client (D-61)
17//!
18//! | requirement | why |
19//! |---|---|
20//! | a confidential client (any method but `none`) | CIBA Core §7.1: the client authenticates at `bc-authorize` exactly as at the token endpoint |
21//! | `backchannel_token_delivery_mode` = `poll` or `ping` | §4; `push` is not offered (FAPI-CIBA forbids it) |
22//! | ping ⇒ an `https` notification endpoint under the webhook URL policy | §4; the endpoint is an outbound target |
23//! | `backchannel_authentication_request_signing_alg`, if registered, is `PS256`, `ES256` or `EdDSA`, with exactly one key source (`jwks` or `jwks_uri`) and, inline, a key of that algorithm | §7.1.1; the three algorithms AXIAM verifies on any client-signed JWT |
24//! | a registered signing algorithm ⇒ **every** request is a signed `request` JWT under it; no algorithm ⇒ a `request` is refused | §4 "when omitted, the Client will not send signed authentication requests"; a registered switch that accepted unsigned requests anyway would be the SEC-097 shape |
25//! | `fapi2` ⇒ the signing algorithm is registered | FAPI-CIBA §5.2.2: signed authentication requests are required |
26//! | `fapi2` ⇒ `tls_client_auth`, `self_signed_tls_client_auth` or `private_key_jwt`, and sender-constrained tokens | the `fapi2` profile's own rules (`fapi::validate_registration`), which already apply to every grant a `fapi2` client holds |
27//! | no `backchannel_user_code_parameter` | AXIAM has no per-user secret to check a user code against that is not the password |
28//!
29//! At request time a `fapi2` client must also send a `binding_message`
30//! (FAPI-CIBA §5.2.2: a unique authorization context, which AXIAM has no other
31//! carrier for) and, in ping mode, a `client_notification_token` of at least
32//! [`MIN_FAPI_NOTIFICATION_TOKEN_BYTES`] characters.
33//!
34//! Sender-constraining follows the client's registration exactly as for every
35//! other grant (`certificate_binding_for`, and `fapi::enforce_token_request` at
36//! the token endpoint), and a row edited in the datastore past these gates
37//! still meets D-17's request-time rule and the signed-request rule at
38//! `bc-authorize`. Signed requests themselves are
39//! [`crate::ciba_signed_request`].
40//!
41//! # Not a user oracle (D-63)
42//!
43//! A hint that names nobody, names a user who may not sign in, or names a user
44//! under brute-force lockout is answered **exactly like a real one**: a stored
45//! request, an `auth_req_id`, `expires_in` and `interval`. Such a request has
46//! no user, nobody is notified, nothing can approve it, and the client polls
47//! `authorization_pending` until `expired_token`. `unknown_user_id` is never
48//! sent: answering it would let any registered CIBA client enumerate the
49//! tenant's usernames and e-mail addresses at the endpoint's rate limit.
50//!
51//! The per-(client, hint) cap (#599, T-424, [`DEFAULT_REQUESTS_PER_CLIENT_HINT`])
52//! keeps to this. It counts the client's `bc-authorize` calls for the hint as
53//! the request carried it — a `login_hint` as sent, a verified
54//! `id_token_hint`'s subject — in a shared counter, before the hint is looked
55//! up, so a hint that names nobody is refused at exactly the call a real
56//! user's would be. (From 2026-10-13 until its correction the same day the cap
57//! counted the resolved user's open requests, and a request for nobody was
58//! never refused: the fourth call told the client whether the hint named a
59//! user who may sign in.)

159/// Why a CIBA registration is refused. One variant per rule in the module
160/// documentation's table, so a test asserts which rule fired.
161#[derive(Debug, Clone, PartialEq, Eq)]
162pub enum CibaRegistrationError {
163    /// The client holds the grant but registered no delivery mode.
164    DeliveryModeRequired,
165    /// A delivery mode other than `poll` or `ping` (including `push`).
166    UnsupportedDeliveryMode {
167        /// What was asked for.
168        mode: String,
169    },
170    /// Ping mode without a notification endpoint.
171    NotificationEndpointRequired,
172    /// A notification endpoint outside ping mode.
173    NotificationEndpointWithoutPing,
174    /// The notification endpoint fails the outbound URL policy.
175    InvalidNotificationEndpoint {
176        /// The policy rule that failed — never the URL.
177        reason: String,
178    },
179    /// CIBA metadata on a client that does not hold the grant.
180    MetadataWithoutGrant,
181    /// A public client asked for the grant.
182    PublicClient,
183    /// `backchannel_authentication_request_signing_alg` names an algorithm
184    /// AXIAM does not verify.
185    UnsupportedSigningAlg {
186        /// What was asked for.
187        alg: String,
188    },
189    /// A `fapi2` client asked for the grant without registering a signing
190    /// algorithm (FAPI-CIBA requires signed authentication requests).
191    FapiRequiresSignedRequests,
192    /// A signing algorithm without exactly one key source.
193    SigningKeysRequired {
194        /// How many of `jwks` and `jwks_uri` were registered.
195        registered: usize,
196    },
197    /// An inline `jwks` holding no key of the registered algorithm.
198    NoKeyForSigningAlg {
199        /// The registered algorithm.
200        alg: &'static str,
201    },
202    /// `backchannel_user_code_parameter: true` was registered.
203    UserCodeUnsupported,
204}

213            ),
214            Self::UnsupportedDeliveryMode { mode } => write!(
215                f,
216                "backchannel_token_delivery_mode {mode:?} is not supported: AXIAM offers poll and \
217                 ping (push is not offered)"
218            ),
219            Self::NotificationEndpointRequired => write!(
220                f,
221                "ping mode requires backchannel_client_notification_endpoint"
222            ),
223            Self::NotificationEndpointWithoutPing => write!(
224                f,
225                "backchannel_client_notification_endpoint is used only in ping mode; remove it or \
226                 register ping"
227            ),
228            Self::InvalidNotificationEndpoint { reason } => {
229                write!(f, "backchannel_client_notification_endpoint: {reason}")
230            }
231            Self::MetadataWithoutGrant => write!(
232                f,
233                "backchannel_* metadata requires the {CIBA_GRANT_TYPE} grant in grant_types"
234            ),
235            Self::PublicClient => write!(
236                f,
237                "the CIBA grant requires a confidential client: a client registered with \
238                 token_endpoint_auth_method none cannot authenticate at the backchannel \
239                 authentication endpoint"
240            ),
241            Self::UnsupportedSigningAlg { alg } => write!(
242                f,
243                "backchannel_authentication_request_signing_alg {alg:?} is not supported: this \
244                 server verifies PS256, ES256 and EdDSA"
245            ),
246            Self::FapiRequiresSignedRequests => write!(
247                f,
248                "a fapi2 client holding the CIBA grant must register \
249                 backchannel_authentication_request_signing_alg: the FAPI-CIBA profile requires \
250                 signed authentication requests"
251            ),
252            Self::SigningKeysRequired { registered } => write!(
253                f,
254                "backchannel_authentication_request_signing_alg requires exactly one of jwks and \
255                 jwks_uri, to verify the signed requests against (registered: {registered})"
256            ),
257            Self::NoKeyForSigningAlg { alg } => write!(
258                f,
259                "the registered jwks holds no {alg} key, so no request signed with \
260                 backchannel_authentication_request_signing_alg {alg} could be verified"
261            ),
262            Self::UserCodeUnsupported => write!(
263                f,
264                "backchannel_user_code_parameter is not supported: this server holds no user code \
265                 to verify"
266            ),
267        }
268    }

292    /// The registered inline `jwks`, as the row will hold it.

298/// Validate a registration's CIBA metadata and resolve what is stored.
299///
300/// Runs for every registration, CIBA or not: stray `backchannel_*` metadata on
301/// a client without the grant is refused rather than stored unread.
302///
303/// # Errors
304///
305/// The rule that failed.
306pub fn validate_client_registration(
307    reg: CibaRegistrationView<'_>,
308) -> Result<CibaClientMetadata, CibaRegistrationError> {
309    fn blank(v: Option<&str>) -> Option<&str> {
310        v.map(str::trim).filter(|s| !s.is_empty())
311    }
312    let mode_raw = blank(reg.delivery_mode);
313    let endpoint = blank(reg.notification_endpoint);
314
315    // The member AXIAM does not implement, first: whatever else the
316    // registration says, it asked for something it will not get.
317    if reg.user_code_parameter == Some(true) {
318        return Err(CibaRegistrationError::UserCodeUnsupported);
319    }
320    let signing_alg = match blank(reg.signing_alg) {
321        None => None,
322        Some(raw) => Some(CibaRequestSigningAlg::from_wire(raw).ok_or_else(|| {
323            CibaRegistrationError::UnsupportedSigningAlg {
324                alg: raw.to_owned(),
325            }
326        })?),
327    };
328
329    if !holds_ciba_grant(reg.grant_types) {
330        if mode_raw.is_some() || endpoint.is_some() || signing_alg.is_some() {
331            return Err(CibaRegistrationError::MetadataWithoutGrant);
332        }
333        return Ok(CibaClientMetadata::default());
334    }
335
336    if reg.token_endpoint_auth_method.is_public() {
337        return Err(CibaRegistrationError::PublicClient);
338    }
339    // FAPI-CIBA §5.2.2. The profile's client-authentication and
340    // sender-constraining rules are `fapi::validate_registration`'s, which
341    // every registration path runs as well: one statement of them.
342    if reg.profile.is_fapi2() && signing_alg.is_none() {
343        return Err(CibaRegistrationError::FapiRequiresSignedRequests);
344    }
345    if let Some(alg) = signing_alg {
346        let inline = blank(reg.jwks);
347        let sources = usize::from(inline.is_some()) + usize::from(blank(reg.jwks_uri).is_some());
348        if sources != 1 {
349            return Err(CibaRegistrationError::SigningKeysRequired {
350                registered: sources,
351            });
352        }
353        // An inline set is checked now; a `jwks_uri` can only be checked when
354        // it is fetched, and a request whose key cannot be found is refused
355        // then. An unparseable inline set is reported by
356        // `fapi::validate_registration` with the parser's detail; here it
357        // simply holds no usable key.
358        if let Some(raw) = inline {
359            let usable = serde_json::from_str::<jsonwebtoken::jwk::JwkSet>(raw)
360                .is_ok_and(|set| crate::ciba_signed_request::key_set_supports(&set, alg));
361            if !usable {
362                return Err(CibaRegistrationError::NoKeyForSigningAlg { alg: alg.as_str() });
363            }
364        }
365    }
366    let Some(mode_raw) = mode_raw else {
367        return Err(CibaRegistrationError::DeliveryModeRequired);
368    };
369    let mode = CibaDeliveryMode::from_wire(mode_raw).ok_or_else(|| {
370        CibaRegistrationError::UnsupportedDeliveryMode {
371            mode: mode_raw.to_owned(),
372        }
373    })?;
374    let endpoint = match (mode, endpoint) {
375        (CibaDeliveryMode::Ping, None) => {
376            return Err(CibaRegistrationError::NotificationEndpointRequired);
377        }
378        (CibaDeliveryMode::Poll, Some(_)) => {
379            return Err(CibaRegistrationError::NotificationEndpointWithoutPing);
380        }
381        (CibaDeliveryMode::Poll, None) => None,
382        (CibaDeliveryMode::Ping, Some(raw)) => {
383            // The webhook write-time policy (D-49); the delivery-time guard is
384            // the deliverer's, through `guarded_fetch_no_redirect`.
385            crate::ssf::validate_push_endpoint(raw).map_err(|reason| {
386                CibaRegistrationError::InvalidNotificationEndpoint {
387                    reason: reason.replace("endpoint_url", "the endpoint"),
388                }
389            })?;
390            Some(raw.to_owned())
391        }
392    };
393    Ok(CibaClientMetadata {
394        backchannel_token_delivery_mode: Some(mode),
395        backchannel_client_notification_endpoint: endpoint,
396        backchannel_authentication_request_signing_alg: signing_alg,
397    })
398}

457/// Refusals decidable from the request alone, before the client is
458/// authenticated: each names a parameter the caller sent and nothing about the
459/// client, so none is an oracle, and a request that cannot be served whoever
460/// sent it should not first cost an authentication.
461///
462/// # Errors
463///
464/// `invalid_request` naming the parameter.
465pub fn refuse_unsupported_parameters(
466    req: &BackchannelAuthenticationRequest,
467) -> Result<(), OAuth2Error> {
468    let present = |v: &Option<String>| v.as_deref().is_some_and(|s| !s.trim().is_empty());
469    if present(&req.request_uri) {
470        return Err(OAuth2Error::InvalidRequest(
471            "request_uri is not supported: CIBA Core section 7.1.1 defines the signed \
472             authentication request by value, in the request parameter"
473                .into(),
474        ));
475    }
476    if present(&req.request) {
477        // CIBA Core §7.1.1: the parameters "MUST NOT be present outside of the
478        // JWT, in particular they MUST NOT appear as HTTP request parameters".
479        // Refused rather than ignored: a parameter the client believes it sent
480        // and the server silently dropped is a request the two read
481        // differently.
482        let outside: Vec<&str> = [
483            ("scope", &req.scope),
484            ("client_notification_token", &req.client_notification_token),
485            ("acr_values", &req.acr_values),
486            ("login_hint_token", &req.login_hint_token),
487            ("id_token_hint", &req.id_token_hint),
488            ("login_hint", &req.login_hint),
489            ("binding_message", &req.binding_message),
490            ("user_code", &req.user_code),
491            ("requested_expiry", &req.requested_expiry),
492            ("resource", &req.resource),
493        ]
494        .into_iter()
495        .filter(|(_, v)| v.is_some())
496        .map(|(name, _)| name)
497        .collect();
498        if !outside.is_empty() {
499            return Err(OAuth2Error::InvalidRequest(format!(
500                "a signed authentication request carries every parameter inside the request JWT; \
501                 these were also sent outside it: {}",
502                outside.join(", ")
503            )));
504        }
505        return Ok(());
506    }
507    if present(&req.login_hint_token) {
508        return Err(OAuth2Error::InvalidRequest(
509            "login_hint_token is not supported; identify the user with login_hint or \
510             id_token_hint"
511                .into(),
512        ));
513    }
514    if present(&req.user_code) {
515        return Err(OAuth2Error::InvalidRequest(
516            "user_code is not supported by this server".into(),
517        ));
518    }
519    Ok(())
520}

522/// Validate a `binding_message`: at most [`MAX_BINDING_MESSAGE_CHARS`]
523/// characters, no control characters, not blank.
524///
525/// # Errors
526///
527/// `invalid_binding_message`.
528pub fn validate_binding_message(raw: Option<&str>) -> Result<Option<String>, OAuth2Error> {
529    let Some(raw) = raw else {
530        return Ok(None);
531    };
532    let trimmed = raw.trim();
533    if trimmed.is_empty() {
534        return Err(OAuth2Error::InvalidBindingMessage(
535            "binding_message must not be blank".into(),
536        ));
537    }
538    if trimmed.chars().count() > MAX_BINDING_MESSAGE_CHARS {
539        return Err(OAuth2Error::InvalidBindingMessage(format!(
540            "binding_message must be at most {MAX_BINDING_MESSAGE_CHARS} characters"
541        )));
542    }
543    // Printable: shown verbatim on two screens and in an e-mail, so a control
544    // character (a newline, a bidi override) could make the two disagree.
545    if trimmed
546        .chars()
547        .any(|c| c.is_control() || matches!(c, '\u{202A}'..='\u{202E}' | '\u{2066}'..='\u{2069}'))
548    {
549        return Err(OAuth2Error::InvalidBindingMessage(
550            "binding_message must contain printable characters only".into(),
551        ));
552    }
553    Ok(Some(trimmed.to_owned()))
554}

561/// `[MIN_REQUESTED_EXPIRY_SECS, MAX_REQUESTED_EXPIRY_SECS]`.
562pub fn resolve_expiry(raw: Option<&str>) -> Result<u64, OAuth2Error> {
563    let Some(raw) = raw.map(str::trim).filter(|s| !s.is_empty()) else {
564        return Ok(DEFAULT_EXPIRES_IN_SECS);
565    };
566    let secs: u64 = raw.parse().map_err(|_| {
567        OAuth2Error::InvalidRequest("requested_expiry must be a positive integer".into())
568    })?;
569    if !(MIN_REQUESTED_EXPIRY_SECS..=MAX_REQUESTED_EXPIRY_SECS).contains(&secs) {
570        return Err(OAuth2Error::InvalidRequest(format!(
571            "requested_expiry must be between {MIN_REQUESTED_EXPIRY_SECS} and \
572             {MAX_REQUESTED_EXPIRY_SECS} seconds"
573        )));
574    }
575    Ok(secs)
576}

598/// Resolve the requested scopes: `openid` is required (CIBA Core §7.1), and
599/// every value must be one the client is registered for.
600///
601/// # Errors
602///
603/// `invalid_request` without `openid`; `invalid_scope` for an unregistered
604/// value.
605pub fn resolve_scopes(
606    raw: Option<&str>,
607    registered: &[String],
608) -> Result<Vec<String>, OAuth2Error> {
609    let mut scopes: Vec<String> = Vec::new();
610    for s in raw.unwrap_or("").split_whitespace() {
611        if !scopes.iter().any(|seen| seen == s) {
612            scopes.push(s.to_owned());
613        }
614    }
615    if !scopes.iter().any(|s| s == "openid") {
616        return Err(OAuth2Error::InvalidRequest(
617            "scope is required and must include openid (CIBA Core section 7.1)".into(),
618        ));
619    }
620    if let Some(bad) = scopes.iter().find(|s| !registered.iter().any(|r| r == *s)) {
621        return Err(OAuth2Error::InvalidScope(format!(
622            "scope {bad:?} is not registered for this client"
623        )));
624    }
625    Ok(scopes)
626}

637/// Select the request's hint (CIBA Core §7.1: exactly one).
638///
639/// # Errors
640///
641/// `invalid_request` for none or more than one, or an oversized `login_hint`.
642pub fn select_hint(req: &BackchannelAuthenticationRequest) -> Result<CibaHint, OAuth2Error> {
643    let login = req
644        .login_hint
645        .as_deref()
646        .map(str::trim)
647        .filter(|s| !s.is_empty());
648    let id_token = req
649        .id_token_hint
650        .as_deref()
651        .map(str::trim)
652        .filter(|s| !s.is_empty());
653    match (login, id_token) {
654        (Some(_), Some(_)) => Err(OAuth2Error::InvalidRequest(
655            "exactly one of login_hint, id_token_hint and login_hint_token may be sent".into(),
656        )),
657        (None, None) => Err(OAuth2Error::InvalidRequest(
658            "one of login_hint or id_token_hint is required".into(),

663                    "login_hint must be at most {MAX_LOGIN_HINT_BYTES} bytes"
664                )));
665            }
666            Ok(CibaHint::LoginHint(hint.to_owned()))
667        }
668        (None, Some(token)) => Ok(CibaHint::IdTokenHint(token.to_owned())),
669    }

672/// Verify an `id_token_hint` and return its subject.
673///
674/// The hint must be an ID token **this deployment** signed (its EdDSA key),
675/// issued **to this client** (`aud`) under **one of the issuers this request
676/// may name** (`iss`: the deployment's, or the tenant path's the request
677/// arrived under). Expiry is not checked: CIBA Core §7.1 describes the hint as
678/// a token "previously issued", and the hint authenticates nothing — it only
679/// names the user to ask. What it may not do is name a user of another tenant
680/// or another client's relying party, which `aud` and the tenant-scoped user
681/// lookup that follows both prevent.
682///
683/// # Errors
684///
685/// `invalid_request` for anything that fails; the message does not say which.
686pub fn verify_id_token_hint(
687    token: &str,
688    public_key_pem: &str,
689    client_id: &str,
690    acceptable_issuers: &[String],
691) -> Result<Uuid, OAuth2Error> {
692    use jsonwebtoken::{Algorithm, DecodingKey, Validation};
693
694    let invalid = || {
695        OAuth2Error::InvalidRequest(
696            "id_token_hint is not an ID token this server issued to this client".into(),
697        )
698    };
699    let key = DecodingKey::from_ed_pem(public_key_pem.as_bytes()).map_err(|_| invalid())?;
700    let mut validation = Validation::new(Algorithm::EdDSA);
701    validation.validate_exp = false;
702    validation.validate_aud = false;
703    validation.required_spec_claims.clear();
704    let claims = jsonwebtoken::decode::<axiam_auth::token::IdTokenClaims>(token, &key, &validation)
705        .map_err(|_| invalid())?
706        .claims;
707    if claims.aud != client_id {
708        return Err(invalid());
709    }
710    if !acceptable_issuers.iter().any(|i| i == &claims.iss) {
711        return Err(invalid());
712    }
713    Uuid::parse_str(&claims.sub).map_err(|_| invalid())
714}

718/// and refresh use) **and** is not under brute-force lockout. The second half
719/// is the Keycloak 26.7.x lesson: a lockout that only the password path reads

726/// Decide a token request's back-off: `(too_fast, interval to store)`.
727///
728/// RFC 8628 §3.5's rule, which CIBA Core §11 adopts: a request inside the
729/// current interval is `slow_down` and raises the interval by
730/// [`SLOW_DOWN_STEP_SECS`], capped at [`MAX_INTERVAL_SECS`].
731#[must_use]
732pub fn poll_backoff(
733    interval_secs: u64,
734    last_polled_at: Option<DateTime<Utc>>,
735    now: DateTime<Utc>,
736) -> (bool, u64) {
737    let too_fast = last_polled_at
738        .is_some_and(|last| (now - last).num_milliseconds() < (interval_secs as i64) * 1000);
739    let next = if too_fast {
740        (interval_secs + SLOW_DOWN_STEP_SECS).min(MAX_INTERVAL_SECS)
741    } else {
742        interval_secs
743    };
744    (too_fast, next)
745}

785/// The shipped allowance of `bc-authorize` calls one client may have admitted
786/// for one hint in any [`HINT_CAP_WINDOW_SECS`] (#599, T-424). The deployment
787/// sets its own with `AXIAM__RATE_LIMIT__BC_AUTHORIZE_PER_HINT` (#639,
788/// [`CibaHintCap::with_per_hint`]); a call past the allowance is refused before
789/// the hint is looked up, stored or mailed, with the `slow_down` the
790/// per-client limiter answers.
791///
792/// `requested_expiry` is the client's to choose, so without a per-client bound
793/// a client that may address a user could keep the whole list full of
794/// short-lived requests of its own. Three is room for a retry or two while the
795/// first is still on the user's phone; a client that needs more is waiting on
796/// a user who has not answered. A conformance suite or an SDK's integration
797/// suite, which runs many flows for one test user from one client within
798/// minutes, needs more, and sets the knob for the deployment it tests.
799///
800/// **What is counted is admitted calls, not open requests.** The count is keyed
801/// on (tenant, client, a keyed digest of the hint) — never on the user the hint
802/// resolves to — so a hint that names nobody, a user who may not sign in and a
803/// real user are refused at the same call, and the refusal says nothing about
804/// the hint (D-63, T-422). A request that has been approved, denied or has
805/// expired therefore still counts until its window has passed. A **refused**
806/// call does not count (#639; until 1.1.0 it did, so a client that kept
807/// retrying stayed refused): a client that stops for the rest of the window
808/// after the one in which it used its allowance is admitted again. The hint is
809/// the one the request carried, as hint resolution normalises it (a
810/// `login_hint` trimmed and otherwise exact, as the username and e-mail lookups
811/// match it; an `id_token_hint` reduced to its verified subject), so one user
812/// named by username, by e-mail address and by ID token is three hints — three
813/// allowances a window from one client.
814///
815/// Admission requires the admitted calls in this window and the one before it,
816/// this call included, to come to at most the allowance, so any
817/// [`HINT_CAP_WINDOW_SECS`]-long stretch admits at most the allowance; as no
818/// request outlives that, one client never holds more open requests for one
819/// hint than the allowance. The price is coarseness: a client that has used the
820/// allowance in one window is refused for the whole of the next, so it waits
821/// between one and two windows. The count is the shared rate-limit table,
822/// written atomically in the datastore, so the bound holds across replicas and
823/// under concurrent calls (see [`CibaHintCap`] for the protocol and the
824/// argument).
825pub const DEFAULT_REQUESTS_PER_CLIENT_HINT: u32 = 3;

827/// The window of the per-hint allowance ([`DEFAULT_REQUESTS_PER_CLIENT_HINT`]):
828/// the longest a request may live ([`MAX_REQUESTED_EXPIRY_SECS`]), not the
829/// default ([`DEFAULT_EXPIRES_IN_SECS`]), so a client that asks for the longest
830/// expiry still cannot hold more open requests for one hint than the allowance.
831pub const HINT_CAP_WINDOW_SECS: u64 = MAX_REQUESTED_EXPIRY_SECS;

833/// What a hint names, as the cap counts it and the lookup reads it: a
834/// `login_hint` as sent (already trimmed), or a verified `id_token_hint`'s
835/// subject. Computed without looking anyone up.
836#[derive(Debug, Clone, PartialEq, Eq)]

840    /// The subject of an ID token this deployment signed for this client.

844/// The per-(client, hint) cap on `bc-authorize` (#599, T-424): see
845/// [`DEFAULT_REQUESTS_PER_CLIENT_HINT`].
846///
847/// Counted in the deployment's shared rate-limit table (`rate_limit_bucket`)
848/// through [`axiam_db::SharedRateLimitStore`] — not through the write-behind
849/// [`axiam_db::SharedRateLimitCounter`], whose window is the limiters' minute
850/// and whose local buckets are pruned after two of them. Two buckets per
851/// (tenant, client, hint), one for even and one for odd windows, so the table
852/// holds at most two rows per hint a client has named, however long it keeps
853/// naming it.
854///
855/// The bucket key is `ciba_hint_cap:{tenant}:` followed by an HMAC-SHA256,
856/// under a key only the deployment holds, of the client and the hint: the
857/// table is not a dictionary of hashes of the usernames and addresses clients
858/// have tried.
859///
860/// # The protocol, and the bound it guarantees (#639)
861///
862/// A call stamped in window `s` (its own clock) does three things, each one
863/// statement on one record:
864///
865/// 1. **counts itself**: an atomic increment of window `s`'s bucket, which
866///    answers the count after it, `v`;
867/// 2. **reads** window `s − 1`'s bucket (a `SELECT`, which writes nothing): its
868///    count when the bucket still holds `s − 1`, zero when it holds an older
869///    window or does not exist, and **overtaken** when it already holds
870///    `s + 1` — a call stamped in the next window has written, so this one is
871///    late;
872/// 3. is **admitted** when it was not overtaken and `v` plus the previous
873///    window's count is at most the allowance; otherwise it is refused and
874///    **takes its count back** with a conditional decrement (which only
875///    touches the bucket while it still holds window `s`).
876///
877/// *The bound.* For every two consecutive windows the admitted calls stamped
878/// in them come to at most the allowance, so any window-long stretch admits at
879/// most the allowance — exactly, under concurrent calls and across replicas,
880/// with no overshoot. Within one window: the admitted call whose increment
881/// came last counted every admitted call of its window before it (admitted
882/// counts are never taken back; a refused call's count is taken back only
883/// after it was made, so it can only inflate `v`), so `v` is at least the
884/// window's admissions. Across a boundary: a call stamped `s − 1` that is
885/// admitted read window `s`'s bucket (its "previous" bucket by parity) before
886/// any call stamped `s` had counted itself — had one done so, the bucket would
887/// hold `s` and the call would be overtaken and refused. So every call stamped
888/// `s − 1` that is admitted counted itself before any call stamped `s` read
889/// window `s − 1`'s bucket, and the last admitted call of window `s` saw all of
890/// them. Two calls racing across a boundary can both be refused (each sees the
891/// other); they cannot both be admitted past the allowance.
892///
893/// *What it assumes.* No call stays in flight — from its clock read to its
894/// last statement — while a call stamped two windows later writes; that is,
895/// a call's latency plus the replicas' clock skew stays under one window (ten
896/// minutes). Beyond that the error is still on the strict side: a call whose
897/// own bucket has been taken over adds to the newer window's count and its
898/// previous bucket reads as overtaken.
899///
900/// *What it costs.* A refusal may be spurious only while another call for the
901/// same hint is between its count and its take-back, or when a call is
902/// overtaken at a window boundary (or by a replica whose clock runs ahead).
903/// A store error after the count leaves the count in place (strict: the
904/// allowance is one smaller until the window passes) and the call fails with
905/// `server_error`; a take-back that fails leaves it in place too, and the call
906/// is refused as decided.
907///
908/// A row is read until the end of the window after the one it was written in,
909/// so the server's `rate_limit_bucket` sweep deletes a row once it is more
910/// than twice [`HINT_CAP_WINDOW_SECS`] old (with a margin), which bounds the
911/// table by the hints named in that stretch instead of every hint ever named.
912#[derive(Clone)]
913pub struct CibaHintCap {
914    store: std::sync::Arc<dyn axiam_db::SharedRateLimitStore>,
915    key: [u8; 32],
916    per_hint: u64,
917}
918
919impl std::fmt::Debug for CibaHintCap {
920    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
921        f.debug_struct("CibaHintCap")
922            .field("per_hint", &self.per_hint)
923            .finish_non_exhaustive()
924    }
925}

927/// What [`CibaHintCap`] read in the previous window's bucket.
928#[derive(Debug, Clone, Copy, PartialEq, Eq)]
929enum PreviousWindow {
930    /// The admitted (and not yet taken back) calls of the previous window.
931    Counted(u64),
932    /// The bucket already holds the window after this call's: this call is
933    /// late, and the previous window's count is gone.
934    Overtaken,
935}
936
937impl CibaHintCap {
938    /// The domain label of [`Self::derived_from`]'s derivation.
939    const KEY_LABEL: &'static [u8] = b"axiam/ciba/hint-cap/v1";
940
941    /// A cap over `store`, keying its buckets with `key`, with the shipped
942    /// allowance ([`DEFAULT_REQUESTS_PER_CLIENT_HINT`]).
943    pub fn new(store: std::sync::Arc<dyn axiam_db::SharedRateLimitStore>, key: [u8; 32]) -> Self {
944        Self {
945            store,
946            key,
947            per_hint: u64::from(DEFAULT_REQUESTS_PER_CLIENT_HINT),
948        }
949    }
950
951    /// A cap whose bucket key is derived from a secret every replica already
952    /// shares — the deployment's token signing key, PEM-encoded — as
953    /// HMAC-SHA256(secret, a fixed label). One-way, so the derived key tells
954    /// nothing about the signing key; a new signing key starts every hint's
955    /// count afresh, which errs lenient for one window and no further.
956    pub fn derived_from(
957        store: std::sync::Arc<dyn axiam_db::SharedRateLimitStore>,
958        deployment_secret: &[u8],
959    ) -> Self {
960        Self::new(store, hmac_sha256(deployment_secret, &[Self::KEY_LABEL]))
961    }
962
963    /// The allowance per (client, hint) per [`HINT_CAP_WINDOW_SECS`] (#639):
964    /// `RateLimitConfig::bc_authorize_per_hint`,
965    /// `AXIAM__RATE_LIMIT__BC_AUTHORIZE_PER_HINT`. At least one by type; the
966    /// configuration refuses `0` at startup. Every replica sharing the table
967    /// must be given the same allowance (each enforces its own against the
968    /// shared counts). Builder-style.
969    #[must_use]
970    pub fn with_per_hint(mut self, per_hint: std::num::NonZeroU32) -> Self {
971        self.per_hint = u64::from(per_hint.get());
972        self
973    }
974
975    /// The bucket base for (tenant, client, hint); the window's parity is
976    /// appended.
977    fn bucket(&self, tenant_id: Uuid, client_id: &str, hint: &HintName) -> String {
978        let tenant = tenant_id.to_string();
979        let (kind, value): (&[u8], String) = match hint {
980            HintName::Login(v) => (b"login", v.clone()),
981            HintName::Subject(sub) => (b"sub", sub.to_string()),
982        };
983        // Length-prefixed parts, so no two (tenant, client, kind, value)
984        // tuples encode alike.
985        let mac = hmac_sha256(
986            &self.key,
987            &[
988                tenant.as_bytes(),
989                client_id.as_bytes(),
990                kind,
991                value.as_bytes(),
992            ],
993        );
994        format!("ciba_hint_cap:{tenant_id}:{}", hex::encode(mac))
995    }
996
997    /// Count this call, decide, and take the count back if it is refused: the
998    /// protocol in [`CibaHintCap`]'s documentation. A hint's first call
999    /// creates one row, its window's; the read of the previous window writes
1000    /// nothing, and a take-back never creates a row.
1001    async fn admit(
1002        &self,
1003        tenant_id: Uuid,
1004        client_id: &str,
1005        hint: &HintName,
1006        now: DateTime<Utc>,
1007    ) -> Result<bool, OAuth2Error> {
1008        let window = HINT_CAP_WINDOW_SECS as i64;
1009        let index = now.timestamp().div_euclid(window);
1010        let start = |i: i64| DateTime::<Utc>::from_timestamp(i * window, 0).unwrap_or(now);
1011        let base = self.bucket(tenant_id, client_id, hint);
1012        let slot = |i: i64| format!("{base}:{}", i.rem_euclid(2));
1013        let failed = |e: axiam_db::DbError| OAuth2Error::ServerError(e.to_string());
1014        let own = slot(index);
1015        // Concurrent calls for one hint write one record: the datastore
1016        // aborts all but one with a retryable write conflict, and an aborted
1017        // statement wrote nothing, so it is replayed (not counted twice).
1018        let current = retry_on_write_conflict(|| self.store.increment_by(&own, start(index), 1))
1019            .await
1020            .map_err(failed)?;
1021        let previous = match self.store.peek_bucket(&slot(index - 1)).await {
1022            Ok(None) => PreviousWindow::Counted(0),
1023            Ok(Some((stored, count))) => match stored.cmp(&start(index - 1)) {
1024                std::cmp::Ordering::Less => PreviousWindow::Counted(0),
1025                std::cmp::Ordering::Equal => PreviousWindow::Counted(count),
1026                std::cmp::Ordering::Greater => PreviousWindow::Overtaken,
1027            },
1028            // The count stays: strict, never lenient.
1029            Err(e) => return Err(failed(e)),
1030        };
1031        let admitted = match previous {
1032            PreviousWindow::Counted(count) => current.saturating_add(count) <= self.per_hint,
1033            PreviousWindow::Overtaken => false,
1034        };
1035        if !admitted {
1036            // A refused call does not consume the allowance (#639). A failed
1037            // take-back leaves the count in place, which is strict; the call
1038            // is refused either way.
1039            if let Err(e) =
1040                retry_on_write_conflict(|| self.store.decrement(&own, start(index))).await
1041            {
1042                tracing::warn!(error = %e, "the CIBA hint cap could not take back a refused call's count");
1043            }
1044        }
1045        Ok(admitted)
1046    }
1047}

1049/// HMAC-SHA256 of the length-prefixed `parts` under `key`.
1050fn hmac_sha256(key: &[u8], parts: &[&[u8]]) -> [u8; 32] {
1051    use hmac::{KeyInit, Mac};
1052    let mut mac = <hmac::Hmac<sha2::Sha256> as KeyInit>::new_from_slice(key)
1053        .expect("HMAC accepts a key of any length");
1054    for part in parts {
1055        mac.update(&(part.len() as u64).to_be_bytes());
1056        mac.update(part);
1057    }
1058    mac.finalize().into_bytes().into()
1059}

1099/// The class a request's `acr_values` still need, given the authentication the
1100/// approving session performed — `None` when the request asked for no class
1101/// AXIAM implements, or when the session already achieved one of them.
1102///
1103/// The one place the rule lives: [`CibaService::approve`] refuses with it, and
1104/// the approval page asks for it beforehand so that it can offer the step-up
1105/// before the user presses Approve. The class a session achieved is derived
1106/// from its `amr` ([`acr_for`]); nothing the caller says moves it.
1107#[must_use]
1108pub fn step_up_required(acr_values: &[String], amr: &[Amr]) -> Option<Acr> {
1109    let achieved = acr_for(amr);
1110    let requested: Vec<Acr> = acr_values
1111        .iter()
1112        .filter_map(|v| Acr::from_wire(v))
1113        .collect();
1114    if requested.is_empty() || requested.iter().any(|wanted| achieved.satisfies(*wanted)) {
1115        return None;
1116    }
1117    Some(requested.iter().copied().min().unwrap_or(Acr::MultiFactor))
1118}

1202    /// Resolve the parameters this request is made of: the signed `request`
1203    /// JWT's claims for a client that registered a signing algorithm, the
1204    /// form for one that did not — never a mixture, and never the other form.
1205    async fn effective_request<'r>(
1206        &self,
1207        client: &OAuth2Client,
1208        req: &'r BackchannelAuthenticationRequest,
1209        acceptable_issuers: &[String],
1210    ) -> Result<std::borrow::Cow<'r, BackchannelAuthenticationRequest>, OAuth2Error> {
1211        use std::borrow::Cow;
1212        let signed = req
1213            .request
1214            .as_deref()
1215            .map(str::trim)
1216            .filter(|s| !s.is_empty());
1217        match (
1218            client.ciba.backchannel_authentication_request_signing_alg,
1219            signed,
1220        ) {
1221            (None, None) => {
1222                // A `fapi2` row reaches here only if edited past the
1223                // registration gate (`FapiRequiresSignedRequests`).
1224                if client.profile.is_fapi2() {
1225                    tracing::error!(
1226                        client_id = %client.client_id,
1227                        "a fapi2 CIBA client has no backchannel_authentication_request_signing_alg; \
1228                         this registration cannot have passed validate_client_registration"
1229                    );
1230                    return Err(OAuth2Error::UnauthorizedClient(
1231                        "a fapi2 client must send signed authentication requests".into(),
1232                    ));
1233                }
1234                Ok(Cow::Borrowed(req))
1235            }
1236            (Some(alg), None) => Err(OAuth2Error::InvalidRequest(format!(
1237                "this client registered backchannel_authentication_request_signing_alg {}: send \
1238                 the authentication request as a signed request JWT (CIBA Core section 7.1.1)",
1239                alg.as_str()
1240            ))),
1241            (None, Some(_)) => Err(OAuth2Error::InvalidRequest(
1242                "this client has not registered backchannel_authentication_request_signing_alg, \
1243                 so it cannot send a signed request; register the algorithm it signs with"
1244                    .into(),
1245            )),
1246            (Some(_), Some(jwt)) => {
1247                let Some(verifier) = self.signed_requests.as_ref() else {
1248                    tracing::error!(
1249                        client_id = %client.client_id,
1250                        "a signed CIBA request arrived and no signed-request verifier is wired"
1251                    );
1252                    return Err(OAuth2Error::ServerError(
1253                        "signed authentication requests are not available on this deployment"
1254                            .into(),
1255                    ));
1256                };
1257                Ok(Cow::Owned(
1258                    verifier.verify(client, jwt, acceptable_issuers).await?,
1259                ))
1260            }
1261        }
1262    }

1320    /// `POST /oauth2/bc-authorize` after client authentication (CIBA Core
1321    /// §7). The caller has authenticated `client`, applied D-17, checked the
1322    /// grant and counted the request; this validates and stores it.
1323    ///
1324    /// `acceptable_issuers` are the `iss` values an `id_token_hint` may carry
1325    /// for this request.
1326    ///
1327    /// # Errors
1328    ///
1329    /// CIBA Core §13's codes for a malformed request; `slow_down` when the
1330    /// client has already been admitted its allowance for this hint
1331    /// ([`CibaHintCap::with_per_hint`], default
1332    /// [`DEFAULT_REQUESTS_PER_CLIENT_HINT`]) in the cap's window (#599, #639),
1333    /// whoever the hint names;
1334    /// `server_error` for a datastore failure (or a
1335    /// ping request with no sealing key).
1336    pub async fn initiate(
1337        &self,
1338        client: &OAuth2Client,
1339        req: &BackchannelAuthenticationRequest,
1340        acceptable_issuers: &[String],
1341    ) -> Result<CibaInitiation, OAuth2Error> {
1342        let tenant_id = client.tenant_id;
1343        let mode = client.ciba.backchannel_token_delivery_mode.ok_or_else(|| {
1344            OAuth2Error::UnauthorizedClient(
1345                "this client has no backchannel_token_delivery_mode registered".into(),
1346            )
1347        })?;
1348
1349        // D-61: a signed request is verified (and its `jti` spent) before
1350        // anything it carries is read; from here on `req` is what the client
1351        // signed, or the form of a client that signs nothing.
1352        let req = self
1353            .effective_request(client, req, acceptable_issuers)
1354            .await?;
1355        let req: &BackchannelAuthenticationRequest = &req;
1356        // The parameters AXIAM does not implement, again: inside a signed
1357        // request they could not be seen before it was verified.
1358        refuse_unsupported_parameters(req)?;
1359        let fapi = client.profile.is_fapi2();
1360        if fapi
1361            && req
1362                .binding_message
1363                .as_deref()
1364                .is_none_or(|m| m.trim().is_empty())
1365        {
1366            // FAPI-CIBA §5.2.2: a unique authorization context or a binding
1367            // message. AXIAM has no other carrier for the former.
1368            return Err(OAuth2Error::InvalidRequest(
1369                "a fapi2 client must send a binding_message (FAPI-CIBA)".into(),
1370            ));
1371        }
1372
1373        let scopes = resolve_scopes(req.scope.as_deref(), &client.scopes)?;
1374        let hint = select_hint(req)?;
1375        let binding_message = validate_binding_message(req.binding_message.as_deref())?;
1376        let expires_in = resolve_expiry(req.requested_expiry.as_deref())?;
1377        let acr_values = parse_acr_values(req.acr_values.as_deref())?;
1378        let resource =
1379            crate::resource::resolve_requested(&client.allowed_resources, req.resource.as_deref())?;
1380
1381        let auth_req_id = generate_auth_req_id();
1382        let ping = match mode {
1383            CibaDeliveryMode::Poll => None,
1384            CibaDeliveryMode::Ping => {
1385                let token = req
1386                    .client_notification_token
1387                    .as_deref()
1388                    .filter(|t| !t.is_empty())
1389                    .ok_or_else(|| {
1390                        OAuth2Error::InvalidRequest(
1391                            "client_notification_token is required in ping mode".into(),
1392                        )
1393                    })?;
1394                if token.len() > MAX_NOTIFICATION_TOKEN_BYTES
1395                    || !token.bytes().all(|b| b.is_ascii_graphic())
1396                {
1397                    return Err(OAuth2Error::InvalidRequest(format!(
1398                        "client_notification_token must be at most {MAX_NOTIFICATION_TOKEN_BYTES} \
1399                         visible ASCII characters"
1400                    )));
1401                }
1402                if fapi && token.len() < MIN_FAPI_NOTIFICATION_TOKEN_BYTES {
1403                    return Err(OAuth2Error::InvalidRequest(format!(
1404                        "a fapi2 client's client_notification_token must be at least \
1405                         {MIN_FAPI_NOTIFICATION_TOKEN_BYTES} characters (128 bits of entropy)"
1406                    )));
1407                }
1408                Some(CibaPingCredentials {
1409                    auth_req_id: auth_req_id.clone(),
1410                    client_notification_token: token.to_owned(),
1411                })
1412            }
1413        };
1414
1415        // Validation is complete; only now is the hint read, so a malformed
1416        // request is refused identically whoever it names.
1417        let named = self.name_in_hint(&hint, &client.client_id, acceptable_issuers)?;
1418
1419        // #599 (T-424): the per-(client, hint) cap, before the hint is looked
1420        // up and before anything is stored or mailed. It counts the hint, not
1421        // the user it names, so it refuses a hint naming nobody at the same
1422        // call as a real user's and its answer — and its cost, a count and a
1423        // read, and a take-back when refused, whoever the hint names — says
1424        // nothing about the hint (D-63).
1425        // `slow_down` is the answer the per-client limiter gives; the handler
1426        // renders it as that limiter's 429.
1427        if !self
1428            .hint_cap
1429            .admit(tenant_id, &client.client_id, &named, Utc::now())
1430            .await?
1431        {
1432            return Err(OAuth2Error::SlowDown);
1433        }
1434
1435        let subject = self.resolve_subject(tenant_id, &named).await?;
1436
1437        let expires_at = Utc::now() + Duration::seconds(expires_in as i64);
1438        let stored = self
1439            .requests
1440            .create(CreateCibaRequest {
1441                tenant_id,
1442                client_id: client.client_id.clone(),
1443                auth_req_id_hash: hash_auth_req_id(&auth_req_id),
1444                user_id: subject.as_ref().map(|u| u.id),
1445                scopes: scopes.clone(),
1446                binding_message: binding_message.clone(),
1447                acr_values,
1448                resource,
1449                delivery_mode: mode,
1450                ping,
1451                interval_secs: DEFAULT_INTERVAL_SECS,
1452                expires_at,
1453            })
1454            .await
1455            .map_err(|e| match e {
1456                axiam_core::error::AxiamError::ServiceUnavailable(detail) => {
1457                    tracing::error!(%detail, "a ping-mode CIBA request could not be stored");
1458                    OAuth2Error::ServerError("ping mode is not available on this deployment".into())
1459                }
1460                other => OAuth2Error::ServerError(other.to_string()),
1461            })?;
1462
1463        let notification = subject.map(|user| CibaUserNotification {
1464            tenant_id,
1465            request_id: stored.id,
1466            user_id: user.id,
1467            client_id: client.client_id.clone(),
1468            client_name: client.name.clone(),
1469            binding_message,
1470            scopes,
1471            expires_at,
1472        });
1473
1474        Ok(CibaInitiation {
1475            response: BackchannelAuthenticationResponse {
1476                auth_req_id,
1477                expires_in,
1478                interval: DEFAULT_INTERVAL_SECS,
1479            },
1480            request: stored,
1481            notification,
1482        })
1483    }

1650    ) -> Result<CibaDecisionOutcome, OAuth2Error> {
1651        if !recorded {
1652            return Ok(CibaDecisionOutcome::NotDecidable);
1653        }
1654        match self
1655            .requests
1656            .get_by_id(tenant_id, request_id)
1657            .await
1658            .map_err(|e| OAuth2Error::ServerError(e.to_string()))?
1659        {
1660            Some(req) => {
1661                self.enqueue_ping(&req).await;
1662                Ok(CibaDecisionOutcome::Recorded(Box::new(req)))
1663            }
1664            // Swept between the write and the read: decided, but gone.
1665            None => Ok(CibaDecisionOutcome::NotDecidable),
1666        }
1667    }

1669    /// Queue the ping of a just-decided ping-mode request (D-65). After an
1670    /// approval **and** after a denial: the client learns that the request was
1671    /// decided, never how — it asks the token endpoint, where it authenticates.
1672    async fn enqueue_ping(&self, request: &CibaRequest) {
1673        let Some(publisher) = &self.ping else {
1674            return;
1675        };
1676        if request.delivery_mode != CibaDeliveryMode::Ping {
1677            return;
1678        }
1679        let message = crate::ciba_ping::ping_message(request.tenant_id, request.id);
1680        if let Err(e) = publisher.enqueue(&message).await {
1681            tracing::error!(
1682                error = %e,
1683                request_id = %request.id,
1684                "a decided CIBA request's ping could not be queued; the client can still \
1685                 collect the result from the token endpoint"
1686            );
1687        }
1688    }

2142    /// datastore's semantics: the windowed upsert (a newer window resets the
2143    /// bucket, an older one adds to the stored window), the plain read, and
2144    /// the conditional take-back (only while the bucket holds the window
2145    /// named, never below zero, never creating a bucket). Each statement
2146    /// yields first, so concurrent calls interleave between statements as
2147    /// they do against the datastore; each is atomic, as one statement on one
2148    /// record is.
2149    #[derive(Default)]
2150    struct MemStore(std::sync::Mutex<std::collections::HashMap<String, (DateTime<Utc>, u64)>>);

2152    impl axiam_db::SharedRateLimitStore for MemStore {
2153        fn increment_by<'a>(
2154            &'a self,
2155            key: &'a str,
2156            window_start: DateTime<Utc>,
2157            delta: u64,
2158        ) -> axiam_db::StoreIncrementFuture<'a> {
2159            Box::pin(async move {
2160                tokio::task::yield_now().await;
2161                let mut map = self.0.lock().unwrap();
2162                let entry = map.entry(key.to_owned()).or_insert((window_start, 0));
2163                if entry.0 < window_start {
2164                    *entry = (window_start, 0);
2165                }
2166                entry.1 += delta;
2167                Ok(entry.1)
2168            })
2169        }
2170
2171        fn peek_bucket<'a>(&'a self, key: &'a str) -> axiam_db::StorePeekFuture<'a> {
2172            Box::pin(async move {
2173                tokio::task::yield_now().await;
2174                Ok(self.0.lock().unwrap().get(key).copied())
2175            })
2176        }
2177
2178        fn decrement<'a>(
2179            &'a self,
2180            key: &'a str,
2181            window_start: DateTime<Utc>,
2182        ) -> axiam_db::StoreDecrementFuture<'a> {
2183            Box::pin(async move {
2184                tokio::task::yield_now().await;
2185                match self.0.lock().unwrap().get_mut(key) {
2186                    Some((stored, count)) if *stored == window_start && *count > 0 => {
2187                        *count -= 1;
2188                        Ok(true)
2189                    }
2190                    _ => Ok(false),
2191                }
2192            })
2193        }
2194    }

2403    /// Runs `stamps.len()` concurrent calls for one hint, alternating between
2404    /// two replicas' caps over one store (each with the allowance `per_hint`),
2405    /// and answers which were admitted, by stamp.
2406    async fn concurrent_calls(
2407        store: std::sync::Arc<dyn axiam_db::SharedRateLimitStore>,
2408        per_hint: u32,
2409        stamps: &[DateTime<Utc>],
2410    ) -> Vec<(DateTime<Utc>, Result<bool, String>)> {
2411        let per_hint = std::num::NonZeroU32::new(per_hint).unwrap();
2412        let replicas = [
2413            CibaHintCap::derived_from(store.clone(), deployment_secret()).with_per_hint(per_hint),
2414            CibaHintCap::derived_from(store, deployment_secret()).with_per_hint(per_hint),
2415        ];
2416        let tenant = Uuid::from_u128(7);
2417        let hint = HintName::Login("contended".into());
2418        let barrier = std::sync::Arc::new(tokio::sync::Barrier::new(stamps.len()));
2419        let tasks: Vec<_> = stamps
2420            .iter()
2421            .enumerate()
2422            .map(|(i, stamp)| {
2423                let cap = replicas[i % 2].clone();
2424                let hint = hint.clone();
2425                let barrier = barrier.clone();
2426                let stamp = *stamp;
2427                tokio::spawn(async move {
2428                    barrier.wait().await;
2429                    let admitted = cap.admit(tenant, "oa_a", &hint, stamp).await;
2430                    (stamp, admitted.map_err(|e| e.to_string()))
2431                })
2432            })
2433            .collect();
2434        let mut out = Vec::new();
2435        for task in tasks {
2436            out.push(task.await.unwrap());
2437        }
2438        out
2439    }
