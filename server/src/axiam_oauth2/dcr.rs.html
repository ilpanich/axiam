1//! RFC 7591 dynamic client registration — the request, the policy and the
2//! refusals (T21.4).
3//!
4//! `POST /oauth2/register` is the first endpoint in AXIAM that **writes** on
5//! behalf of a caller holding no credential. Everything in this module exists
6//! because of that sentence. The REST handler owns the transport, the audit
7//! event, the quota and the rate limit; this module owns the question *may
8//! this registration exist, and what exactly does it become*, and answers it
9//! as a pure function of the request and the tenant's policy so that the
10//! answer can be tested without a database.
11//!
12//! # What a self-registered client may not decide
13//!
14//! Four things, and each one is a decision the tenant took in advance:
15//!
16//! | The request may name | It is decided by |
17//! | --- | --- |
18//! | `redirect_uris` | the request, within `dcr_allowed_redirect_hosts` |
19//! | `scope` | the request, within `dcr_allowed_scopes` |
20//! | `grant_types` | the request, within `{authorization_code, refresh_token}` |
21//! | `token_endpoint_auth_method` | the request, within four methods |
22//! | **audiences** (`allowed_resources`) | **the tenant, always** (D3) |
23//! | **profile** | **forced to `standard`** (I5) |
24//! | **provenance** (`managed_by`) | **forced to `dcr`** (D5) |
25//! | **consent** | **forced on** (D4) |
26//!
27//! The bottom four are not validated, they are *overwritten*: a request
28//! naming them is not refused, its value is discarded and the tenant's is
29//! used. That is deliberate. RFC 7591 §3.2.1 already contemplates a server
30//! returning metadata different from what was requested — "the authorization
31//! server MAY replace any of the client's requested metadata values" — and a
32//! refusal would turn a field an MCP client sends by habit into a registration
33//! failure, while silently ignoring it would be a lie. The response echoes
34//! what was actually stored, so a client that cares can see what it got.
35//!
36//! D3 is the one that matters. `allowed_resources` is what decides which
37//! audiences a token this client obtains may carry; a stranger who could name
38//! it could mint tokens for any service the deployment fronts. The list comes
39//! from `OidcPolicy::external_client_allowed_resources` and from nowhere else,
40//! and the settings layer refuses to enable anonymous registration while that
41//! list is empty — see `axiam_core::models::settings::validate_dcr_policy`.
42

48/// The grants a self-registered client may hold.
49///
50/// The two halves of a browser-driven code flow and nothing else.
51/// `client_credentials` and the RFC 8693 exchange are absent for the reason
52/// `GRANTS_FORBIDDEN_TO_PUBLIC_CLIENTS` gives in the admin handler and one
53/// more besides: both mint a token on the strength of the client's own
54/// identity, and the identity of a self-registered client is a row a stranger
55/// created. The device grant is absent because a device that cannot open a
56/// browser cannot run a registration request either.
57pub const DCR_GRANT_TYPES: [&str; 2] = ["authorization_code", "refresh_token"];

59/// The client-authentication methods a registration may name.
60///
61/// The four RFC 7591 §2 lists that AXIAM implements and that make sense for a
62/// client nobody vetted. The two mutual-TLS methods are absent: they name a
63/// certificate the deployment's listener must already trust, so registering
64/// one is a claim about the deployment's PKI rather than about the client, and
65/// an open endpoint has no business making it.
66pub const DCR_AUTH_METHODS: [ClientAuthMethod; 4] = [
67    ClientAuthMethod::None,
68    ClientAuthMethod::ClientSecretBasic,
69    ClientAuthMethod::ClientSecretPost,
70    ClientAuthMethod::PrivateKeyJwt,
71];

73/// The hosts a redirect URI may always use, whatever `dcr_allowed_redirect_hosts`
74/// says.
75///
76/// Every desktop MCP client — Claude Code, VS Code, MCP Inspector — receives
77/// its callback on the loopback interface under RFC 8252 §7.3, so a tenant
78/// whose host glob excluded them would have enabled registration for nobody.
79/// Allowing them adds no reach: a loopback URI is reachable only from the
80/// machine the browser is running on, which is the machine the end user is
81/// sitting at.
82const ALWAYS_ALLOWED_REDIRECT_HOSTS: [&str; 3] = ["127.0.0.1", "[::1]", "localhost"];

84/// An RFC 7591 §2 client metadata document, as a registration request.
85///
86/// Only the members AXIAM can act on are fields. RFC 7591 §2 says a server
87/// "MUST ignore any metadata parameters it does not understand", which is what
88/// `serde` does with the rest — `client_uri`, `logo_uri`, `contacts`,
89/// `tos_uri`, `policy_uri` and the localised `client_name#xx` forms all arrive
90/// from MCP Inspector and are dropped. `software_statement` is the one
91/// unimplemented member that is **not** ignored: see
92/// [`DcrError::UnsupportedSoftwareStatement`].
93#[derive(Debug, Clone, Default, Deserialize, utoipa::ToSchema)]
94pub struct RegistrationRequest {
95    /// RFC 7591 §2 `redirect_uris`. Required here, because every grant this
96    /// endpoint issues is browser-driven.
97    #[serde(default)]
98    pub redirect_uris: Vec<String>,
99    /// RFC 7591 §2 `client_name`. Shown to the end user on the consent screen
100    /// D4 forces, so a registration that omits it gets a generated one rather
101    /// than an empty label.
102    #[serde(default)]
103    pub client_name: Option<String>,
104    /// RFC 7591 §2 `grant_types`. Defaults to `["authorization_code"]`, as
105    /// §2 specifies.
106    #[serde(default)]
107    pub grant_types: Option<Vec<String>>,
108    /// RFC 7591 §2 `response_types`. Defaults to `["code"]`, as §2 specifies,
109    /// and `code` is the only value AXIAM implements.
110    #[serde(default)]
111    pub response_types: Option<Vec<String>>,
112    /// RFC 7591 §2 `token_endpoint_auth_method`. Defaults to
113    /// `client_secret_basic`, as §2 specifies — see
114    /// [`resolve_auth_method`] for why the RFC's default is used here rather
115    /// than AXIAM's own.
116    #[serde(default)]
117    pub token_endpoint_auth_method: Option<String>,
118    /// RFC 7591 §2 `scope`, space-delimited.
119    #[serde(default)]
120    pub scope: Option<String>,
121    /// RFC 7591 §2 `jwks` — an inline JWK Set, for `private_key_jwt`.
122    #[serde(default)]
123    pub jwks: Option<serde_json::Value>,
124    /// RFC 7591 §2 `jwks_uri`.
125    #[serde(default)]
126    pub jwks_uri: Option<String>,
127    /// RFC 7591 §2 `software_statement`. Refused rather than ignored.
128    #[serde(default)]
129    pub software_statement: Option<String>,
130}

132/// Why a registration was refused, with the RFC 7591 §3.2.2 code it is
133/// answered with.
134///
135/// A type rather than a string so the handler cannot invent a code, and so the
136/// tests can assert which refusal fired rather than matching prose.
137#[derive(Debug, Clone, PartialEq, Eq)]
138pub enum DcrError {
139    /// The tenant's policy is `disabled`.
140    ///
141    /// RFC 7591 §3.2.2 defines no code for "this server does not do that", and
142    /// inventing one would tell a caller something about the deployment. The
143    /// plan's answer is `403` with an `invalid_request`-shaped body: the path
144    /// exists and the feature does not, and the two are indistinguishable from
145    /// outside.
146    RegistrationDisabled,
147    /// `initial_access_token` mode and no usable bearer was presented.
148    ///
149    /// One variant for "absent", "malformed", "expired", "already spent" and
150    /// "another tenant's", because the response must not distinguish them: a
151    /// caller probing handles would otherwise learn which of its guesses named
152    /// a real token.
153    InitialAccessTokenRequired,
154    /// A `redirect_uris` entry is unusable or outside the tenant's host glob.
155    InvalidRedirectUri(String),
156    /// Any other metadata the server will not accept (RFC 7591 §3.2.2).
157    InvalidClientMetadata(String),
158    /// `software_statement` was present.
159    ///
160    /// Said plainly rather than ignored. A software statement is a *signed*
161    /// assertion about the client, so a server that dropped it would be
162    /// treating an unverified request as though it had been verified — the one
163    /// failure mode the member exists to prevent. RFC 7591 §3.2.2 defines
164    /// `invalid_software_statement` for exactly this.
165    UnsupportedSoftwareStatement,
166    /// The tenant already holds `dcr_max_clients` self-registered clients.
167    ClientQuotaExhausted { limit: u32 },
168}
169
170impl DcrError {
171    /// The RFC 7591 §3.2.2 `error` code.
172    pub const fn error_code(&self) -> &'static str {
173        match self {
174            // §3.2.2 lists three codes and none of them means "refused by
175            // policy"; `invalid_request` is what the plan specifies and what
176            // an OAuth client library will already understand.
177            Self::RegistrationDisabled
178            | Self::InitialAccessTokenRequired
179            | Self::ClientQuotaExhausted { .. } => "invalid_request",
180            Self::InvalidRedirectUri(_) => "invalid_redirect_uri",
181            Self::InvalidClientMetadata(_) => "invalid_client_metadata",
182            Self::UnsupportedSoftwareStatement => "invalid_software_statement",
183        }
184    }
185
186    /// The HTTP status the handler answers with.
187    ///
188    /// `403` for the three policy refusals and `400` for the metadata ones,
189    /// which is the ordinary split: the first three say "not you, or not
190    /// here", and the rest say "not like that".
191    pub const fn http_status(&self) -> u16 {
192        match self {
193            Self::RegistrationDisabled
194            | Self::InitialAccessTokenRequired
195            | Self::ClientQuotaExhausted { .. } => 403,
196            _ => 400,
197        }
198    }
199
200    /// The `error_description`.
201    pub fn description(&self) -> String {
202        match self {
203            Self::RegistrationDisabled => {
204                "dynamic client registration is not enabled for this tenant".to_owned()
205            }
206            Self::InitialAccessTokenRequired => {
207                "this tenant requires an initial access token: present one as \
208                 `Authorization: Bearer <token>` (RFC 7591 section 1.2)"
209                    .to_owned()
210            }
211            Self::InvalidRedirectUri(d) | Self::InvalidClientMetadata(d) => d.clone(),
212            Self::UnsupportedSoftwareStatement => {
213                "software_statement is not supported by this authorization server; send the \
214                 metadata directly"
215                    .to_owned()
216            }
217            Self::ClientQuotaExhausted { limit } => format!(
218                "this tenant has reached its limit of {limit} dynamically registered clients"
219            ),
220        }
221    }
222}
223
224impl std::fmt::Display for DcrError {
225    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
226        write!(f, "{}: {}", self.error_code(), self.description())
227    }
228}

232/// Whether `host` matches one glob `pattern`.
233///
234/// The grammar is deliberately tiny — a literal host, or `*` as the **whole**
235/// leftmost label (`*.example.com`), or `*` alone — because a host allow-list
236/// in front of a redirect is a security check, and a general-purpose glob in
237/// front of a security check is a place for a subtle matching bug to become an
238/// open redirect. In particular:
239///
240/// * `*.example.com` matches `mcp.example.com` and `a.b.example.com`. It does
241///   **not** match `example.com` itself (the pattern says there is a label
242///   there) and it does not match `evil-example.com` (the dot is part of the
243///   pattern, so the match is on a label boundary rather than on a suffix).
244///   That last case is the whole reason this is not `ends_with`.
245/// * `*` matches anything, which is what a tenant that wants no host
246///   restriction writes. It is spelled out as a value rather than implied by
247///   an empty list, because an empty list means the opposite: no host is
248///   allowed beyond the loopback three.
249/// * A pattern with `*` anywhere else (`mcp*.example.com`, `*.*.com`) matches
250///   nothing at all. Refusing to guess is the fail-closed direction, and the
251///   settings page documents the two forms.
252///
253/// Comparison is ASCII-case-insensitive, matching the DNS rule and what
254/// `url::Url` already does to a host it parsed.
255pub fn host_glob_matches(pattern: &str, host: &str) -> bool {
256    let pattern = pattern.trim();
257    if pattern == "*" {
258        return true;
259    }
260    if let Some(suffix) = pattern.strip_prefix("*.") {
261        // The remainder must itself be a plain host: `*.*.com` is not a
262        // pattern this grammar admits.
263        if suffix.contains('*') || suffix.is_empty() {
264            return false;
265        }
266        // `host` must end with `.suffix`, so the wildcard covers at least one
267        // whole label and the comparison lands on a label boundary.
268        return host.len() > suffix.len() + 1
269            && host[host.len() - suffix.len()..].eq_ignore_ascii_case(suffix)
270            && host.as_bytes()[host.len() - suffix.len() - 1] == b'.';
271    }
272    if pattern.contains('*') {
273        return false;
274    }
275    pattern.eq_ignore_ascii_case(host)
276}

278/// Whether a redirect URI's host is one this tenant admits.
279pub fn redirect_host_is_allowed(policy_hosts: &[String], host: &str) -> bool {
280    ALWAYS_ALLOWED_REDIRECT_HOSTS
281        .iter()
282        .any(|h| h.eq_ignore_ascii_case(host))
283        || policy_hosts.iter().any(|p| host_glob_matches(p, host))
284}

286/// Resolve the requested `token_endpoint_auth_method`.
287///
288/// An absent value is `client_secret_basic`, which is **RFC 7591 §2's**
289/// default rather than AXIAM's (`client_secret_post`). Two defaults in one
290/// server needs a reason, and it is this: a client registering through RFC
291/// 7591 and then reading RFC 7591 to decide how to authenticate will use the
292/// RFC's default, so a server that quietly stored a different one would have
293/// created a client that cannot authenticate the way it believes it can. The
294/// admin API's default is untouched, so nothing existing changes (I1); the
295/// response echoes the stored method, so a client that omitted the member can
296/// see what it got.
297fn resolve_auth_method(raw: Option<&str>) -> Result<ClientAuthMethod, DcrError> {
298    let Some(raw) = raw.map(str::trim).filter(|s| !s.is_empty()) else {
299        return Ok(ClientAuthMethod::ClientSecretBasic);
300    };
301    let method = ClientAuthMethod::from_wire(raw).filter(|m| DCR_AUTH_METHODS.contains(m));
302    method.ok_or_else(|| {
303        DcrError::InvalidClientMetadata(format!(
304            "token_endpoint_auth_method {raw:?} is not one this endpoint issues (allowed: {})",
305            DCR_AUTH_METHODS
306                .iter()
307                .map(|m| m.as_str())
308                .collect::<Vec<_>>()
309                .join(", ")
310        ))
311    })
312}

326/// Validate a registration against a tenant's policy (RFC 7591 §3.1).
327///
328/// Pure: no clock, no database, no randomness. The caller has already decided
329/// that the tenant's mode permits this request at all (and, in
330/// `initial_access_token` mode, has already spent the token), because both of
331/// those need state this module deliberately does not have.
332///
333/// # Order of refusals
334///
335/// Structural before policy, and the cheapest structural check first. A
336/// registration with three problems should hear about the one that is most
337/// obviously the client's own — a `software_statement` it should not have
338/// sent, a grant type this server does not issue — before it hears about a
339/// tenant allow-list, which is an operator's decision the client cannot act
340/// on.
341pub fn validate(
342    tenant_id: Uuid,
343    req: &RegistrationRequest,
344    policy: &OidcPolicy,
345) -> Result<ValidatedRegistration, DcrError> {
346    // RFC 7591 §2's one unimplemented member, said plainly. First, because a
347    // request carrying one is asking for a guarantee nothing below provides.
348    if req
349        .software_statement
350        .as_deref()
351        .is_some_and(|s| !s.trim().is_empty())
352    {
353        return Err(DcrError::UnsupportedSoftwareStatement);
354    }
355
356    // `response_types` defaults to `["code"]` (RFC 7591 §2), which is the only
357    // value AXIAM implements — `authorize` refuses everything else, so
358    // accepting another here would create a client that fails its first
359    // request.
360    if let Some(types) = &req.response_types
361        && let Some(bad) = types.iter().find(|t| t.trim() != "code")
362    {
363        return Err(DcrError::InvalidClientMetadata(format!(
364            "response_type {bad:?} is not supported; this server issues authorization codes only"
365        )));
366    }
367
368    let grant_types: Vec<String> = match &req.grant_types {
369        // RFC 7591 §2: absent means `["authorization_code"]`.
370        None => vec!["authorization_code".to_owned()],
371        Some(requested) => {
372            if requested.is_empty() {
373                return Err(DcrError::InvalidClientMetadata(
374                    "grant_types must not be empty".into(),
375                ));
376            }
377            for g in requested {
378                if !DCR_GRANT_TYPES.contains(&g.trim()) {
379                    return Err(DcrError::InvalidClientMetadata(format!(
380                        "grant_type {g:?} is not one this endpoint issues (allowed: {})",
381                        DCR_GRANT_TYPES.join(", ")
382                    )));
383                }
384            }
385            // `refresh_token` alone is a client that can refresh a token it can
386            // never obtain. Refused rather than silently topped up with
387            // `authorization_code`, because adding a grant nobody asked for is
388            // how a registration ends up more capable than its request.
389            if !requested.iter().any(|g| g.trim() == "authorization_code") {
390                return Err(DcrError::InvalidClientMetadata(
391                    "grant_types must include authorization_code: refresh_token alone would \
392                     register a client that can refresh a token it cannot obtain"
393                        .into(),
394                ));
395            }
396            requested.iter().map(|g| g.trim().to_owned()).collect()
397        }
398    };
399
400    let token_endpoint_auth_method =
401        resolve_auth_method(req.token_endpoint_auth_method.as_deref())?;
402
403    // --- redirect URIs ------------------------------------------------------
404    //
405    // Structure is the caller's to check with the same `validate_redirect_uris`
406    // the admin API uses — one rule, one place. What is left here is the
407    // tenant's host allow-list, which the admin API has no equivalent of
408    // because an administrator registering a URI has already decided it is
409    // acceptable.
410    if req.redirect_uris.is_empty() {
411        return Err(DcrError::InvalidRedirectUri(
412            "redirect_uris must name at least one URI: every grant this endpoint issues is \
413             completed through a browser redirect"
414                .into(),
415        ));
416    }
417    for uri in &req.redirect_uris {
418        let parsed: url::Url = uri
419            .parse()
420            .map_err(|_| DcrError::InvalidRedirectUri(format!("{uri:?} is not a valid URI")))?;
421        let host = parsed.host_str().ok_or_else(|| {
422            DcrError::InvalidRedirectUri(format!("{uri:?} has no host component"))
423        })?;
424        if !redirect_host_is_allowed(&policy.dcr_allowed_redirect_hosts, host) {
425            return Err(DcrError::InvalidRedirectUri(format!(
426                "the host {host:?} is not one this tenant accepts a self-registered redirect \
427                 for; an administrator sets dcr_allowed_redirect_hosts"
428            )));
429        }
430    }
431
432    // --- scopes -------------------------------------------------------------
433    //
434    // RFC 7591 §2 makes `scope` a space-delimited string, not an array. An
435    // absent one registers no scopes at all rather than the tenant's whole
436    // list: a client gets what it asked for, and a client that asked for
437    // nothing is not handed everything.
438    let scopes: Vec<String> = req
439        .scope
440        .as_deref()
441        .unwrap_or("")
442        .split_whitespace()
443        .map(str::to_owned)
444        .collect();
445    for scope in &scopes {
446        if !policy.dcr_allowed_scopes.iter().any(|s| s == scope) {
447            return Err(DcrError::InvalidClientMetadata(format!(
448                "scope {scope:?} is not one this tenant offers to self-registered clients; an \
449                 administrator sets dcr_allowed_scopes"
450            )));
451        }
452    }
453
454    // --- the four the request does not decide -------------------------------
455    let name = req
456        .client_name
457        .as_deref()
458        .map(str::trim)
459        .filter(|n| !n.is_empty())
460        .map_or_else(|| "Dynamically registered client".to_owned(), str::to_owned);
461
462    Ok(ValidatedRegistration {
463        create: CreateOAuth2Client {
464            tenant_id,
465            name,
466            redirect_uris: req.redirect_uris.clone(),
467            grant_types,
468            scopes,
469            post_logout_redirect_uris: Vec::new(),
470            backchannel_logout_uri: None,
471            require_par: false,
472            // I5 — forced, never read from the request. `fapi::validate_registration`
473            // refuses the combination anyway (a `dcr` row may carry no FAPI
474            // profile at all), so this is the first of two gates rather than
475            // the only one.
476            profile: ClientProfile::Standard,
477            token_endpoint_auth_method,
478            tls_client_auth_subject_dn: None,
479            tls_client_auth_san_dns: None,
480            tls_client_auth_san_uri: None,
481            self_signed_tls_client_auth_thumbprints: Vec::new(),
482            tls_client_certificate_bound_access_tokens: false,
483            // RFC 7591 §2's key sources, carried through for
484            // `private_key_jwt`. `fapi::validate_registration` enforces the
485            // "exactly one" rule (`fapi.rs`'s `JwksSourceCount`) and refuses a
486            // non-https `jwks_uri`, which is also the SSRF guard: the URL is
487            // fetched later, by the same cache a federated IdP's JWKS goes
488            // through.
489            jwks: req.jwks.as_ref().map(ToString::to_string),
490            jwks_uri: req.jwks_uri.clone(),
491            dpop_bound_access_tokens: false,
492            dpop_require_nonce: false,
493            authn_request_params: axiam_core::models::oauth2_client::AuthnRequestParamsMode::Ignore,
494            browser_sso: false,
495            // D3 — the tenant's list, verbatim. The single most important line
496            // in this module: it is what stops a party that registered itself
497            // from naming the audience of the tokens it will obtain.
498            allowed_resources: policy.external_client_allowed_resources.clone(),
499            // D5 — forced. A request cannot claim to be an administrator's
500            // client, because this value is built here rather than echoed.
501            managed_by: axiam_core::models::oauth2_client::ManagedBy::Dcr,
502        },
503    })
504}

506/// What the tenant's mode demands of a caller, before any metadata is looked
507/// at.
508///
509/// Separated from [`validate`] because the answer needs the request's
510/// `Authorization` header and, in one case, a database write — neither of
511/// which belongs in a pure validator. The handler asks this first, so a tenant
512/// with registration off never reaches the metadata rules at all and cannot be
513/// probed for what they are.
514pub const fn gate(mode: DynamicRegistrationMode, bearer_present: bool) -> Result<(), DcrError> {
515    match mode {
516        DynamicRegistrationMode::Disabled => Err(DcrError::RegistrationDisabled),
517        DynamicRegistrationMode::InitialAccessToken if !bearer_present => {
518            Err(DcrError::InitialAccessTokenRequired)
519        }
520        _ => Ok(()),
521    }
522}

524/// An RFC 7591 §3.2.1 registration response.
525///
526/// `registration_access_token` and `registration_client_uri` are **absent**:
527/// RFC 7592's client configuration endpoint is deferred (the plan's item 4),
528/// and RFC 7591 §3.2.1 makes both OPTIONAL. Returning them would promise an
529/// endpoint that does not exist, which a conforming client would then try.
530#[derive(Debug, Clone, Serialize, utoipa::ToSchema)]
531pub struct RegistrationResponse {
532    /// The issued `client_id`.
533    pub client_id: String,
534    /// The issued secret, shown exactly once.
535    ///
536    /// Absent for a `none` registration, which is every MCP desktop client:
537    /// a public client is created with no secret at all, and sending `""`
538    /// would read as a secret that happens to be empty.
539    #[serde(skip_serializing_if = "Option::is_none")]
540    pub client_secret: Option<String>,
541    /// RFC 7591 §3.2.1 — when the `client_id` was issued, as a Unix timestamp.
542    pub client_id_issued_at: i64,
543    /// RFC 7591 §3.2.1 — `0` means the secret does not expire.
544    ///
545    /// Present only when a secret was issued, as §3.2.1 requires ("REQUIRED if
546    /// `client_secret` is issued"). AXIAM does not expire client secrets, so
547    /// the value is always `0`; a client that read a non-zero value here and
548    /// planned a rotation around it would be planning around a promise this
549    /// server does not make.
550    #[serde(skip_serializing_if = "Option::is_none")]
551    pub client_secret_expires_at: Option<i64>,
552    /// The stored client name.

638    /// The case this grammar exists for. `ends_with` would admit every one of

640    #[test]
641    fn a_wildcard_label_matches_on_a_label_boundary_and_never_on_a_suffix() {
642        assert!(host_glob_matches("*.example.com", "mcp.example.com"));
643        assert!(host_glob_matches("*.example.com", "a.b.example.com"));
644        assert!(host_glob_matches("*.example.com", "MCP.EXAMPLE.COM"));
645
646        for host in [
647            // The pattern says there is a label there.
648            "example.com",
649            // The dot is part of the pattern, so this is not a match.

651            "notexample.com",
652            // A different registrable domain that merely ends the same way.
653            "example.com.attacker.test",
654        ] {
655            assert!(
656                !host_glob_matches("*.example.com", host),
657                "{host} must not match *.example.com"
658            );
659        }

874        for (err, code, status) in [
875            (DcrError::RegistrationDisabled, "invalid_request", 403),
876            (DcrError::InitialAccessTokenRequired, "invalid_request", 403),
877            (
878                DcrError::ClientQuotaExhausted { limit: 20 },

880                403,
881            ),
882            (
883                DcrError::InvalidRedirectUri("x".into()),
884                "invalid_redirect_uri",
885                400,
886            ),
887            (
888                DcrError::InvalidClientMetadata("x".into()),
889                "invalid_client_metadata",
890                400,
891            ),
892            (
893                DcrError::UnsupportedSoftwareStatement,
894                "invalid_software_statement",
895                400,
896            ),
897        ] {
