1//! DPoP — Demonstrating Proof of Possession (RFC 9449) — X5.1.
2//!
3//! The second half of X5.1's sender-constraining row, and the counterpart to
4//! [`crate::mtls`]'s §3. Both answer the same question — *may this bearer use
5//! this token?* — and they differ in what the holder must possess:
6//!
7//! | | Possession proved by | Cost per request |
8//! |---|---|---|
9//! | mTLS binding (RFC 8705 §3) | a TLS handshake the transport already performed | one SHA-256 |
10//! | DPoP (RFC 9449) | a freshly signed proof JWT, per request | **one asymmetric signature verification** |
11//!
12//! That second row is the reason DPoP exists and the reason it is not free.
13//! mTLS binding is cheap because the expensive part — proving possession of the
14//! certificate's private key — happened during the handshake and is amortised
15//! over every request on the connection. DPoP has no connection to amortise
16//! over, so it pays a public-key verification *per request*. `bench_dpop_proof`
17//! in `axiam-auth`'s benchmark measures it, and §X5.1's write-up publishes the
18//! number rather than an adjective. A client that can do mTLS should.
19//!
20//! What DPoP buys for that cost is the deployment it fits: a client behind a
21//! TLS-terminating load balancer it does not control cannot present a client
22//! certificate to AXIAM at all. Before this module, such a client had no route
23//! to a sender-constrained token — which the conformance runbook recorded as a
24//! coverage gap. It is now closed.
25//!
26//! # What a proof is checked against
27//!
28//! RFC 9449 §4.3. Every one of these is a refusal, never a warning:
29//!
30//! 1. `typ` is exactly `dpop+jwt`. A proof that is not typed as one is not one —
31//!    this is the header confusion the `typ` member exists to prevent, and it is
32//!    what stops an access token or an ID token being replayed as a proof.
33//! 2. `alg` is an asymmetric algorithm this profile permits, **taken from the
34//!    embedded key** (see [`crate::jose`]) rather than believed from the header.
35//! 3. The header carries a public `jwk`, and the signature verifies under it.
36//!    A `jwk` carrying private key material is refused outright (§4.3 step 4):
37//!    a client that leaks its private key in a proof has already lost, and
38//!    accepting it would make the leak silent.
39//! 4. `htm` matches the HTTP method and `htu` the request URI, compared after
40//!    stripping query and fragment (§4.3 step 9).
41//! 5. `iat` is within [`DEFAULT_PROOF_MAX_AGE_SECS`] of now, in both directions.
42//! 6. `jti` is present and, at the caller's discretion, single-use. **Freshness
43//!    is not replay protection**: `iat` bounds the window, and the `jti` guard
44//!    is what makes the window unusable. See [`crate::private_key_jwt`] for the
45//!    storage mechanism both share.
46//! 7. When the server requires one, `nonce` matches the nonce the server
47//!    issued — otherwise the caller answers `use_dpop_nonce` with a fresh one.
48//! 8. When a proof accompanies an access token, `ath` is the base64url SHA-256
49//!    of that token, so a proof captured on one request cannot be re-aimed at
50//!    another token held by the same key.
51//!
52//! # What this module deliberately does not do
53//!
54//! It does not touch the database and it does not know what a client is. Replay
55//! recording is the caller's, because the caller is the one that knows the
56//! tenant and holds the repository — and because keeping the signature check
57//! synchronous and pure is what makes it benchmarkable and unit-testable
58//! against RFC 9449's own vectors.
59

73pub const TOKEN_TYPE_DPOP: &str = "DPoP";

75/// RFC 6749 §7.1: the `token_type` of everything AXIAM issued before X5.1, and
76/// of every unbound token it will ever issue.
77pub const TOKEN_TYPE_BEARER: &str = "Bearer";

79/// RFC 9449 §5: the `token_type` a response should carry for a given `cnf`.
80///
81/// `DPoP` when the token is DPoP-bound, `Bearer` otherwise — including for a
82/// certificate-bound token, which RFC 8705 leaves as a bearer token at the HTTP
83/// layer (the constraint is enforced by the TLS connection, not by a different
84/// authorization scheme).
85///
86/// A client that has never heard of DPoP therefore sees `Bearer`, exactly as it
87/// always has. That is the property the whole design turns on.
88///
89/// A free function rather than a `TokenService` associated one (SEC-096):
90/// `TokenService` serves three grants and `TokenExchangeService` serves a
91/// fourth, and the answer must not depend on which of them minted the token.
92pub fn token_type_for(cnf: Option<&axiam_auth::token::CnfClaim>) -> String {
93    match cnf {
94        Some(c) if c.dpop_thumbprint().is_some() => TOKEN_TYPE_DPOP.to_owned(),
95        _ => TOKEN_TYPE_BEARER.to_owned(),
96    }
97}

99/// How far `iat` may be from now, in either direction, for a proof to be fresh
100/// (RFC 9449 §4.3 step 12 leaves the window to the server).
101///
102/// Sixty seconds both ways. Forwards because a client's clock can legitimately
103/// run fast and refusing those proofs is an outage with no attacker in it;
104/// backwards because the window is the *only* thing bounding how long a
105/// captured proof stays interesting to somebody who cannot reach the replay
106/// table. Sixty is the value RFC 9449's own security considerations use as the
107/// illustrative "relatively brief period".
108pub const DEFAULT_PROOF_MAX_AGE_SECS: i64 = 60;

123/// Why a DPoP proof was refused.
124///
125/// RFC 9449 §7.1 gives the wire mapping: everything here is `invalid_dpop_proof`
126/// except [`DpopError::NonceRequired`] and [`DpopError::NonceMismatch`], which
127/// are `use_dpop_nonce` — a *challenge*, not a rejection, and the one case where
128/// the client is expected to retry rather than give up.
129#[derive(Debug, Clone, PartialEq, Eq)]
130pub enum DpopError {
131    /// Not a JWT, or not one carrying the claims a proof must carry.
132    Malformed(String),
133    /// `typ` was absent or was not `dpop+jwt`.
134    WrongTyp { got: Option<String> },
135    /// The header carried no `jwk`, or one that cannot be used.
136    Key(jose::JoseKeyError),
137    /// The header's `jwk` contained private key material.
138    PrivateKeyInProof,
139    /// The signature did not verify under the embedded key.
140    Signature,
141    /// `iat` is outside the freshness window.
142    Stale { iat: i64, now: i64 },
143    /// `htm` does not name the method this request used.
144    MethodMismatch { expected: String, got: String },
145    /// `htu` does not name the URI this request targeted.
146    UriMismatch { expected: String, got: String },
147    /// The server requires a nonce and the proof carried none.
148    NonceRequired,
149    /// The proof carried a nonce that is not the one the server issued.
150    NonceMismatch,
151    /// `ath` does not hash the access token presented alongside the proof.
152    AccessTokenHashMismatch,
153    /// A proof accompanied an access token but carried no `ath`.
154    AccessTokenHashMissing,
155}
156
157impl std::fmt::Display for DpopError {
158    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
159        match self {
160            Self::Malformed(d) => write!(f, "malformed DPoP proof: {d}"),
161            Self::WrongTyp { got } => write!(
162                f,
163                "a DPoP proof must be typed {DPOP_TYP:?}, got {got:?}; an untyped JWT is not a \
164                 proof"
165            ),
166            Self::Key(e) => write!(f, "DPoP proof key: {e}"),
167            Self::PrivateKeyInProof => write!(
168                f,
169                "the DPoP proof's jwk carries private key material, which RFC 9449 §4.3 forbids"
170            ),
171            Self::Signature => write!(f, "the DPoP proof signature does not verify"),
172            Self::Stale { iat, now } => write!(
173                f,
174                "the DPoP proof's iat ({iat}) is outside the {DEFAULT_PROOF_MAX_AGE_SECS}s \
175                 freshness window around {now}"
176            ),
177            Self::MethodMismatch { expected, got } => {
178                write!(f, "the DPoP proof's htm is {got:?}, not {expected:?}")
179            }
180            Self::UriMismatch { expected, got } => {
181                write!(f, "the DPoP proof's htu is {got:?}, not {expected:?}")
182            }
183            Self::NonceRequired => write!(f, "a DPoP nonce is required and the proof carried none"),
184            Self::NonceMismatch => write!(f, "the DPoP proof carries a stale or unknown nonce"),
185            Self::AccessTokenHashMismatch => write!(
186                f,
187                "the DPoP proof's ath does not hash the access token it was presented with"
188            ),
189            Self::AccessTokenHashMissing => write!(
190                f,
191                "a DPoP proof presented with an access token must carry ath (RFC 9449 §4.2)"
192            ),
193        }
194    }
195}

199impl DpopError {
200    /// The RFC 9449 §7.1 error code this refusal is reported as.
201    ///
202    /// `use_dpop_nonce` is not a failure the client should give up on — it is
203    /// the server saying "retry with this". Everything else is.
204    pub const fn error_code(&self) -> &'static str {
205        match self {
206            Self::NonceRequired | Self::NonceMismatch => "use_dpop_nonce",
207            _ => "invalid_dpop_proof",
208        }
209    }
210
211    /// Whether the client is expected to retry with a server-supplied nonce.
212    pub const fn is_nonce_challenge(&self) -> bool {
213        matches!(self, Self::NonceRequired | Self::NonceMismatch)
214    }
215}

223/// What the verifier checks a proof against.
224///
225/// A struct rather than eight positional parameters because two of them are
226/// `Option<&str>` and swapping them would compile — and would mean checking the
227/// nonce against the access token.
228#[derive(Debug, Clone, Copy)]
229pub struct DpopExpectation<'a> {
230    /// The HTTP method of the request the proof accompanies.
231    pub htm: &'a str,
232    /// The full request URI, which the verifier strips of query and fragment
233    /// before comparing (RFC 9449 §4.3 step 9).
234    pub htu: &'a str,
235    /// The nonce the server most recently issued to this client, if any.
236    pub expected_nonce: Option<&'a str>,
237    /// Whether a nonce is mandatory for this client. When true and the proof
238    /// carries none, the answer is [`DpopError::NonceRequired`] — a challenge.
239    pub require_nonce: bool,
240    /// The access token the proof was presented with, at a resource server.
241    /// `None` at the token endpoint, where no access token exists yet.
242    pub access_token: Option<&'a str>,
243    /// Unix seconds. Passed in rather than read from the clock so a test can
244    /// pin it and the benchmark can exclude it.
245    pub now: i64,
246    /// Freshness window in seconds; [`DEFAULT_PROOF_MAX_AGE_SECS`] unless a
247    /// deployment has a reason.
248    pub max_age_secs: i64,
249}
250
251impl<'a> DpopExpectation<'a> {
252    /// A token-endpoint expectation: no access token, no nonce.
253    pub fn at_token_endpoint(htm: &'a str, htu: &'a str, now: i64) -> Self {
254        Self {
255            htm,
256            htu,
257            expected_nonce: None,
258            require_nonce: false,
259            access_token: None,
260            now,
261            max_age_secs: DEFAULT_PROOF_MAX_AGE_SECS,
262        }
263    }
264
265    /// A resource-server expectation: the proof must hash the token it
266    /// accompanies.
267    pub fn at_resource_server(htm: &'a str, htu: &'a str, access_token: &'a str, now: i64) -> Self {
268        Self {
269            htm,
270            htu,
271            expected_nonce: None,
272            require_nonce: false,
273            access_token: Some(access_token),
274            now,
275            max_age_secs: DEFAULT_PROOF_MAX_AGE_SECS,
276        }
277    }
278}

280/// A proof that verified, and the facts a caller needs from it.
281#[derive(Debug, Clone, PartialEq, Eq)]
282pub struct VerifiedDpopProof {
283    /// RFC 7638 thumbprint of the proof key — the `cnf.jkt` a token issued
284    /// against this proof will carry, and the replay scope of [`Self::jti`].
285    pub jkt: String,
286    /// The proof's unique identifier. The caller records it against `jkt` to
287    /// make the proof single-use.
288    pub jti: String,
289    /// `iat`, so the caller can size the replay row's lifetime to the
290    /// freshness window rather than guessing.
291    pub iat: i64,
292}
293
294impl VerifiedDpopProof {
295    /// When a replay row for this proof stops being useful.
296    ///
297    /// Exactly the end of the freshness window: past it, a replay is refused by
298    /// [`DpopError::Stale`] without the table being consulted, so keeping the
299    /// row longer costs storage and buys nothing.
300    pub fn replay_expiry(&self, max_age_secs: i64) -> chrono::DateTime<chrono::Utc> {
301        chrono::DateTime::from_timestamp(self.iat + max_age_secs, 0)
302            .unwrap_or_else(chrono::Utc::now)
303    }
304}

306/// Whether an `Authorization` scheme names DPoP.
307///
308/// Case-insensitive because RFC 9110 §11.1 makes auth schemes
309/// case-insensitive, and a client that sends `dpop` is not making a mistake
310/// worth an outage over.
311pub fn is_dpop_scheme(scheme: &str) -> bool {
312    scheme.eq_ignore_ascii_case(TOKEN_TYPE_DPOP)
313}

315/// RFC 9449 §4.3 step 9: compare `htu` with query and fragment removed.
316///
317/// Kept as a plain string operation rather than a URL parse. A parser would
318/// normalise — default ports, percent-encoding, case in the host — and every
319/// one of those normalisations is a place where two strings that are not equal
320/// become equal. The direction of the risk matters: an over-strict comparison
321/// fails an onboarding, an over-lenient one accepts a proof minted for a
322/// different endpoint.
323fn strip_query_and_fragment(uri: &str) -> &str {
324    let end = uri.find(['?', '#']).unwrap_or(uri.len());
325    &uri[..end]
326}

328/// A JWK is public if it carries none of the private members RFC 7518 defines.
329///
330/// Enumerated positively — the members that make a key private — rather than
331/// trusting `serde` to have dropped them, because `jsonwebtoken`'s `Jwk` types
332/// simply have no fields for `d`, `p`, `q` and friends, so a private key
333/// deserializes into a *public* `Jwk` with the private half silently discarded.
334/// That is a safe outcome for verification and a terrible one for the client
335/// whose key just travelled over the wire, so the check is made against the raw
336/// JSON the proof actually carried.
337fn contains_private_key_material(raw_header: &serde_json::Value) -> bool {
338    const PRIVATE_MEMBERS: [&str; 8] = ["d", "p", "q", "dp", "dq", "qi", "oth", "k"];
339    raw_header
340        .get("jwk")
341        .and_then(|j| j.as_object())
342        .is_some_and(|o| PRIVATE_MEMBERS.iter().any(|m| o.contains_key(*m)))
343}

345/// Decode a JWS header as raw JSON, for the checks the typed `Header` cannot
346/// make.
347fn raw_header_of(proof: &str) -> Result<serde_json::Value, DpopError> {
348    use base64::Engine as _;
349    let encoded = proof
350        .split('.')
351        .next()
352        .ok_or_else(|| DpopError::Malformed("not a JWT".into()))?;
353    let bytes = base64::engine::general_purpose::URL_SAFE_NO_PAD
354        .decode(encoded)
355        .map_err(|e| DpopError::Malformed(format!("header is not base64url: {e}")))?;
356    serde_json::from_slice(&bytes)
357        .map_err(|e| DpopError::Malformed(format!("header is not JSON: {e}")))
358}

360/// Verify a DPoP proof against what the request actually was (RFC 9449 §4.3).
361///
362/// Returns the proof's `jkt` and `jti` on success. **The caller must still
363/// record the `jti`** — see the module docs on why freshness alone is not
364/// replay protection.
365pub fn verify_dpop_proof(
366    proof: &str,
367    expect: &DpopExpectation<'_>,
368) -> Result<VerifiedDpopProof, DpopError> {
369    // --- header: typ, and the embedded key -------------------------------
370    let header =
371        decode_header(proof).map_err(|e| DpopError::Malformed(format!("bad JWS header: {e}")))?;
372
373    // RFC 9449 §4.3 step 3. Checked before anything expensive, and before the
374    // key is even looked at: a JWT that does not claim to be a proof must not
375    // be able to reach the verification path at all, or an access token signed
376    // by a client's own key becomes a proof.
377    match header.typ.as_deref() {
378        Some(t) if t.eq_ignore_ascii_case(DPOP_TYP) => {}
379        other => {
380            return Err(DpopError::WrongTyp {
381                got: other.map(str::to_owned),
382            });
383        }
384    }
385
386    let raw_header = raw_header_of(proof)?;
387    if contains_private_key_material(&raw_header) {
388        return Err(DpopError::PrivateKeyInProof);
389    }
390
391    let jwk: Jwk = header
392        .jwk
393        .ok_or_else(|| DpopError::Malformed("the proof header carries no jwk".into()))?;
394
395    // Belt and braces on the same property: `AlgorithmParameters::OctetKey` is
396    // the one variant that *is* private key material by construction, and it
397    // has a typed home in `Jwk` rather than being dropped.
398    if matches!(jwk.algorithm, AlgorithmParameters::OctetKey(_)) {
399        return Err(DpopError::PrivateKeyInProof);
400    }
401
402    // The algorithm comes from the key. See `crate::jose`'s module docs.
403    let key_alg = jose::algorithm_for_key(&jwk)?;
404    let alg = jose::verify_permitted_header(header.alg, key_alg)?;
405    let jkt = jose::jwk_thumbprint(&jwk)?;
406    let decoding_key: DecodingKey = jose::decoding_key_for(&jwk)?;
407
408    // --- signature and claims --------------------------------------------
409    let mut validation = Validation::new(alg);
410    // A proof has no audience and no issuer, and its `iat` is checked against
411    // this module's own window rather than jsonwebtoken's `exp` machinery —
412    // proofs have no `exp` at all. Turning these off is what lets the freshness
413    // rule be the one in RFC 9449 rather than the one in RFC 7519.
414    validation.validate_exp = false;
415    validation.validate_aud = false;
416    validation.required_spec_claims.clear();
417
418    let claims = decode::<ProofClaims>(proof, &decoding_key, &validation)
419        .map_err(|e| match e.kind() {
420            jsonwebtoken::errors::ErrorKind::InvalidSignature => DpopError::Signature,
421            _ => DpopError::Malformed(e.to_string()),
422        })?
423        .claims;
424
425    // --- freshness --------------------------------------------------------
426    if (claims.iat - expect.now).abs() > expect.max_age_secs {
427        return Err(DpopError::Stale {
428            iat: claims.iat,
429            now: expect.now,
430        });
431    }
432
433    // --- binding to *this* request ---------------------------------------
434    if !claims.htm.eq_ignore_ascii_case(expect.htm) {
435        return Err(DpopError::MethodMismatch {
436            expected: expect.htm.to_owned(),
437            got: claims.htm,
438        });
439    }
440    let expected_htu = strip_query_and_fragment(expect.htu);
441    let presented_htu = strip_query_and_fragment(&claims.htu);
442    if presented_htu != expected_htu {
443        return Err(DpopError::UriMismatch {
444            expected: expected_htu.to_owned(),
445            got: presented_htu.to_owned(),
446        });
447    }
448
449    // --- nonce (RFC 9449 §4.3 step 11, §8) --------------------------------
450    //
451    // Two independent conditions, in this order:
452    //
453    // 1. If the server *requires* a nonce, an absent one is a **challenge**
454    //    (`use_dpop_nonce`), not a rejection — the client is expected to retry
455    //    with the value the response supplies.
456    // 2. If the server *provided* a nonce, the proof must carry that one.
457    //
458    // A nonce the server never issued, on a request where none is required, is
459    // not checked. That is deliberately the RFC's rule rather than a stricter
460    // one: the server decides whether the mechanism is in force, so an
461    // unsolicited value cannot weaken anything, and refusing it would fail a
462    // client that is merely still sending a nonce from a window that has since
463    // been turned off.
464    if expect.require_nonce && claims.nonce.is_none() {
465        return Err(DpopError::NonceRequired);
466    }
467    if let Some(expected) = expect.expected_nonce
468        && claims.nonce.as_deref() != Some(expected)
469    {
470        return Err(DpopError::NonceMismatch);
471    }
472
473    // --- ath --------------------------------------------------------------
474    if let Some(token) = expect.access_token {
475        let Some(ath) = claims.ath.as_deref() else {
476            return Err(DpopError::AccessTokenHashMissing);
477        };
478        // Constant-time for the same reason the thumbprint comparison in
479        // `crate::mtls` is: cheap, and the one scenario where it matters is an
480        // attacker holding a stolen token probing what a proof must contain.
481        let matches: bool = {
482            use subtle::ConstantTimeEq;
483            ath.as_bytes()
484                .ct_eq(jose::access_token_hash(token).as_bytes())
485                .into()
486        };
487        if !matches {
488            return Err(DpopError::AccessTokenHashMismatch);
489        }
490    }
491
492    if claims.jti.trim().is_empty() {
493        return Err(DpopError::Malformed(
494            "a DPoP proof must carry a non-empty jti; without one it cannot be made single-use"
495                .into(),
496        ));
497    }
498
499    Ok(VerifiedDpopProof {
500        jkt,
501        jti: claims.jti,
502        iat: claims.iat,
503    })
504}

506/// Mint a `DPoP-Nonce` value.
507///
508/// Opaque and random, with no structure a client could predict or forge. RFC
509/// 9449 §8 leaves the format entirely to the server; what it must be is
510/// unguessable, because the whole point is that the client cannot have
511/// pre-computed a proof carrying it.
512pub fn new_nonce() -> String {
513    use base64::Engine as _;
514    use rand::RngExt as _;
515    let bytes: [u8; 24] = rand::rng().random();
516    base64::engine::general_purpose::URL_SAFE_NO_PAD.encode(bytes)
517}

627    /// The `alg` in the header cannot select a different algorithm from the one
628    /// the embedded key implies. This is the check `crate::jose` exists for.
629    #[test]
630    fn a_header_alg_that_disagrees_with_the_key_is_refused() {
631        let key = ed25519_key();
632        let mut header = proof_header(&key);
633        header["alg"] = json!("ES256");
634        // Signing with a header the encoder disagrees with fails outright in
635        // jsonwebtoken, so build the proof by hand from the honest signature.
636        let honest = sign(&key, proof_header(&key), claims(NOW));
637        let mut parts = honest.split('.');
638        let (_, payload, signature) = (
639            parts.next().unwrap(),
640            parts.next().unwrap(),
641            parts.next().unwrap(),
642        );
643        use base64::Engine as _;
644        let forged_header = base64::engine::general_purpose::URL_SAFE_NO_PAD
645            .encode(serde_json::to_vec(&header).unwrap());
646        let forged = format!("{forged_header}.{payload}.{signature}");
647        assert!(matches!(
648            verify_dpop_proof(&forged, &expectation(NOW)),
649            Err(DpopError::Key(jose::JoseKeyError::AlgorithmMismatch { .. }))
650        ));
651    }

653    /// A proof whose `jwk` leaks the private half is refused outright.
654    ///
655    /// The proof has to be assembled by hand: `jsonwebtoken`'s typed `Header`
656    /// has no field for `d`, so signing through it would silently drop the very
657    /// member under test and the assertion would pass for the wrong reason.
658    /// That silent drop is also exactly why `contains_private_key_material`
659    /// inspects the **raw** header JSON rather than the parsed `Jwk`.
660    #[test]
661    fn a_proof_carrying_private_key_material_is_refused() {
662        use base64::Engine as _;
663        let key = ed25519_key();
664        let honest = sign(&key, proof_header(&key), claims(NOW));
665        let mut parts = honest.split('.');
666        let (_, payload, signature) = (
667            parts.next().unwrap(),
668            parts.next().unwrap(),
669            parts.next().unwrap(),
670        );
671
672        let mut header = proof_header(&key);
673        header["jwk"]["d"] = json!("cGxlYXNlLWRvLW5vdC1zZW5kLXRoaXM");
674        let leaky = base64::engine::general_purpose::URL_SAFE_NO_PAD
675            .encode(serde_json::to_vec(&header).unwrap());
676
677        assert_eq!(
678            verify_dpop_proof(&format!("{leaky}.{payload}.{signature}"), &expectation(NOW)),
679            Err(DpopError::PrivateKeyInProof)

850    #[test]
851    fn a_resource_server_proof_must_hash_the_token_it_accompanies() {
852        let key = ed25519_key();
853        // Any string works here: this test asserts that `ath` BINDS the proof
854        // to whatever token accompanied it, not that the hash function is
855        // right. Cross-checking the hash against RFC 9449 §4.2's published
856        // vector is `jose::tests::ath_matches_the_rfc_9449_vector`'s job, and
857        // keeping the vector in exactly one place stops a secret scanner
858        // finding the same high-entropy literal twice.
859        let token = "test-access-token-not-a-credential";
860
861        let mut c = claims(NOW);
862        c["htm"] = json!("GET");
863        c["htu"] = json!("https://rs.example/resource");
864        c["ath"] = json!(jose::access_token_hash(token));
865        let proof = sign(&key, proof_header(&key), c.clone());
866        let expect =
867            DpopExpectation::at_resource_server("GET", "https://rs.example/resource", token, NOW);
868        assert!(verify_dpop_proof(&proof, &expect).is_ok());
869
870        // The same proof re-aimed at a different token held by the same key.
871        let other = DpopExpectation::at_resource_server(
872            "GET",
873            "https://rs.example/resource",
874            "a-different-token",
875            NOW,
876        );
877        assert_eq!(
878            verify_dpop_proof(&proof, &other),
879            Err(DpopError::AccessTokenHashMismatch)
880        );
881
882        // ...and a proof with no `ath` at all cannot be used with a token.
883        c.as_object_mut().unwrap().remove("ath");
884        let no_ath = sign(&key, proof_header(&key), c);
885        assert_eq!(
886            verify_dpop_proof(&no_ath, &expect),
887            Err(DpopError::AccessTokenHashMissing)
888        );
