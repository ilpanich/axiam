1//! The FAPI 2.0 profile switch (X5.1).
2//!
3//! FAPI 2.0 Security Profile (Final) is not one feature. It is a bundle of
4//! constraints, and a client that satisfies eleven of twelve is not
5//! "mostly FAPI" — it is a client with a hole. This module is where the bundle
6//! is defined once, so that:
7//!
8//! - an operator turns the whole posture on with **one field**
9//!   (`profile: "fapi2"`), exactly as the rate-limit postures work; and
10//! - **ordinary clients are untouched.** Every function here is a no-op for
11//!   [`ClientProfile::Standard`], which is the serde default and what every
12//!   row written before schema v38 decodes to. There is no behaviour change
13//!   for a deployment that never sets the flag — that is a property the tests
14//!   at the bottom of this file assert directly, not an aspiration.
15//!
16//! # What the switch actually requires
17//!
18//! | Constraint | Where enforced | FAPI 2.0 §|
19//! |---|---|---|
20//! | PAR mandatory | `require_par` forced true at registration; `authorize` refuses a direct request | 5.3.1.2 |
21//! | PKCE with `S256` mandatory | [`enforce_authorization_request`]; `S256`-only is already global | 5.3.1.2 |
22//! | `response_type=code` only | already global in `authorize` — no other value is accepted for any client | 5.3.1.1 |
23//! | Strong client authentication | [`validate_registration`] requires an mTLS method **or** `private_key_jwt` | 5.3.1.1 |
24//! | Sender-constrained tokens | [`validate_registration`] requires certificate binding **or** DPoP | 5.3.1.1 |
25//! | Strict `redirect_uri` equality | already global — `redirect_uris.contains()`, no prefix or wildcard matching anywhere | 5.3.1.2 |
26//! | Authorization code single-use | already global, and since #318/schema v37 guaranteed by a transaction plus a post-commit nonce read-back | 5.3.1.2 |
27//! | No token in any URL | already global — `response_type=token` does not exist in this server | 5.3.1.1 |
28//! | EdDSA/PS256/ES256, never `none` | already global — `Algorithm::EdDSA` is hard-coded at both encode and decode | 5.3.1.1 |
29//!
30//! Four of those nine rows say "already global". That is the honest reading of
31//! the tree and the reason X5.1's gap table listed them as *audit* items
32//! rather than *work* items: AXIAM never implemented the relaxations FAPI
33//! forbids. What this module adds is the machinery for the five that were
34//! genuinely absent, plus tests that pin the four so a later convenience
35//! change cannot quietly reintroduce one.
36//!
37//! # Registration-time, not just request-time
38//!
39//! The heavy lifting is [`validate_registration`], which refuses to *create* a
40//! FAPI client that could not satisfy the profile. Enforcing only at request
41//! time would leave a registered client that answers `invalid_request` to
42//! every request it ever makes — a configuration error discovered by the
43//! client's users rather than by the operator who made it. Request-time checks
44//! remain as defence in depth, because a row edited directly in the database
45//! never passes through registration validation.
46//!
47//! # Two families, two mechanisms, and the pairing rule
48//!
49//! FAPI 2.0 §5.3.1.1 asks two independent questions, and each has two
50//! acceptable answers:
51//!
52//! | | mutual TLS | asymmetric JWT |
53//! |---|---|---|
54//! | **Client authentication** | `tls_client_auth`, `self_signed_tls_client_auth` (RFC 8705 §2) | `private_key_jwt` (RFC 7523 §2.2) |
55//! | **Sender-constraining** | `tls_client_certificate_bound_access_tokens` (RFC 8705 §3) | `dpop_bound_access_tokens` (RFC 9449) |
56//!
57//! All four pairings are legitimate, and the gate accepts all four. The profile
58//! does **not** require the two columns to match: a client may authenticate
59//! with `private_key_jwt` and bind its tokens to a certificate, or authenticate
60//! with mTLS and bind with DPoP. What it requires is one answer from each *row*,
61//! and [`validate_registration`] refuses a client that has authentication from
62//! one family and sender-constraining from neither — which is the shape a
63//! half-finished migration produces and the one an operator is most likely to
64//! create by accident.
65

72/// Why a client registration cannot satisfy the profile it asked for.
73///
74/// A typed error rather than a string so the REST layer can render it as a
75/// 400 with a field-specific message, and so a test can assert *which*
76/// constraint failed rather than pattern-matching prose.
77#[derive(Debug, Clone, PartialEq, Eq)]
78pub enum FapiRegistrationError {
79    /// FAPI 2.0 requires PAR for every authorization request.
80    ParNotRequired,
81    /// FAPI 2.0 requires `private_key_jwt` or mTLS client authentication.
82    /// AXIAM implements both families; this is a client registered with
83    /// neither — that is, with a shared secret.
84    WeakClientAuth { method: ClientAuthMethod },
85    /// FAPI 2.0 requires sender-constrained access tokens.
86    TokensNotSenderConstrained,
87    /// `tls_client_auth` needs exactly one registered subject DN or SAN
88    /// (RFC 8705 §2.1.2).
89    MtlsBindingCount { registered: usize },
90    /// `self_signed_tls_client_auth` needs at least one registered thumbprint.
91    NoSelfSignedThumbprint,
92    /// A registered thumbprint is not a base64url-unpadded SHA-256 digest, so
93    /// it can never match a real certificate.
94    MalformedThumbprint { value: String },
95    /// `private_key_jwt` needs exactly one key source: an inline `jwks` or a
96    /// `jwks_uri` (RFC 7591 §2), never both and never neither.
97    JwksSourceCount { registered: usize },
98    /// A registered `jwks` document is not a parseable JWK Set, so no assertion
99    /// signed by the client could ever be verified against it.
100    MalformedJwks { detail: String },
101    /// A registered `jwks_uri` is not an absolute `https` URL.
102    InsecureJwksUri { value: String },
103}
104
105impl std::fmt::Display for FapiRegistrationError {
106    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
107        match self {
108            Self::ParNotRequired => write!(
109                f,
110                "a fapi2 client must set require_par: FAPI 2.0 §5.3.1.2 requires pushed \
111                 authorization requests"
112            ),
113            Self::WeakClientAuth { method } => write!(
114                f,
115                "a fapi2 client may not authenticate with {}: FAPI 2.0 §5.3.1.1 requires \
116                 private_key_jwt or mutual-TLS client authentication (use tls_client_auth or \
117                 self_signed_tls_client_auth)",
118                method.as_str()
119            ),
120            Self::TokensNotSenderConstrained => write!(
121                f,
122                "a fapi2 client must set tls_client_certificate_bound_access_tokens: FAPI 2.0 \
123                 §5.3.1.1 requires sender-constrained access tokens"
124            ),
125            Self::MtlsBindingCount { registered } => write!(
126                f,
127                "tls_client_auth requires exactly one of tls_client_auth_subject_dn, \
128                 tls_client_auth_san_dns or tls_client_auth_san_uri (RFC 8705 §2.1.2); \
129                 {registered} were registered"
130            ),
131            Self::NoSelfSignedThumbprint => write!(
132                f,
133                "self_signed_tls_client_auth requires at least one registered certificate \
134                 thumbprint in self_signed_tls_client_auth_thumbprints"
135            ),
136            Self::MalformedThumbprint { value } => write!(
137                f,
138                "{value:?} is not a valid x5t#S256 thumbprint: expected 43 base64url \
139                 characters (an unpadded SHA-256 digest, RFC 8705 §3.1)"
140            ),
141            Self::JwksSourceCount { registered } => write!(
142                f,
143                "private_key_jwt requires exactly one of jwks or jwks_uri (RFC 7591 §2); \
144                 {registered} were registered"
145            ),
146            Self::MalformedJwks { detail } => write!(
147                f,
148                "the registered jwks is not a parseable JWK Set ({detail}); no client assertion \
149                 could ever be verified against it"
150            ),
151            Self::InsecureJwksUri { value } => write!(
152                f,
153                "jwks_uri {value:?} must be an absolute https URL: AXIAM fetches it to obtain \
154                 the keys that authenticate this client, and a plaintext or relative URL makes \
155                 that credential rewritable in transit"
156            ),
157        }
158    }
159}

169/// Length of a base64url-unpadded SHA-256 digest: ceil(32 * 4 / 3) = 43.
170const THUMBPRINT_LEN: usize = 43;
171
172/// Whether a string could be an `x5t#S256` value at all.
173///
174/// Checked at registration rather than at authentication, because a
175/// thumbprint that can never match is a typo an operator wants to hear about
176/// while they are onboarding the client — not six weeks later as an
177/// unexplained `invalid_client`. A padded or standard-base64 value is the
178/// common form of this mistake, and both are rejected here by construction:
179/// `=`, `+` and `/` are not in the base64url alphabet.
180fn is_wellformed_thumbprint(value: &str) -> bool {
181    value.len() == THUMBPRINT_LEN
182        && value
183            .bytes()
184            .all(|b| b.is_ascii_alphanumeric() || b == b'-' || b == b'_')
185}

187/// The registration fields the profile rules actually look at.
188///
189/// A borrowed view rather than an `OAuth2Client`, so the **same** rules run
190/// against a pending `CreateOAuth2Client` (before anything is written), a
191/// merged `UpdateOAuth2Client` (before the write lands), and a stored
192/// `OAuth2Client` (as a runtime audit). Validating only the stored form would
193/// mean creating an impossible client and then telling the operator about it —
194/// or worse, leaving it created.
195#[derive(Debug, Clone, Copy)]
196pub struct RegistrationView<'a> {
197    pub profile: ClientProfile,
198    pub token_endpoint_auth_method: ClientAuthMethod,
199    pub require_par: bool,
200    pub tls_client_certificate_bound_access_tokens: bool,
201    /// Result of `axiam_core::models::oauth2_client::count_mtls_bindings`.
202    pub mtls_binding_count: usize,
203    pub self_signed_thumbprints: &'a [String],
204    /// Result of `axiam_core::models::oauth2_client::count_jwks_sources`.
205    pub jwks_source_count: usize,
206    pub jwks: Option<&'a str>,
207    pub jwks_uri: Option<&'a str>,
208    pub dpop_bound_access_tokens: bool,
209}
210

247/// Validate a client registration against the profile it declares.
248///
249/// Runs for **every** registration, not only FAPI ones: the RFC 8705 checks
250/// (exactly one `tls_client_auth_*` parameter, well-formed thumbprints) apply
251/// to any client using an mTLS method, whatever its profile. The FAPI-specific
252/// requirements are gated on [`ClientProfile::Fapi2`].
253///
254/// A `standard` client registered with `client_secret_post` — that is, every
255/// client that existed before X5.1 — passes without a single check running
256/// against it.
257pub fn validate_registration<'a>(
258    reg: impl Into<RegistrationView<'a>>,
259) -> Result<(), FapiRegistrationError> {
260    let reg = reg.into();
261
262    // --- RFC 8705 / RFC 7591 consistency, for any client using a strong
263    //     method, whatever its profile ---------------------------------------
264    match reg.token_endpoint_auth_method {
265        ClientAuthMethod::TlsClientAuth => {
266            if reg.mtls_binding_count != 1 {
267                return Err(FapiRegistrationError::MtlsBindingCount {
268                    registered: reg.mtls_binding_count,
269                });
270            }
271        }
272        ClientAuthMethod::SelfSignedTlsClientAuth => {
273            if reg.self_signed_thumbprints.is_empty() {
274                return Err(FapiRegistrationError::NoSelfSignedThumbprint);
275            }
276        }
277        ClientAuthMethod::PrivateKeyJwt => {
278            // RFC 7591 §2 permits `jwks` **or** `jwks_uri`. Neither leaves a
279            // client that can authenticate nothing; both leaves a client whose
280            // credential is the union of a document it controls and one it
281            // publishes, which is two answers to a question that has one.
282            if reg.jwks_source_count != 1 {
283                return Err(FapiRegistrationError::JwksSourceCount {
284                    registered: reg.jwks_source_count,
285                });
286            }
287        }
288        ClientAuthMethod::ClientSecretPost => {}
289    }
290
291    // Thumbprints are validated whenever any are registered, even under
292    // `tls_client_auth` where they are unused: a malformed value sitting in
293    // the row is a landmine for the day somebody switches the method.
294    for t in reg.self_signed_thumbprints {
295        if !is_wellformed_thumbprint(t) {
296            return Err(FapiRegistrationError::MalformedThumbprint { value: t.clone() });
297        }
298    }
299
300    // Key material is validated on the same principle, and for the same reason
301    // the thumbprint check exists: an operator wants to hear about an unparseable
302    // JWKS while they are onboarding the client, not six weeks later as an
303    // unexplained `invalid_client` that the wire response is deliberately unable
304    // to explain.
305    if let Some(raw) = non_blank(reg.jwks)
306        && let Err(e) = serde_json::from_str::<jsonwebtoken::jwk::JwkSet>(raw)
307    {
308        return Err(FapiRegistrationError::MalformedJwks {
309            detail: e.to_string(),
310        });
311    }
312    if let Some(uri) = non_blank(reg.jwks_uri)
313        && !is_https_absolute(uri)
314    {
315        return Err(FapiRegistrationError::InsecureJwksUri {
316            value: uri.to_owned(),
317        });
318    }
319
320    // --- the profile bundle -----------------------------------------------
321    if !reg.profile.is_fapi2() {
322        return Ok(());
323    }
324
325    if !reg.require_par {
326        return Err(FapiRegistrationError::ParNotRequired);
327    }
328    // Either family satisfies §5.3.1.1. `is_strong` is asked rather than the
329    // two methods enumerated, so a future third strong method joins the profile
330    // by answering one question rather than by being added at every gate.
331    if !reg.token_endpoint_auth_method.is_strong() {
332        return Err(FapiRegistrationError::WeakClientAuth {
333            method: reg.token_endpoint_auth_method,
334        });
335    }
336    // Likewise either sender-constraining mechanism. A client with strong
337    // authentication and *neither* constraint is the shape a half-finished
338    // migration produces, and it is refused rather than served: the profile's
339    // whole security argument is that a stolen token is inert.
340    if !reg.tls_client_certificate_bound_access_tokens && !reg.dpop_bound_access_tokens {
341        return Err(FapiRegistrationError::TokensNotSenderConstrained);
342    }
343
344    Ok(())
345}

347/// A registered value counts only when it is present and non-blank — the same
348/// emptiness rule `count_jwks_sources` applies, so the counter and the
349/// validators cannot disagree about whether `Some("  ")` is registered.
350fn non_blank(value: Option<&str>) -> Option<&str> {
351    value.map(str::trim).filter(|v| !v.is_empty())
352}

354/// Whether a `jwks_uri` is an absolute `https` URL.
355///
356/// Deliberately a prefix check rather than a URL parse. This is a registration
357/// guard, not the fetch guard: the fetch goes through
358/// `axiam_federation::jwks_cache`, which resolves, applies the SEC-054
359/// private-network classifier, and pins the validated IP into the connection.
360/// Duplicating a URL parser here would add a second, weaker opinion about what
361/// a URL means, and the failure mode of the two disagreeing is the interesting
362/// one. What this catches is the operator mistake — `http://`, or a relative
363/// path — at the moment it is made.
364fn is_https_absolute(uri: &str) -> bool {
365    uri.len() > "https://".len() && uri[.."https://".len()].eq_ignore_ascii_case("https://")
366}

368/// Request-time gate on the authorization endpoint (X5.1).
369///
370/// One check that `authorize` does not already make for every client: PKCE is
371/// mandatory. AXIAM requires PKCE for *public* clients (SEC-025) and accepts
372/// only `S256` from anybody, so under the FAPI profile the remaining gap is a
373/// confidential client omitting `code_challenge` entirely.
374///
375/// A no-op for a `standard` client — see the module docs.
376pub fn enforce_authorization_request(
377    client: &OAuth2Client,
378    code_challenge: Option<&str>,
379) -> Result<(), OAuth2Error> {
380    if !client.profile.is_fapi2() {
381        return Ok(());
382    }
383    if code_challenge.is_none_or(str::is_empty) {
384        return Err(OAuth2Error::InvalidRequest(
385            "PKCE (code_challenge) is required for clients on the fapi2 profile".into(),
386        ));
387    }
388    Ok(())
389}

391/// Request-time gate on the token endpoint (X5.1).
392///
393/// Defence in depth behind [`validate_registration`]. A FAPI client whose row
394/// was edited directly in the database — bypassing registration validation —
395/// must not be able to authenticate with a secret or receive an unbound
396/// token, so the invariants are re-checked at the moment they matter.
397///
398/// `evidence` is what the request actually carried: a verified client
399/// certificate on the connection, a verified DPoP proof, or neither. The FAPI
400/// profile requires whatever the client's own registration says it requires, so
401/// the absence of the *relevant* evidence is refused here even though the
402/// authentication and binding paths would also refuse it — this way the refusal
403/// names the profile, which is what an operator needs to see.
404///
405/// A no-op for a `standard` client.
406pub fn enforce_token_request(
407    client: &OAuth2Client,
408    evidence: TokenRequestEvidence,
409) -> Result<(), OAuth2Error> {
410    if !client.profile.is_fapi2() {
411        return Ok(());
412    }
413
414    if !client.token_endpoint_auth_method.is_strong() {
415        tracing::error!(
416            client_id = %client.client_id,
417            method = client.token_endpoint_auth_method.as_str(),
418            "a client on the fapi2 profile is registered with a shared-secret authentication \
419             method; this registration cannot have passed validate_registration and the row \
420             should be investigated"
421        );
422        return Err(OAuth2Error::InvalidClient(
423            crate::mtls::MTLS_AUTH_FAILED.into(),
424        ));
425    }
426
427    if !client.is_sender_constrained() {
428        tracing::error!(
429            client_id = %client.client_id,
430            "a client on the fapi2 profile is registered with neither certificate-bound nor \
431             DPoP-bound access tokens; refusing to issue an unconstrained token under a FAPI \
432             profile"
433        );
434        return Err(OAuth2Error::InvalidClient(
435            crate::mtls::MTLS_AUTH_FAILED.into(),
436        ));
437    }
438
439    // A certificate is required when the client authenticates by one, or binds
440    // its tokens to one. The two are independent (RFC 8705 §3.4), so this is an
441    // OR over reasons rather than a single flag.
442    let needs_certificate = client.token_endpoint_auth_method.is_mtls()
443        || client.tls_client_certificate_bound_access_tokens;
444    if needs_certificate && !evidence.presented_certificate {
445        return Err(OAuth2Error::InvalidClient(
446            crate::mtls::MTLS_AUTH_FAILED.into(),
447        ));
448    }
449
450    if client.dpop_bound_access_tokens && !evidence.verified_dpop_proof {
451        return Err(OAuth2Error::InvalidClient(
452            crate::mtls::MTLS_AUTH_FAILED.into(),
453        ));
454    }
455
456    Ok(())
457}

459/// What a token request actually carried, as opposed to what its body claimed.
460///
461/// A named struct rather than two `bool` parameters: `enforce_token_request(c,
462/// true, false)` and `enforce_token_request(c, false, true)` both compile and
463/// mean opposite things.
464#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
465pub struct TokenRequestEvidence {
466    /// A client certificate rustls verified on this connection.
467    pub presented_certificate: bool,
468    /// A DPoP proof that **already verified** — not merely one that was
469    /// present. A caller that sets this from the presence of a `DPoP` header
470    /// has turned the proof into a self-signed permission slip.
471    pub verified_dpop_proof: bool,
472}
473
474/// Whether a token issued to this client must carry a `cnf.x5t#S256`
475/// certificate confirmation.
476///
477/// Driven by the client's own `tls_client_certificate_bound_access_tokens`
478/// flag rather than by its profile, because RFC 8705 §3.4 makes binding
479/// independent of the authentication method: a deployment may want bound
480/// tokens for a client that still authenticates with a secret over an mTLS
481/// connection. The FAPI profile forces at least one constraint on; it is not
482/// the only thing that can.
483pub const fn wants_certificate_binding(client: &OAuth2Client) -> bool {
484    client.tls_client_certificate_bound_access_tokens
485}
486
487/// Whether a token issued to this client must carry a `cnf.jkt` DPoP
488/// confirmation (RFC 9449 §5).
489///
490/// Independent of [`wants_certificate_binding`] on purpose — a client may ask
491/// for both, and a token that carries both confirmations must satisfy both at
492/// the resource server (`axiam_auth::token::verify_token_binding`).
493pub const fn wants_dpop_binding(client: &OAuth2Client) -> bool {
494    client.dpop_bound_access_tokens
495}
