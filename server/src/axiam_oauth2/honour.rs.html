1//! The honour lane: what a security-bearing authentication-request parameter
2//! actually does (W4, plan §4.2/§4.3/§4.4).
3//!
4//! W1 parsed `prompt`, `max_age`, `acr_values`, `claims.id_token.acr` and
5//! `id_token_hint` and honoured none of them. W2 recorded, on every session,
6//! the evidence that would be needed to answer them. W3 built the browser
7//! login hop, so that "the answer is: authenticate the user again" became a
8//! thing the authorization endpoint could actually *do*. This module is where
9//! those three become one decision, **for a client registered
10//! `authn_request_params = honour` and for nobody else**.
11//!
12//! It is a pure function over four things — what was asked, what the session
13//! proves, who the request is acting for, and whether this request has already
14//! been through the login hop once — so that every hard case in the plan is a
15//! unit test rather than an HTTP round trip.
16//!
17//! # The shape of the answer
18//!
19//! [`evaluate`] returns one of three things, and the caller cannot confuse
20//! them:
21//!
22//! - [`Outcome::Proceed`] — issue a code, and record this `acr` on it.
23//! - [`Outcome::Interact`] — send the browser through the login hop, demanding
24//!   at most the one factor named. This is the only arm that produces a login
25//!   redirect, and it is unreachable when the request carries `prompt=none`.
26//! - [`Outcome::Refuse`] — a terminal OIDC error, redirected to the relying
27//!   party's registered `redirect_uri` by the caller.
28//!
29//! # Why the return leg matters so much
30//!
31//! `authorize → /login → authorize` terminates because the second leg carries
32//! [`crate::login_hop::LOGIN_HOP_MARKER`] and this module never asks for a
33//! second interaction when it sees one. That turns every requirement into two
34//! questions rather than one: *can this session satisfy it?* and, if not,
35//! *have we already tried?* A requirement that survives one interaction is
36//! answered — with a token when what was asked was voluntary (an `acr_values`
37//! preference, a `prompt=login` whose ceremony has now happened), and with an
38//! error when it was not (`max_age`, an essential `acr`, an `id_token_hint`
39//! naming somebody else).
40//!
41//! `prompt=none` reads the marker too, and reads it as a *refusal condition*:
42//! a request that has been through the login page has, by definition, had the
43//! interaction it asked not to have, so it is answered `login_required` rather
44//! than with a code. That is what closes the one gap the carrier split would
45//! otherwise leave — a pushed request whose `prompt=none` cannot be read until
46//! after the handle is consumed, i.e. after the hop has already happened.
47//!
48//! The marker travels in a URL and a relying party could send one itself. It
49//! never selects a principal and it never adds a claim: the strongest thing a
50//! forged marker does is make the server skip an interaction *the forger asked
51//! for*, and every claim the resulting token carries — `auth_time`, `acr`,
52//! `amr` — still describes the authentication that really happened.
53//!
54//! # `max_age = 0`
55//!
56//! **Decision D-14 (T23.1.4): `max_age=0` is handled as `prompt=login`.**
57//! OIDC Core §3.1.2.1 (1.0 incorporating errata set 2) re-authenticates when
58//! the elapsed time is *greater than* `max_age` and says `max_age=0` is
59//! equivalent to `prompt=login`. The plan's literal `elapsed >= max_age`
60//! applied to `0` meant the reauthentication the hop produces was itself
61//! "too old" (`0 >= 0`), so the return leg answered `login_required` and an RP
62//! sending `max_age=0` could never sign in.
63//!
64//! So `max_age=0` takes **the `prompt=login` path and no path of its own**:
65//! the outbound leg always interacts (`reauth=1`, [`Reason::PromptAsked`]), and
66//! the return leg — whose session the hop itself just created — proceeds to a
67//! code whose `auth_time` is that new authentication. A forged return-leg
68//! marker on an old session behaves exactly as it does for `prompt=login`: the
69//! interaction is skipped, which only the request's author could have asked
70//! for, and `auth_time` still reports the old authentication truthfully.
71//! `prompt=none` with `max_age=0` is `login_required` (it can never be
72//! satisfied without interaction; not `invalid_request`, because `max_age` is
73//! not a `prompt` value and the parse treats them as independent).
74//!
75//! Positive values keep `elapsed >= max_age` (floored whole seconds, no
76//! leeway): one instant stricter than the clause, harmless, and pinned by the
77//! Basic OP module `oidcc-max-age-1`. An unmet positive `max_age` on the return
78//! leg is still `login_required`.
79//!
80//! # W5's cosmetic four are not here
81//!
82//! `login_hint`, `display`, `ui_locales` and `claims_locales` are carried on
83//! the same [`AuthnRequestParams`] bundle this module reads, and this module
84//! reads none of them. That is deliberate and it is the whole of their design:
85//! they change how a page *looks*, so there is no [`Outcome`] they could
86//! select. Threading them through [`evaluate`] to reach the login redirect
87//! would give the honour lane's one security decision four inputs that cannot
88//! affect it, and would put a relying-party-controlled string inside the
89//! function whose job is to decide whether to mint a code.
90//!
91//! Instead they are assembled by [`crate::login_hop::Cosmetic::from_params`],
92//! at the point the redirect is built, from the same bundle — so they reach
93//! the page without ever having been in scope where the decision was made. A
94//! test below pins the consequence: setting all four to anything at all leaves
95//! every `Outcome` in this module identical.

107/// Everything [`evaluate`] is allowed to see.
108///
109/// A struct rather than eight positional arguments because two of them are
110/// `Option<DateTime>`-shaped and one is a bare `bool`; a call site that
111/// transposed them would still compile.
112#[derive(Debug, Clone, Copy)]
113pub struct Request<'a> {
114    /// The parsed bundle, from whichever carrier delivered it.
115    pub params: &'a AuthnRequestParams,
116    /// When the end user authenticated, from the session behind this request.
117    /// `None` when no session row could be read at all — which is the strict
118    /// state, not an error: nothing can be asserted about an authentication
119    /// that cannot be found.
120    pub auth_time: Option<DateTime<Utc>>,
121    /// What that authentication proved.
122    pub amr: &'a [Amr],
123    /// The subject this request is acting for.
124    pub subject: Uuid,
125    /// The client the request is for — the `aud` an `id_token_hint` must name.
126    pub client_id: &'a str,
127    /// The decoded `id_token_hint`, when there was one and it verified.
128    ///
129    /// `None` covers both "no hint was sent" and "a hint was sent and did not
130    /// verify"; [`AuthnRequestParams::id_token_hint`] distinguishes them, and
131    /// a hint that was sent and did not verify is treated as naming somebody
132    /// else (OIDC Core §3.1.2.1 asks for an error, preferably `login_required`,
133    /// rather than for the hint to be dropped).
134    pub id_token_hint: Option<&'a IdTokenHint>,
135    /// Whether this request carries [`crate::login_hop::LOGIN_HOP_MARKER`],
136    /// i.e. has already been through the login page once.
137    pub return_leg: bool,
138    /// The clock. A parameter so that freshness is testable without sleeping.
139    pub now: DateTime<Utc>,
140}

142/// Why an interaction is being asked for. Logged, never sent to the RP.
143#[derive(Debug, Clone, Copy, PartialEq, Eq)]
144pub enum Reason {
145    /// `prompt=login`, `prompt=select_account` or `prompt=consent`.
146    PromptAsked,
147    /// The session is older than `max_age` — or there is no session.
148    MaxAgeExceeded,
149    /// `id_token_hint` names a different subject, a different client, or did
150    /// not verify.
151    HintMismatch,
152    /// The requested authentication context class is not satisfied.
153    AcrUnsatisfied,
154    /// W7 — the request asks for a GDPR-sensitive scope (`address`, `phone`)
155    /// that this end user has not consented to release to this client.
156    ///
157    /// The one variant this enum carries that [`evaluate`] never produces:
158    /// consent needs a database read, so `crate::sensitive` decides it and
159    /// `crate::authorize` raises it. It lives here anyway because it is the
160    /// same kind of thing as the other four — a reason the browser is being
161    /// sent to a first-party page before a code exists — and the caller that
162    /// renders the hop should have one exhaustive match, not two.
163    ///
164    /// It is also the only reason that is **not** a reason to distrust the
165    /// current session: the end user is signed in, and the question is what
166    /// they are willing to hand over. The redirect it produces therefore does
167    /// not carry `reauth`, unlike every other reason here.
168    ConsentRequired,
169}
170
171impl Reason {
172    /// Whether a hop for this reason should tell the sign-in page not to trust
173    /// what the browser already holds.
174    ///
175    /// True for the four authentication reasons — `prompt=login`, an
176    /// unsatisfiable `max_age`, a step-up, an `id_token_hint` naming somebody
177    /// else — because reusing the current session would return the same
178    /// unsatisfying session and the loop guard would have to catch it.
179    ///
180    /// False for [`Self::ConsentRequired`], and this is the whole reason the
181    /// method exists rather than the `true` the caller used to pass
182    /// unconditionally: signing the user in again does not answer a question
183    /// about consent, and making them re-enter a password to say yes to
184    /// releasing a postal address is a dark pattern with a spec citation
185    /// attached.
186    pub fn requires_reauthentication(self) -> bool {
187        !matches!(self, Self::ConsentRequired)
188    }
189}

191/// A login hop this evaluation is asking the caller to perform.
192#[derive(Debug, Clone, Copy, PartialEq, Eq)]
193pub struct Interaction {
194    /// The single factor the sign-in page must demand, when the reason for the
195    /// hop is an unsatisfied ACR.
196    ///
197    /// At most one value, and it is a member of the closed vocabulary — the
198    /// page never chooses an authentication context class, it only learns
199    /// which factor to insist on.
200    pub required_acr: Option<Acr>,
201    /// What produced the hop.
202    pub reason: Reason,
203}
204
205/// What the honour lane decided.
206#[derive(Debug)]
207pub enum Outcome {
208    /// Issue a code. `acr` is the value to record on it, `None` when there is
209    /// no session evidence to speak for.
210    Proceed {
211        /// The `acr` claim this authorization earns, already filtered through
212        /// [`report_acr`] so it can only name a class the session satisfies.
213        acr: Option<&'static str>,
214    },
215    /// Send the browser through the login hop.
216    Interact(Interaction),
217    /// Answer the relying party with a terminal error.
218    Refuse(OAuth2Error),
219}
220
221/// Decide what an authorization request on the honour lane earns.
222///
223/// Callers must have refused a malformed bundle
224/// ([`AuthnRequestParams::parse_error`]) before reaching here: this function
225/// reads meanings, and a value that has no meaning is `invalid_request` at the
226/// gate rather than a decision here.
227///
228/// # `prompt=consent` (a W4 decision that W7 supersedes)
229///
230/// Plan §4.2 sends `prompt=consent` to a first-party consent screen that G8
231/// (wave W7) renders. That screen does not exist yet, and the two available
232/// answers were *ignore it* — the silent downgrade this whole lane exists to
233/// prevent, so not an option — or refuse with `interaction_required`.
234///
235/// W4 treats it as `login` instead, and the argument is that refusing buys no
236/// security property while costing the lane its adopters. OIDC Core §3.1.2.1
237/// says of `consent` that the server "SHOULD prompt the End-User for consent",
238/// leaving the OP to choose the ceremony; a fresh credential check *is* an
239/// interaction, performed by the user, in front of a page naming this
240/// deployment, before any code is issued. Nothing is asserted about it — there
241/// is no consent claim to be false, and no consent-gated data exists to be
242/// released without one until W7 defines the sensitive scopes. Meanwhile
243/// `interaction_required` would make the honour lane unusable for every
244/// relying party whose library sends `prompt=consent` by reflex, and an
245/// operator who cannot adopt `honour` keeps `ignore` — where `max_age` and
246/// `prompt=none` are dropped silently too. W7 replaces the ceremony behind the
247/// same redirect and no relying party has to change.
248pub fn evaluate(req: Request<'_>) -> Outcome {
249    let params = req.params;
250    let has_session = req.auth_time.is_some();
251    let achieved = acr_for(req.amr);
252
253    // What the relying party asked about the authentication context class.
254    // `claims.id_token.acr` wins over `acr_values` when it names values, per
255    // OIDC Core §5.5.1.1 — it is the form that can be *essential*, and an RP
256    // that sent both said the specific thing in the specific place.
257    let acr_essential = params.claims_acr.as_ref().is_some_and(|c| c.essential);
258    let wanted: &[String] = match params.claims_acr.as_ref() {
259        Some(c) if !c.values.is_empty() => &c.values,
260        _ => &params.acr_values,
261    };
262    let acr_requested = params.claims_acr.is_some() || !params.acr_values.is_empty();
263
264    // Satisfied when nothing was asked; when something was asked with no
265    // constraint, satisfied by having any evidence at all to report; otherwise
266    // by the achieved class covering one of the values named.
267    let acr_satisfied = if !acr_requested {
268        true
269    } else if wanted.is_empty() {
270        has_session
271    } else {
272        has_session
273            && wanted
274                .iter()
275                .filter_map(|v| Acr::from_wire(v))
276                .any(|required| achieved.satisfies(required))
277    };
278
279    // `max_age`: whole seconds, floored, never in the relying party's favour.
280    // No session is "infinitely old" rather than "unconstrained".
281    //
282    // D-14: `max_age=0` is `prompt=login`, so it is not a freshness *test* at
283    // all (it would fail on the return leg, `0 >= 0`); it is folded into
284    // `asked_for_interaction` below and shares every rule of that path.
285    let max_age_is_login = params.max_age == Some(0);
286    let max_age_unmet = match params.max_age {
287        None | Some(0) => false,
288        Some(limit) => match req.auth_time {
289            None => true,
290            Some(at) => elapsed_secs(req.now, at) >= limit,
291        },
292    };
293
294    // `id_token_hint`: present means it must name *this* subject and *this*
295    // client. A hint that failed to verify arrives as `None` and is a mismatch
296    // — never a hint that is quietly dropped.
297    let hint_mismatch = params.id_token_hint.is_some()
298        && !req.id_token_hint.is_some_and(|hint| {
299            hint.subject_id == Some(req.subject) && hint.client_id == req.client_id
300        });
301
302    let asked_for_interaction = max_age_is_login
303        || params
304            .prompt
305            .iter()
306            .any(|p| matches!(p, Prompt::Login | Prompt::Consent | Prompt::SelectAccount));
307    let select_account = params.prompt.contains(&Prompt::SelectAccount);
308
309    // The value the code would carry, if a code is issued. Computed once so
310    // that every `Proceed` below reports the same thing, and only ever from
311    // `achieved` — see `crate::acr` for why that is the whole defence.
312    let reported = has_session.then(|| report_acr(achieved, wanted));
313
314    if params.prompt.contains(&Prompt::None) {
315        // `prompt=none` is exclusive (the parser refuses it combined with
316        // anything else), so no interaction was also asked for. Nothing below
317        // may interact, and a request that already has is refused.
318        if req.return_leg {
319            return Outcome::Refuse(OAuth2Error::LoginRequired(
320                "prompt=none was requested, but this authorization request has already been \
321                 through the sign-in page; a silent authorization cannot follow an interactive \
322                 one"
323                .into(),
324            ));
325        }
326        if hint_mismatch {
327            return Outcome::Refuse(OAuth2Error::LoginRequired(
328                "the id_token_hint names a different end user or a different client than the \
329                 session this request arrives with"
330                    .into(),
331            ));
332        }
333        if max_age_unmet {
334            return Outcome::Refuse(OAuth2Error::LoginRequired(
335                "the authentication behind this session is older than the requested max_age, \
336                 and prompt=none forbids asking the end user to authenticate again"
337                    .into(),
338            ));
339        }
340        if max_age_is_login {
341            // D-14: `max_age=0` is `prompt=login`, which `prompt=none` forbids.
342            return Outcome::Refuse(OAuth2Error::LoginRequired(
343                "max_age=0 asks the end user to authenticate again, and prompt=none forbids \
344                 asking the end user to do anything"
345                    .into(),
346            ));
347        }
348        if !acr_satisfied && acr_essential {
349            return Outcome::Refuse(OAuth2Error::UnmetAuthenticationRequirements(
350                "the requested authentication context class is essential and this session does \
351                 not satisfy it, and prompt=none forbids a step-up"
352                    .into(),
353            ));
354        }
355        // A voluntary ACR that is not satisfied cannot be stepped up under
356        // `prompt=none`, so the class actually achieved is reported. That is
357        // the disappointing answer and the true one.
358        return Outcome::Proceed { acr: reported };
359    }
360
361    let unmet = hint_mismatch || max_age_unmet || !acr_satisfied || asked_for_interaction;
362    if !unmet {
363        return Outcome::Proceed { acr: reported };
364    }
365
366    if !req.return_leg {
367        let reason = if hint_mismatch {
368            Reason::HintMismatch
369        } else if max_age_unmet {
370            Reason::MaxAgeExceeded
371        } else if !acr_satisfied {
372            Reason::AcrUnsatisfied
373        } else {
374            Reason::PromptAsked
375        };
376        // The page is told which factor to demand, and only when an ACR is
377        // what is missing. It is the strongest class the RP named that AXIAM
378        // implements — asking for less would not satisfy the request, and
379        // there is nothing to ask for beyond the vocabulary.
380        let required_acr = (!acr_satisfied)
381            .then(|| wanted.iter().filter_map(|v| Acr::from_wire(v)).max())
382            .flatten();
383        return Outcome::Interact(Interaction {
384            required_acr,
385            reason,
386        });
387    }
388
389    // The return leg: one interaction has happened and did not produce what
390    // was asked for. Whatever is still unmet is answered rather than retried.
391    if hint_mismatch {
392        return Outcome::Refuse(if select_account {
393            OAuth2Error::AccountSelectionRequired(
394                "the end user who signed in is not the one the id_token_hint names".into(),
395            )
396        } else {
397            OAuth2Error::LoginRequired(
398                "the end user who signed in is not the one the id_token_hint names".into(),
399            )
400        });
401    }
402    if max_age_unmet {
403        return Outcome::Refuse(OAuth2Error::LoginRequired(
404            "the sign-in did not produce an authentication newer than the requested max_age".into(),
405        ));
406    }
407    if !acr_satisfied && acr_essential {
408        return Outcome::Refuse(OAuth2Error::UnmetAuthenticationRequirements(
409            "the end user did not complete an authentication satisfying the essential \
410             authentication context class this request requires"
411                .into(),
412        ));
413    }
414    // What is left is voluntary: an `acr_values` preference the step-up did
415    // not meet (the end user declined the second factor, or has none), or a
416    // `prompt` whose interaction has now happened. A token is issued, carrying
417    // the class that was actually achieved.
418    Outcome::Proceed { acr: reported }
419}
420
421/// Whole seconds between an authentication and now, never negative.
422///
423/// A clock that ran backwards (or an upstream provider asserting an
424/// authentication instant slightly in the future) yields `0` rather than a
425/// wrapped value: the session then reads as brand new, which is the *only*
426/// direction that cannot manufacture a refusal out of a clock error.
427fn elapsed_secs(now: DateTime<Utc>, authenticated_at: DateTime<Utc>) -> u64 {
428    let secs = (now - authenticated_at).num_seconds();
429    u64::try_from(secs).unwrap_or(0)
430}
