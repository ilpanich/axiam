1//! The honour lane: what a security-bearing authentication-request parameter
2//! actually does (W4, plan §4.2/§4.3/§4.4).
3//!
4//! W1 parsed `prompt`, `max_age`, `acr_values`, `claims.id_token.acr` and
5//! `id_token_hint` and honoured none of them. W2 recorded, on every session,
6//! the evidence that would be needed to answer them. W3 built the browser
7//! login hop, so that "the answer is: authenticate the user again" became a
8//! thing the authorization endpoint could actually *do*. This module is where
9//! those three become one decision, **for a client registered
10//! `authn_request_params = honour` and for nobody else**.
11//!
12//! It is a pure function over four things — what was asked, what the session
13//! proves, who the request is acting for, and whether this request has already
14//! been through the login hop once — so that every hard case in the plan is a
15//! unit test rather than an HTTP round trip.
16//!
17//! # The shape of the answer
18//!
19//! [`evaluate`] returns one of three things, and the caller cannot confuse
20//! them:
21//!
22//! - [`Outcome::Proceed`] — issue a code, and record this `acr` on it.
23//! - [`Outcome::Interact`] — send the browser through the login hop, demanding
24//!   at most the one factor named. This is the only arm that produces a login
25//!   redirect, and it is unreachable when the request carries `prompt=none`.
26//! - [`Outcome::Refuse`] — a terminal OIDC error, redirected to the relying
27//!   party's registered `redirect_uri` by the caller.
28//!
29//! # Why the return leg matters so much
30//!
31//! `authorize → /login → authorize` terminates because the second leg carries
32//! [`crate::login_hop::LOGIN_HOP_MARKER`] and this module never asks for a
33//! second interaction when it sees one. That turns every requirement into two
34//! questions rather than one: *can this session satisfy it?* and, if not,
35//! *have we already tried?* A requirement that survives one interaction is
36//! answered — with a token when what was asked was voluntary (an `acr_values`
37//! preference, a `prompt=login` whose ceremony has now happened), and with an
38//! error when it was not (`max_age`, an essential `acr`, an `id_token_hint`
39//! naming somebody else).
40//!
41//! `prompt=none` reads the marker too, and reads it as a *refusal condition*:
42//! a request that has been through the login page has, by definition, had the
43//! interaction it asked not to have, so it is answered `login_required` rather
44//! than with a code. That is what closes the one gap the carrier split would
45//! otherwise leave — a pushed request whose `prompt=none` cannot be read until
46//! after the handle is consumed, i.e. after the hop has already happened.
47//!
48//! The marker travels in a URL and a relying party could send one itself. It
49//! never selects a principal and it never adds a claim: the strongest thing a
50//! forged marker does is make the server skip an interaction *the forger asked
51//! for*, and every claim the resulting token carries — `auth_time`, `acr`,
52//! `amr` — still describes the authentication that really happened.
53//!
54//! # `max_age = 0`
55//!
56//! `elapsed = floor(now − authenticated_at)`, reauthenticate iff
57//! `elapsed >= max_age`, per plan §4.3 — no special case and no leeway in the
58//! relying party's disfavour. One consequence is worth stating out loud
59//! because the plan's prose does not: **`max_age=0` can never be satisfied by
60//! any code.** It always demands a reauthentication, and the reauthentication
61//! it produces is itself zero seconds old, so `0 >= 0` holds again on the
62//! return leg and the answer is `login_required`. An RP that sends `max_age=0`
63//! is asking for an authentication of age zero, which no clock can report; the
64//! honest answer is the refusal, not a code minted under a rounder comparison.
65//!
66//! # W5's cosmetic four are not here
67//!
68//! `login_hint`, `display`, `ui_locales` and `claims_locales` are carried on
69//! the same [`AuthnRequestParams`] bundle this module reads, and this module
70//! reads none of them. That is deliberate and it is the whole of their design:
71//! they change how a page *looks*, so there is no [`Outcome`] they could
72//! select. Threading them through [`evaluate`] to reach the login redirect
73//! would give the honour lane's one security decision four inputs that cannot
74//! affect it, and would put a relying-party-controlled string inside the
75//! function whose job is to decide whether to mint a code.
76//!
77//! Instead they are assembled by [`crate::login_hop::Cosmetic::from_params`],
78//! at the point the redirect is built, from the same bundle — so they reach
79//! the page without ever having been in scope where the decision was made. A
80//! test below pins the consequence: setting all four to anything at all leaves
81//! every `Outcome` in this module identical.

93/// Everything [`evaluate`] is allowed to see.
94///
95/// A struct rather than eight positional arguments because two of them are
96/// `Option<DateTime>`-shaped and one is a bare `bool`; a call site that
97/// transposed them would still compile.
98#[derive(Debug, Clone, Copy)]
99pub struct Request<'a> {
100    /// The parsed bundle, from whichever carrier delivered it.
101    pub params: &'a AuthnRequestParams,
102    /// When the end user authenticated, from the session behind this request.
103    /// `None` when no session row could be read at all — which is the strict
104    /// state, not an error: nothing can be asserted about an authentication
105    /// that cannot be found.
106    pub auth_time: Option<DateTime<Utc>>,
107    /// What that authentication proved.
108    pub amr: &'a [Amr],
109    /// The subject this request is acting for.
110    pub subject: Uuid,
111    /// The client the request is for — the `aud` an `id_token_hint` must name.
112    pub client_id: &'a str,
113    /// The decoded `id_token_hint`, when there was one and it verified.
114    ///
115    /// `None` covers both "no hint was sent" and "a hint was sent and did not
116    /// verify"; [`AuthnRequestParams::id_token_hint`] distinguishes them, and
117    /// a hint that was sent and did not verify is treated as naming somebody
118    /// else (OIDC Core §3.1.2.1 asks for an error, preferably `login_required`,
119    /// rather than for the hint to be dropped).
120    pub id_token_hint: Option<&'a IdTokenHint>,
121    /// Whether this request carries [`crate::login_hop::LOGIN_HOP_MARKER`],
122    /// i.e. has already been through the login page once.
123    pub return_leg: bool,
124    /// The clock. A parameter so that freshness is testable without sleeping.
125    pub now: DateTime<Utc>,
126}

128/// Why an interaction is being asked for. Logged, never sent to the RP.
129#[derive(Debug, Clone, Copy, PartialEq, Eq)]
130pub enum Reason {
131    /// `prompt=login`, `prompt=select_account` or `prompt=consent`.
132    PromptAsked,
133    /// The session is older than `max_age` — or there is no session.
134    MaxAgeExceeded,
135    /// `id_token_hint` names a different subject, a different client, or did
136    /// not verify.
137    HintMismatch,
138    /// The requested authentication context class is not satisfied.
139    AcrUnsatisfied,
140    /// W7 — the request asks for a GDPR-sensitive scope (`address`, `phone`)
141    /// that this end user has not consented to release to this client.
142    ///
143    /// The one variant this enum carries that [`evaluate`] never produces:
144    /// consent needs a database read, so `crate::sensitive` decides it and
145    /// `crate::authorize` raises it. It lives here anyway because it is the
146    /// same kind of thing as the other four — a reason the browser is being
147    /// sent to a first-party page before a code exists — and the caller that
148    /// renders the hop should have one exhaustive match, not two.
149    ///
150    /// It is also the only reason that is **not** a reason to distrust the
151    /// current session: the end user is signed in, and the question is what
152    /// they are willing to hand over. The redirect it produces therefore does
153    /// not carry `reauth`, unlike every other reason here.
154    ConsentRequired,
155}
156
157impl Reason {
158    /// Whether a hop for this reason should tell the sign-in page not to trust
159    /// what the browser already holds.
160    ///
161    /// True for the four authentication reasons — `prompt=login`, an
162    /// unsatisfiable `max_age`, a step-up, an `id_token_hint` naming somebody
163    /// else — because reusing the current session would return the same
164    /// unsatisfying session and the loop guard would have to catch it.
165    ///
166    /// False for [`Self::ConsentRequired`], and this is the whole reason the
167    /// method exists rather than the `true` the caller used to pass
168    /// unconditionally: signing the user in again does not answer a question
169    /// about consent, and making them re-enter a password to say yes to
170    /// releasing a postal address is a dark pattern with a spec citation
171    /// attached.
172    pub fn requires_reauthentication(self) -> bool {
173        !matches!(self, Self::ConsentRequired)
174    }
175}

177/// A login hop this evaluation is asking the caller to perform.
178#[derive(Debug, Clone, Copy, PartialEq, Eq)]
179pub struct Interaction {
180    /// The single factor the sign-in page must demand, when the reason for the
181    /// hop is an unsatisfied ACR.
182    ///
183    /// At most one value, and it is a member of the closed vocabulary — the
184    /// page never chooses an authentication context class, it only learns
185    /// which factor to insist on.
186    pub required_acr: Option<Acr>,
187    /// What produced the hop.
188    pub reason: Reason,
189}
190
191/// What the honour lane decided.
192#[derive(Debug)]
193pub enum Outcome {
194    /// Issue a code. `acr` is the value to record on it, `None` when there is
195    /// no session evidence to speak for.
196    Proceed {
197        /// The `acr` claim this authorization earns, already filtered through
198        /// [`report_acr`] so it can only name a class the session satisfies.
199        acr: Option<&'static str>,
200    },
201    /// Send the browser through the login hop.
202    Interact(Interaction),
203    /// Answer the relying party with a terminal error.
204    Refuse(OAuth2Error),
205}
206
207/// Decide what an authorization request on the honour lane earns.
208///
209/// Callers must have refused a malformed bundle
210/// ([`AuthnRequestParams::parse_error`]) before reaching here: this function
211/// reads meanings, and a value that has no meaning is `invalid_request` at the
212/// gate rather than a decision here.
213///
214/// # `prompt=consent` (a W4 decision that W7 supersedes)
215///
216/// Plan §4.2 sends `prompt=consent` to a first-party consent screen that G8
217/// (wave W7) renders. That screen does not exist yet, and the two available
218/// answers were *ignore it* — the silent downgrade this whole lane exists to
219/// prevent, so not an option — or refuse with `interaction_required`.
220///
221/// W4 treats it as `login` instead, and the argument is that refusing buys no
222/// security property while costing the lane its adopters. OIDC Core §3.1.2.1
223/// says of `consent` that the server "SHOULD prompt the End-User for consent",
224/// leaving the OP to choose the ceremony; a fresh credential check *is* an
225/// interaction, performed by the user, in front of a page naming this
226/// deployment, before any code is issued. Nothing is asserted about it — there
227/// is no consent claim to be false, and no consent-gated data exists to be
228/// released without one until W7 defines the sensitive scopes. Meanwhile
229/// `interaction_required` would make the honour lane unusable for every
230/// relying party whose library sends `prompt=consent` by reflex, and an
231/// operator who cannot adopt `honour` keeps `ignore` — where `max_age` and
232/// `prompt=none` are dropped silently too. W7 replaces the ceremony behind the
233/// same redirect and no relying party has to change.
234pub fn evaluate(req: Request<'_>) -> Outcome {
235    let params = req.params;
236    let has_session = req.auth_time.is_some();
237    let achieved = acr_for(req.amr);
238
239    // What the relying party asked about the authentication context class.
240    // `claims.id_token.acr` wins over `acr_values` when it names values, per
241    // OIDC Core §5.5.1.1 — it is the form that can be *essential*, and an RP
242    // that sent both said the specific thing in the specific place.
243    let acr_essential = params.claims_acr.as_ref().is_some_and(|c| c.essential);
244    let wanted: &[String] = match params.claims_acr.as_ref() {
245        Some(c) if !c.values.is_empty() => &c.values,
246        _ => &params.acr_values,
247    };
248    let acr_requested = params.claims_acr.is_some() || !params.acr_values.is_empty();
249
250    // Satisfied when nothing was asked; when something was asked with no
251    // constraint, satisfied by having any evidence at all to report; otherwise
252    // by the achieved class covering one of the values named.
253    let acr_satisfied = if !acr_requested {
254        true
255    } else if wanted.is_empty() {
256        has_session
257    } else {
258        has_session
259            && wanted
260                .iter()
261                .filter_map(|v| Acr::from_wire(v))
262                .any(|required| achieved.satisfies(required))
263    };
264
265    // `max_age`: whole seconds, floored, never in the relying party's favour.
266    // No session is "infinitely old" rather than "unconstrained".
267    let max_age_unmet = match params.max_age {
268        None => false,
269        Some(limit) => match req.auth_time {
270            None => true,
271            Some(at) => elapsed_secs(req.now, at) >= limit,
272        },
273    };
274
275    // `id_token_hint`: present means it must name *this* subject and *this*
276    // client. A hint that failed to verify arrives as `None` and is a mismatch
277    // — never a hint that is quietly dropped.
278    let hint_mismatch = params.id_token_hint.is_some()
279        && !req.id_token_hint.is_some_and(|hint| {
280            hint.subject_id == Some(req.subject) && hint.client_id == req.client_id
281        });
282
283    let asked_for_interaction = params
284        .prompt
285        .iter()
286        .any(|p| matches!(p, Prompt::Login | Prompt::Consent | Prompt::SelectAccount));
287    let select_account = params.prompt.contains(&Prompt::SelectAccount);
288
289    // The value the code would carry, if a code is issued. Computed once so
290    // that every `Proceed` below reports the same thing, and only ever from
291    // `achieved` — see `crate::acr` for why that is the whole defence.
292    let reported = has_session.then(|| report_acr(achieved, wanted));
293
294    if params.prompt.contains(&Prompt::None) {
295        // `prompt=none` is exclusive (the parser refuses it combined with
296        // anything else), so no interaction was also asked for. Nothing below
297        // may interact, and a request that already has is refused.
298        if req.return_leg {
299            return Outcome::Refuse(OAuth2Error::LoginRequired(
300                "prompt=none was requested, but this authorization request has already been \
301                 through the sign-in page; a silent authorization cannot follow an interactive \
302                 one"
303                .into(),
304            ));
305        }
306        if hint_mismatch {
307            return Outcome::Refuse(OAuth2Error::LoginRequired(
308                "the id_token_hint names a different end user or a different client than the \
309                 session this request arrives with"
310                    .into(),
311            ));
312        }
313        if max_age_unmet {
314            return Outcome::Refuse(OAuth2Error::LoginRequired(
315                "the authentication behind this session is older than the requested max_age, \
316                 and prompt=none forbids asking the end user to authenticate again"
317                    .into(),
318            ));
319        }
320        if !acr_satisfied && acr_essential {
321            return Outcome::Refuse(OAuth2Error::UnmetAuthenticationRequirements(
322                "the requested authentication context class is essential and this session does \
323                 not satisfy it, and prompt=none forbids a step-up"
324                    .into(),
325            ));
326        }
327        // A voluntary ACR that is not satisfied cannot be stepped up under
328        // `prompt=none`, so the class actually achieved is reported. That is
329        // the disappointing answer and the true one.
330        return Outcome::Proceed { acr: reported };
331    }
332
333    let unmet = hint_mismatch || max_age_unmet || !acr_satisfied || asked_for_interaction;
334    if !unmet {
335        return Outcome::Proceed { acr: reported };
336    }
337
338    if !req.return_leg {
339        let reason = if hint_mismatch {
340            Reason::HintMismatch
341        } else if max_age_unmet {
342            Reason::MaxAgeExceeded
343        } else if !acr_satisfied {
344            Reason::AcrUnsatisfied
345        } else {
346            Reason::PromptAsked
347        };
348        // The page is told which factor to demand, and only when an ACR is
349        // what is missing. It is the strongest class the RP named that AXIAM
350        // implements — asking for less would not satisfy the request, and
351        // there is nothing to ask for beyond the vocabulary.
352        let required_acr = (!acr_satisfied)
353            .then(|| wanted.iter().filter_map(|v| Acr::from_wire(v)).max())
354            .flatten();
355        return Outcome::Interact(Interaction {
356            required_acr,
357            reason,
358        });
359    }
360
361    // The return leg: one interaction has happened and did not produce what
362    // was asked for. Whatever is still unmet is answered rather than retried.
363    if hint_mismatch {
364        return Outcome::Refuse(if select_account {
365            OAuth2Error::AccountSelectionRequired(
366                "the end user who signed in is not the one the id_token_hint names".into(),
367            )
368        } else {
369            OAuth2Error::LoginRequired(
370                "the end user who signed in is not the one the id_token_hint names".into(),
371            )
372        });
373    }
374    if max_age_unmet {
375        return Outcome::Refuse(OAuth2Error::LoginRequired(
376            "the sign-in did not produce an authentication newer than the requested max_age; \
377             a max_age of 0 cannot be satisfied by any authentication, since one is never \
378             zero seconds old"
379                .into(),
380        ));
381    }
382    if !acr_satisfied && acr_essential {
383        return Outcome::Refuse(OAuth2Error::UnmetAuthenticationRequirements(
384            "the end user did not complete an authentication satisfying the essential \
385             authentication context class this request requires"
386                .into(),
387        ));
388    }
389    // What is left is voluntary: an `acr_values` preference the step-up did
390    // not meet (the end user declined the second factor, or has none), or a
391    // `prompt` whose interaction has now happened. A token is issued, carrying
392    // the class that was actually achieved.
393    Outcome::Proceed { acr: reported }
394}
395
396/// Whole seconds between an authentication and now, never negative.
397///
398/// A clock that ran backwards (or an upstream provider asserting an
399/// authentication instant slightly in the future) yields `0` rather than a
400/// wrapped value: the session then reads as brand new, which is the *only*
401/// direction that cannot manufacture a refusal out of a clock error — and
402/// `max_age = 0` still refuses it, because `0 >= 0`.
403fn elapsed_secs(now: DateTime<Utc>, authenticated_at: DateTime<Utc>) -> u64 {
404    let secs = (now - authenticated_at).num_seconds();
405    u64::try_from(secs).unwrap_or(0)
406}

452    fn proceeds(outcome: &Outcome) -> Option<Option<&'static str>> {
453        match outcome {
454            Outcome::Proceed { acr } => Some(*acr),
455            _ => None,
456        }

459    fn refusal_code(outcome: &Outcome) -> &'static str {
460        match outcome {
461            Outcome::Refuse(e) => e.error_code(),
462            other => panic!("expected a refusal, got {other:?}"),
463        }
464    }

466    fn interaction(outcome: &Outcome) -> Interaction {
467        match outcome {
468            Outcome::Interact(i) => *i,
469            other => panic!("expected an interaction, got {other:?}"),
470        }

980    /// Every shape this module can answer with is unchanged by setting all
981    /// four — including a hostile `ui_locales`, which is the value the plan
982    /// most wants kept away from a decision.
983    #[test]
984    fn the_cosmetic_four_change_no_outcome() {
985        use crate::authn_params::RawAuthnParams;
986
987        let cosmetic_only = |base: RawAuthnParams<'static>| {
988            let mut with = base;
989            with.login_hint = Some("ada@example.com");
990            with.display = Some("popup");
991            with.ui_locales = Some("<img onerror=alert(1)> it");
992            with.claims_locales = Some("it");
993            (
994                AuthnRequestParams::parse(&base),
995                AuthnRequestParams::parse(&with),
996            )
997        };
998
999        for base in [
1000            // Nothing asked: Proceed.
1001            RawAuthnParams::default(),
1002            // An interaction asked for: Interact.
1003            RawAuthnParams {

1008            RawAuthnParams {
1009                max_age: Some("0"),
1010                ..Default::default()

1012            // Silent authorization: Proceed or Refuse, never Interact.
1013            RawAuthnParams {
1014                prompt: Some("none"),
1015                ..Default::default()
1016            },
1017            // An essential class this session does not satisfy.
1018            RawAuthnParams {

1021                ),
1022                ..Default::default()
1023            },
1024        ] {

1029                    amr: &'a [Amr],
1030                    return_leg: bool,
