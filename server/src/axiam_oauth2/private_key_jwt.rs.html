1//! `private_key_jwt` client authentication (RFC 7523 §2.2, OIDC Core §9) —
2//! X5.1.
3//!
4//! The second of the two client-authentication families FAPI 2.0 §5.3.1.1
5//! permits, and the counterpart to [`crate::mtls`]'s §2. Both replace the shared
6//! secret with proof of possession of a private key; they differ only in where
7//! the proof happens:
8//!
9//! | | Proof carried by | Needs from the deployment |
10//! |---|---|---|
11//! | mTLS (RFC 8705 §2) | the TLS handshake | an mTLS listener the client can reach *directly* |
12//! | `private_key_jwt` (RFC 7523 §2.2) | a signed assertion in the request body | nothing at the transport layer |
13//!
14//! That second column is the whole reason this family exists. A client behind a
15//! TLS-terminating load balancer, an API gateway, or a CDN cannot present a
16//! client certificate to AXIAM — the connection AXIAM sees is the proxy's. Such
17//! a client had no route to strong authentication here before X5.1's second
18//! half, which the conformance runbook recorded as a gap and which this module
19//! closes. mTLS remains AXIAM's differentiator and the cheaper option; this is
20//! the one that works everywhere.
21//!
22//! # What is checked, and in what order
23//!
24//! RFC 7523 §3, with OIDC Core §9's tightening of `iss`/`sub`:
25//!
26//! 1. **The signature**, under a key the *client registered* — inline `jwks` or
27//!    a fetched `jwks_uri`, never a key the assertion supplies. This is the
28//!    difference between an assertion and a DPoP proof, and it is not
29//!    cosmetic: a DPoP proof names a key that only has to be *consistent*
30//!    across a token's life, whereas a client assertion names an identity, and
31//!    an identity that can supply its own key is not authenticated.
32//! 2. **`alg` from the registered key, never the header.** See [`crate::jose`].
33//! 3. `iss` and `sub` are both exactly the `client_id` (OIDC Core §9). RFC 7523
34//!    alone would permit an `iss` that merely identifies the issuer of the
35//!    assertion; OIDC pins both to the client, and pinning both is what stops
36//!    one registered client minting an assertion that authenticates as another.
37//! 4. `aud` names this authorization server. An assertion is a bearer
38//!    credential for whoever holds it, so an assertion minted for *another* AS
39//!    must not authenticate here — that is the cross-AS replay RFC 7523 §3's
40//!    audience requirement exists for.
41//! 5. `exp` is in the future and the assertion's total life is bounded
42//!    ([`MAX_ASSERTION_LIFETIME_SECS`]).
43//! 6. `jti` is present, and **single-use**. The caller records it; see below.
44//!
45//! # `jti` replay is the caller's, and it is not optional
46//!
47//! This module returns the `jti` and refuses to pretend it has recorded it.
48//! Recording is `axiam_core::repository::ProofReplayRepository`'s job, and that
49//! repository decides replay by a `UNIQUE` index violation rather than by
50//! reading first — the same mechanism `saml_replay` and `amqp_nonce_replay` use,
51//! and for the same reason. A read-then-write check leaves a window in which two
52//! concurrent copies of one assertion both authenticate, which is the race
53//! X6 (#316) and #318 closed for authorization codes.
54//!
55//! Freshness alone is not enough. `exp` bounds how long a captured assertion
56//! stays interesting; the `jti` guard is what makes that window unusable.
57

64/// RFC 7521 §4.2 `client_assertion_type` — the only value AXIAM accepts.
65pub const CLIENT_ASSERTION_TYPE: &str = "urn:ietf:params:oauth:client-assertion-type:jwt-bearer";
66
67/// The longest total life an assertion may claim, in seconds.
68///
69/// One hour, matching FAPI 2.0's bound. The value is not really about the
70/// legitimate client — a well-behaved one mints an assertion valid for seconds —
71/// it is about the size of the replay table and the window a captured assertion
72/// is useful in if the replay guard is ever unavailable. An assertion claiming a
73/// year is refused rather than trimmed, because trimming would silently accept a
74/// credential the client believes has different semantics.
75pub const MAX_ASSERTION_LIFETIME_SECS: i64 = 3600;
76
77/// Tolerance for clock disagreement between the client and AXIAM, in seconds.
78///
79/// Applied to `exp`, `nbf` and `iat` alike. Sixty seconds is enough for the
80/// NTP-adjacent drift real deployments have and short enough that it does not
81/// meaningfully extend an assertion's usable life.
82pub const CLOCK_SKEW_SECS: i64 = 60;

84/// `aud` is a string or an array of strings (RFC 7519 §4.1.3).
85#[derive(Debug, Clone, Serialize, Deserialize)]
86#[serde(untagged)]
87enum Audience {
88    One(String),
89    Many(Vec<String>),
90}
91
92impl Audience {
93    fn contains_any(&self, acceptable: &[String]) -> bool {
94        match self {
95            Self::One(a) => acceptable.iter().any(|x| x == a),
96            Self::Many(list) => list.iter().any(|a| acceptable.iter().any(|x| x == a)),
97        }
98    }
99}

101/// Which `aud` values a client-authentication assertion may carry.
102///
103/// Two rules, because two specifications disagree and AXIAM serves clients
104/// under both.
105#[derive(Debug, Clone, Copy)]
106pub enum AudiencePolicy<'a> {
107    /// The interop rule, for every client not on a FAPI profile.
108    ///
109    /// RFC 7523 §3 wants an identifier of the authorization server; OIDC Core
110    /// §9 wants the token endpoint URL. Refusing a client for following the
111    /// other specification would be an interop failure with no security
112    /// content, so both are accepted, in a string or in an array.
113    AnyOf(&'a [String]),
114    /// The FAPI 2.0 rule.
115    ///
116    /// FAPI 2.0 Security Profile Final §5.3.2.1: the authorization server
117    /// "shall **only** accept its issuer identifier value (as defined in
118    /// [RFC8414]) **as a string** in the aud claim received in client
119    /// authentication assertions" — and the client half of the profile adds
120    /// "The issuer identifier value shall be sent as a string not as an item
121    /// in an array."
122    ///
123    /// Both halves are enforced here. An array is refused *even when it
124    /// contains the issuer*, which is the point: the profile removes the
125    /// ambiguity about which audience a token was meant for rather than
126    /// resolving it.
127    IssuerStringOnly(&'a str),
128}
129
130impl AudiencePolicy<'_> {
131    fn accepts(&self, aud: &Audience) -> bool {
132        match (self, aud) {
133            (Self::AnyOf(acceptable), _) => aud.contains_any(acceptable),
134            (Self::IssuerStringOnly(issuer), Audience::One(a)) => a == issuer,
135            (Self::IssuerStringOnly(_), Audience::Many(_)) => false,
136        }
137    }
138}

153/// Why a client assertion did not authenticate.
154///
155/// Typed rather than stringly so a test can assert *which* constraint failed.
156/// The wire never sees the distinction: every variant is reported to the client
157/// as `invalid_client` with [`ASSERTION_AUTH_FAILED`], for exactly the reason
158/// [`crate::mtls::MTLS_AUTH_FAILED`] gives.
159#[derive(Debug, Clone, PartialEq, Eq)]
160pub enum AssertionError {
161    /// `client_assertion_type` was absent or was not the JWT-bearer URN.
162    WrongAssertionType { got: Option<String> },
163    /// Not a JWT, or missing a claim RFC 7523 requires.
164    Malformed(String),
165    /// The client registered no usable key material.
166    NoRegisteredKeys,
167    /// The registered keys could not supply a verifier for this assertion.
168    Key(jose::JoseKeyError),
169    /// The signature did not verify under any registered key.
170    Signature,
171    /// `iss` or `sub` is not this client.
172    SubjectMismatch { claim: &'static str, got: String },
173    /// `aud` does not name this authorization server.
174    AudienceMismatch,
175    /// `exp` has passed, `nbf` has not arrived, or `iat` is in the future.
176    NotCurrentlyValid(&'static str),
177    /// The assertion claims a longer life than the profile permits.
178    LifetimeTooLong { seconds: i64 },
179    /// `jti` is absent or blank, so the assertion cannot be made single-use.
180    UnusableJti,
181    /// This `jti` has already authenticated once.
182    Replayed,
183}
184
185/// The single `error_description` every `private_key_jwt` failure returns.
186///
187/// Word for word the same as [`crate::mtls::MTLS_AUTH_FAILED`] and
188/// `token::CLIENT_AUTH_FAILED`, deliberately: an unauthenticated caller must not
189/// be able to tell "no such client" from "wrong key" from "assertion expired"
190/// from "already used", because each of those is a fact about a `client_id` they
191/// have not authenticated as. The distinctions go to the tracing log.
192pub const ASSERTION_AUTH_FAILED: &str = "invalid client credentials";
193
194impl std::fmt::Display for AssertionError {
195    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
196        match self {
197            Self::WrongAssertionType { got } => write!(
198                f,
199                "client_assertion_type must be {CLIENT_ASSERTION_TYPE:?}, got {got:?}"
200            ),
201            Self::Malformed(d) => write!(f, "malformed client assertion: {d}"),
202            Self::NoRegisteredKeys => write!(
203                f,
204                "the client registered no jwks or jwks_uri, so no assertion of its can be verified"
205            ),
206            Self::Key(e) => write!(f, "client assertion key: {e}"),
207            Self::Signature => {
208                write!(
209                    f,
210                    "the client assertion does not verify under any registered key"
211                )
212            }
213            Self::SubjectMismatch { claim, got } => write!(
214                f,
215                "the assertion's {claim} is {got:?}, which is not the client it authenticates as \
216                 (OIDC Core §9 requires iss = sub = client_id)"
217            ),
218            Self::AudienceMismatch => write!(
219                f,
220                "the assertion's aud does not name this authorization server; an assertion minted \
221                 for another server must not authenticate here"
222            ),
223            Self::NotCurrentlyValid(which) => {
224                write!(f, "the assertion is not currently valid: {which}")
225            }
226            Self::LifetimeTooLong { seconds } => write!(
227                f,
228                "the assertion claims a life of {seconds}s, longer than the \
229                 {MAX_ASSERTION_LIFETIME_SECS}s this profile permits"
230            ),
231            Self::UnusableJti => write!(
232                f,
233                "the assertion carries no usable jti, so it cannot be made single-use"
234            ),
235            Self::Replayed => write!(f, "this client assertion has already been used"),
236        }
237    }
238}

254/// An assertion that authenticated, and what the caller must still do with it.
255#[derive(Debug, Clone, PartialEq, Eq)]
256pub struct VerifiedAssertion {
257    /// The `jti` the caller records to make this assertion single-use.
258    pub jti: String,
259    /// When the assertion expires — the natural lifetime of its replay row,
260    /// because past `exp` a replay is refused without the table being read.
261    pub exp: i64,
262}
263
264impl VerifiedAssertion {
265    /// When a replay row for this assertion stops being useful.
266    pub fn replay_expiry(&self) -> chrono::DateTime<chrono::Utc> {
267        chrono::DateTime::from_timestamp(self.exp + CLOCK_SKEW_SECS, 0)
268            .unwrap_or_else(chrono::Utc::now)
269    }
270}

272/// Check the `client_assertion_type` form parameter (RFC 7521 §4.2).
273///
274/// A separate function because it is checked before anything is parsed: an
275/// assertion of an unrecognised type is not something to attempt to verify.
276pub fn check_assertion_type(presented: Option<&str>) -> Result<(), AssertionError> {
277    match presented {
278        Some(t) if t == CLIENT_ASSERTION_TYPE => Ok(()),
279        other => Err(AssertionError::WrongAssertionType {
280            got: other.map(str::to_owned),
281        }),
282    }
283}

285/// Verify a `client_assertion` against the keys a client registered.
286///
287/// `audience` says which `aud` values this client may use — see
288/// [`AudiencePolicy`], which carries the two rules and why there are two.
289///
290/// Returns the `jti` for the caller to record. **A caller that drops it has not
291/// implemented replay protection**, which is why the return type carries it
292/// rather than the function answering `Ok(())`.
293pub fn verify_client_assertion(
294    assertion: &str,
295    client_id: &str,
296    audience: AudiencePolicy<'_>,
297    keys: &JwkSet,
298    now: i64,
299) -> Result<VerifiedAssertion, AssertionError> {
300    if keys.keys.is_empty() {
301        return Err(AssertionError::NoRegisteredKeys);
302    }
303
304    let header = decode_header(assertion)
305        .map_err(|e| AssertionError::Malformed(format!("bad JWS header: {e}")))?;
306
307    // Every candidate is a key the client registered. The header's `kid`
308    // narrows the set; it can never widen it, and it can never introduce a key
309    // from the assertion itself — which is the difference between this and a
310    // DPoP proof.
311    let candidates: Vec<(&Jwk, jsonwebtoken::Algorithm)> =
312        jose::candidate_keys(&keys.keys, header.kid.as_deref())?;
313
314    let mut claims: Option<AssertionClaims> = None;
315    for (jwk, key_alg) in &candidates {
316        // The algorithm is the key's. A header naming something else is not a
317        // request to verify differently, it is a refusal — and it is a refusal
318        // for *this key*, not for the whole set, because a client publishing an
319        // Ed25519 and a P-256 key legitimately signs with either.
320        let Ok(alg) = jose::verify_permitted_header(header.alg, *key_alg) else {
321            continue;
322        };
323        let Ok(decoding_key) = jose::decoding_key_for(jwk) else {
324            continue;
325        };
326        let mut validation = Validation::new(alg);
327        // Every temporal and audience rule is applied below with RFC 7523's
328        // semantics and AXIAM's error vocabulary. Leaving jsonwebtoken's
329        // checks on as well would mean two definitions of "expired" that could
330        // drift, and would collapse four distinct refusals into one opaque one.
331        validation.validate_exp = false;
332        validation.validate_aud = false;
333        validation.required_spec_claims.clear();
334
335        match decode::<AssertionClaims>(assertion, &decoding_key, &validation) {
336            Ok(data) => {
337                claims = Some(data.claims);
338                break;
339            }
340            Err(e) => match e.kind() {
341                // A signature that does not verify under *this* key says
342                // nothing about the next one.
343                jsonwebtoken::errors::ErrorKind::InvalidSignature => continue,
344                // A payload that is not a well-formed assertion will not become
345                // one under another key.
346                _ => return Err(AssertionError::Malformed(e.to_string())),
347            },
348        }
349    }
350
351    let Some(claims) = claims else {
352        return Err(AssertionError::Signature);
353    };
354
355    // --- RFC 7523 §3 / OIDC Core §9 --------------------------------------
356    if claims.iss != client_id {
357        return Err(AssertionError::SubjectMismatch {
358            claim: "iss",
359            got: claims.iss,
360        });
361    }
362    if claims.sub != client_id {
363        return Err(AssertionError::SubjectMismatch {
364            claim: "sub",
365            got: claims.sub,
366        });
367    }
368    if !audience.accepts(&claims.aud) {
369        return Err(AssertionError::AudienceMismatch);
370    }
371
372    if claims.exp <= now - CLOCK_SKEW_SECS {
373        return Err(AssertionError::NotCurrentlyValid("exp has passed"));
374    }
375    if let Some(nbf) = claims.nbf
376        && nbf > now + CLOCK_SKEW_SECS
377    {
378        return Err(AssertionError::NotCurrentlyValid("nbf is in the future"));
379    }
380    if let Some(iat) = claims.iat {
381        if iat > now + CLOCK_SKEW_SECS {
382            return Err(AssertionError::NotCurrentlyValid("iat is in the future"));
383        }
384        let life = claims.exp - iat;
385        if life > MAX_ASSERTION_LIFETIME_SECS {
386            return Err(AssertionError::LifetimeTooLong { seconds: life });
387        }
388    }
389    // Bound the life even when the client omitted `iat`, which RFC 7523 makes
390    // optional. Without this, omitting one optional claim would buy an
391    // unbounded assertion — the kind of asymmetry an attacker looks for.
392    let remaining = claims.exp - now;
393    if remaining > MAX_ASSERTION_LIFETIME_SECS {
394        return Err(AssertionError::LifetimeTooLong { seconds: remaining });
395    }
396
397    if claims.jti.trim().is_empty() {
398        return Err(AssertionError::UnusableJti);
399    }
400
401    Ok(VerifiedAssertion {
402        jti: claims.jti,
403        exp: claims.exp,
404    })
405}

407/// Where a client's verification keys come from.
408///
409/// RFC 7591 §2 permits `jwks` **or** `jwks_uri`, never both, and AXIAM enforces
410/// that at registration (`fapi::validate_registration`). This enum is the
411/// runtime consequence of that rule: there is one source, and which one it is
412/// determines whether resolving it touches the network.
413#[derive(Debug, Clone, PartialEq, Eq)]
414pub enum ClientKeySource {
415    /// An inline `jwks` document, already parsed.
416    Inline(Box<JwkSet>),
417    /// A `jwks_uri` to fetch — through `axiam_federation::jwks_cache`, which
418    /// carries the SSRF guard and the TTL/stale-while-revalidate policy. Never
419    /// through a bare HTTP client.
420    Remote(String),
421    /// The client registered neither, so nothing it signs can be verified.
422    None,
423}
424
425/// Read a client's registered key source.
426///
427/// A malformed inline `jwks` resolves to [`ClientKeySource::None`] rather than
428/// an error, and the caller reports the ordinary authentication failure. The
429/// alternative — surfacing a parse error — would let an unauthenticated caller
430/// distinguish "this client has a broken key document" from "this client does
431/// not exist", which is precisely the probe [`ASSERTION_AUTH_FAILED`] exists to
432/// prevent. The parse failure is logged.
433pub fn key_source_of(client: &axiam_core::models::oauth2_client::OAuth2Client) -> ClientKeySource {
434    if let Some(raw) = client
435        .jwks
436        .as_deref()
437        .map(str::trim)
438        .filter(|s| !s.is_empty())
439    {
440        return match serde_json::from_str::<JwkSet>(raw) {
441            Ok(set) => ClientKeySource::Inline(Box::new(set)),
442            Err(e) => {
443                tracing::warn!(
444                    client_id = %client.client_id,
445                    error = %e,
446                    "client has a registered jwks that is not a parseable JWK Set; it cannot \
447                     authenticate with private_key_jwt until the document is fixed"
448                );
449                ClientKeySource::None
450            }
451        };
452    }
453    if let Some(uri) = client
454        .jwks_uri
455        .as_deref()
456        .map(str::trim)
457        .filter(|s| !s.is_empty())
458    {
459        return ClientKeySource::Remote(uri.to_owned());
460    }
461    ClientKeySource::None
462}

473/// Resolve a client's keys, verify its assertion, and record the `jti` — the
474/// three steps `crate::token::TokenService` cannot do itself.
475///
476/// A trait object rather than two more generic parameters on `TokenService`,
477/// which already carries six. It is also the seam that keeps the *pure* half of
478/// this module — [`verify_client_assertion`], which is where every RFC 7523
479/// rule lives — free of the database and the network, so it can be tested
480/// against vectors and benchmarked.
481///
482/// `None` on a `TokenService` means no client may authenticate with
483/// `private_key_jwt` in that deployment. That is a refusal, not a bypass: a
484/// client registered for the method is refused outright rather than falling
485/// back to a secret.
486pub trait ClientAssertionVerifier: Send + Sync {
487    fn verify<'a>(
488        &'a self,
489        tenant_id: uuid::Uuid,
490        client: &'a axiam_core::models::oauth2_client::OAuth2Client,
491        assertion: &'a str,
492    ) -> VerifyFuture<'a>;
493}

495/// The production [`ClientAssertionVerifier`].
496///
497/// Composed of the two things the pure verifier deliberately does not know
498/// about, and nothing else:
499///
500/// * `jwks` — `axiam_federation::jwks_cache::JwksCache`, so a client's
501///   `jwks_uri` is fetched through the **same** TTL, stale-while-revalidate and
502///   SEC-054 SSRF-guarded path a federated IdP's JWKS goes through. A
503///   client-supplied URL the server will fetch on demand is the same threat
504///   surface whichever feature asked for it, and giving it a second, weaker
505///   guard is how one of the two ends up missing a fix.
506/// * `replay` — `ProofReplayRepository`, which decides replay by a `UNIQUE`
507///   index violation rather than by reading first.
508pub struct JwksAssertionVerifier<R> {
509    jwks: axiam_federation::jwks_cache::JwksCache,
510    http: reqwest::Client,
511    replay: R,
512    /// AXIAM's issuer identifier — the only `aud` a FAPI 2.0 client may name,
513    /// and the first choice for everyone else.
514    issuer: String,
515    /// The `aud` values a non-FAPI client's assertion may name: the issuer and
516    /// the token-endpoint URL. See [`AudiencePolicy`] for why both, and why a
517    /// FAPI 2.0 client gets neither this list nor an array.
518    acceptable_audiences: Vec<String>,
519}
520
521impl<R> JwksAssertionVerifier<R> {
522    /// `issuer` is AXIAM's issuer identifier; `also_acceptable` are the extra
523    /// audiences a non-FAPI client may use, conventionally the token-endpoint
524    /// URL. The issuer is always acceptable and need not be repeated.
525    pub fn new(
526        jwks: axiam_federation::jwks_cache::JwksCache,
527        http: reqwest::Client,
528        replay: R,
529        issuer: String,
530        also_acceptable: Vec<String>,
531    ) -> Self {
532        let mut acceptable_audiences = vec![issuer.clone()];
533        acceptable_audiences.extend(also_acceptable);
534        Self {
535            jwks,
536            http,
537            replay,
538            issuer,
539            acceptable_audiences,
540        }
541    }
542}

544impl<R> ClientAssertionVerifier for JwksAssertionVerifier<R>
545where
546    R: axiam_core::repository::ProofReplayRepository,
547{
548    fn verify<'a>(
549        &'a self,
550        tenant_id: uuid::Uuid,
551        client: &'a axiam_core::models::oauth2_client::OAuth2Client,
552        assertion: &'a str,
553    ) -> VerifyFuture<'a> {
554        Box::pin(async move {
555            use crate::error::OAuth2Error;
556            use axiam_core::repository::ProofKind;
557
558            let failed = || OAuth2Error::InvalidClient(ASSERTION_AUTH_FAILED.into());
559
560            let keys: JwkSet = match key_source_of(client) {
561                ClientKeySource::Inline(set) => *set,
562                ClientKeySource::Remote(uri) => {
563                    // The cache is keyed by `(tenant_id, client.id)`, which is
564                    // the natural unit here: two clients that happen to publish
565                    // the same URI still get independent entries, so one
566                    // client's rotation cannot serve another client a stale
567                    // key set.
568                    match self
569                        .jwks
570                        .get_or_fetch(&self.http, (tenant_id, client.id), &uri)
571                        .await
572                    {
573                        Ok(set) => set,
574                        Err(e) => {
575                            tracing::warn!(
576                                client_id = %client.client_id,
577                                error = %e,
578                                "could not obtain the client's jwks_uri key set; refusing the \
579                                 assertion rather than authenticating without checking it"
580                            );
581                            return Err(failed());
582                        }
583                    }
584                }
585                ClientKeySource::None => {
586                    tracing::warn!(
587                        client_id = %client.client_id,
588                        "client is registered for private_key_jwt but has no usable key source"
589                    );
590                    return Err(failed());
591                }
592            };
593
594            // FAPI 2.0 §5.3.2.1 narrows RFC 7523's audience rule to the issuer
595            // alone, sent as a string. Every other client keeps the interop
596            // list — a profile tightens what it covers and nothing else.
597            let audience = if client.profile.is_fapi2() {
598                AudiencePolicy::IssuerStringOnly(&self.issuer)
599            } else {
600                AudiencePolicy::AnyOf(&self.acceptable_audiences)
601            };
602
603            let now = chrono::Utc::now().timestamp();
604            let verified =
605                verify_client_assertion(assertion, &client.client_id, audience, &keys, now)
606                    .map_err(|e| {
607                        tracing::debug!(
608                            client_id = %client.client_id,
609                            reason = %e,
610                            "private_key_jwt client authentication failed"
611                        );
612                        failed()
613                    })?;
614
615            // The signature proved possession of the key. This is what makes
616            // the assertion single-*use* rather than merely single-*purpose*,
617            // and it happens after verification so a garbage assertion cannot
618            // fill the table.
619            match self
620                .replay
621                .insert_proof_jti(
622                    tenant_id,
623                    ProofKind::ClientAssertion,
624                    &client.client_id,
625                    &verified.jti,
626                    verified.replay_expiry(),
627                )
628                .await
629            {
630                Ok(()) => Ok(()),
631                Err(axiam_core::error::AxiamError::ReplayDetected) => {
632                    tracing::warn!(
633                        client_id = %client.client_id,
634                        "a client assertion was replayed; refusing"
635                    );
636                    Err(failed())
637                }
638                Err(e) => {
639                    // A replay guard that cannot record must not authenticate.
640                    // Failing open here would turn a database blip into an
641                    // unlimited replay window, which is the one failure mode
642                    // this whole mechanism exists to prevent.
643                    tracing::error!(
644                        client_id = %client.client_id,
645                        error = %e,
646                        "could not record a client assertion's jti; refusing the authentication \
647                         rather than accepting an assertion that cannot be made single-use"
648                    );
649                    Err(failed())
650                }
651            }
652        })
653    }

1168/// The `client_id` an assertion *claims*, read before anything is verified.
1169///
1170/// # Why reading an unverified JWT here is not a hole
1171///
1172/// RFC 7521 §4.2 makes `client_id` optional when a client authenticates with an
1173/// assertion, and OIDC Core §9 makes the assertion's `sub` the client's
1174/// identifier. So when the body carries no `client_id` there is exactly one
1175/// place left to learn which client row to load, and it is inside a token
1176/// nobody has checked yet.
1177///
1178/// That is safe because of what happens next and only because of it: the row
1179/// this names is loaded, and [`verify_client_assertion`] then verifies the
1180/// signature **against that row's registered key** and re-checks that `iss` and
1181/// `sub` equal that client id. An attacker who writes somebody else's client id
1182/// into a `sub` has chosen which public key their forgery will be checked
1183/// against, and it will not be theirs. The value is a routing hint, never a
1184/// credential.
1185///
1186/// The one thing this must not do is grow a second use. It is deliberately not
1187/// exposed as "the client id of an assertion" — nothing downstream may treat
1188/// the result as established, and `verify_client_assertion` remains the only
1189/// function that decides whose assertion this is.
1190///
1191/// `None` for anything that is not a JWT with a string `sub`: three
1192/// dot-separated parts, a base64url payload, an object with a `sub`. A caller
1193/// receiving `None` is in exactly the position it was in before — no client id
1194/// from anywhere — and answers as it always did.
1195#[must_use]
1196pub fn unverified_client_id(assertion: &str) -> Option<String> {
1197    use base64::Engine as _;
1198
1199    let payload = assertion.split('.').nth(1)?;
1200    let bytes = base64::engine::general_purpose::URL_SAFE_NO_PAD
1201        .decode(payload)
1202        .ok()?;
1203    let value: serde_json::Value = serde_json::from_slice(&bytes).ok()?;
1204    let sub = value.get("sub")?.as_str()?;
1205    (!sub.is_empty()).then(|| sub.to_owned())
1206}
