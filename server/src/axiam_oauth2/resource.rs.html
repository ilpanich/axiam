1//! RFC 8707 resource indicators (T21.3).
2//!
3//! One question, asked in five places: *may this client name this target
4//! service, and what is the audience if it may?* The authorization endpoint,
5//! the PAR endpoint, the device-authorization endpoint and the token endpoint
6//! all ask it, and they must all get the same answer — a `resource` accepted
7//! at `/oauth2/par` and refused at `/oauth2/authorize` would hand the user
8//! agent a `request_uri` standing for a request that cannot complete, which is
9//! the failure [`crate::redirect_uri`] was written to avoid on the URI side.
10//!
11//! # What a resource is
12//!
13//! RFC 8707 §2:
14//!
15//! > The parameter value is an absolute URI ... The `resource` URI MUST NOT
16//! > include a fragment component. It SHOULD NOT include a query component,
17//! > but it MUST be a valid URI.
18//!
19//! So: absolute (a scheme and, for the hierarchical schemes clients actually
20//! use, an authority), no fragment. A query is permitted and kept, because the
21//! RFC only discourages it and a deployment that has one has one.
22//!
23//! # Why comparison is normalised and never prefixed
24//!
25//! The registered list is an allow-list of audiences, and a token's `aud` is
26//! what a resource server checks to decide the token is for *it*. A prefix
27//! match would make `https://mcp.example.com` authorise
28//! `https://mcp.example.com.attacker.test` — the audience equivalent of the
29//! open redirect that exact `redirect_uri` matching exists to prevent (T-52) —
30//! so there is no prefix rule here and there must never be one.
31//!
32//! What there is instead is RFC 3986 §6.2.2 **syntax-based normalisation**,
33//! and only that: case normalisation of the scheme and host (§6.2.2.1), and
34//! removal of a default port and of dot segments (§6.2.2.3, §6.2.3). Those are
35//! transformations RFC 3986 declares produce an *equivalent* URI, so applying
36//! them compares what two strings mean rather than how they were typed.
37//!
38//! Nothing scheme-based is done — no trailing-slash forgiveness on a non-empty
39//! path, no case folding of the path, no `https://host` to `https://host/`
40//! guess beyond the RFC's own empty-path rule. Those would widen an
41//! allow-list on a deployment's behalf, and an allow-list widened by the
42//! server is one the operator cannot audit from what they wrote down.
43//!
44//! # The one §6.2.2 rule that is deliberately not applied
45//!
46//! §6.2.2.2 says a percent-encoded **unreserved** character should be decoded,
47//! so `/%6Dcp` and `/mcp` are the same path. The `url` crate does not do this
48//! in the path component, and this module does not add it, for the reason
49//! [`crate::redirect_uri`] gives about normalising comparisons: a hand-rolled
50//! decoder in front of a security check is a place for a decoder bug to become
51//! an authorisation bug, and this one would be re-deriving a rule the URL
52//! parser already had an opinion about.
53//!
54//! Skipping it fails **closed**. `/%6Dcp` and `/mcp` stay two resources, so a
55//! client asking for one when the other is registered is refused; no request
56//! is admitted that would not have been. The cost is an operator who registers
57//! a needlessly-encoded URI and finds their client refused — which the
58//! read-back of the stored, normalised list makes visible at registration
59//! time, because the stored string is the one that will be compared.
60

63/// The URI scheme AXIAM's own audiences live under (`axiam:user`,
64/// `axiam:m2m`). Reserved against use as a resource indicator — see
65/// [`ResourceError::ReservedAudience`].
66const RESERVED_AUDIENCE_SCHEME: &str = "axiam";
67
68/// Why a `resource` value is not usable (RFC 8707 §2).
69///
70/// A type rather than a `bool` because the four refusals are different
71/// operator-facing problems and the registration API should be able to say
72/// which one it found. On the wire they all become `invalid_target`, which is
73/// the only code RFC 8707 defines for a target the server will not serve.
74#[derive(Debug, Clone, Copy, PartialEq, Eq)]
75pub enum ResourceError {
76    /// Not a URI at all, or a relative reference.
77    NotAnAbsoluteUri,
78    /// RFC 8707 §2 forbids a fragment: it is a client-side construct that
79    /// never reaches a server, so two resources differing only by fragment are
80    /// one resource wearing two names — and an allow-list that cannot tell
81    /// them apart is an allow-list with a second entry nobody registered.
82    HasFragment,
83    /// Empty or whitespace-only. Distinguished from
84    /// [`Self::NotAnAbsoluteUri`] because "you sent `resource=`" and "you sent
85    /// something that is not a URI" are different mistakes.
86    Empty,
87    /// The value is in AXIAM's own audience namespace (MCP-02).
88    ///
89    /// `axiam:user` and `axiam:m2m` are the two audiences AXIAM's own
90    /// extractors accept, and — because a scheme followed by a path is all an
91    /// absolute URI needs — they are also perfectly well-formed resource
92    /// indicators. Nothing else here would have refused them: the parser
93    /// deliberately admits any scheme, because `urn:` resources are legitimate
94    /// and an MCP server reached over loopback `http` during development is a
95    /// resource like any other.
96    ///
97    /// Admitting them collapses the boundary I3 is built out of. The sharpest
98    /// case is `client_credentials`, which mints `axiam:m2m` when no resource
99    /// is named: naming `axiam:user` as the resource makes the *same* grant
100    /// mint a token stamped with the user audience, which is the one claim the
101    /// user-facing extractors gate on. The whole `axiam` scheme is reserved
102    /// rather than the two literals, so that an audience added later is
103    /// covered without anybody having to remember this rule exists.
104    ReservedAudience,
105}
106
107impl ResourceError {
108    /// A message in the voice the token endpoint's other refusals use.
109    pub const fn message(self) -> &'static str {
110        match self {
111            Self::NotAnAbsoluteUri => {
112                "resource must be an absolute URI (RFC 8707 section 2), for example \
113                 https://mcp.example.com/mcp"
114            }
115            Self::HasFragment => "resource must not contain a fragment (RFC 8707 section 2)",
116            Self::Empty => "resource must not be empty",
117            Self::ReservedAudience => {
118                "the axiam scheme is reserved for AXIAM's own token audiences and cannot be \
119                 named as a resource; a resource server is identified by the URL it serves"
120            }
121        }
122    }
123}

125/// Normalise `raw` under RFC 3986 §6.2.2, or say why it is not a resource.
126///
127/// The returned string is the **canonical form** used for every comparison and
128/// for the `aud` claim that is ultimately minted, so a client that registers
129/// `https://MCP.example.com:443/mcp` and asks for `https://mcp.example.com/mcp`
130/// gets a token whose audience is one string and not two.
131///
132/// # What `Url::parse` does, and what is checked on top of it
133///
134/// `url` implements the WHATWG URL Standard, whose serialisation performs
135/// §6.2.2's normalisations for the hierarchical schemes with one exception:
136/// the scheme and host are lowercased, a default port is dropped and dot
137/// segments are removed, but a percent-encoded unreserved character in the
138/// path is left as it was written (see the module documentation for why that
139/// is left alone rather than added here). It also **refuses a relative
140/// reference** outright, which is the absolute-URI half of RFC 8707 §2. What
141/// it does not do is refuse a fragment — a fragment is perfectly legal in a
142/// URL and simply illegal in a *resource indicator* — so that is checked here.
143pub fn normalise(raw: &str) -> Result<String, ResourceError> {
144    let trimmed = raw.trim();
145    if trimmed.is_empty() {
146        return Err(ResourceError::Empty);
147    }
148    let parsed = Url::parse(trimmed).map_err(|_| ResourceError::NotAnAbsoluteUri)?;
149    if parsed.fragment().is_some() {
150        return Err(ResourceError::HasFragment);
151    }
152    // MCP-02. Checked after parsing rather than on the raw string, so that the
153    // comparison is against the scheme `url` actually resolved (it lowercases
154    // it, so `AXIAM:user` cannot slip past a byte comparison on the input).
155    if parsed.scheme() == RESERVED_AUDIENCE_SCHEME {
156        return Err(ResourceError::ReservedAudience);
157    }
158    Ok(parsed.as_str().to_owned())
159}

161/// Whether `presented` is one of the resources `allowed` names.
162///
163/// Both sides are normalised before comparison, and an entry of `allowed` that
164/// does not normalise is skipped rather than compared as a string: a stored
165/// value this function cannot make sense of must not authorise anything, and
166/// silently falling back to string equality is how a malformed row becomes a
167/// second matching rule nobody reviewed.
168///
169/// An empty `allowed` matches nothing, which is the correct reading of a
170/// client that registered no resources — and is why every client that predates
171/// T21.3 is refused the parameter rather than granted the whole world with it.
172pub fn is_allowed(allowed: &[String], presented: &str) -> bool {
173    let Ok(target) = normalise(presented) else {
174        return false;
175    };
176    allowed
177        .iter()
178        .filter_map(|entry| normalise(entry).ok())
179        .any(|entry| entry == target)
180}
181
182/// Validate a list destined for `OAuth2Client::allowed_resources`, returning
183/// the normalised list to store.
184///
185/// Storing the normalised form rather than the operator's spelling means the
186/// read-back through the admin API shows exactly what will be compared, and
187/// means a duplicate that differs only in case or default port is visible as a
188/// duplicate. The error names the offending entry, because an operator
189/// registering six resources needs to know which one is wrong.
190pub fn normalise_registration(entries: &[String]) -> Result<Vec<String>, (String, ResourceError)> {
191    entries
192        .iter()
193        .map(|e| normalise(e).map_err(|err| (e.clone(), err)))
194        .collect()
195}

197/// Resolve the `resource` a request carries against a client's allow-list.
198///
199/// The **registration** gate, used wherever a client first names a target: the
200/// authorization endpoint, PAR, device authorization, and the
201/// `client_credentials` grant.
202///
203/// - Absent → `Ok(None)`, which is today's behaviour and the whole of I2: the
204///   caller mints `axiam:user` or `axiam:m2m` exactly as it did before this
205///   parameter existed.
206/// - Present and registered → `Ok(Some(normalised))`, the string that becomes
207///   the token's `aud`.
208/// - Present and anything else → `invalid_target`, the code RFC 8707 §2
209///   defines for a target the server will not issue a token for.
210///
211/// A malformed value and an unregistered one are both `invalid_target`, with
212/// different descriptions. RFC 8707 gives no separate code for "that is not a
213/// URI", and inventing `invalid_request` for it would make the two
214/// distinguishable to a caller probing which resources a client may address —
215/// a registration-enumeration oracle for whoever holds a `client_id`, which on
216/// a public client is everybody.
217pub fn resolve_requested(
218    client_allowed: &[String],
219    presented: Option<&str>,
220) -> Result<Option<String>, crate::error::OAuth2Error> {
221    let Some(raw) = presented.map(str::trim).filter(|r| !r.is_empty()) else {
222        return Ok(None);
223    };
224    let normalised = normalise(raw).map_err(|e| {
225        crate::error::OAuth2Error::InvalidTarget(format!("{} (RFC 8707 section 2)", e.message()))
226    })?;
227    if !is_allowed(client_allowed, &normalised) {
228        return Err(crate::error::OAuth2Error::InvalidTarget(
229            "the requested resource is not one this client may address; register it in              allowed_resources first"
230                .into(),
231        ));
232    }
233    Ok(Some(normalised))
234}

236/// Resolve the `resource` a token request carries against the one the grant is
237/// already bound to.
238///
239/// The **redemption** gate, used wherever a credential minted earlier is spent:
240/// the `authorization_code`, `refresh_token` and `device_code` grants. Its rule
241/// is one sentence — *a grant's audience is decided when the grant is made* —
242/// and the three cases fall out of it:
243///
244/// - The request repeats the bound value, or omits it → the bound value.
245/// - The request names a different value → `invalid_target`.
246/// - The grant is bound to nothing and the request names something →
247///   `invalid_target`.
248///
249/// The third case is the one worth spelling out, because it is the one that
250/// looks harmless. A refresh token issued for `axiam:user` represents a
251/// consent the end user gave to a client acting *as them at AXIAM*; letting a
252/// refresh add `resource=https://mcp.example.com` would mint a token for a
253/// service the end user was never asked about, fifteen minutes after they
254/// stopped watching. **A token cannot be widened by refreshing it**, and it
255/// cannot be widened by redeeming a code either — which is why this function
256/// never consults the client's allow-list. The allow-list was consulted when
257/// the grant was made; consulting it again here would let a registration
258/// edited in the meantime change what an outstanding grant means.
259///
260/// Comparison is by normalised form, so a client that pushes
261/// `https://mcp.example.com:443/mcp` and redeems with
262/// `https://mcp.example.com/mcp` is repeating its value, not changing it.
263pub fn resolve_bound(
264    bound: Option<&str>,
265    presented: Option<&str>,
266) -> Result<Option<String>, crate::error::OAuth2Error> {
267    let bound = bound.map(str::to_owned);
268    let Some(raw) = presented.map(str::trim).filter(|r| !r.is_empty()) else {
269        return Ok(bound);
270    };
271    let requested = normalise(raw).map_err(|e| {
272        crate::error::OAuth2Error::InvalidTarget(format!("{} (RFC 8707 section 2)", e.message()))
273    })?;
274    match bound {
275        Some(ref b) if normalise(b).ok().as_deref() == Some(requested.as_str()) => Ok(bound),
276        Some(_) => Err(crate::error::OAuth2Error::InvalidTarget(
277            "this grant is bound to a different resource; a token cannot be re-addressed when              it is redeemed or refreshed. Start a new authorization for the other resource"
278                .into(),
279        )),
280        None => Err(crate::error::OAuth2Error::InvalidTarget(
281            "this grant was not issued for any resource, and a token cannot acquire one when              it is redeemed or refreshed. Start a new authorization that names the resource"
282                .into(),
283        )),
284    }
285}

291    /// The RFC 3986 §6.2.2 transformations, each asserted to produce the same
292    /// canonical string as the form an operator would have typed instead.
293    #[test]
294    fn syntax_based_normalisation_makes_equivalent_uris_one_string() {
295        for (a, b) in [
296            // Case normalisation of scheme and host (§6.2.2.1).
297            ("HTTPS://MCP.Example.COM/mcp", "https://mcp.example.com/mcp"),
298            // Default port removed (§6.2.3, and what every client omits).
299            (
300                "https://mcp.example.com:443/mcp",
301                "https://mcp.example.com/mcp",
302            ),
303            (
304                "http://mcp.example.com:80/mcp",
305                "http://mcp.example.com/mcp",
306            ),
307            // Dot segments removed (§6.2.2.3).
308            (
309                "https://mcp.example.com/a/../mcp",
310                "https://mcp.example.com/mcp",
311            ),
312        ] {
313            assert_eq!(
314                normalise(a).unwrap(),
315                normalise(b).unwrap(),
316                "{a} and {b} are the same resource under RFC 3986 section 6.2.2"
317            );
318        }
