1//! Certificate revocation lists — one per issuing CA (RFC 5280 §5; #565,
2//! T-102).
3//!
4//! Revoking a certificate sets the status on its row. Until this module that
5//! status reached exactly the places that read the row — device sign-in, and
6//! since the same change OAuth2 `tls_client_auth` — and nowhere else: a
7//! relying party that validates AXIAM-issued certificates itself, a FreeRADIUS
8//! server doing EAP-TLS or a VPN gateway, had no channel through which to learn
9//! of a revocation, although every AXIAM CA carries the `cRLSign` bit.
10//!
11//! # What is published
12//!
13//! A complete, version 2 CRL per issuing CA, DER-encoded, at
14//! `GET /pki/v1/{org_id}/ca/{ca_id}/crl` ([`crl_path`]), unauthenticated:
15//!
16//! - **signed with the CA's own key, fetched from the CA's own custodian** —
17//!   the custodian the CA row names, through the same `load` the leaf path
18//!   uses, so an RSA-4096 CA and an Ed25519 CA sign their lists exactly as they
19//!   sign certificates;
20//! - `thisUpdate` the start of the refresh epoch it was signed in, or the
21//!   newest revocation on it if later (#608, below); `nextUpdate` a
22//!   configurable interval later ([`DEFAULT_CRL_NEXT_UPDATE_SECS`]) and never
23//!   past the CA's own `notAfter`;
24//! - a CRL number and an authority key identifier equal to the CA's subject key
25//!   identifier — the two extensions RFC 5280 §5.2 requires of every CRL;
26//! - an entry for every certificate the CA signed and revoked that has not
27//!   expired, or expired during the previous refresh epoch or this one (so it
28//!   appears on a list issued after its expiry, as RFC 5280 §3.3 asks): its
29//!   leaves in every tenant, and the subordinate CAs it signed, so
30//!   an organization CA's list names a revoked tenant signing CA. Each entry
31//!   carries the serial read out of the certificate and the date AXIAM recorded
32//!   the revocation. No reason code: AXIAM does not record one, and RFC 5280
33//!   §5.3.1 prefers an absent reason to `unspecified`.
34//!
35//! # Which CAs publish one
36//!
37//! A CA AXIAM can sign with, while it is active and in date. Three kinds
38//! answer `404` instead, the same `404` as a CA that does not exist:
39//!
40//! - **a revoked or expired CA.** AXIAM signs nothing with one; its own status
41//!   is on its parent's list;
42//! - **an imported trust anchor with no key** (`external` custody): it cannot
43//!   sign anything, a list included;
44//! - **a CA whose key Vault's PKI engine holds** (`vault_pki`). Vault signs on
45//!   AXIAM's behalf only certificate requests; it has no operation that signs a
46//!   list AXIAM composed, and AXIAM never holds the key. Vault publishes that
47//!   CA's list itself, and AXIAM revokes each leaf there too
48//!   ([`crate::CertService::revoke`], T-470), so Vault's list names it. Leaves of
49//!   such a CA carry no AXIAM distribution point — Vault issues them with its
50//!   own profile, naming whatever the operator configured on the mount
51//!   (`config/urls`) — so nothing points at a route that cannot answer, and
52//!   relying parties read Vault's list (`/v1/<mount>/issuer/<issuer>/crl/der`).
53//!
54//! # Signing on request, and the cache in front of it
55//!
56//! A list is signed when it is first asked for and kept, per CA, until either
57//! the set of revoked certificates changes or its refresh epoch ends; every
58//! request still reads the set, so a revocation is in the next response.
59//! Two things follow. A relying party revalidating with `If-None-Match` gets a
60//! `304` until the list really changes, because an unchanged list is the same
61//! bytes. And a flood of requests costs one database read each and no
62//! signature, which matters on an unauthenticated route whose custodian may be
63//! a Vault round trip away.
64//!
65//! That read is light (#607): each revoked certificate's fingerprint and the
66//! date its entry states, never the certificate. The PEMs — what an entry's
67//! serial is read from — are read only when the list is actually signed.
68//!
69//! Each CA is re-signed on its own (#607). One flight at a time re-signs a
70//! given CA's list, through the custodian `load`, the crypto permit and the
71//! signature; requests for the same CA's changed list wait for it, and nothing
72//! else does. A cached list is answered without waiting on any re-sign, this
73//! CA's or another's. The permit comes from the semaphore issuance and password
74//! hashing share, and a flight waits for one at most
75//! [`DEFAULT_CRL_PERMIT_WAIT`]; past that it fails with `503`.
76//!
77//! The flight's outcome is shared (#616). A request that finds one in flight
78//! waits for it at most the same permit wait, then answers `503`, and is handed
79//! what the flight ended with — its `503` included — instead of starting a
80//! re-sign of its own behind it. So callers queued on a saturated gate all
81//! answer within about one permit wait, not one wait each in turn, and an
82//! unauthenticated caller is never queued without bound. A waiter that read a
83//! later state than the flight signed (a revocation committed meanwhile)
84//! starts the next flight rather than take a list without it. A flight runs as
85//! a task of its own, so a caller hanging up does not abandon it: its list is
86//! cached for the next request.
87//!
88//! # The same list from every replica (#608)
89//!
90//! Time is cut into **refresh epochs**, half the `nextUpdate` interval long and
91//! aligned to the Unix epoch, so every replica cuts at the same instants. What
92//! a list says is a function of the revocations in the store and of the epoch
93//! alone — `thisUpdate` is the epoch's start or the newest revocation date on
94//! the list, whichever is later, but never past the epoch's last second, and
95//! the CRL number is that `thisUpdate`, in seconds, above the entry count. Both
96//! CA key types sign deterministically (Ed25519, and RSA PKCS#1 v1.5), so two
97//! replicas signing the same state in the same epoch produce the same bytes and
98//! the same `ETag`, and a relying party behind a load balancer revalidates to
99//! `304`s wherever its request lands. A list served at the end of its epoch
100//! still has half its interval left.
101//!
102//! # When the number only grows (#615)
103//!
104//! RFC 5280 §5.2.3 asks for a CRL number that increases. The derivation gives
105//! one — `list_identity` argues each step — on two conditions, and the
106//! datastore's clock is not among them:
107//!
108//! - **The interval is unchanged.** Epochs are cut from it, so another
109//!   `AXIAM__PKI__CRL_NEXT_UPDATE_SECS` cuts other epochs: raising it moves the
110//!   current epoch's start back, and lowering it ends an expired entry's stay
111//!   sooner, while `thisUpdate` may stay put. Either can step the number back
112//!   once. A relying party that keeps its list until `nextUpdate` and refuses a
113//!   lower number is offered a greater one when it fetches again at
114//!   `nextUpdate` as long as the new interval is at most twice every interval
115//!   its list may have been signed under: lowering is safe once every replica
116//!   runs the new value, and raising goes in steps of at most a doubling, an
117//!   old interval apart. The PKI guide (`docs/pki/README.md`) gives the
118//!   operator the procedure.
119//! - **The replicas' clocks agree within half an epoch.** A replica whose clock
120//!   has passed a boundary serves the new epoch's list and one that has not
121//!   still serves the old, so a relying party alternating between the two can
122//!   see the previous epoch's number again for as long as the clocks disagree —
123//!   never an older epoch's, and never at its own `nextUpdate`, by which time
124//!   every such replica is past the boundary.
125//!
126//! A revocation date is written by the datastore's clock, which can be ahead of
127//! the signing replica's and so lie past the end of the epoch. `thisUpdate` is
128//! clamped to the epoch's last second and every entry's stated date to
129//! `thisUpdate`, so no list states a time outside its epoch and the next
130//! epoch's list, starting after every second of this one, has a greater number
131//! whatever left it (#615). What remains is that `thisUpdate` can be ahead of
132//! the replica's clock — and a strict relying party's — by as much as the
133//! datastore's clock leads, never past the epoch's end.
134//!
135//! The route's `Cache-Control: max-age` runs to the end of the epoch — at most
136//! half the interval — not to `nextUpdate`, so a shared cache revalidates with
137//! the `ETag` at least that often instead of serving a list from before a
138//! revocation until `nextUpdate`.
139//!
140//! # The distribution point
141//!
142//! [`CrlDistribution`] is the absolute URL of the route, built from the
143//! deployment's public base URL. `CertService` and `CaService` write it into
144//! every certificate they sign in-process from then on — leaves on both paths,
145//! and subordinate CAs — so a relying party that follows distribution points
146//! finds the list without being told. With no public base URL there is no
147//! absolute URL to write, and the extension is omitted; the composition root
148//! says so at boot.

175/// Default interval between a list's `thisUpdate` and its `nextUpdate`: one
176/// day. Env: `AXIAM__PKI__CRL_NEXT_UPDATE_SECS`.
177///
178/// It bounds how long a relying party that caches a list honours a certificate
179/// revoked after the list was fetched, which is the revocation window this
180/// whole module exists to shorten. A day is the common choice for a CA whose
181/// relying parties fetch on schedule; a deployment that needs a shorter window
182/// sets a shorter interval and pays for it in fetches.
183pub const DEFAULT_CRL_NEXT_UPDATE_SECS: u64 = 86_400;
184
185/// Shortest accepted interval: five minutes. Below it a relying party would
186/// spend more time fetching the list than trusting it.
187pub const MIN_CRL_NEXT_UPDATE_SECS: u64 = 300;
188
189/// Longest accepted interval: seven days. Past it the list stops being a
190/// revocation channel anybody should rely on.
191pub const MAX_CRL_NEXT_UPDATE_SECS: u64 = 604_800;
192
193/// The route a CA's list is published at, relative to the deployment's public
194/// base URL.
195pub fn crl_path(organization_id: Uuid, ca_id: Uuid) -> String {
196    format!("/pki/v1/{organization_id}/ca/{ca_id}/crl")
197}
198
199/// Check an operator's `nextUpdate` interval against
200/// [`MIN_CRL_NEXT_UPDATE_SECS`] and [`MAX_CRL_NEXT_UPDATE_SECS`].
201pub fn validate_next_update_secs(secs: u64) -> Result<u64, String> {
202    if (MIN_CRL_NEXT_UPDATE_SECS..=MAX_CRL_NEXT_UPDATE_SECS).contains(&secs) {
203        Ok(secs)
204    } else {
205        Err(format!(
206            "the CRL nextUpdate interval must be between {MIN_CRL_NEXT_UPDATE_SECS} and \
207             {MAX_CRL_NEXT_UPDATE_SECS} seconds, not {secs}"
208        ))
209    }
210}

212/// Where a relying party finds a CA's list: the absolute URL written into the
213/// CRL distribution points extension of every certificate signed after it is
214/// configured.
215#[derive(Debug, Clone, PartialEq, Eq)]
216pub struct CrlDistribution {
217    /// `scheme://host[:port][/path]`, with no trailing slash.
218    base: String,
219}
220
221impl CrlDistribution {
222    /// Validate a public base URL: absolute, `http` or `https`, with a host,
223    /// no userinfo and no query or fragment.
224    ///
225    /// What is stored is the parser's own serialisation of what was validated
226    /// (without the trailing slash), not the operator's text: the parser drops
227    /// tabs and newlines, lowercases the host and percent-encodes what needs
228    /// it, so the URI written into certificates is exactly the URL that passed
229    /// these checks.
230    ///
231    /// `http` is accepted on purpose. A CRL is signed, so the transport adds no
232    /// integrity, and RFC 5280 §4.2.1.13 expects distribution points that a
233    /// relying party can fetch before it can validate anything — some cannot
234    /// follow an `https` one without the chain they are trying to check.
235    pub fn new(base_url: &str) -> Result<Self, String> {
236        let trimmed = base_url.trim();
237        let parsed = url::Url::parse(trimmed)
238            .map_err(|e| format!("the CRL base URL is not an absolute URL: {e}"))?;
239        if !matches!(parsed.scheme(), "http" | "https") {
240            return Err(format!(
241                "the CRL base URL must be http or https, not {}",
242                parsed.scheme()
243            ));
244        }
245        if parsed.host_str().is_none_or(str::is_empty) {
246            return Err("the CRL base URL has no host".into());
247        }
248        if parsed.query().is_some() || parsed.fragment().is_some() {
249            return Err("the CRL base URL must carry no query or fragment".into());
250        }
251        if !parsed.username().is_empty() || parsed.password().is_some() {
252            return Err("the CRL base URL must carry no credentials (userinfo)".into());
253        }
254        Ok(Self {
255            base: parsed.as_str().trim_end_matches('/').to_owned(),
256        })
257    }
258
259    /// The distribution point configured explicitly, or else the one derived
260    /// from the deployment's issuer URL — `None` when neither is an absolute
261    /// `http(s)` URL.
262    ///
263    /// An explicit value that does not parse is an error rather than a
264    /// fallback: an operator who set one meant it, and certificates naming the
265    /// issuer instead would point somewhere they did not choose. An issuer that
266    /// is not a URL (the JWT `iss` fallback is often a bare name) yields `None`.
267    pub fn resolve(explicit: Option<&str>, issuer_url: &str) -> Result<Option<Self>, String> {
268        match explicit.map(str::trim).filter(|v| !v.is_empty()) {
269            Some(value) => Self::new(value).map(Some),
270            None => Ok(Self::new(issuer_url).ok()),
271        }
272    }
273
274    /// The absolute URL of a CA's list.
275    pub fn uri_for(&self, organization_id: Uuid, ca_id: Uuid) -> String {
276        format!("{}{}", self.base, crl_path(organization_id, ca_id))
277    }
278
279    /// The extension value for a certificate `issuer` signs.
280    pub(crate) fn point_for(&self, issuer: &CaCertificate) -> CrlDistributionPoint {
281        CrlDistributionPoint {
282            uris: vec![self.uri_for(issuer.organization_id, issuer.id)],
283        }
284    }
285}

287/// A signed list, as the route serves it.
288#[derive(Debug, Clone)]
289pub struct PublishedCrl {
290    /// The DER encoding.
291    pub der: Arc<[u8]>,
292    /// The list's `thisUpdate`.
293    pub this_update: DateTime<Utc>,
294    /// The list's `nextUpdate`.
295    pub next_update: DateTime<Utc>,
296    /// The list's CRL number.
297    pub crl_number: u64,
298    /// A strong entity tag over the DER, quoted.
299    pub etag: String,
300    /// When the origin re-signs the list even if nothing was revoked: the end
301    /// of the refresh epoch it was signed in, half a `nextUpdate` interval at
302    /// most after it was served (#608).
303    pub refresh_at: DateTime<Utc>,
304}
305
306impl PublishedCrl {
307    /// Seconds a shared cache may keep this list before revalidating it with
308    /// its `ETag` (#608): until the origin's next scheduled re-sign, so at most
309    /// half the `nextUpdate` interval and never past `nextUpdate`; never
310    /// negative.
311    ///
312    /// Not until `nextUpdate`, which is what a relying party may trust the list
313    /// for: an intermediary honouring that would serve the list from before a
314    /// revocation for up to the whole interval, although the origin answers
315    /// with the new one at once. Revalidating an unchanged list is a `304`.
316    pub fn max_age_secs(&self, now: DateTime<Utc>) -> u64 {
317        let until = self.refresh_at.min(self.next_update);
318        u64::try_from((until - now).num_seconds().max(0)).unwrap_or(0)
319    }
320
321    /// Whether an `If-None-Match` header names this list (RFC 9110 §13.1.2):
322    /// `*`, or any listed tag equal to [`Self::etag`], weak or strong.
323    pub fn matches_if_none_match(&self, header: &str) -> bool {
324        let wanted = self.etag.trim_start_matches("W/");
325        header
326            .split(',')
327            .map(str::trim)
328            .any(|candidate| candidate == "*" || candidate.trim_start_matches("W/") == wanted)
329    }
330}

332/// What the cache keeps per CA.
333struct CachedCrl {
334    crl: PublishedCrl,
335    /// Digest of the entries the list was signed over.
336    entries_digest: [u8; 32],
337    /// When the list is re-signed even if nothing was revoked: the end of its
338    /// refresh epoch, so a cached response always has at least half the
339    /// `nextUpdate` interval left.
340    refresh_at: DateTime<Utc>,
341}
342
343/// One CA's place in the cache: its last list, and the re-sign of it in flight
344/// (#607, #616).
345///
346/// Two locks, both `std` and neither held across an `await`, so that reading
347/// never waits on signing. `published` is held only to look at or replace the
348/// cached list; `flight` only to see whether a re-sign of this CA's list is in
349/// flight, and to claim it when none is. A request for an unchanged list takes
350/// only the first; a request for a changed list joins the flight already under
351/// way for the same CA, and waits on nothing any other CA is doing.
352#[derive(Default)]
353struct CaSlot {
354    published: StdMutex<Option<CachedCrl>>,
355    /// The outcome of the re-sign in flight, if one is: `None` in the channel
356    /// until it lands. Set only by [`Self::join_or_lead`] when unset, and
357    /// cleared only by the flight's own [`Landing`], so while a flight runs the
358    /// marker is that flight's.
359    flight: StdMutex<Option<watch::Receiver<Option<FlightOutcome>>>>,
360}
361
362/// What a re-sign ends with, as every request waiting on it receives it.
363type FlightOutcome = AxiamResult<PublishedCrl>;
364
365/// A request's part in a CA's re-sign (#616).
366enum Turn {
367    /// Another request's flight is under way: wait for its outcome.
368    Join(watch::Receiver<Option<FlightOutcome>>),
369    /// None was: this request starts one, and lands it.
370    Lead(Landing),
371}
372
373/// The claim on a CA's one flight, held by whatever runs it. Landing it hands
374/// every waiter the outcome; dropping it unlanded — a cancelled or panicking
375/// flight — clears the claim all the same, and the waiters, finding the channel
376/// closed with nothing in it, look again.
377struct Landing {
378    slot: Arc<CaSlot>,
379    outcome: watch::Sender<Option<FlightOutcome>>,
380    landed: bool,
381}
382
383impl Landing {
384    fn subscribe(&self) -> watch::Receiver<Option<FlightOutcome>> {
385        self.outcome.subscribe()
386    }
387
388    /// End the flight with `outcome`. The claim is cleared before the outcome
389    /// is sent: a request arriving in between finds no flight and the cache as
390    /// the flight left it, and one already waiting receives the outcome.
391    fn land(mut self, outcome: FlightOutcome) {
392        self.slot.end_flight();
393        self.landed = true;
394        self.outcome.send_replace(Some(outcome));
395    }
396}
397
398impl Drop for Landing {
399    fn drop(&mut self) {
400        // Not after `land`: by then another flight may hold the claim.
401        if !self.landed {
402            self.slot.end_flight();
403        }
404    }
405}
406
407impl CaSlot {
408    /// The cached list, if it was signed over exactly `digest` and is not yet
409    /// due for its refresh.
410    fn fresh(&self, digest: &[u8; 32], now: DateTime<Utc>) -> Option<PublishedCrl> {
411        let published = self
412            .published
413            .lock()
414            .unwrap_or_else(PoisonError::into_inner);
415        published
416            .as_ref()
417            .filter(|cached| {
418                cached.entries_digest == *digest
419                    && cached.crl.this_update <= now
420                    && now < cached.refresh_at
421            })
422            .map(|cached| cached.crl.clone())
423    }
424
425    fn store(&self, cached: CachedCrl) {
426        *self
427            .published
428            .lock()
429            .unwrap_or_else(PoisonError::into_inner) = Some(cached);
430    }
431
432    /// Join the flight under way for this CA, or claim it.
433    fn join_or_lead(self: &Arc<Self>) -> Turn {
434        let mut flight = self.flight.lock().unwrap_or_else(PoisonError::into_inner);
435        if let Some(outcome) = flight.as_ref() {
436            return Turn::Join(outcome.clone());
437        }
438        let (outcome, waiting) = watch::channel(None);
439        *flight = Some(waiting);
440        Turn::Lead(Landing {
441            slot: Arc::clone(self),
442            outcome,
443            landed: false,
444        })
445    }
446
447    fn end_flight(&self) {
448        self.flight
449            .lock()
450            .unwrap_or_else(PoisonError::into_inner)
451            .take();
452    }
453}

455/// How long a re-sign waits for a permit of the shared crypto semaphore before
456/// the route answers `503` (#607): five seconds, the default wait of the
457/// password-hash gate the semaphore also serves. It also bounds how long a
458/// request waits on a re-sign of the same CA's list already in flight (#616).
459///
460/// The semaphore is shared with issuance and with every Argon2id hash and
461/// verify. Without a bound a saturated gate would queue unauthenticated CRL
462/// requests without limit; with it, a caller is told to come back, and a cached
463/// list — which needs no permit — is served throughout.
464pub const DEFAULT_CRL_PERMIT_WAIT: std::time::Duration = std::time::Duration::from_secs(5);

466/// Signs and caches each issuing CA's certificate revocation list.
467#[derive(Clone)]
468pub struct CrlService<CA, CR> {
469    ca_repo: CA,
470    cert_repo: CR,
471    /// Shared bounding semaphore for CPU-bound crypto (CQ-B02).
472    crypto_semaphore: Arc<Semaphore>,
473    /// How long a re-sign waits for a crypto permit, and a request for a
474    /// re-sign in flight ([`DEFAULT_CRL_PERMIT_WAIT`]).
475    permit_wait: std::time::Duration,
476    /// Who holds the CA signing keys. See [`crate::ca_key_store`].
477    custodians: Arc<CaKeyCustodians>,
478    next_update: Duration,
479    /// One slot per CA that publishes a list. The map's lock is held only to
480    /// find or insert a slot, and a slot is inserted only for a CA that exists
481    /// and publishes one, so requests for made-up CA ids — the route is
482    /// unauthenticated — add nothing to it; a CA found to publish no list
483    /// (revoked or expired since) has its slot removed.
484    slots: Arc<StdMutex<HashMap<Uuid, Arc<CaSlot>>>>,
485}

487impl<CA: CaCertificateRepository, CR: CertificateRepository> CrlService<CA, CR> {
488    /// `next_update_secs` is the `thisUpdate` → `nextUpdate` interval; the
489    /// composition root validates it with [`validate_next_update_secs`].
490    pub fn new(
491        ca_repo: CA,
492        cert_repo: CR,
493        crypto_semaphore: Arc<Semaphore>,
494        custodians: Arc<CaKeyCustodians>,
495        next_update_secs: u64,
496    ) -> Self {
497        Self {
498            ca_repo,
499            cert_repo,
500            crypto_semaphore,
501            permit_wait: DEFAULT_CRL_PERMIT_WAIT,
502            custodians,
503            next_update: Duration::seconds(i64::try_from(next_update_secs).unwrap_or(i64::MAX)),
504            slots: Arc::default(),
505        }
506    }
507
508    /// Replace [`DEFAULT_CRL_PERMIT_WAIT`].
509    #[must_use]
510    pub fn with_permit_wait(mut self, wait: std::time::Duration) -> Self {
511        self.permit_wait = wait;
512        self
513    }

515    /// The current list of CA `ca_id` of organization `organization_id`.
516    ///
517    /// `NotFound` for a CA that does not exist in that organization **and** for
518    /// one that publishes no list (see the module docs): the route is
519    /// unauthenticated, and which of the two it is — or which custodian holds a
520    /// key — is not an outsider's business. The reason is logged.
521    ///
522    /// `ServiceUnavailable` when the list has to be signed and no crypto permit
523    /// came free within the permit wait ([`Self::with_permit_wait`]).
524    ///
525    /// When the list has to be re-signed and a re-sign of the same CA's list is
526    /// already in flight, the request waits for that one's outcome — at most the
527    /// permit wait, then `ServiceUnavailable` — and receives it, a
528    /// `ServiceUnavailable` included (#616).
529    pub async fn current(&self, organization_id: Uuid, ca_id: Uuid) -> AxiamResult<PublishedCrl>
530    where
531        CA: Clone + 'static,
532        CR: Clone + 'static,
533    {
534        self.current_from(organization_id, ca_id, Utc::now(), true)
535            .await
536    }

538    /// [`Self::current`], as of `now`.
539    ///
540    /// Everything the list says is a function of the revocations in the store
541    /// and of the refresh epoch `now` falls in (#608), so two replicas — or two
542    /// services in a test — asked at instants in the same epoch about the same
543    /// store answer with the same bytes. Exposed so a test can name the instant
544    /// rather than wait for an epoch to pass.
545    ///
546    /// The named instant is kept, in the past as in the future (#666): a list
547    /// asked for as of an earlier instant is signed with that instant's epoch
548    /// and validity window, not at the wall clock. Only [`Self::current`],
549    /// which asks as of the clock, lets a request that waited across an epoch
550    /// boundary move on to the new epoch.
551    pub async fn current_at(
552        &self,
553        organization_id: Uuid,
554        ca_id: Uuid,
555        now: DateTime<Utc>,
556    ) -> AxiamResult<PublishedCrl>
557    where
558        CA: Clone + 'static,
559        CR: Clone + 'static,
560    {
561        self.current_from(organization_id, ca_id, now, false).await
562    }
563
564    /// The body of [`Self::current`] and [`Self::current_at`]; `follow_clock`
565    /// says whether `now` is the wall clock, and so may be advanced while the
566    /// request waits.
567    async fn current_from(
568        &self,
569        organization_id: Uuid,
570        ca_id: Uuid,
571        now: DateTime<Utc>,
572        follow_clock: bool,
573    ) -> AxiamResult<PublishedCrl>
574    where
575        CA: Clone + 'static,
576        CR: Clone + 'static,
577    {
578        let not_published = || not_published(ca_id);
579
580        // Organization-scoped, as every CA lookup is (T-98): a CA id under the
581        // wrong organization is not found, not served.
582        let ca = match self.ca_repo.get_by_id(organization_id, ca_id).await {
583            Ok(ca) => ca,
584            Err(AxiamError::NotFound { .. }) => return Err(not_published()),
585            Err(e) => return Err(e),
586        };
587        if let Some(reason) = Self::why_unpublished(&ca, now) {
588            tracing::debug!(%organization_id, %ca_id, reason, "no CRL is published for this CA");
589            self.forget(ca.id);
590            return Err(not_published());
591        }
592        let store = self.custodians.store_for(ca.key_custody)?;
593        if store.signs_remotely() {
594            tracing::debug!(
595                %organization_id,
596                %ca_id,
597                "no CRL is published for this CA: its key is held by a custodian that signs \
598                 certificate requests only (vault_pki), and publishes the CA's list itself"
599            );
600            self.forget(ca.id);
601            return Err(not_published());
602        }
603
604        // Read on every request, and before any lock: a revocation is in the
605        // very next response. Only fingerprints and dates (#607) — whether the
606        // list changed is decided without reading a single certificate.
607        let epoch = self.epoch_of(now);
608        let mut stamps = self
609            .cert_repo
610            .list_revocation_stamps_by_issuer(ca.id, epoch.expiring_after)
611            .await?;
612        stamps.extend(
613            self.ca_repo
614                .list_revoked_children_stamps(ca.id, epoch.expiring_after)
615                .await?,
616        );
617        stamps.sort_by(|a, b| a.fingerprint.cmp(&b.fingerprint));
618        let digest = entries_digest(stamps.iter().map(|s| {
619            (
620                s.fingerprint.as_str(),
621                revocation_time(s.revoked_at, s.not_before),
622            )
623        }));
624
625        let slot = self.slot(ca.id);
626        if let Some(crl) = slot.fresh(&digest, now) {
627            return Ok(crl);
628        }
629        self.resign(slot, ca, digest, now, follow_clock).await
630    }
631
632    /// The list of `ca` as of a state whose entries digest is `digest`, which
633    /// the cache does not hold: from the re-sign of this CA's list already in
634    /// flight, or from one this request starts (#607, #616).
635    ///
636    /// One re-sign per CA at a time, and its outcome is shared. A request that
637    /// finds one in flight waits for it, at most the permit wait from when it
638    /// began waiting, then answers `ServiceUnavailable`; it is handed the
639    /// flight's failure, a `ServiceUnavailable` included, rather than starting
640    /// a re-sign of its own behind it, so callers queued on a saturated gate all
641    /// answer within about one permit wait instead of one each in turn. A
642    /// flight that signed a list leaves it in the cache, and a waiter takes it
643    /// from there only if it is of the state the waiter read; one that read a
644    /// later state — a revocation committed while the flight ran — starts the
645    /// next flight, so a revocation is still in the next response.
646    ///
647    /// The flight runs as a task of its own, so it ends — and its list is
648    /// cached — even when the request that started it is gone (an
649    /// unauthenticated caller can hang up at will). That request waits for it
650    /// without the waiters' bound: the flight bounds its own wait for a crypto
651    /// permit, and the custodian its own key read.
652    async fn resign(
653        &self,
654        slot: Arc<CaSlot>,
655        ca: CaCertificate,
656        digest: [u8; 32],
657        now: DateTime<Utc>,
658        follow_clock: bool,
659    ) -> AxiamResult<PublishedCrl>
660    where
661        CA: Clone + 'static,
662        CR: Clone + 'static,
663    {
664        let deadline = tokio::time::Instant::now() + self.permit_wait;
665        loop {
666            // A request asking as of the clock is never earlier than it: one
667            // that waited across an epoch boundary takes, or signs, the new
668            // epoch's list, not one older than the list a flight ahead of it
669            // may just have cached. A named instant (`current_at`) is kept.
670            let now = if follow_clock {
671                now.max(Utc::now())
672            } else {
673                now
674            };
675            match slot.join_or_lead() {
676                Turn::Lead(landing) => {
677                    // A flight that landed between this request's look at the
678                    // cache and its claim may have left exactly this list.
679                    if let Some(crl) = slot.fresh(&digest, now) {
680                        landing.land(Ok(crl.clone()));
681                        return Ok(crl);
682                    }
683                    let mut outcome = landing.subscribe();
684                    let flight = self.clone();
685                    let flight_slot = Arc::clone(&slot);
686                    tokio::spawn(async move {
687                        let signed = flight.sign(&flight_slot, &ca, now).await;
688                        landing.land(signed);
689                    });
690                    return match outcome.wait_for(Option::is_some).await {
691                        Ok(landed) => landed.clone().unwrap_or_else(|| Err(interrupted())),
692                        Err(_dropped) => Err(interrupted()),
693                    };
694                }
695                Turn::Join(mut outcome) => {
696                    let landed =
697                        match tokio::time::timeout_at(deadline, outcome.wait_for(Option::is_some))
698                            .await
699                        {
700                            Ok(Ok(landed)) => landed.clone(),
701                            // The flight ended without an outcome: look again.
702                            Ok(Err(_dropped)) => None,
703                            Err(_elapsed) => {
704                                tracing::debug!(
705                                    organization_id = %ca.organization_id,
706                                    ca_id = %ca.id,
707                                    "the CRL re-sign in flight did not land within the permit wait"
708                                );
709                                return Err(busy());
710                            }
711                        };
712                    if let Some(Err(failed)) = landed {
713                        return Err(failed);
714                    }
715                    if let Some(crl) = slot.fresh(
716                        &digest,
717                        if follow_clock {
718                            now.max(Utc::now())
719                        } else {
720                            now
721                        },
722                    ) {
723                        return Ok(crl);
724                    }
725                    // Signed over another state than this request read: the
726                    // next flight is this request's, or one it joins.
727                }
728            }
729        }
730    }

732    /// Sign `ca`'s list as of the store now, and cache it — the body of one
733    /// flight (#616).
734    async fn sign(
735        &self,
736        slot: &CaSlot,
737        ca: &CaCertificate,
738        now: DateTime<Utc>,
739    ) -> AxiamResult<PublishedCrl> {
740        let (organization_id, ca_id) = (ca.organization_id, ca.id);
741        let store = self.custodians.store_for(ca.key_custody)?;
742        // The certificates, read only to sign — and read again rather than
743        // trusted from the stamps, so the list is of the state as it is now.
744        let epoch = self.epoch_of(now);
745        let mut entries = self
746            .cert_repo
747            .list_revoked_by_issuer(ca.id, epoch.expiring_after)
748            .await?;
749        entries.extend(
750            self.ca_repo
751                .list_revoked_children(ca.id, epoch.expiring_after)
752                .await?,
753        );
754        entries.sort_by(|a, b| a.fingerprint.cmp(&b.fingerprint));
755        let digest = entries_digest(entries.iter().map(|e| {
756            (
757                e.fingerprint.as_str(),
758                revocation_time(e.revoked_at, e.not_before),
759            )
760        }));
761
762        // Derived, not read off the clock (#608): see `list_identity`.
763        let revocation_times: Vec<DateTime<Utc>> = entries
764            .iter()
765            .map(|e| revocation_time(e.revoked_at, e.not_before))
766            .collect();
767        // Never before the CA itself: a CA created mid-epoch states its own
768        // notBefore, a constant of the CA, so the derivation stays the same on
769        // every replica. Never past the epoch's last second (#615).
770        let (this_update, crl_number) = list_identity(
771            epoch.start.max(ca.not_before),
772            epoch.last_second(),
773            &revocation_times,
774        );
775        let next_update = (this_update + self.next_update).min(ca.not_after);
776        if next_update <= this_update {
777            tracing::debug!(%organization_id, %ca_id, "no CRL is published: the CA expires now");
778            return Err(not_published(ca_id));
779        }
780
781        let key_ref = CaService::<CA>::key_ref(ca);
782        let ca_key_pem = store
783            .load(&key_ref, ca.encrypted_private_key.as_deref())
784            .await?
785            .to_string();
786        let _permit = self.crypto_permit(organization_id, ca_id).await?;
787        let ca_cert_pem = ca.public_cert_pem.clone();
788        let der = tokio::task::spawn_blocking(move || {
789            sign_crl(
790                &ca_cert_pem,
791                ca_key_pem,
792                &entries,
793                this_update,
794                next_update,
795                crl_number,
796            )
797        })
798        .await
799        .map_err(|e| AxiamError::Internal(format!("spawn_blocking join error: {e}")))??;
800
801        let etag = format!("\"{}\"", hex::encode(&Sha256::digest(&der)[..16]));
802        let crl = PublishedCrl {
803            der: Arc::from(der),
804            this_update,
805            next_update,
806            crl_number,
807            etag,
808            refresh_at: epoch.end,
809        };
810        slot.store(CachedCrl {
811            crl: crl.clone(),
812            entries_digest: digest,
813            refresh_at: epoch.end,
814        });
815        Ok(crl)
816    }

818    /// The refresh epoch `now` falls in (#608).
819    fn epoch_of(&self, now: DateTime<Utc>) -> RefreshEpoch {
820        RefreshEpoch::of(self.next_update, now)
821    }

823    /// A permit of the shared crypto semaphore, or `ServiceUnavailable` once
824    /// the permit wait has passed (#607).
825    async fn crypto_permit(
826        &self,
827        organization_id: Uuid,
828        ca_id: Uuid,
829    ) -> AxiamResult<tokio::sync::SemaphorePermit<'_>> {
830        match tokio::time::timeout(self.permit_wait, self.crypto_semaphore.acquire()).await {
831            Ok(Ok(permit)) => Ok(permit),
832            Ok(Err(_closed)) => Err(AxiamError::Internal("crypto semaphore closed".into())),
833            Err(_elapsed) => {
834                tracing::warn!(
835                    %organization_id,
836                    %ca_id,
837                    wait_ms = u64::try_from(self.permit_wait.as_millis()).unwrap_or(u64::MAX),
838                    "the CRL could not be re-signed: no crypto permit came free in time"
839                );
840                Err(busy())
841            }
842        }
843    }

868    /// Why `ca` publishes no list, if it does not — the reasons that need no
869    /// custodian to answer.
870    fn why_unpublished(ca: &CaCertificate, now: DateTime<Utc>) -> Option<&'static str> {
871        if ca.status != CertificateStatus::Active {
872            return Some("the CA is not active; its own status is on its parent's list");
873        }
874        if now < ca.not_before || now >= ca.not_after {
875            return Some("the CA is outside its validity window");
876        }
877        if ca.key_custody == CaKeyCustody::External {
878            return Some("AXIAM holds no key for this CA: it was imported as a trust anchor");
879        }
880        None
881    }

906/// A digest that changes exactly when the list's entries would: over each
907/// entry's fingerprint and stated date, in fingerprint order.
908fn entries_digest<'a>(entries: impl Iterator<Item = (&'a str, DateTime<Utc>)>) -> [u8; 32] {
909    let mut hasher = Sha256::new();
910    for (fingerprint, revoked) in entries {
911        hasher.update(fingerprint.as_bytes());
912        hasher.update(b":");
913        hasher.update(revoked.timestamp().to_be_bytes());
914        hasher.update(b"\n");
915    }
916    hasher.finalize().into()
917}

919/// The date an entry states: when AXIAM recorded the revocation, or — for a
920/// certificate revoked before the date was kept — its own `notBefore`, the
921/// earliest moment anyone could have relied on it.
922fn revocation_time(revoked_at: Option<DateTime<Utc>>, not_before: DateTime<Utc>) -> DateTime<Utc> {
923    revoked_at.unwrap_or(not_before)
924}

926/// The date a list whose `thisUpdate` is `this_update` states for an entry
927/// revoked at `revoked` (#615): never later than the list itself. Only a
928/// revocation date past the epoch's end — written by a datastore clock ahead of
929/// the replica's — is moved, to the epoch's last second, and it states its own
930/// date again on the next epoch's list.
931fn stated_revocation_time(revoked: DateTime<Utc>, this_update: DateTime<Utc>) -> DateTime<Utc> {
932    revoked.min(this_update)
933}

935/// A slice of time half a `nextUpdate` interval long, aligned to the Unix
936/// epoch, so that every replica cuts time at the same instants (#608).
937struct RefreshEpoch {
938    /// Its first second: the earliest `thisUpdate` a list signed in it states.
939    start: DateTime<Utc>,
940    /// The first second of the next one, when a cached list is re-signed.
941    end: DateTime<Utc>,
942    /// The start of the previous epoch. A list names every revoked certificate
943    /// whose `notAfter` is later, so an entry stays until a list issued after
944    /// its expiry has named it (RFC 5280 §3.3) and leaves only when the epoch
945    /// moves on — never in the middle of one.
946    expiring_after: DateTime<Utc>,
947}
948
949impl RefreshEpoch {
950    /// Its last second: the latest `thisUpdate` a list signed in it states
951    /// (#615), so that every list of the next epoch states a later one.
952    fn last_second(&self) -> DateTime<Utc> {
953        self.end - Duration::seconds(1)
954    }
955
956    /// The epoch `now` falls in, for lists valid for `next_update`.
957    fn of(next_update: Duration, now: DateTime<Utc>) -> Self {
958        let half = (next_update.num_seconds() / 2).max(1);
959        let start = now.timestamp().div_euclid(half) * half;
960        let at = |secs: i64| DateTime::from_timestamp(secs, 0).unwrap_or(now);
961        Self {
962            start: at(start),
963            end: at(start.saturating_add(half)),
964            expiring_after: at(start.saturating_sub(half)),
965        }
966    }
967}

969/// Bits of the CRL number below `thisUpdate`, holding the entry count.
970const CRL_NUMBER_COUNT_BITS: u32 = 24;
971
972/// The `thisUpdate` and CRL number of a list of entries with these revocation
973/// dates, signed in the refresh epoch starting at `floor` — or, for a CA whose
974/// own `notBefore` is later, starting at that — and ending after `ceiling`, its
975/// last second (#608, #615).
976///
977/// Both are functions of the list's contents and its epoch alone, so every
978/// replica signing the same state in the same epoch states the same ones — and,
979/// with a deterministic signature (Ed25519; RSA PKCS#1 v1.5, the two key types
980/// a CA can have), produces the same bytes and `ETag`:
981///
982/// - `thisUpdate` is the later of `floor` and the newest revocation date on
983///   the list, in whole seconds — the moment the list's contents were last
984///   made true, never before the epoch began nor before the CA existed — but
985///   never later than `ceiling`. A revocation date is written by the
986///   datastore's clock, which may be ahead of the replica's; one past the
987///   epoch's end would otherwise carry `thisUpdate` out of its epoch, and the
988///   next epoch's first list could then state the same `thisUpdate` with fewer
989///   entries — a lower number (#615). [`sign_crl`] states no entry's date later
990///   than `thisUpdate`;
991/// - the CRL number is `thisUpdate` in seconds since the Unix epoch, shifted
992///   left 24 bits, plus the number of entries.
993///
994/// Under one interval the number grows with every change of a CA's list,
995/// whatever the datastore's clock says. Within an epoch the set of entries
996/// only grows: a revocation is never undone, an expired entry stays until the
997/// epoch ends (see [`RefreshEpoch::expiring_after`]), and the tenant purge
998/// keeps a revoked row for longer than that. A new entry raises `thisUpdate`
999/// or, when its date is not the newest (a revocation committed late, two in one
1000/// second) or `thisUpdate` is already at `ceiling`, the count. When the epoch
1001/// moves on, `thisUpdate` is at least the new epoch's start, later than
1002/// `ceiling` and so than every `thisUpdate` the old epoch stated — so even a
1003/// list that lost entries, because they expired, has a greater number. The
1004/// count saturates at 2^24 − 1 entries, past which two lists stating the same
1005/// `thisUpdate` would share a number. What the derivation cannot see — another
1006/// interval, another replica's clock — is in the module docs.
1007fn list_identity(
1008    floor: DateTime<Utc>,
1009    ceiling: DateTime<Utc>,
1010    revocation_times: &[DateTime<Utc>],
1011) -> (DateTime<Utc>, u64) {
1012    let secs = revocation_times
1013        .iter()
1014        .map(DateTime::timestamp)
1015        .fold(floor.timestamp(), i64::max)
1016        .min(ceiling.timestamp());
1017    let this_update = DateTime::from_timestamp(secs, 0).unwrap_or(floor);
1018    let count = u64::try_from(revocation_times.len())
1019        .unwrap_or(u64::MAX)
1020        .min((1 << CRL_NUMBER_COUNT_BITS) - 1);
1021    let number = (u64::try_from(secs).unwrap_or(0) << CRL_NUMBER_COUNT_BITS) | count;
1022    (this_update, number)
1023}

1030/// Sign a CRL over `entries` with the CA's key. Pure and blocking — the caller
1031/// runs it under the crypto semaphore, off the async runtime.
1032///
1033/// A revoked certificate whose PEM does not parse fails the whole list rather
1034/// than being left off it: a list that silently omits a revocation is worse
1035/// than no list, because a relying party trusts what it says.
1036pub(crate) fn sign_crl(
1037    ca_cert_pem: &str,
1038    mut ca_key_pem: String,
1039    entries: &[RevokedCertificate],
1040    this_update: DateTime<Utc>,
1041    next_update: DateTime<Utc>,
1042    crl_number: u64,
1043) -> AxiamResult<Vec<u8>> {
1044    let key_pair = KeyPair::from_pem(&ca_key_pem)
1045        .map_err(|e| AxiamError::Certificate(format!("invalid CA private key: {e}")));
1046    // Scrubbed as soon as it is parsed, as on the leaf path.
1047    ca_key_pem.zeroize();
1048    let key_pair = key_pair?;
1049
1050    // The authority key identifier must equal the CA certificate's subject key
1051    // identifier, whatever method produced it — an imported CA's is usually a
1052    // SHA-1 of its key, not rcgen's default — so it is read from the
1053    // certificate rather than derived again.
1054    let (_, ca_block) = x509_parser::pem::parse_x509_pem(ca_cert_pem.as_bytes())
1055        .map_err(|e| AxiamError::Certificate(format!("invalid CA certificate PEM: {e}")))?;
1056    let (_, ca_x509) = X509Certificate::from_der(&ca_block.contents)
1057        .map_err(|e| AxiamError::Certificate(format!("invalid CA certificate: {e}")))?;
1058    let key_identifier_method = ca_x509
1059        .extensions()
1060        .iter()
1061        .find_map(|ext| match ext.parsed_extension() {
1062            ParsedExtension::SubjectKeyIdentifier(kid) => Some(kid.0.to_vec()),
1063            _ => None,
1064        })
1065        .map_or(KeyIdMethod::Sha256, KeyIdMethod::PreSpecified);
1066
1067    let issuer = Issuer::from_ca_cert_pem(ca_cert_pem, key_pair)
1068        .map_err(|e| AxiamError::Certificate(format!("invalid CA certificate PEM: {e}")))?;
1069
1070    let revoked_certs = entries
1071        .iter()
1072        .map(|entry| {
1073            let (_, block) = x509_parser::pem::parse_x509_pem(entry.public_cert_pem.as_bytes())
1074                .map_err(|e| {
1075                    AxiamError::Internal(format!(
1076                        "revoked certificate {} is not PEM: {e}",
1077                        entry.fingerprint
1078                    ))
1079                })?;
1080            let (_, cert) = X509Certificate::from_der(&block.contents).map_err(|e| {
1081                AxiamError::Internal(format!(
1082                    "revoked certificate {} does not parse: {e}",
1083                    entry.fingerprint
1084                ))
1085            })?;
1086            Ok(RevokedCertParams {
1087                serial_number: SerialNumber::from_slice(&cert.serial.to_bytes_be()),
1088                revocation_time: to_offset(stated_revocation_time(
1089                    revocation_time(entry.revoked_at, entry.not_before),
1090                    this_update,
1091                ))?,
1092                reason_code: None,
1093                invalidity_date: None,
1094            })
1095        })
1096        .collect::<AxiamResult<Vec<_>>>()?;
1097
1098    let params = CertificateRevocationListParams {
1099        this_update: to_offset(this_update)?,
1100        next_update: to_offset(next_update)?,
1101        crl_number: SerialNumber::from(crl_number),
1102        // A complete list: every certificate this CA signed, leaves and CAs.
1103        issuing_distribution_point: None,
1104        revoked_certs,
1105        key_identifier_method,
1106    };
1107    let crl = params
1108        .signed_by(&issuer)
1109        .map_err(|e| AxiamError::Certificate(format!("CRL signing failed: {e}")))?;
1110    Ok(crl.der().to_vec())
1111}

1273    /// #615: a revocation dated past the epoch's end — a datastore clock ahead
1274    /// of the replica's — leaves `thisUpdate` at the epoch's last second and is
1275    /// stated no later than it; the next epoch's list, which no longer names an
1276    /// entry that expired at the boundary, still has a greater number.
1277    #[test]
1278    fn a_revocation_dated_past_the_epoch_is_stated_at_its_last_second() {
1279        let start = at(1_800_000_000);
1280        let last = last_of(start);
1281        let ahead = last + Duration::seconds(11);
1282        let older = at(1_799_999_000);
1283        let (this_update, number) = list_identity(start, last, &[older, ahead]);
1284        assert_eq!(this_update, last, "thisUpdate stays in its epoch");
1285        assert_eq!(number, (u64::try_from(last.timestamp()).unwrap() << 24) | 2);
1286        assert_eq!(stated_revocation_time(ahead, this_update), last);
1287        assert_eq!(
1288            stated_revocation_time(older, this_update),
1289            older,
1290            "a date inside the list's time is stated as recorded"
1291        );
1292        // The next epoch: the older entry expired at the boundary and left, and
1293        // the one dated ahead now states its own date.
1294        let next = last + Duration::seconds(1);
1295        let (next_update, next_number) = list_identity(next, last_of(next), &[ahead]);
1296        assert_eq!(next_update, ahead);
1297        assert!(next_number > number, "fewer entries, a greater number");
1298        // Before #615 the first list stated `ahead` as its thisUpdate, and the
1299        // second — the same thisUpdate, one entry fewer — a lower number.
1300        let unclamped = (u64::try_from(ahead.timestamp()).unwrap() << 24) | 2;
1301        assert!(next_number < unclamped);
1302    }

1304    /// #608: every change a CA's list can undergo raises its number.
1305    #[test]
1306    fn the_number_grows_with_every_change_of_the_list() {
1307        let epoch = at(1_800_000_000);
1308        let last = last_of(epoch);
1309        let (_, empty) = list_identity(epoch, last, &[]);
1310        // A revocation, dated in the epoch.
1311        let first = at(1_800_000_100);
1312        let (_, one) = list_identity(epoch, last, &[first]);
1313        assert!(one > empty);
1314        // A second one in the same second: thisUpdate stays, the count grows.
1315        let (_, two) = list_identity(epoch, last, &[first, first]);
1316        assert!(two > one);
1317        // A revocation committed late, dated before the newest: the count.
1318        let (_, late) = list_identity(epoch, last, &[first, first, at(1_800_000_050)]);
1319        assert!(late > two);
1320        // One dated past the epoch's end (#615): thisUpdate stops at the last
1321        // second, and the next one dated past it raises the count.
1322        let ahead = last + Duration::seconds(30);
1323        let (_, clamped) = list_identity(epoch, last, &[first, first, first, ahead]);
1324        assert!(clamped > late);
1325        let (_, clamped_again) = list_identity(epoch, last, &[first, first, first, ahead, ahead]);
1326        assert!(clamped_again > clamped);
1327        // The next epoch, after both earlier entries expired and left: fewer
1328        // entries, a greater number, because thisUpdate is the new epoch's
1329        // start.
1330        let next = at(1_800_000_000 + 43_200);
1331        let (this_update, emptied) = list_identity(next, last_of(next), &[]);
1332        assert_eq!(this_update, next);
1333        assert!(emptied > clamped_again);
1334    }
