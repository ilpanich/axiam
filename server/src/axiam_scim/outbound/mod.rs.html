1//! Outbound SCIM provisioning: AXIAM as the **client** of a downstream SCIM 2.0
2//! service provider (G-6, T23.6.2; decision D-57).
3//!
4//! The rest of this crate is a SCIM *server*. This module is the other
5//! direction: a tenant registers downstream service providers
6//! ([`axiam_core::models::scim_target::ScimTarget`]) and AXIAM pushes user and
7//! group lifecycle changes to them.
8//!
9//! # Four pieces
10//!
11//! * [`ScimProvisioner`] — the **source**. It implements the core
12//!   [`ProvisioningSink`](axiam_core::provisioning::ProvisioningSink) the user
13//!   and group repositories report every committed change to, and enqueues one
14//!   *reference* (`{resource_type, axiam_id}`, nothing else) per enabled target
15//!   on the shared outbound dispatcher as
16//!   [`OutboundKind::ScimPush`](axiam_core::outbound::OutboundKind::ScimPush).
17//! * [`ScimPushDeliverer`] — the **attempt**. It implements the core
18//!   [`OutboundDeliverer`](axiam_core::outbound::OutboundDeliverer) the
19//!   dispatcher's consumer calls: one attempt, classify, never decide — and no
20//!   request at all to a target whose per-target breaker is open (#550).
21//! * [`ScimReconciliation`] — the **repair** (T23.6.3, D-58): a nightly and an
22//!   on-demand run, claimed in the datastore so that one replica makes it, that
23//!   queues a reference for everything in scope and everything linked, reads
24//!   the downstream, clears the digest of what drifted, forgets links whose
25//!   resource is gone and deprovisions what AXIAM's tenant no longer wants
26//!   there — and **never touches an account the downstream's own application
27//!   made**. It is a method set of the deliverer (`reconcile_now`), because it
28//!   must go out through the very same guarded, credential-checked path.
29//! * [`wire`] — the RFC 7643 / RFC 7644 documents the deliverer sends and the
30//!   digest that lets it skip a `PATCH` that would change nothing.
31//!
32//! # Level-triggered delivery
33//!
34//! No attribute of a person ever sits in a queue or in the dead-letter queue.
35//! Each attempt re-reads the target, the resource and its link, and computes
36//! what the downstream **should** look like *now*; retries, reordering and
37//! duplicates therefore converge on the same state.
38//!
39//! | The resource, at the attempt | Link | The attempt does |
40//! |---|---|---|
41//! | user `Active` and in scope | none | `POST /Users` (a `409` adopts by `externalId`) |
42//! | user `Active` and in scope | yes | `PATCH` the mapped attributes, **skipped** when the digest is unchanged |
43//! | user out of scope, or any other live status | yes | per `deprovision`: `PATCH active=false`, or `DELETE` |
44//! | user out of scope, or any other live status | none | nothing (nothing is created downstream to deactivate) |
45//! | user `Deleted`, `Anonymized` or gone | yes | `DELETE`, **whatever** `deprovision` says; the link is removed |
46//! | group in scope (`push_groups`) | none / yes | `POST /Groups` / `PATCH` (`displayName`, `externalId`, `members`) |
47//! | group out of scope or gone | yes | `DELETE`; the link is removed |
48//!
49//! # The way out of the process
50//!
51//! Every request — SCIM calls and the OAuth2 token request alike — goes through
52//! `guarded_fetch_no_redirect` with `allow_private = false`: the host is
53//! resolved fresh, every address must be globally routable, the validated
54//! address is pinned, `https` is required, and a `3xx` is returned instead of
55//! followed, so neither the credential nor a person's attributes can reach a
56//! host the administrator did not name. Before the credential is sent the
57//! target is read once more and its `updated_at` compared with the read the
58//! attempt started from (T-406). Reasons that reach the audit log and the
59//! target's state are a fixed vocabulary: never a URL, a body, a name or a
60//! value.
